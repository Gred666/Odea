## 1. 结论

| 问题 | 结论 |
|---|---|
| 做成什么样 | 一块 24 高的墨色小块（暗色里是比界面亮一档的灰 #3A3A35），12px 字，左右 9；圆角 R=6，用规定的弧线（技术方案 §9.6）。有快捷键的带浅一档的等宽小键帽；状态类的多一行浅色说明；一行超过 280 就折行。**没有箭头、没有阴影**：离目标只有 6px，指向已经清楚；纯色块在什么底上都站得住，也省掉阴影在动画里的开销 |
| 什么时候出 | 第一次停 **500ms**；看完一个、400ms 内移到下一个，**立刻出**；离开后留 80ms，鼠标能移到提示上；按下按钮、Esc、滚动、切走窗口立刻收；键盘 Tab 到（`:focus-visible`）立刻出；触屏不出 |
| 怎么动 | 出现 120ms、消失 90ms，只淡 opacity。在挨着的按钮之间换目标（一排图标、状态栏那几颗，160px 以内）：**底色滑过去、宽度跟着变（180ms），字不动** —— 新字在终点原地淡入，旧字原地淡出。隔得远就直接换 |
| 给谁用 | 只有图标的按钮；被截断的文字（截断了才出）；状态类控件（「O」、同步）。和看得见的字重复的不出；能点的内容不放提示里（那是浮层） |
| 怎么做 | 一个不依赖 React 的小引擎 `src/lib/tooltip.ts`：每个窗口装一份，委托在 `document` 上，元素挂 `data-tip` 就有提示；整个窗口只有一个提示节点，反复用。137 处 `title=` 全换掉，加一条单测不许再出现 |
| 不用 Radix Tooltip | 装了没用（技术方案 §9.5）。它每个按钮要包一层组件、每个提示一个 portal，换目标是关一个再开一个，做不了「滑过去」；137 处要改成组件写法。委托 + 一个节点更轻，弹出窗口里也一样装 |

## 2. 现状

- **137 处 `title=`**，分在 25 个文件里（`DocumentView` 13、`NotesView` 9、`PropertiesPanel` 9、`CollabDialog` 9、`Launcher` 8、`bases/Toolbar` 7……）。
- 系统原生提示的毛病：要停一秒多才出；出在鼠标指针底下，压住目标；样式跟着系统走，暗色主题里也是亮的；在一排按钮之间移动，每一个都要重新等；带不了快捷键、带不了第二行；不同系统长得不一样。
- 正文里已经有一套自绘的悬停卡片：`src/editor/hoverCard.ts`（脚注预览、缩写全称）。做法就是这份方案要推广的：元素挂 `data-odea-tip`，卡片挂在 `body` 上、`position: fixed`，320ms 出、400ms 内移到下一个不用等、离开留 80ms。它是「读内容」的卡片（白底、带阴影），和这里的「标签」是两种东西，引擎可以共用（§5.4）。

## 3. 调研

- **WCAG 1.4.13（AA）**：悬停或聚焦时冒出来的内容要满足三条：**能关掉**（不移动鼠标、不挪焦点也能关，通常是 Esc）、**能悬停**（鼠标移到提示上它不消失）、**不自己消失**（不定时收，等触发的东西走了、用户关了、或者内容失效才收）。系统原生的 `title` 由浏览器管、不在要求内；自绘的就要做到。所以：Esc 收；离开留 80ms、提示本身接鼠标；不设定时消失。
- **Radix Tooltip 的默认值**：停 700ms 才出（`delayDuration`）；关掉以后 300ms 内移到另一个不用再等（`skipDelayDuration`）。这就是「一组提示」的通行做法：第一次要等，之后跟着走。Odea 取 500 / 400：700 对只有图标的按钮偏慢；400 和正文悬停卡片一致。
- **Apple HIG**：Mac 上指针停在元素上时出提示；建议按状态给不同的字（同一个按钮在不同状态下说不同的话）；以前的 Aqua 规范要求越短越好，60–75 个字符以内。Odea：「O」的提示随同步状态变；一句话为主，最多一行说明。
- **Odea 自己的规矩**（技术方案 §10.1、PITFALLS/动效）：带字的元素不缩放、不在合成器上位移（字先糊再抖）；淡入淡出之前对齐整物理像素，否则结束那一帧闪一下；只动 transform / opacity。所以「滑过去」只能让**没有字的底色**动，字原地淡入淡出。

## 4. 设计

### 4.1 长相

| 项 | 值 |
|---|---|
| 底色 | 亮：`ink` #1A1A18；暗：#3A3A35（比 `raised` #2B2B28 亮一档，落在 `canvas` #1E1E1C 上看得清，不刺眼）。新加 token `tip-bg` / `tip-fg` / `tip-dim` / `tip-key` |
| 字 | 12px，行高 17；主字 `tip-fg`（亮 #F2F2ED / 暗 #EEEEE9）；说明那一行 `tip-dim` #A8A8A0 |
| 尺寸 | 单行高 24（上 3 下 4 + 17）；左右 9；一行超过 280 宽就按 280 折行 |
| 圆角 | R = 6（`sm`），规定的弧线 |
| 快捷键 | 主字后面空 8；每个键一个小键帽：等宽 11px（纯英文数字才用 11，排版规范）、`tip-key` 底（白 12% / 10%）、圆角 4、左右 4、高 16。**只给真有的快捷键配**（Ctrl K、导出……），原型里刘海那几个 Ctrl 1–4 是示意，应用里没有 |
| 箭头、阴影 | 都没有 |

### 4.2 位置

- 每个触发元素自己说放哪边：`data-tip-side="bottom | top | right | left"`，默认 bottom。刘海的格子、「O」在下面；状态栏、底部的按钮在上面；侧栏里截断的标题在右边。
- 离目标 6px；那一边放不下就翻到对面；顺着那一边的方向夹在窗口里，离窗口边至少 8px。
- 坐标对齐整物理像素（`Math.round(x × dpr) / dpr`）。

### 4.3 时间

| 情形 | 数 |
|---|---|
| 第一次停下 | 500ms |
| 刚看完一个（400ms 内）移到下一个 | 0ms |
| 离开后 | 80ms 宽限，期间移到提示上就不收 |
| 出现 / 消失 | 120ms ease-out-quint / 90ms，只淡 opacity |
| 挨着的按钮之间换目标（160px 以内） | 底色 180ms ease-out-quint 滑过去；旧字 70ms 原地淡出，新字晚 50ms、120ms 原地淡入 |
| 隔得远换目标 | 直接换 |
| 按下按钮 | 立刻收，鼠标离开这个按钮之前不再出 |
| Esc、滚动（任何一层）、窗口失焦 | 立刻收；Esc 不拦，照常往下传 |
| 键盘焦点（`:focus-visible`） | 立刻出；鼠标点出来的焦点不出 |
| 触屏 | 不出 |
| 减少动效 | 不淡、不滑，直接出、直接收 |

### 4.4 「滑过去」怎么做

- 底色拆三片：左圆头、中间、右圆头。左圆头不动；中间那片 `scaleX`；右圆头 `translateX`；整块 `translate`。全是 transform，圆头不变形（中间那片是纯色矩形，缩放看不出来）。片和片叠 1px。
- 字是另一层，不跟底色动：新字放在终点，透明度从 0 到 1；旧字在原地淡出、淡完撤掉。字从头到尾没有位移、没有缩放。
- 打断：动画进行中换了目标，从当前算出来的位置接着滑（`commitStyles` 再开新动画）。
- 用户可以在原型里切「直接换」比较；推荐「滑过去」。

### 4.5 什么时候用、写什么

- **用**：只有图标的按钮（必须有）；被截断的文字（`data-tip-overflow`，量 `scrollWidth > clientWidth` 才出）；状态类控件，字跟状态走（「O」：「已同步 · 3 分钟前」；第二行「正在读取笔记 702 / 2000 · 离线」）。
- **不用**：按钮上本来就有字、提示和字一样；能点的东西（链接、按钮）放进提示 —— 那是浮层；长段说明 —— 放进对话框或文档。
- **写法**：动词开头说它做什么（「新建一篇笔记」「在文件夹中显示」），不写「点击这里……」；一句话，必要时第二行补条件或后果（「能在回收站里找回来」）；和命令面板里那条命令同名。

### 4.6 无障碍

- 无障碍名字还是 `aria-label`（图标按钮本来就要有）。提示的字和 `aria-label` 一样时，提示层 `aria-hidden`；多出来的（快捷键、说明）出现时挂到触发元素的 `aria-describedby` 上，收了撤掉。
- 提示层 `role="tooltip"`。
- 键盘：Tab 到就出（`:focus-visible`），Esc 收。

## 5. 怎么实现

### 5.1 引擎 `src/lib/tooltip.ts`

- 不依赖 React：`installTooltips(win: Window): () => void`。主窗口在 `Shell` 挂载时装一次；弹出窗口（`Popouts`）每个装一份，用 `paneWindow` 拿到那个窗口。
- 委托：`pointerover` / `pointerout` / `pointerdown`（捕获）/ `focusin` / `focusout` / `keydown`（Esc）/ `scroll`（捕获）/ `blur`。没有逐个元素的监听，没有 React 重渲染。
- 一个窗口一个提示节点（`position: fixed`，挂在 `body` 上），反复用；底色三片 + 两层字。
- 读 `data-tip`（主字）、`data-tip-kbd`（快捷键，空格分键）、`data-tip-detail`（第二行）、`data-tip-side`、`data-tip-overflow`。
- 内容在显示中变了（同步状态变了）：观察那个元素的 `data-tip*` 属性（`MutationObserver`，只在显示时挂），原地换字、宽度跟着变。

### 5.2 写法

```tsx
// 一个小帮手，返回 aria-label + data-tip*；快捷键从 lib/platform 的 shortcut() 来
<button {...tip("导出", { kbd: shortcut("Shift E"), side: "top" })}>…</button>
// 截断的文字
<span data-tip-overflow data-tip-side="right">{title}</span>
```

### 5.3 换掉 137 处 `title=`

- 图标按钮：`title` → `tip(...)`，`aria-label` 保留或由 `tip` 给。
- 截断的文字（标题、路径）：`title` → `data-tip-overflow`。
- 说明性的长 `title`（同步那一格的「已同步：……团队里谁在线」这种）：拆成主字 + 说明。
- 加一条单测（照 `styles/uiScale.test.ts`）：`src` 里的 TSX 不许再出现 `title=` 属性（SVG 的 `<title>`、`document.title` 不算）。
- 正在做的边栏改版先保留 `title`，这一步统一换。

### 5.4 和正文悬停卡片的关系

`editor/hoverCard.ts` 留着它自己的长相（白底卡片、标签、正文、操作提示）和 320ms（读内容要快一点）。计时、定位、Esc、多窗口这些抽到 `lib/tooltip.ts` 共用，免得两套行为不一样。

### 5.5 样式

`globals.css` 里加 `.odea-tip*` 和 `tip-*` token（亮暗两套）；圆角走 §9.6 的规定。

## 6. 验收标准

1. `src` 里 TSX 没有 `title=`（单测守着）；每个只有图标的按钮都有提示和 `aria-label`。
2. 时间：第一次 500ms；400ms 内换目标立刻出；离开留 80ms、能移到提示上；按下立刻收、离开前不再出；Esc、滚动、失焦立刻收；键盘焦点出、鼠标焦点不出；触屏不出。
3. 动效：出现 / 消失只淡；挨着的按钮之间底色滑、字不位移不缩放；逐帧对比（`scripts/perf/fade-frames.mjs` 加一个 `tooltip` 场景，1.5 倍屏、放慢 10 倍）：字所在区域和终帧的差异一路降到 0，没有「平台」、没有最后一帧的跳。
4. 位置：四个方向、翻面、夹在窗口里；1 / 1.25 / 1.5 倍屏上字是清楚的（整物理像素）。
5. 长相：亮暗两套、键帽、两行、折行，和原型一致。
6. 弹出窗口里也有，用的是那个窗口自己的节点。
7. 性能：显示一次只读一次触发元素的位置；`perf.mjs` 的常用操作不变慢。
8. 读屏：图标按钮读出 `aria-label`；有快捷键、说明时读得到（`aria-describedby`）。

## 7. 风险、待定

**要用户定的**（原型里能切着看）：

- 换目标时「滑过去」（推荐）还是「直接换」。
- 第一次 500ms 合不合手。
- 暗色用 #3A3A35 的灰块，还是反过来用浅色块。

**没核实的**：

- 原型的动画在内置浏览器里看不全（窗格隐藏时不走帧），终态截图看过（单行、键帽、两行、折行、贴窗口边夹回来），过程要在可见的窗口里看。
- macOS（WKWebView）没跑过：`corner-shape` 不支持时圆头退回普通圆角（§9.6 的退路）。
- 137 处里有没有藏着只靠 `title` 传递关键信息、换了以后要另想办法的，要逐个看。

## 9. 实现记录

### 9.1 做了什么（2026-11-20）

- **引擎** `src/lib/tooltip.ts`：照原型写成 TS。`installTooltips(win)` 返回拆掉的函数，同一个窗口重复装拿到同一份；
  委托在 `document` 上（`pointerover / pointerout / pointerdown` 捕获、`focusin / focusout`），`keydown`（Esc，捕获、不拦）、
  `scroll`（捕获）、`blur` 在 `window` 上；一个窗口一个节点 `.odea-tip`（`role="tooltip"`、`id="odea-tip"`），底色三片 + 一层层字。
  时间、尺寸全在 `TIP` 里（500 / 400 / 80 / 120 / 90 / 180 / 70 / 50、离目标 6、离窗口边 8、160 以内才滑、280 折行）。
  `placeBeside()` 放哪边、翻面、夹在窗口里、对齐整物理像素；字的宽高往上取到整物理像素。显示时只读一次目标的位置。
  节点上有 `data-state="shown | hiding | hidden"`，给测试和逐帧脚本看。
- **装在哪**：`boot/mount.tsx`（仓库窗口、启动器、速记小窗、做客窗口都经过它），弹出窗口在 `Popouts.tsx` 的 `PopoutWindow` 里各装一份。
- **写法** `tip(label, { kbd, detail, side, name })`：返回 `data-tip*`，`name` 默认顺手给 `aria-label`；元素上本来有字的传 `name: false`
  （无障碍名字还是那几个字，提示的字出现时挂到 `aria-describedby`）。重载过：`name: false` 的返回类型里没有 `aria-label`，
  和元素上自己写的 `aria-label` 不冲突（TS2783）。截断的字写 `data-tip-overflow`（值可选：给了就出这个值，不然出元素自己的字）。
  键帽：`lib/platform.ts` 加了 `ALT_KEY`、`keyCaps(...)`（mac 上连写 ⌘⌥J，别处 Ctrl Alt J）。只配真有的快捷键：
  关标签 `Ctrl W`（只给当前标签的关闭按钮）、换摆法 `Ctrl Shift B`、全局搜索的三个开关 `Alt C / W / R`、日程切换 `Ctrl Alt J`、命令面板返回 `Esc`。
- **样式** `globals.css`：`--color-tip-bg / fg / dim / key` 亮暗两套（暗色 #3A3A35）；`.odea-tip*` 一节，圆头 `var(--corner-sm)` + `corner-continuous`、
  键帽 `var(--corner-xs)`，`radius.test.ts` 过。`.odea-tip` 一直 `will-change: opacity`，`z-index` 在换主题那层旧页面副本之下。
- **替换**：TSX 里落到 DOM 上的 `title` 93 处，加上把 `title` 原样转给元素的 `BannerButton`、属性面板的 `FooterButton`（都改名 `hint`）、
  `DropdownMenu.Item`，全换掉，48 个文件。图标按钮 `tip(...)`；截断的字（侧栏、列表、标签、路径、Toast、链接、值）`data-tip-overflow`；
  长说明拆成主字 + 第二行（删除「可以撤销」、类型图标「点了换类型」、同步那几句、协作「记住 TA」……）。
  另外给侧栏、列表里的笔记 / 文件夹标题加了 `data-tip-overflow`（以前没有 `title`，截断了看不全）。
- **单测**：`lib/tooltip.test.ts` 扫 `src` 的 TSX（TypeScript 语法树）：小写标签（含 `motion.*`）和带命名空间的原件（`DropdownMenu.Item`）上不许有 `title`；
  `plugins/whiteboard/` 列为例外（还在做、没提交，白板合并时一起换）。`tip()`、`placeBeside()` 四个方向、翻面、夹边、1.25 / 1.5 倍屏整物理像素。
  `lib/tooltip.dom.test.ts`（happy-dom）：500ms、warm 400ms、离开留 80ms、移到提示上不收、不定时收、触屏不出、键盘焦点立刻出 / 鼠标焦点不出、
  Esc 收且不拦、按下收且离开前不再出、目标那一层滚动 / 失焦收、目标被拆掉收、截断才出、键帽 + 第二行 + `aria-describedby`、内容变了原地换、一窗一个节点。
- **正文的悬停卡片**（§5.4）：`editor/hoverCard.ts` 改用 `placeBeside()`（首选上方、放不下翻到下方、夹在窗口里、对齐物理像素）和 `TIP.warm`、`TIP.grace`；
  320ms、长相、状态机留着自己的。状态机没合：它是 CodeMirror 的 ViewPlugin，只听 `contentDOM`、目标会被重建（`update` 里查 `isConnected`），
  合成一套要改它的生命周期，收益小、风险大。
- **逐帧**：`scripts/perf/fade-frames.mjs` 加了 `tooltip`（第一次淡入）、`tooltip-glide`（刘海「文件」→「今日TODO」滑过去）两个场景：
  setup 用合成的指针事件演一遍量出终点那层字在哪，截的就是那一块。顺手修了脚本的平台判断：开头还没动的那几帧（第一次要停 500ms 真时间）不算平台。

### 9.2 和方案不一样的地方

- 主窗口装在 `boot/mount.tsx` 而不是 `Shell`：启动器、速记、做客窗口也有 `title`，一处装全有。
- 滚动只在**目标所在的那一层**（或整页）滚的时候收：别处自己在滚（同步时正文跟着动、列表在加载）不碍事。§4.3 写的是「任何一层」。
- 多了一条：**提示和元素上看得见的字重复就不出**（`repeatsVisibleText`：没带快捷键、说明，元素的 `innerText` 已经包含主字，且没被截断）。
  `bases` 工具条的按钮宽的时候写着「筛选」，窄的时候只剩图标，一份 `tip("筛选")` 两种情况都对。
- 键盘焦点在输入框上不出：输入框一聚焦就算 `:focus-visible`，鼠标点进去也会出。
- 表情选择器的格子不再出提示（以前是 `title`）：名字和短码本来就在底栏里跟着指到的走；格子一格挨一格，能悬停的提示会挡住下一行。
- 属性面板值的输入框：以前 `title` 兼当它的无障碍描述（「类型不符」），换成一个 `sr-only` 的 `<span>` + `aria-describedby`，悬停时照样出提示。
- 单测守的是「落到 DOM 上的 `title`」：自己组件叫 `title` 的 prop（`<Empty title>`、`<PanelHeader title>` 这些是标题）不算，没改名。
- 换摆法按钮的数据 `ViewSwitch.title`（「以白板查看（Ctrl+Shift+B）」）改成 `kbd`（`NoteViewHost.tsx`）。

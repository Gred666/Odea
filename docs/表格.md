## 1. 结论

| 问题 | 方案 | 为什么 |
|---|---|---|
| 编辑时整张表跳 | 一进表格就把列宽量下来锁住（`table-layout: fixed` + `<colgroup>`），离开时滑到新的自动列宽；编辑态不换字号 | 现在点一格列宽挪 6–24px，打几个字整列宽度翻倍（§2） |
| 一次只能动一格 | 加「格子选区」：拖过格子、Shift+方向键选一片，复制、清空、粘贴、合并都对着这一片 | 所有像样的表格编辑器都有（ProseMirror 的 `CellSelection`、Notion、Obsidian 1.5） |
| 工具栏 | 去掉右上角那条 9 个图标的工具栏。改成：悬停时行左边、列上面出一个抓手（点 = 选中整行 / 整列 + 菜单，拖 = 换位置），边上出「+」；右键菜单 | 操作贴着被操作的东西；不用的时候什么都不显示 |
| 不规则表格 | GFM 表格 + 两个记号：格子里只写 `<` = 和左边合并，只写 `^` = 和上面合并 | 还是一张合法的 GFM 表格：GitHub、Typora 看到的是多了几个 `<` `^` 的普通表格，不丢东西；git diff、协同按字合并都和现在一样。和 Obsidian 的 Structural Tables / Sheets 插件同一套写法 |
| 新建表格 | `/表格`、Ctrl+T 直接插一张渲染好的 3 列 × 2 行空表，光标在第一格 | 现在插进去的是源码、「标题 / 内容」占位字被选中，第一眼看到的是一堆竖线 |
| 粘贴 | 从 Excel / 飞书 / 网页复制的表格：在正文里粘贴变成 Markdown 表格（合并的格子写成 `<` `^`），在格子里粘贴从这一格起铺开、不够就加行加列 | 现在整块挤进一格，换行变 `<br>`、Tab 原样留着 |
| 同类的东西 | CSV / TSV 围栏、HTML 表格共用同一个表格编辑器；「把一批笔记的属性列成表」另开一期 | 前两个本来就是表格，只是写法不同；后一个是数据库视图，不是文档里的表格 |

## 2. 现在的表格哪里差（实测）

2026-10-30 在浏览器预览里（1280×860、1 倍屏）放一张 5 列的表实测，数字是 `getBoundingClientRect` 量的：

| 操作 | 量到的 | 用户看到的 |
|---|---|---|
| 点「备注」列的一格（里面有 `**重点**`） | 第 2–5 列的左边从 526 / 628 / 734 / 851 变成 520 / 616 / 716 / 827 | 点一下整张表往左缩一截。格子露出源码比渲染的宽，自动表格布局按新内容重新分列宽 |
| 点表头的一格 | 表高 189 → 192，表身下移 3px | 表头编辑时从 13px / 600 换成 15px / 500（`globals.css` 的 `th.is-editing`），行高变了 |
| 在表头格子里打一句话 | 这一列 104 → 266px，别的列挤窄，表高 192 → 262 | 每打一个字整张表重新分一次列宽，字在眼前左右跳 |

不是 bug、是缺的：

1. **只能一格一格改。** 每格是一个独立的 `contenteditable`（`tableWidget.ts` 的 `beginEdit`），拖不过格子边界：选不了一片、复制不了一块、清空不了一列
2. **粘贴。** `paste` 一律当纯文本塞进当前格，换行写成 `<br>`（`tableWidget.ts:891`）。从 Excel 复制 3×3 进来是一格里的一长串
3. **工具栏。** 9 个 15px 的图标浮在表格右上角，没有字；行插入 / 行删除、左插列 / 右插列的图标要猜；操作的是「正在编辑的那一格」，那一格可能在表格最左下角，离工具栏很远。对齐是按列的，却放在整张表的工具栏上
4. **点到边框整张表变回源码**（`tableWidget.ts:844`）。格子之间的缝、表格的外框都算，一不小心就是满屏竖线
5. **新建就是源码**（`markdownCommands.ts:157`、`suggest.ts:223`）
6. **没有加行加列的入口**，除了工具栏和最后一格 Tab；不能拖动换行换列；不能按列排序
7. **不规则表格只能手写 HTML**，渲染出来只读，点一下回到 `<table><tr><td rowspan="2">` 源码

## 3. 调研：别家怎么做

### 3.1 编辑体验

| | 选区 | 加 / 删 / 换位置 | 合并 | 存成 |
|---|---|---|---|---|
| Notion 简单表格 | 拖选一片格子；Esc 选中当前格 | 行、列抓手：点开菜单、拖动换位置；右边、下边悬停出「+」，拖着能一次加好几行 | 2026-05 加的：选一片 → 格子菜单 → 合并 | 自己的块结构 |
| Obsidian 1.5+（自带） | 选行、选列、复制粘贴 | 点表格两边加行加列；排序、换位置；右键菜单、命令面板、快捷键都能做；1.5.8 起边打字边排版源码 | 不支持 | 纯 GFM |
| Obsidian Structural Tables 插件 | Shift+方向键选一片，Delete 清空 | 行 / 列抓手：点 = 选中，拖 = 换位置，Shift+点扩选；右键：删行列、转置、编辑源码 | `<` 和左边合并、`^` 和上面合并；分隔行上面的行都是表头 | GFM + 记号 |
| ProseMirror `prosemirror-tables`（Tiptap、GitLab 富文本编辑器用的） | `CellSelection`：拖过格子边界变成选格子 | 命令 | `mergeCells` / `splitCell` | 文档模型里有 `colspan` / `rowspan` |
| Typora | 无 | 右键菜单、悬停工具条 | 不支持 | 纯 GFM |

几家共同的地方：**平时什么控件都不露**，鼠标到哪一行 / 哪一列才在那里出抓手；**加东西的「+」出在要加的位置**；**菜单挂在抓手和右键上**，不放常驻工具栏。

### 3.2 合并单元格的写法

| 写法 | 合并 | 别的编辑器里 | 问题 |
|---|---|---|---|
| `<` / `^`（Obsidian Sheets、Structural Tables） | `<` 左、`^` 上 | 合法 GFM，显示成带 `<` `^` 的普通表 | 格子内容恰好是 `<`、`^` 要写成 `\<`、`\^` |
| `>` / `^`（VS Code 的 Markdown Preview Enhanced） | `>` 向右、`^` 向上 | 同上 | 和 Obsidian 生态不一样 |
| MultiMarkdown / `markdown-it-multimd-table` | 行尾 `\|\|` 横跨、`^^` 向上 | 同上 | `\|\|` 在 GFM 里本来就是「一个空格子」，同一份源码两种意思 |
| Pandoc grid table（`+---+` 画框） | 3.7 起写出时支持跨行跨列 | GitHub、Obsidian、Typora 都不认 | 改一个字要重画整个框：git diff、协同按字合并都是灾难 |
| HTML `<table>`（GitLab 富文本编辑器里格子放了块级内容时就退回 HTML） | `rowspan` / `colspan` | 到处都能渲染 | 源码难读难改，HTML 里的 Markdown 多数渲染器不认 |

## 4. 不规则表格存成什么

### 4.1 写法

GFM 表格不变，多两个记号。一格里**只有** `<`（两边空白不算）= 这一格并进左边那一格；只有 `^` = 并进上面那一格。

```markdown
| 阶段   | 内容       | 负责人 |
|:-------|:-----------|:-------|
| 第一期 | 编辑体验   | 张三   |
| ^      | 格子选区   | ^      |
| 第二期 | 合并单元格 | 李四   |
| 备注   | 第二期才引入新写法 | <  |
```

渲染出来：「第一期」「张三」竖着跨两行；最后一行「第二期才引入新写法」横跨后两列。

- **矩形合并**：左上角那一格放内容；第一行其余写 `<`；下面几行第一格写 `^`、其余写 `<`。读的时候 `<`、`^` 都顺着指过去找到同一个起点就行，写的时候按这个固定写法
- **表头和表身之间不能竖着并**（表头下面一行的 `^` 当普通字）。表头里可以横着并
- **字面的 `<`、`^`**：写成 `\<`、`\^`（CommonMark 本来就认这两个转义，别处显示的还是 `<`、`^`）。格子里输入一个单独的 `<` 时写回自动加反斜杠，和现在 `|` 自动转义一样
- **对不上的记号**（`<` 在第一列、`^` 在第一行、并出来不是矩形）当普通字显示，不报错

### 4.2 为什么不用别的

- **HTML**：源码没法看，Typora 式「点进去露出源码」的手感就没了。HTML 表格照样**能读、能渲染、能在格子里改**（§8），只是新建的、合并出来的不写成 HTML
- **Grid table**：改一个字整个框重画，团队仓库的 git diff、协同的按字合并都扛不住
- **只给 Odea 自己认的写法**（比如 ```` ```table ```` 里放 JSON）：离开 Odea 就是一坨数据。笔记是用户的 Markdown 文件，这条不碰

### 4.3 代价

- GitHub、Typora、没装插件的 Obsidian 里看到 `<`、`^`。内容不丢、行列不乱，能看懂
- 想发给别人看合并效果：右键「复制为 HTML」/ 导出时转成 `<table>`
- `numericColumns`（数字列右对齐）、`formatGfmTable`（插删列重新排版）要跳过记号格

## 5. 交互

### 5.1 三种状态

| 状态 | 怎么进 | 样子 |
|---|---|---|
| 平常 | — | 渲染好的表 |
| 改一格 | 单击格子 | 这一格露出源码（和现在一样），列宽锁住 |
| 选了一片格子 | 在格子里按下、拖到别的格子；改一格时按 Esc；Shift+点；点行 / 列抓手 | 选中的格子铺一层浅主色，外面一圈 2px 主色框 |

### 5.2 鼠标

- **行抓手**：鼠标在哪一行，表格左边外面出一个竖的六点抓手；**列抓手**：在哪一列，表头上沿出一个横的六点抓手。点 = 选中整行 / 整列并弹菜单；按住拖 = 换位置（拖的时候一条主色细线标出放在哪）
- **「+」**：表格下边、右边悬停出一条细的「+」条，点一下加一行 / 一列，按住往外拖一次加好几行（Notion 的做法）。两行之间：行抓手那一栏里，鼠标靠近两行的分界时出一个小「+」，点了在那里插一行；列同理
- **右键**：插入（上 / 下 / 左 / 右）、删除行 / 列、合并 / 拆分、对齐、按这一列排序（升 / 降）、复制为 Markdown / CSV / HTML、清空、删除表格、编辑源码
- **选了一片（两格以上）**：这一片右上角浮一个小胶囊「合并」（已经是合并格时是「拆分」）
- **点外框、格子之间的缝**：不再整张表退回源码。源码只从菜单进

### 5.3 键盘

改一格时（保留现在的）：Tab / Shift+Tab、Enter 下一行、Shift+Enter `<br>`、Mod+Enter 下面插一行、方向键在格子两头时跨格、走出表格回到正文、Mod+Z 走正文的历史。改一处：**Esc 先选中这一格，再按一次 Esc 回正文**（Notion 的做法；现在一按就走）。

选了一片时：

| 键 | 做什么 |
|---|---|
| 方向键 / Shift+方向键 | 移动 / 扩大选区（跨过合并格按看到的位置走） |
| Enter、F2、双击 | 改这一格（内容保留，光标在末尾） |
| 直接打字 | 清空这一格、开始改（和 Excel 一样） |
| Delete / Backspace | 清空选中的格子 |
| Mod+C / X / V | 复制（同时放 TSV、HTML、Markdown）/ 剪切 / 粘贴（从左上角铺开，不够就加行加列） |
| Mod+A | 改一格时第一下全选这一格的字，第二下选整张表 |
| Alt+Shift+↑↓←→ | 整行 / 整列换位置 |

### 5.4 合并和拆分怎么动

- **合并**：选中的格子里有字的按「先行后列」用 `<br>` 接起来放进左上角（Notion、飞书都不丢字）
- **拆分**：左上角留着内容，其余变空格子
- **插行插到一个竖着合并的格子中间**：新行这一列写 `^`，合并格跟着变高（电子表格的习惯）
- **删掉合并格的第一行**：下一行接手内容，`^` 换成内容
- **排序**：表身里有竖着合并的格子时不给排（菜单里灰掉，悬停说为什么）

### 5.5 新建、粘贴

- `/表格`、Ctrl+T：插一张渲染好的空表（表头 + 2 行 × 3 列），光标在第一格。源码里写成 `|   |   |   |` 这种空格子
- 正文里粘贴剪贴板里的 HTML 表格（Excel、Numbers、飞书、网页都会放 `text/html`）或成块的 TSV：变成 Markdown 表格，`rowspan` / `colspan` 换成 `^` / `<`；格子里有图片、列表这类块级内容的，按纯文字收
- 格子里粘贴多格：从这一格起铺开；只有一段文字的照旧插在光标处

## 6. 界面

- **平常的样子基本不动**：圆角卡片、细横线、极淡竖线、浅底表头（排版规范 §5）。合并格就是一个大格子，竖线、横线跟着断开
- **编辑态不换字号、字重**：表头改的时候还是 13px / 600，只是露出源码、白底、主色框
- **列宽锁住**：第一次点进表格时量每一列的宽度写进 `<colgroup>`，`table-layout: fixed`；格子里字多了只往下长。离开表格（焦点出去、Esc 回正文）再放开：先量出新的自动列宽，再从锁住的宽度滑过去（§10.3）
- **抓手、「+」、胶囊**：整张表只有一个行抓手、一个列抓手，跟着鼠标换位置 —— 按 CLAUDE.md 是「会淡入淡出的小控件」：`will-change: opacity`、每次淡之前 `snapToDevicePixels`，只淡 `opacity`。拖动换位置时被拖的那一行不跟着鼠标走（不做位移动画），只画落点线，松手直接换
- **选区**：底色用 `--color-accent-wash`，外框是盖在选区上的一个 `border: 2px` 的框（不用 `box-shadow`），四个角上的跟着外框的内圆角走（现在编辑格子的那一套）
- **宽表**：留在卡片里横向滑动，第一列钉住、右边缘渐隐（§10.4）
- **右上角的工具栏、CSV 的标签栏**：工具栏去掉；CSV / TSV 的标签栏留着（格式名、行列数、复制），「源码」挪进右键菜单

## 7. 实现思路

还是 CodeMirror 块级替身里放一张自己管的表（现在的架构），换掉里面的两层：

**模型。** `markdownTable.ts` 解析出来的从「`header` + `rows` 两个字符串数组」换成网格：每一格有内容、源码位置、`rowSpan` / `colSpan`，被盖住的格子指向它的起点。GFM（带 `<` `^`）、CSV / TSV、简单的 HTML 表格三种源码都解析成同一种网格。

**写回。** 所有操作都变成「网格上的操作 → 源码改动」：
- 改字：只换这一格变了的那几个字（现在的 `minimalChange`，协同靠它）
- 合并 / 拆分：只改被盖住的那几格（写成 `<`、`^` 或清空），不重排整张表
- 插删行：插删那一行源码；插删列、换列的位置：整张表 `formatGfmTable` 重排（现在就是这样）
- 每一个操作是一次 `dispatch`，撤销一下回来一步

**格子里的编辑器。** 现在是 `contenteditable` 一格露整格源码，光标是系统的。想和正文一个手感（只有光标碰到的 `**` 才露出来、自绘光标、自绘选区），换成**只给正在改的那一格建一个子 CodeMirror**，装上正文的行内装饰层（`typoraInlineDecorations`），改动转发进主编辑器、撤销走主编辑器的历史。Obsidian 自带的表格编辑器就是每格一个子编辑器。要先验证：组字、撤销合并、协同时远端改了同一格、`<br>` 在子编辑器里显示成换行。验证不过就先留 `contenteditable`，不挡别的。

**和现有机制的交界**：块级层的表格缓存（`parsedTable`）、估计高度（合并格按行算）、协同时远端插删行列的对齐（`alignTo` 改成按网格对）、窗格里别写死 `document`（`docOf` / `winOf`，标签页与分屏 §18）。

## 8. 和表格同类的东西

| 东西 | 现在 | 打算 |
|---|---|---|

## 10. 定下来的四件事

2026-10-30 再查了一轮之后定的。

### 10.1 合并记号：`<` 和 `^`

- 用的人最多的两个 Obsidian 插件（Structural Tables、Sheets Extended）都是 `<` 向左、`^` 向上，Structural Tables 的说明里写明「整格只有 `<`、`^` 的归它解释」。Odea 的仓库常常就是 Obsidian 的仓库（`odea-desktop-p112` 那一套就是拿 Obsidian 仓库测的），同一份文件两边看到同一种合并，比什么都重要
- `>` 向右（VS Code 的 Markdown Preview Enhanced）的问题：内容写在合并块的**最右边**，左边一串 `>`。在不认这套写法的地方（GitHub）看，先看到一排箭头才看到字；`<` 是先看到字、后面跟着「同左」，读起来顺
- 两个记号都指向内容所在的那一格：`<` 指左、`^` 指上，看源码就知道往哪边找
- MultiMarkdown 的 `||` 在 GFM 里本来就是「一个空格子」，同一份源码两种意思，排除

### 10.2 多行表头：不做

- GFM 要求表头只有一行、紧跟着分隔行。Structural Tables 的多行表头（分隔行上面好几行）在 GitHub、Typora 里，上面多出来的那几行不算表格，变成表格上方的一段带竖线的文字；它的「行表头」在分隔行里写 `||`，GFM 认不出分隔行，整张表都不是表格了
- 两种都会让文件在别处坏掉，违背 §4.2「离开 Odea 不能变成一坨」。分组表头用「表头里横着合并」就能表达大多数情况
- Odea 读到这样的表时和 GitHub 一样处理（上面几行是普通段落），不另外认

### 10.3 列宽：不存，编辑时锁住

- GFM 没有放列宽的地方。Pandoc 有一条规矩：某一行超过 `--columns`（默认 72）时，按分隔行里 `-` 的个数分列宽，否则忽略。拿它存列宽，分隔行的横线就不能再跟着内容对齐（插删列时 `formatGfmTable` 的排版），而且只在长表里生效，规矩说不清楚
- 存在 HTML 注释里能做到，但每张表前面多一行别人看不懂的东西，换来的只是「拖一下列宽」，不值
- 所以：平时是自动列宽；进了表格（改格子、选格子）就锁住，离开时**列宽用 ease-out cubic 滑到新的自动列宽**（CLAUDE.md 动效规矩 7：动排版用起步就走、收尾短的曲线），不是一下跳过去。插列、删列也一样：新列从 0 宽长出来，别的列滑到新宽度

### 10.4 宽表：不撑出正文栏

- 正文栏是 `max-w-[860px]`，右边可能有目录树、可能是分屏的窄栏、可能在弹出窗口里；撑出去要和这几样都商量，专注模式、列表栏收起时正文栏还在滑动（`CenteredColumn` 的 layout 动画），表格跟着撑宽撑窄会抖
- 宽表留在卡片里横向滑动，补两样：
  - **第一列钉住**（`position: sticky`），往右滑也知道每一行是什么；只在表格真的比卡片宽时才钉（不宽的表不多出图层）
  - **右边缘渐隐**：右边还有内容时，卡片右边缘一截渐隐（`mask-image`），滑到头就没有；钉住的第一列右边一道分隔线。都是随滚动直接换，不做过渡

### 10.5 顺带定的

- **格子里的编辑器**（§7）这一轮留 `contenteditable`：列宽锁住以后露源码只会让格子变高、不会让表格跳，最难受的那一下已经没了。子编辑器放到 P13.3
- **选中格子时直接打字**（Excel 的「打字即改」）要照顾中文输入法：选中格子时焦点在一个看不见的输入框上，组字一开始它就盖到那一格上、样子和正在编辑的格子一样，组完字再把字交给格子、光标接着放在后面。直接在按键里把焦点挪进格子会吃掉第一下组字
- **复制**：同时放三份 —— `text/plain` 是 TSV（Excel、Numbers 认），`text/html` 是带 `rowspan` / `colspan` 的表格（Word、飞书认），再加一份 Odea 自己的（源码原文，贴回 Odea 时 `**粗**` 不丢）

来源（这一轮）：[Structural Tables](https://www.obsidianstats.com/plugins/structural-tables)、[Pandoc 的 pipe table 列宽规矩](https://pandoc.org/chunkedhtml-demo/8.9-tables.html)

### 11.2 踩到的

- **右键会把光标挪进表格**：浏览器在右键按下时把光标放到点的地方，CodeMirror 读到 DOM 选区落在表格的替身上，当成光标进了表格，整张表退回源码，菜单弹在一堆竖线上。右键的 `mousedown` 一律 `preventDefault`（正在改的那一格除外，那里要系统的剪切、复制菜单）
- **行抓手够不着**：抓手在表格左边外面，鼠标从格子移过去的路上先离开了表格的盒子，`pointerleave` 一来就收起了。表格块左右各伸出 28px 看不见的感应区（`::before` / `::after`），算在表格里。无头 Chrome 里从格子每 4px 往左挪一步，一次都没丢
- **收起编辑时格子会失焦**：去掉 `contenteditable` 的那一刻焦点没了，`focusout` 当成离开表格，列宽放开又锁上。只认「拿着焦点的那个」（正在改的格子、选区的输入框）失焦
- **松手事件没送到**：在窗口外面松开鼠标，`mouseup` 不来，「按住拖选」一直不结束，合并胶囊、悬停控件都被挡着。`mousemove` 里看 `buttons`，下一次按下也先把上一次的收掉
- **CSV 的「缩进」**：替身从围栏那一行开始，表格源码前面是「```csv」整行，插删列整张重写时拿它当续行的缩进，每一行前面都多了一个围栏。CSV 不要缩进
- **引用里的表格以前根本没认**：续行带着 `> `，分隔行被切成三格对不上表头，整张表一直是源码。解析时去掉每行前面的缩进和引用符号（`LINE_PREFIX_RE`），写回时照原样带上
- **打字时的字被换成源码的样子**：格子里打 `<`，源码写成 `\<`（不然就成了合并记号，这一格当场消失）；以前同步时比的是「格子里的字 == 源码」，下一次别处一改就把 `<` 换成 `\<`、空格、竖线同理。现在比「格子里的字写回去是不是这份源码」（`encodeCell`）

### 12.2 和正文怎么对上

- **写回按差异，不按位置**：子编辑器每改一次，把它的文字写成源码的样子（`cellFromEditor`：换行写成 `<br>`、`|` 补转义、两头空白去掉）和正文里这一格比，掐头去尾写回（和以前的 `contenteditable` 一样，协同按字合并靠它）。不进子编辑器自己的历史，撤销走正文的
- **正文变了跟过来**：表格替身的 `updateDOM` 里，正在改的那一格让子编辑器 `pull`：正文里这一格的源码换成子编辑器的写法，按差异派发进去，光标跟着改动挪（`Transaction.remote`：自绘光标直接落位）
- **只差写法的不算改了**：`<br/>` 和 `<br>`、空格子里的空格。以前点进格子什么都没改，收起时也可能按自己的写法写回去
- **组字**：组字期间不写回（拼音不进正文、不发给协作的人），别人改了这一格也先不跟（免得打断输入法）。组完字一起写回：组字前那一份是 base，这边改成 ours、那边改成 theirs，用 ChangeSet 的 `map` 把这边的改动挪到那边的结果上（`rebase`），谁的字都不丢
- **在正文的 update 里不能写回正文**：`pull` 是在 `updateDOM` 里调的；这时要写回的（自己还有没写回的、刚组完字）挪到这一轮之后的微任务。收表格（替身整个换掉）时先摘掉状态再收子编辑器，收的时候不再写

### 12.3 踩到的

- **组完字到写回之间别人的字先到了，刚上屏的词被盖掉**：`table-ime.mjs same`（机器人打在同一格最前面）抓到的，40 个词丢了一个「格子」。CodeMirror 在组字期间就把最后那一下读进来了（这时不写回），compositionend 之后等这一轮事件过去才写；中间别人的字到了，`pull` 看子编辑器和正文对不上，直接拿正文盖了过来。现在记着「有没写回的改动」（`dirty`），`pull` 碰到它先合并写回；派发之前先把 DOM 里还没读进来的输入读完（`observer.flush`，`collab/binding.ts` 同一个坑）
- **空格子的源码是几个空格**：`| 1 |   |` 那一格在源码里的范围是中间的空格（写字时连空格一起换掉，`splitRow` 故意的），`tableData` 拿它当了内容：点进空格子光标停在一个空格后面，收起时还把它当改动写回成 `|  |`。`tableData` 里只有空白的格子算空串
- **删掉一列以后整行被 rowspan 盖住**：那一行变成 `<tr></tr>`，HTML 里合法，解析器以前不认，删完列整张表退回只读。空行也认
- **HTML 表格搬行要按「换了顺序」重拼**：形状没变时按格子换字，`<td class="a">甲</td>` 的 class 留在原地、字换成乙。搬行、排序本来就传 `reorder`；HTML 搬列也传（GFM 搬列不用：列数没变，按格子换字、排版跟着位置走没问题）
- **HTML 格子里打 `<p>`**：表格当场不再是简单的表，整块退回只读的 HTML 块，正在改的格子跟着没了。块级标签写成字（`&lt;p>`，`escapeBlockTags`）
- **只读的协作访客能改表格**：表格替身一直没看 `state.readOnly`，点格子、菜单、抓手、「+」照样往正文里写（只读只拦正文自己的输入）。现在只读时点格子是选中，菜单只有「复制为 Markdown」「查看源码」，不出抓手和「+」
- **happy-dom 写 DOM 选区时同步发 selectionchange**（浏览器是排到后面的）：子编辑器在自己的 update 里又读一次 DOM，报「update 进行中」。只有单测里会这样，那一条用例先把事件挡掉
- **浮在表格上的东西只在鼠标移动时摆一次**（用户 2026-11-03 截图：点下边的「+」加了一行，那条「+」压在新的一行上）：抓手、「+」、两行之间的「+」的位置和行号都是 `pointermove` 里算的。加行删行、搬行、格子里打字撑高一行之后鼠标不动，下边的「+」停在旧的底边上、右边的「+」短一截、抓手不居中，还记着旧的行号（这时点它选中的是另一行）；页面滚动时鼠标底下换了一行，抓手还在原来那行；列宽滑动的 200ms 里列抓手、合并胶囊不跟着走；横着滑宽表时控件直接藏掉。现在记着鼠标最后停在哪（`hoverAt`），按它重摆（`refresh`）：fill 之后、表格大小变了（ResizeObserver，布局之后画之前，当帧就摆好）、列宽动画的每一帧、页面和表格自己滚动的时候。已经显示着的控件挪了位置也重新对齐整物理像素
- **列宽锁住和插删搬列对不上**：没进表格时点右边的「+」，列宽还没锁，新列一下子出现、别的列跳到新宽度；进了表格搬列，锁住的宽度留在原位，长内容挪进了窄的那一列，一直挤到离开表格；删好几列时按位置从后面掐列宽，动画第一帧就是错的。插删列先锁住列宽，自己说清楚旧列宽怎么对到新的列上（`columnsFrom`），搬列时锁住的宽度跟着列一起搬
- **加在最后的行进了 tfoot**：HTML 表格的 tfoot 浏览器画在最下面，「+」加在最后一行下面的就跟着进 tfoot，Odea 里和别处看到的顺序一样；紧挨着表身插的算表身

## 1. 结论

| 问题 | 结论 |
|---|---|
| 六个导航放哪 | **左上角的刘海**，挂在窗口顶边上，不放顶部正中。正中的顶边是每个窗格的标签栏（`NoteTabs`，贴着窗格顶边，右边还给窗口按钮留了位）、是正文那一列的中轴；分屏时还正好压在两栏的分界线上。左上角离它管的那一栏最近（§4.1） |
| 刘海和笔记的大侧栏 | **同一块。** 侧栏从刘海里往下长：笔记、归档拉到底；日历只长到月格子那么高；今日TODO、/GOAL、扩展只剩刘海。收起侧栏 = 缩回刘海。64 宽的窄栏整条拿掉（§4.2） |
| 导航多了、少了 | 刘海**按格子数收放**（宽 = 56 + 40 × 格数：2 格 136，3 格 176，6 格 296），图标靠左、位置只在增删时挪；**侧栏永远 300 宽**，导航再多也不加宽。300 里放得下「O」+ 6 格，第 7 项起最后一格换成「⋯」，放不下的收进它的菜单（§4.3） |
| 挤不挤编辑区 | 不挤。刘海只占顶上 48 高的一条，横向从不吃正文的宽度；侧栏收起时它压在标签栏的左头，标签栏从刘海右边开始。最窄的窗口（940）：侧栏开着时正文那一块还是 640，收起时标签栏有 484 宽、正文第一行离刘海底边 14px，原型里看过（§4.3） |
| 底下三个 | **不要了。** 状态长到「O」上（灵动岛的 minimal：同步中外面一圈在转、读索引是进度环、离线 / 出错 / 有新版本是右上角一个点），点「O」展开**控制中心**：同步、读索引、新版本、外观（跟随系统 / 亮 / 暗）、搜索与命令（Ctrl K）。侧栏拉到底，左下角什么都不放（§4.4、§4.5） |
| 弧线 | 参考图的弧线是圆弧拼的，在直边接圆弧、凹弧接凸弧的地方曲率突然跳变，眼睛看到的是「接缝」。改成**直接设计曲率**：每个转角的曲率用 sin² 从 0 爬到 1/R、平一段、再落回 0（`κ` 和 `dκ/ds` 在两端都是 0，G3）。R 的意思和 `border-radius` 一样（最小半径），另有一个平滑度 ξ。刘海那种窄的台阶 = 一个凹角 + 一个凸角背靠背，拐点处曲率是 0，照样连续（§3） |
| 参数 | 凸角 R=16（刘海里选中块 36 高、圆角 10，离刘海底边 6，同心：10+6），贴边的凹弯 R=12，ξ=0.6。刘海高 48：两个角一共占 41.8，剩 6.2 的直边（§3.4） |
| 划过去、点了展开 | 导航要一下点到，六个图标一直露着；悬停只给反馈（底色、标签）。**收起**侧栏以后，鼠标移到刘海上，刘海底下探出一个小把手（同一种弧线），点它展开；点当前那一区照旧收起 / 展开（§5） |
| 日历 | 侧栏**只长到月格子那么高**，下面不再是一大块空的列表栏。备选是把月历做成从刘海里展开的浮层、日历不占侧栏，但看一天换一天要反复打开，不推荐（§4.6） |
| 动效守不守得住「只动 transform 和 opacity」 | 守得住：形状拆成几块固定的弧线片，伸缩只是中间那块底色 `scaleY`、底下那块 `translateY`，不逐帧重算路径（§6.2） |

## 3. 弧线：什么样的最舒服

### 3.1 眼睛看的是曲率

一条轮廓线在哪里「顺」、哪里「有接缝」，看的不是切线（位置和方向接上了就是 G1），而是曲率接没接上（G2）、曲率的变化率接没接上（G3）。

- **CSS 的 `border-radius`、参考图里的弧线，都是圆弧。** 直边的曲率是 0，圆弧是 1/R，接上的那一点曲率从 0 一下跳到 1/R。
  Apple 的「连续圆角」、Figma 的 corner smoothing 解决的就是这一跳：Figma 的说法是曲率连续的形状读起来「是一个完整的东西」，
  不像「一个方块被做了手术」；SwiftUI 把它做成了 `RoundedCornerStyle.continuous`。
- **铁路、公路是同一个问题。** 直道直接接圆曲线，横向加速度在接点上突变，乘客感到一顿；所以中间插一段缓和曲线（回旋线，曲率随路程线性增长）。
  后来的研究认为回旋线也不是最舒服的（它的曲率变化率在两端是突变的），五次多项式那一类更好。
- **两段圆弧拼的 S 形更糟。** 参考图竖条两头的 S 形是一段凹弧接一段凸弧，起点、拐点、终点各跳一次，拐点那一跳是 2/R（曲率从 −1/R 翻到 +1/R）。

### 3.2 量出来的

`curves.mjs`（§3.5），S 形台阶宽 40、沿边 56（参考图那种比例）：

| 曲线 | 端点曲率 | 中间的跳变 | 最小曲率半径 |
|---|---|---|---|
| 两段圆弧（参考图） | 0.0338（跳） | 拐点处翻一次 | 29.6 |
| 三次 ease（smoothstep） | **0.0765（跳得更厉害）** | 没有 | 13.1 |
| 五次（smootherstep） | 0.0002（≈ 0） | 没有 | 17.3 |
| 七次 | 0.0000 | 没有 | 15.3 |

- 常用的 `cubic-bezier` 缓动拿来当形状不行：端点曲率不是 0，比圆弧跳得还狠。
- 五次那条是「最小加加速度」曲线：在 `x(y)` 这个写法下，它是让 `∫(x‴)² dy` 最小、两端一阶二阶导数都是 0 的那一条（欧拉—拉格朗日方程给出 `x⁽⁶⁾ = 0`），
  和人手从一点伸到另一点的轨迹是同一个式子（Flash & Hogan 1985）。坡度小的时候 `x‴ ≈ dκ/ds`，所以它近似是曲率变化最平缓的那条（CAD 里叫 MVC）。
- 代价是一样的：曲率连续的曲线，最弯的那一点比同样尺寸的圆弧更弯（17.3 对 29.6）。要一样「圆」，就得多占一点直边。Figma 的平滑圆角也是这样（平滑越大，吃掉的直边越多）。

顺带发现：网上常用的 figma-squircle 那套公式（我按它的公式复现，切线角逐项对得上），三次段和圆弧接上的那一点曲率不相等 ——
ξ=0.6 时三次段末端是 1.47/R，圆弧是 1/R，还是有一跳，只是比圆角小。没有对过 Figma 自己的实现，只说明「拿现成的 squircle 库」不能保证连续。

### 3.3 用什么：曲率剖面转角

直接把曲率写成路程的函数，再积分出形状：

```
κ(s) = (1/R)·sin²(π s / 2Lr)    0 ≤ s < Lr          爬坡
     = 1/R                        Lr ≤ s < Lr + Lp    平台（圆弧）
     = 对称地落回 0                                    下坡
Lr = ξ·θ·R，Lp = (1−ξ)·θ·R      θ 是转角
```

- `κ` 和 `dκ/ds` 在两端都是 0：接直线是 G3，比 G2 还多一阶。
- ξ = 0 就是普通圆角，一个像素都不差；ξ = 1 没有圆弧段，曲率是一整个钟形。
- R 永远是最小曲率半径，和 `border-radius` 一个意思，设计上照样能说「圆角 16」。
- 转过的总角度 = ∫κ ds = θ，自动对；对称，两条边吃掉的长度一样。
- **S 形不用另做：** 一个凹角（−90°）后面直接接一个凸角（+90°）。两个角在接点上曲率都是 0，拼起来照样 G3。中间可以再插一段直线（刘海深一点时就有）。
- 刘海底下的小把手是另一种形状（平顶的鼓包），用五次曲线落下来，也是两端曲率为 0（§5.3）。

占掉的直边（数值积分，`profile.mjs`）：

| R | ξ=0 | 0.5 | 0.6 | 0.8 | 1 |
|---|---|---|---|---|---|
| 12 | 12.0 | 16.9 | 17.9 | 19.9 | 22.0 |
| 16 | 16.0 | 22.5 | 23.9 | 26.6 | 29.4 |
| 20 | 20.0 | 28.1 | 29.8 | 33.2 | 36.7 |

约等于 `R·(1 + 0.83ξ)`。

### 3.4 参数

| 用在哪 | R | ξ | 占边 | 依据 |
|---|---|---|---|---|
| 凸角（刘海右下、侧栏右下） | 16 | 0.6 | 23.9 | 同心：刘海里选中块的圆角 10（`rounded-lg`），离刘海底边 (48−36)/2 = 6，10 + 6 = 16（Apple 的 concentric：外圆角 = 内圆角 + 间距） |
| 贴边的凹弯（接顶边、接左边） | 12 | 0.6 | 17.9 | 比凸角小一档：凹弯是「黏」在边上的那一下，大了显得肉 |
| 平滑 ξ | — | 0.6 | — | 和 iOS 的 60% 同一个位置；原型里拉 0–1 看过，0.6 往上差别已经很小、占边越来越多 |

刘海高 48：17.9 + 23.9 = 41.8，剩 6.2 的直边。拿不准的话在原型里拖滑块看，参数都在一处。

### 3.5 脚本

`curves.mjs`、`profile.mjs`、`corner-check.mjs` 是这次的一次性脚本，没放进仓库（它们只量曲线，不碰应用）。
正式实现时把转角的积分写进 `src/lib/edgeShape.ts`，单测守住「两端曲率为 0、没有跳变、占边长度」（§7）。

### 3.6 为什么不用 CSS 的 `corner-shape`

`corner-shape: superellipse()` 只有 Chromium 139 起支持（WebView2 有），Safari / WKWebView、Firefox 都没有；
而且它只管盒子自己的四个角，贴边的凹弯在盒子外面，它画不了。所以统一用 SVG 画。

## 4. 布局

### 4.1 刘海为什么在左上角

- 顶部正中是每个窗格的标签栏（`NoteTabs` 贴着窗格的顶边，左对齐），刘海挂在那里会压住标签。
- 正文那一列居中，顶部正中是它的中轴，上面就是路径和标题；Odea 一直让正文上方「什么都没有」（`TitleBar` 的注释）。
- 分屏时窗口正中是两栏的分界线。
- 导航切的是左边那一栏的内容，离它越近越好。
- 有刘海屏的 MacBook 上，窗口最大化时顶部正中正好是真的刘海。

### 4.2 一块形状，三种高度

| 区 | 形状 | 正文那一侧从哪开始 |
|---|---|---|
| 笔记、归档 | 刘海 + 侧栏拉到窗口底边 | x = 300 |
| 日历 | 刘海 + 月格子那么高（约 360） | x = 300 |
| 今日TODO、/GOAL、扩展；任何一区收起了 | 只有刘海（按格子数，§4.3） | x = 0（标签栏从刘海右边开始） |

- 侧栏开着时刘海和侧栏同宽（300），伸缩只在竖直方向，像拉开一个抽屉；只剩刘海时它收到自己格子的宽度。
- 拉到底时侧栏贴着窗口底边，右下角和右上角一样是一处贴边的凹弯：正文那张纸左边两个角都是内凹的，上下对称。
  侧栏短的时候（日历、只剩刘海）下沿是凸角 + 贴左边的凹弯。
- 颜色用窄栏的 `rail`（亮 #F1F1ED / 暗 #141413），整块一个颜色。列表区比现在的 `panel` 暗一点；
  `panel` 和白色正文只差 4%，弧线几乎看不出来。原型里还有一版「墨色」（和参考图一样的黑），刘海单独看很好看，但拉到底就是一整条黑侧栏，太重，不推荐。
- 形状挂在窗口的左上角：顶边那一段和左边那一段都是窗口边缘本身，凹弯和凸角是画出来的。

### 4.3 导航多了、少了

现在能出现在刘海里的：文件（一直在）、扩展（一直在）、归档（开关）、日程的今日TODO / /GOAL / 日历（开关）。所以是 **2 到 6 项**。
第三方插件加不了导航项（L0 只能调顺序，L1 没有这个贡献点，`插件与跨端.md` §6 的贡献点表）；以后会多出来的只有内置插件。

规矩：

1. **刘海按格子数收放。** 左边 12 +「O」28 + 8，每格 36、间隔 4，右边 12：宽 = 56 + 40 × 格数。
   | 格数 | 什么时候 | 刘海宽 |
   |---|---|---|
   | 2 | 日程关、归档关 | 136 |
   | 3 | 日程关 | 176 |
   | 5 | 归档关 | 256 |
   | 6 | 全开（默认） | 296 |
2. **侧栏永远 300。** 导航再多，侧栏也不加宽，编辑区的宽度和导航有几项无关。侧栏开着时刘海就是侧栏的顶上那一条，格子少了右边空着。
3. **图标只在增删时挪。** 收起 / 展开侧栏、切区，图标都不动（肌肉记忆）；开关日程、归档时，拿掉的先原地淡出 140ms，剩下的再滑过去 240ms，
   新来的晚 70ms 淡入 —— 就是现在 `Sidebar.tsx` 的 `useNavRows`，竖着改成横着。刘海的宽度跟着弹簧走。
4. **放不下就收进「⋯」。** 300 里放得下「O」+ 6 格（296）。第 7 项起，第 6 格换成「⋯」，后面的都收进它的菜单；
   当前那一区在菜单里时，选中块停在「⋯」上。哪几项在外面由导航顺序定（`navIds`，L0 插件能调）。
5. **不加宽到侧栏外面。** 也想过让刘海伸出侧栏右边（像灵动岛往外长），但侧栏开着时标签栏就得跟着让，等于为导航挤了标签栏，不做。

挤不挤编辑区（原型里切到 940 看过，940 是 `workspace.rs` 的 `min_inner_size`）：

- 横向：刘海只在顶上 48 高的那一条，从不吃正文的宽度。侧栏开着时正文那一块是 940 − 300 = 640，和现在（940 − 64 − 300 = 576）比还**宽了 64**。
- 侧栏收起、6 格时：标签栏从 296 + 18（凹弯）+ 12 = 326 开始，到窗口按钮前还有约 484 宽；正文第一行（路径）在 y≈62，刘海底边在 48，中间 14。
- 日程关着时刘海只有 176，标签栏从 206 开始。

### 4.4 状态长在「O」上

左下角三颗（同步、命令面板、主题）拿掉。三样东西性质不一样，各去各的地方：

| 原来那颗 | 是什么 | 去哪 |
|---|---|---|
| 同步 | 状态，平时不用管，出事了要一眼看到 | 「O」本身：同步中外面一圈在转；离线黄点、要登录 / 出错红点 |
| 读索引、新版本（临时的两颗） | 状态 | 「O」：读索引时外面那一圈是进度环；有新版本是强调色的点 |
| 命令面板 | 动作，有 Ctrl K | 控制中心里一行「搜索与命令 Ctrl K」；侧栏里本来就有搜标题的框 |
| 主题 | 偏好，很少改 | 控制中心里「跟随系统 / 亮 / 暗」三段；命令面板里本来就有三条 |

「O」：

- 28 的圆按钮，里面是现在窄栏上那个「O」。外面一圈 r=12.2、1.6 粗的环平时不画。
- 同步中：环上一段弧绕着转（转的是 SVG 的 `transform: rotate`，合成器上跑）。读索引：同一个环当进度环，读到哪画到哪（跟着进度一段一段变，不是逐帧动画）。
- 点：右上角 8 的圆点，外面一圈侧栏底色隔开。出错 / 要登录（红）> 离线（黄）> 有新版本（强调色），同时只显示最要紧的那一个。出现时从 0 弹到 1（点里没有字，能缩）。
- 都没有的时候它就是 logo。
- 悬停：一句话的提示，比如「已同步 · 3 分钟前」「正在读取笔记 702 / 2000 · 离线 · 有新版本 0.10.3」。

控制中心（点「O」，从刘海下面展开的一张卡，284 宽；`popoverCard` 从上边展开，不缩放）：

1. 同步：状态 + 一句话 +「立即同步」；点这一行打开同步对话框（现在的 `SyncDialog`）。
2. 读索引（读的时候才有）：进度条和那句「读完之前列表和搜索里暂时缺一部分」。
3. 新版本（有才有）：版本号 +「看看」，打开现在的新版本卡片。
4. 外观：跟随系统 / 亮 / 暗。
5. 搜索与命令：Ctrl K。

Esc、点外面收起。键盘：「O」能 Tab 到，回车打开，焦点进卡片（`useModalFocus`）。

为什么这么放：

- **灵动岛的分法。** Apple 把一个进行中的状态分成三种样子：minimal（只占一个 28pt 的圆）、compact、expanded（点开以后照着原来的样子放大，展开要「可预期」）。
  「O」上的环和点就是 minimal，控制中心就是 expanded。Odea 的刘海本来就是从这里来的，状态长在刘海上是顺的。
- **macOS 的控制中心、Apple 菜单。** 左上角那个 logo 打开全局的东西，Wi-Fi、蓝牙、外观收在一个图标后面，都是这个路数。
- **主题不占位置。** Linear 把主题放在偏好设置里，不在侧栏上；Odea 没有设置页，放进控制中心和命令面板。
- **左下角空出来以后**侧栏能拉到底，下沿和上沿对称；原来那三颗不管侧栏开不开都压在正文左下角。

### 4.5 想过、不要的

| 做法 | 为什么不要 |
|---|---|
| 三颗圆钮横排在左下角（第一稿） | 和侧栏不是一个东西，侧栏收起时浮在正文左下角；三样性质不同的东西（状态、动作、偏好）长得一样 |
| 三颗并成一条胶囊 | 比散着整齐，问题一样 |
| 同步放进状态栏（Obsidian 的做法，点开是暂停、历史、日志的菜单） | Odea 的状态栏是每个窗格一条、扩展页没有；全局的状态放进某一个窗格不对 |
| 放进刘海右头，当灵动岛的「活动」 | 和导航抢宽度，刘海只能放 5 格 |
| 鼠标移过去才出来 | 出错要一直看得到 |

### 4.6 日历

- 侧栏只长到月格子那么高：形状的高度跟着这一区的内容走，日历这一区内容高度是固定的（6 行），量一次就行。
- 月格子下面空出来的是正文的白，不再是一块空的列表栏。以后要在月格子下面加「这一周」之类的，侧栏跟着长。
- 插件的导航项（`plugins/registry.ts`）加一个声明：列表栏是「拉到底」还是「按内容高度」，默认拉到底，日历写按内容。

## 5. 交互与动效

### 5.1 刘海

- 悬停一个格子：底色 80ms 淡入（和现在窄栏一样）；停 350ms 在刘海下面出一个小标签（字在里面，只淡入）。
- 点：切区，选中块用 `layoutId` 滑过去（`spring.smooth`），图标播它自己的「签名动作」（现在 `ICON_MOTION` 那一套，留着）。
  （实现时两样都换成了自己调的 WAAPI，样子不变、在合成器上跑：`layoutId` 和 Motion 的单独 transform 都是主线程逐帧写的，§10.3）
- 点当前那一区：收起 / 展开侧栏（现在的行为）。
- 开关插件、归档：格子的进出见 §4.3 第 3 条；刘海宽度用和侧栏同一个弹簧。

### 5.2 侧栏的伸缩

- 形状：中间那块底色 `scaleY` / `scaleX`，下沿那一片（凸角 + 底边 + 凹弯）`translateY`，右上的凹弯 `translateX`，用同一个弹簧（刚度 260、阻尼 32，基本不过冲）。
- 拉到底时下沿那一片推到窗口外面，右下角那处贴底边的凹弯淡入（等侧栏到了再淡，140ms 后、160ms）；离开拉到底时它先 90ms 淡掉。
- 里面的内容不跟着拉：收的时候先 110ms 淡出，再缩；展开时形状先长，内容晚 110ms、200ms 淡入。
- 正文那一列滑到新的居中位置：现在的 `CenteredColumn`（`layout="position"`，`tween.base`），不动。

### 5.3 收起以后的把手

- 收起了（或者这一区本来有侧栏、被收了），鼠标移到刘海上：刘海底边中间探出一个 66 × 11 的平顶鼓包，里面一个向下的箭头；
  探出来 240ms、ease-out-quint，只动 `translateY`。鼠标到把手上再往下 3px，箭头变深。点它展开。
- 这就是参考图左边那部手机竖条下面那一小段弧：平时不在，有需要才出来。

### 5.3.1 展开着时的边缘把手（2026-11-20 加，取代状态栏的侧栏开关）

用户指出状态栏最左边那颗侧栏开关（`PanelLeftClose` 图标套个框）low：它是个普通图标按钮，压在正文那张纸左下角的凹弯旁边，和这块形状不是一个东西；新设计里也多余。改成：

- **拿掉状态栏的侧栏开关**（`DocumentView` 的 `panelToggle` 那一颗）。
- **边缘把手**：侧栏展开时，鼠标移到侧栏右边缘外侧那一条（正文那一侧 0–12px，不碰列表的滚动条），侧栏的右边缘在鼠标那个高度往外鼓出一个把手 —— 和收起时刘海底下那个是同一个形状（平顶、两头五次曲线落下、66 × 11），竖过来，里面一个「‹」。
  鼓出来 240ms ease-out-quint，只动 `translateX`；鼠标沿着边缘上下移，把手用弹簧（`spring.smooth`）跟着走，只动 `translateY`，上下各留 24px 不碰到凹弯；鼠标到把手上再往外 3px、箭头变深。点它收起。离开那一条 120ms 后缩回去。
- ~~快捷键 Ctrl+\\~~：**不加**（2026-11-20 用户定）。Ctrl+\\ 已经被占了两次（笔记区「向右拆分」、正文里「清除格式」），Ctrl+Shift+\\、Ctrl+Shift+L 编辑器里也有用，换键得丢掉别的习惯；命令面板「收起 / 展开侧栏」那一条一直在。
- 收起 / 展开因此有三条路，都在形状本身上或者命令面板里：点当前那一区、两个把手、命令面板。

### 5.4 「O」和控制中心

- 环出现 / 消失淡 200ms；转圈 1.1s 一圈、匀速；点从 0 弹到 1（220ms，带一点回弹）。
- 控制中心：`popoverCard`，从上边展开；里面的行跟着状态增减时，卡片的高度规矩照 §10.1 第 5 条（打开以后不跳）。

### 5.5 减少动效

全部直接跳到终点；环不转，同步中只亮一段弧（`usePrefersReducedMotion` + 应用内开关，和现在一样）。

### 6.2 形状怎么画、怎么动

- **不逐帧重算路径**（那是主线程上的重绘，§10.1 第 1 条）。拆成几片：
  1. 右上的凹弯：一小块固定的 SVG，伸缩宽度时 `translateX`；
  2. 中间的底色：一个纯色的 div，`transform-origin: top left`，伸缩只改 `scaleX` / `scaleY`（里面没有字，缩放不糊）；
  3. 下沿那一片：凸角 + 底边 + 贴左边的凹弯，一块固定的 SVG，伸缩只改 `translateY`；它的宽度跟着刘海宽度变，按 300 画，窄的时候左边对齐、右边由凸角那一小片 `translateX`；
  4. 拉到底时右下角贴底边的凹弯：一小块固定的 SVG，只淡入淡出。
- 片和片之间各叠 2px，同一个不透明的颜色，叠的地方看不出来；不叠的话 1.25 / 1.5 倍屏上缩放后的边缘会露一条发丝缝。
- 路径按 R、ξ 在模块加载时算一次（每个角两三百个点，算一次不到 1ms），亮暗只换颜色。
- 原型里是每帧重算整条路径（为了快），视觉上和拆片是一样的：拆片的每一片在动画里都是刚体。

### 6.3 要处理的边角

- **标题栏的拖拽带盖在刘海上**（它是 z-40、铺满整个宽）：刘海放到它上面一层，刘海那块不能拖窗口；刘海右边的顶边照样能拖、双击最大化。
- **标签栏让位**：侧栏不在时，最左的窗格标签栏从「刘海宽 + 18 + 12」开始（6 格时 326）。状态栏不用让了（左下角不再有东西）。
- **专注模式**：现在是整条 chrome 往左推出去；刘海一起推出去（它在左上角，左推就看不见）。专注模式下「O」上有红点时要不要露出来，待定。
- **当前那一区被关掉**（在日历里关了日程）：回到文件，和现在一样。

## 7. 验收标准

1. 亮、暗、1 / 1.25 / 1.5 / 2 倍屏：刘海、侧栏的颜色和形状都对；放大看片和片的接缝没有发丝缝（无头 Chrome 用 `--force-device-scale-factor` 起，伸缩动画逐帧截，VERIFICATION.md「逐帧对比」）。
2. 所有转角都从 `edgeShape.ts` 来；单测：曲率两端为 0、相邻采样的曲率差不超过峰值的 8%、占边长度和 §3.3 的表一致。
3. 切区（笔记 ↔ 日历 ↔ 今日TODO）、收起 / 展开、开关日程：动画帧里只有合成，没有布局和重绘（Performance 面板）；`perf.mjs` 的「左侧导航」「切换」不比改之前慢（`compare.mjs`，两边交替各跑 3 次）。
4. 导航 2 到 7 项（关日程、关归档、模拟多一项）：刘海宽度对、图标增删时其余的滑过去、第 7 项起进「⋯」；收起 / 展开、切区时图标不动。
5. 940 宽的窗口：侧栏开着时正文那一块 640；收起时标签栏、路径和刘海不重叠。
6. 「O」：已同步什么都不画；同步中转圈；读索引进度环；离线 / 出错 / 新版本的点按优先级只出一个；悬停那句话对；点开控制中心，五行都能用；Esc 和点外面收起；键盘走得通，焦点看得见。
7. 交互：点图标一下就切区；点当前区收起 / 展开；收起后鼠标到刘海上把手探出来、点它展开。
8. 桌面端：刘海上的按钮都点得到；刘海右边的顶边能拖窗口、双击最大化。
9. 开场那个「O」落在刘海里的位置上。
10. 减少动效：全部直接到终点。

## 8. 风险、待定

**要用户定的**（原型里都能切着看）：

- 刘海在左上角，不在顶部正中（§4.1）。
- 颜色：和窄栏同色（推荐）还是墨色。
- 侧栏从 `panel` 变成 `rail`，列表区会暗一点。
- 状态长在「O」上、控制中心收主题和命令面板（§4.4），左下角什么都不放。
- 第 7 项起收进「⋯」（§4.3）。
- 日历按内容高度（推荐），还是做成刘海里展开的浮层。

**没核实的**：

- macOS（WKWebView）上没跑过；SVG 路径本身没有兼容问题，`corner-shape` 没用。
- Windows 11 无边框窗口的圆角会裁掉形状左上角那一点，和现在窄栏一样，没单独看过。
- 原型里的动画在内置浏览器里看不全（窗格隐藏时 rAF、CSS 过渡都不走），各个状态的终态截图看过，过程要在可见的窗口里看一遍。
- 命令面板少了一个一直露着的按钮，只靠 Ctrl K 和控制中心那一行，用鼠标的人找不找得到，要看用起来怎么样。

### 10.2 全项目圆角（技术方案 §9.6）

2026-11-20。TSX 那半（约 50 个文件的 `rounded-*` 归档、`cornerRadius()`）是上一棒做的，这一棒收样式表。

**做法**（`src/styles/globals.css`「弧线」一节）

- `--radius-*` 仍是 R；`--corner-*` = R × `--corner-scale`，`--corner-scale` 平时是 1，`@supports (corner-shape: superellipse(1.58))` 里是 1.4907。不支持的引擎（WKWebView、Firefox）退回普通圆角 R，不放大。
- Tailwind 主题里的 `--radius-*` 写 `initial`，自带的 `rounded-lg` 之类不生成；`rounded-xs … 2xl`、`rounded-t-lg / tl-lg / r-sm`、`rounded-capsule` 用 `@utility` 自己出，都 `@apply corner-continuous`（全文件只有这一处写 `superellipse(1.58)`）。
- 正圆另有 `corner-round`（`corner-shape: round`），`rounded-full` 用 `@utility` 补上它，CSS 里的 `border-radius: 50%` 一律改成 `@apply rounded-full`。原因见下面清单第 1 条。
- 手写的像素值全归档：callout 头尾、代码块围栏封口和源码行、缩进代码块、frontmatter 围栏、折叠的 callout 都是 `var(--corner-md)` + `corner-continuous`。只有一行的缩进代码块同时有 `is-top`、`is-bottom`，那里只写长写法，不用简写（简写会把另一头的角清成 0）。
- `src/render/static.css`（嵌入、导出页）不经过 Tailwind：值写 `var(--corner-*)`，`corner-shape` 集中写在文件末尾那条 `:is(...)` 里；导出页的 token 在 `export/document.ts`。

**白名单**（`radius.test.ts` 的 `EXEMPT`，CSS 里那条规则上面写了理由）

| 规则 | 值 | 理由 |
|---|---|---|
| 表格四个角上那一格的 `::after`（`.at-tl / -tr / -bl / -br`） | `calc(var(--corner-lg) - 1px)` | 选区描边贴着外框（`rounded-lg`、1px 边框）的内沿。浏览器裁 `overflow` 用的内边距盒圆角就是「外框圆角 − 边框宽」、角形不变，照抄才和裁剪线重合；以前写死 9px |
| 图片拖柄 `.cm-odea-image-handle::after` | `2px` | 那个 ⌟ 是 1.5px 笔画拐弯处的圆头，是图标不是盒子（同 SVG 的 `stroke-linejoin`）；6px 的小方块放 xs（×1.49 ≈ 6px）整条边都弯了 |

**以前不好看的圆角（这一棒改掉的）**

1. **正圆键盘聚焦时变方圆**（上一棒引入的）：全局 `:focus-visible` 在 base 层 `@apply rounded-sm`，连带 `corner-shape: superellipse(1.58)`；`rounded-full`、`50%` 不写角形，base 层的就漏进来。现在正圆明写 `corner-shape: round`。
2. **表格的拖柄、加行加列的细带像药丸**：短边 16px，sm 乘 1.49 后约 9px，超过短边一半，被收成两头全圆。改 xs。
3. **图片工具条像药丸**：26px 高放 md（约 12px），差不多是高度的一半。工具条改 sm、里面的按钮改 xs，仍然同心（6 = 4 + 2）。
4. **音视频播放条的按钮不同心**：条是 lg，按钮离条的外沿 6px，按钮却是 sm（6 + 6 ≠ 10）。改 xs（4 + 6 = 10）。
5. **代码块的圆角各处不一样**：编辑器里是 md，阅读占位 `.prose-doc pre` 和静态渲染 `pre.code` 是 lg。占位换成编辑器时角会跳；嵌入卡片是 md，里面的代码块反而比外框圆。两处都改 md。

同心顺手查过的：表格菜单 lg / 菜单项 sm、内边距 4（10 = 6 + 4）；`.odea-menu` lg / 菜单项 sm、内边距 4（浏览器里量过）；图片查看器的条 lg / 按钮 sm、内边距 4；编辑器搜索框 lg / 输入框 xs、内边距 6；`.cm-dialog` lg / 输入框和按钮 xs、内边距 6。这些都对。悬停卡片里只有字，没有嵌套的圆角。

**发现的问题和修法**

1. **侧栏的内容在点击那一帧里挂上**（「切到文件」+160ms 的来源）：`EdgeChrome` 换内容用的是 `AnimatePresence mode="popLayout"`，新的一栏（文件树，挂上要排两千多个元素的样式）和旧的一起挂，
   虽然要晚 110ms 才淡入。改前的列表栏是 `mode="wait"`。改成 wait：旧的淡完（110ms）新的才挂、挂上就淡入；展开（之前没内容）还是挂上、晚 110ms 淡入。
   内容改成 absolute 叠放，拉到底的那一栏淡出时外层先留着原来的高度（`leavingFull`），不然它淡出到一半变成 0 高。复测「文件」512 → 288（改前 288）。
   popLayout 还会往 `<head>` 插一条 `[data-motion-pop-id]` 的样式，一起没了
2. **收起时整棵文件树重算样式**（「切到今日TODO」）：装内容的那一层收起时加 `pointer-events-none`，会继承，两千多个元素在点击那一帧里全部重算（4 倍降速 127ms，NoteTabs 的 `getBoundingClientRect` 逼出来的）。
   拿掉了（淡出的 110ms 里点得到，和改前一样）；复测那一次重算 2190 → 226 个元素
3. **侧栏里的标题、搜索框各自进场**：`ListColumn` 的 h2、按钮、搜索框各带 opacity + `y: 6`，和外面那一层的淡入同时跑；y 是 Motion 主线程逐帧写的，展开、切区时每帧重排一次、整栏重画（4 倍降速 3–7ms）。拿掉了，只留外层的淡入
4. **选中块和图标的签名动作不在合成器上**：Motion 的 `layoutId` 和单独的 rotate / scale / y 都是主线程逐帧写 style（注释里写的「走合成器」不对）。
   选中块改成在新格子里挂上、按 `spring.smooth` 预先算好的关键帧（`springTrack`）从旧格子的偏移滑回来（`Indicator`）；图标动作改成 CSS 单独的 rotate / scale / translate 属性各一条 WAAPI（`playIconMotion`，加了三条单测）。
   样子和以前一样，切区那一下主线程再忙也照常走。`lib/motion.ts` 的 `layoutIds.navIndicator` 没人用了，删掉
5. 量的过程本身：`edge-chrome.mjs` 等动画走完时原来每帧调 `document.getAnimations()`，逼出样式计算，trace 里看着每帧都有布局 —— 改成隔 250ms 查一次（`PITFALLS/性能.md`）

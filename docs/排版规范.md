这份文档回答一个问题：字号、字体、行高、字距、颜色、图标和控件取多大，人读起来、点起来最舒服，依据是什么。改样式之前先看这里，改完回来更新「状态」一列。

---

## 0. 依据分三档

| 档 | 含义 | 例子 |
|---|---|---|
| 研究 | 有实验数据 | 字号、对比度、浅底深字、行长 |
| 规范 | 成文标准：W3C《中文排版需求》（clreq）、WCAG、APCA、平台设计系统 | 密排、两端对齐、中西间距、最小 12px |
| 惯例 | 主流编辑器的共同取值：GitHub、Typora、Obsidian | 标题比例、代码字号、行高的具体数字 |

研究能确定的东西不多：字号偏大更好读（到 18px 左右），对比度要够，读长文时浅底深字更准，一行不宜太长。**行高的具体数字对阅读速度影响很弱**（中英文实验都是这个结论），所以正文取 1.7 是为了舒适感、为了和惯例一致，不是因为 1.4 会读得慢。

屏幕密度、阅读距离、视力的个人差异很大，长远看应该给用户一个字号设置（§9）。

## 1. 字体

### 1.1 字体栈

```css
--font-sans:    -apple-system, BlinkMacSystemFont, "Segoe UI Variable Text", "Segoe UI",
                "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei",
                "Noto Sans SC", system-ui, sans-serif;
--font-display: -apple-system, BlinkMacSystemFont, "Segoe UI Variable Display", "Segoe UI",
                （中文部分同上）;
--font-mono:    "JetBrains Mono", "Cascadia Mono", ui-monospace, "SFMono-Regular", Consolas,
                "Liberation Mono", "Microsoft YaHei UI", "PingFang SC", "Noto Sans Mono CJK SC",
                "Noto Sans SC", monospace;
```

各平台实际落到：

| 平台 | 英文 | 中文 | 等宽（英文 + 中文） |
|---|---|---|---|
| Windows 11 | Segoe UI Variable（正文 Text、标题 Display） | 微软雅黑 UI | Cascadia Mono + 微软雅黑 UI |
| Windows 10 | Segoe UI | 微软雅黑 UI | Consolas + 微软雅黑 UI |
| macOS | SF Pro | 苹方 | SF Mono + 苹方 |
| Linux | 系统默认 | Noto Sans SC | 系统等宽 + Noto Sans Mono CJK |

规则：

- **不写没打包的字体。** 以前栈首是 Inter，但没打包、Windows 也没装，实际落到 Segoe UI Variable **Display** —— 那是给大字号用的光学尺寸，用在 13–17px 偏紧偏细。为 Inter 写的 `font-feature-settings: "cv02"…` 也一直是空写。
- **正文用 Segoe UI Variable 的 Text 光学尺寸，Display 只给 ≥ 20px 的标题。** 微软的说法是在 CSS 里写 `Segoe UI Variable` 会自动按字号选光学尺寸，但有实测说浏览器里不生效，所以直接写明 Text / Display。
- **等宽栈里必须有中文字体。** 否则中文字符落到通用的 `monospace`，在中文 Windows 上是**新宋体**（实测：代码块、行内代码、`![截图](../附件/…)` 这种路径里的中文都是新宋体）。
- **为什么不打包思源黑体：** 雅黑在 Windows 上有针对屏幕的微调，17px 下比思源黑体清楚，而且零体积。代价是没有中间字重（§1.2）、做不了标点挤压（§2）。要不要打包是单独的决定（§9）。

### 1.2 字重

雅黑只有 细 / 常规 / 粗 三档。550、620、650 这类中间值，中文会被吸到 400 或 700，英文（Segoe UI Variable）却会按原值画，同一行里中英文粗细对不上。所以：

- 只用 **400 / 500 / 600 / 700**。500 在中文上等于常规，600 在中文上等于粗体、在英文上是半粗。
- 正文 400，标题 600，`**粗体**` 700。

## 2. 正文

| 项 | 目标 | 依据 | 状态 |
|---|---|---|---|
| 字号 | **17px** | 研究：18px 左右理解得更好（英文眼动实验，104 人）；中文研究的最佳字面约占视角 0.6–1° | 不变 |
| 行高 | **1.7**（一行 28.9px） | 惯例：GitHub / Obsidian 1.5、Ant Design 1.57、Typora 1.6；WCAG 1.4.12 以 1.5 为下限；clreq 讨论行间标点时要求行距不小于半个字 | 已落地（原 1.4） |
| 段距 | 空一行 = 一个行高 | 编辑器里段距就是 Markdown 源文里的空行 | — |
| 字距 | **0.012em**（约等于 0） | clreq：正文密排，不额外加字距 | 不变 |
| 对齐 | **两端对齐**，段落最后一行左对齐 | clreq：正文原则上两端对齐，而不是左齐右不齐 | 已落地 |
| 中西间距 | **`text-autospace: normal`**（约 1/8 字宽，已手打空格的地方不会再加） | clreq：汉字与西文、数字之间不多于 1/4 字宽 | 已落地 |
| 标点挤压 | `text-spacing-trim: normal`（浏览器默认，不用写） | clreq：相邻两个全角标点缩成 1.5 字宽 | **雅黑上不生效**：雅黑没有 `halt` / `chws` 特性。实测同一串文字，思源黑体从 205.8px 挤到 180.3px，雅黑不变 |
| 行长 | 25–40 字，最多 48 字 | 日文规范横排 ≤ 40 字；clreq 草案 17–40 字、横排 ≤ 48；英文每行 55 字母最受偏好 | 普通视图约 33 字，专注模式约 44 字 ✅ |
| 只读占位 | 和编辑器同字号、同行高 | `.prose-doc` 是编辑器分包加载时的占位，尺寸不一样，编辑器挂上的那一刻整篇会跳 | 已落地（原 15.5px / 1.85） |

代码块、行内代码、kbd **不参与**两端对齐和自动中西间距：代码要逐字准确。

很长、中间没有断点的西文串（网址、哈希、一直按着的 kkkk，24 个字符以上、不夹空白和汉字）**允许在串里任意处断行**（`editor/longRuns.ts`，`word-break: break-all` 只加在这一串上）。不然浏览器会在它前面（汉字和西文之间）折行、把整串挪到下一行，两端对齐把前一行剩下的几个字撑满整行，字和字之间拉开一大截（2026-10-18 协作实测时撞上的）。普通英文单词到不了这个长度，照旧整词折行。

输入法组字时光标那一行同理（2026-10-28）：拼音是一串西文，打到行尾放不下就整串挪到下一行，这一行被撑开（最右边的字挪 39px），上屏变回汉字又缩回去，一个词抖一下。组字期间这一行允许任意处断行，只剩两端对齐每次折行本来就有的不到一个字母宽；光标前面有在西文词、数字跟前折的行时不加（加了那个词会被拆开挤上去），`editor/longRuns.ts`。

## 6. 颜色

用两套尺子量：WCAG 2 的对比度（正文 ≥ 4.5:1），和 APCA（WCAG 3 草案用的算法，对暗色更敏感）。APCA 的大致门槛：正文首选 Lc 90、最低 Lc 75；非正文的内容文字 Lc 60；大字 Lc 45；占位符、禁用态最低 Lc 30。

| token | 亮色 | 暗色 | APCA（亮 / 暗） | 用途 |
|---|---|---|---|---|
| ink | `#1a1a18` | `#eeeee9` | 104 / 95 | 标题、粗体 |
| body | `#353532` | `#d2d2cb` → **`#d8d8d1`** | 98 / 77 → 81 | 正文 |
| muted | `#74746e` | `#8d8d85` → **`#a8a8a0`** | 73 / 39 → 53 | 次级文字、元信息、引用 |
| faint | `#a3a39b` → **`#91918a`** | `#61615b` → **`#7f7f78`** | 50 → 59 / 19 → 32 | 占位符、禁用态、刻意做淡的标记 |
| accent | `#2f63d8` | `#6b93f0` → **`#82a4f4`** | 76 / 44 → 52 | 链接、选中、主按钮 |
| accent-hover | `#2a58c2` | `#82a4f4` → **`#9ab6f7`** | | |

规则：

- **需要读的小字（≤ 13px）至少用 muted。** faint 只给占位符、禁用态和刻意做淡的东西（语法标记、日历里别的月份的日期）。改前 faint 只有 2.5:1（APCA 50），却用在 102 处小字说明上。
- 暗色的 muted、faint 改前用 WCAG 量是及格的（5.0:1），但 APCA 只有 39 和 19 —— 暗色下的引用、元信息看着发闷，faint 连占位符的底线都不到。
- 行内代码不用语义色。
- 代码高亮里的注释色同理提了一档：亮色 `#9a9a92` → `#8c8c85`（APCA 51 → 58），暗色 `#6f6f68` → `#8d8d85`（25 → 40）。注释是要读的，不是装饰。
- 暗色不用纯黑纯白（Material：纯白在深色上会「发颤」） ✅
- 浅底深字是长文的默认：研究显示正极性（浅底深字）下校对更准，各年龄段都是。应用跟随系统 ✅

## 7. 界面字号

| 档位 | 用在 |
|---|---|
| 11px | **只给纯英文、数字**的角标和键帽（`Ctrl K`、计数、周数） |
| 12px | 中文的最小字号：分组标题、元信息、提示 |
| 13px | 列表摘要、次级按钮、菜单 |
| 14px | 界面正文、输入框 |
| 15px | 强调的界面文字 |
| 17px | 编辑器正文 |
| 19 / 24 / 30 / 38px | 视图标题、文档标题 |

- **中文最小 12px。** Lighthouse、Ant Design、Fluent 2 的下限都是 12px。
- **不用半像素**（10.5、11.5、12.5、13.5、14.5）：Windows 100% 缩放下中文笔画会发虚；档位一多，相邻元素差半个像素，看着「说不上哪里不齐」。Ant Design 建议一个系统的字阶控制在 3–5 种。
- 改档对照：10 / 10.5 / 11 / 11.5 → 12（纯英文数字 → 11）；12.5 → 13；13.5 → 14；14.5 → 15。
- **列表栏的条目（文件树每一行）、搜索框、仓库名用 14px**，是「界面正文」，不是「列表摘要」。中文 13px 笔画挤，飞书、语雀、Notion 中文版的侧栏都是 14px；macOS 侧栏「中」档 13pt 是给西文定的。
- **右侧目录树 13px**：要扫着读、点着跳（VitePress、Docusaurus 的目录都在 13px 上下）。

## 10. 界面尺寸（图标、控件、三栏的底边）

字号之外，「看着舒不舒服」主要看三样：图标够不够大、能点的东西够不够大、相邻的几块对不对得齐。

### 10.1 依据

| 来源 | 说的是什么 |
|---|---|
| macOS HIG 侧栏 | 三档：行高 24 / 28 / 32pt，图标 16 / 20 / 24px，字 11 / 13 / 15pt。默认是中档 |
| Fluent 2 | 4px 网格；正文 14 / 20、说明 12 / 16；12px 的图标太小，不该用来点 |
| WCAG 2.5.8 | 能点的东西至少 24×24 CSS 像素 |
| WCAG 1.4.11 | 图标、控件的边和状态，跟旁边的颜色至少 3:1 |
| VS Code 活动栏、Obsidian | 活动栏图标约占格子一半；Obsidian 的图标档位 14 / 16 / 18 |

### 10.2 档位

| 项 | 档位 | 用在 |
|---|---|---|
| 图标 | **12 / 14 / 16 / 18 / 20**（空状态插画 24–32） | 12：行内小箭头、键帽、角标；14：菜单、小按钮、状态栏；16：列表行、栏头按钮、对话框标题；18：窄栏底下那几格；20：窄栏的导航项 |
| 图标线宽 | 实际线宽（`strokeWidth × size / 24`）落在 **1.1–1.5px**：20 → 1.75，18 / 16 → 1.8，14 → 1.9，12 → 2.2 | 低于 1px 的线在 1 倍屏上画成一道灰影（以前 13px 配 1.8 只有 0.98px） |
| 控件高 | **24 / 28 / 32 / 36 / 40** | 24：列表行里的「…」、归档的恢复 / 删除、面包屑；28：状态栏按钮、月历翻页；32：栏头按钮、菜单项、主按钮；36：搜索框、输入框；40：窄栏的每一格 |
| 文件树一行 | 34px（底色 30px），字 14、图标 16 | 介于 macOS 侧栏中档和大档之间；中文字在 30px 的底色里上下各留 8px |

### 10.3 三块具体的

| 块 | 现在 | 以前 | 为什么 |
|---|---|---|---|

### 10.4 颜色补充

§6 的规矩（要读的小字至少 muted）这次又查出六十多处 faint：菜单第二行的说明、对话框里的分组标题、弹出层底栏的按键说明、空状态的提示、归档列表的日期。都换成了 muted。保留 faint 的：输入框占位符、别的月份的日期、日历的周数、故意做淡的分隔点。

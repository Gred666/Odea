## 1. 提醒

### 1.1 别家怎么做

- **Todoist**：任务写了几点，就自动加一条提醒，默认提前 30 分钟；提前多久在设置里改，也能关（「No automatic reminder」）。
  只有日期、没写几点的任务不自动提醒 —— 提醒是相对那个时刻算的
  （[Todoist 帮助：Introduction to reminders](https://www.todoist.com/help/articles/introduction-to-reminders-9PezfU)）
- **Obsidian 的 Reminder 插件**（[uphy/obsidian-reminder](https://github.com/uphy/obsidian-reminder)）：和 Tasks 插件一起用时，`📅` 是截止日期，
  另写 `⏰ YYYY-MM-DD HH:MM` 是提醒的时刻，两个分开（[和 Tasks 插件一起用](https://uphy.github.io/obsidian-reminder/guide/interop-tasks.html)）；
  只写日期的，按设置里的「默认提醒时间」响
- **Windows 的通知**有一种 `scenario="reminder"`：一出来就是展开的，一直停在屏幕上直到点掉；要有一个后台激活的按钮，否则这个场景被忽略
  （[toast 元素](https://learn.microsoft.com/en-us/uwp/schemas/tiles/toastschema/element-toast)）。
  Windows 11 的「勿扰」里有一项「勿扰时也显示提醒」，认的就是这种场景

### 1.2 定下来的

**哪些会响。** 没勾的任务，后面写了日期和几点几分：

```
- [ ] 交周报 @2026-11-12 18:00            到点（减去提前量）响
- [ ] 交周报 📅 2026-11-12 18:00          Obsidian Tasks 的写法，一样
- [ ] 交周报 @2026-11-13 ⏰ 2026-11-12 17:30   ⏰ 是提醒的时刻：就这时候响，不管提前量
- [ ] 交周报 @2026-11-12 18:00 ⏰ 17:30    ⏰ 只写几点：任务那一天的几点
- [ ] 打电话 ⏰ 2026-11-12 15:20           只有 ⏰ 的：也进那一天的日历，就这时候响
```

- 写「上午」「下午」「晚上」的不响：这是故意写得含糊的（Todoist 也是只认写了几点的）；想响就写几点或者 `⏰`
- 勾掉了的、归档了的、回收站里的不响；没开日程的仓库不响（带日期的任务是日程插件管的，日历也只在开着日程时有）
- `⏰` 用 obsidian-reminder 的写法，从 Obsidian 过来的照认；只写几点的 `⏰ 17:30` 是我们多认的一种

**提前量：整个应用一个设置，每条想不一样就写 `⏰`。** 默认准点；可选提前 5、10、15、30 分钟、1 小时。
Todoist 是同一个做法（默认提前 30 分钟），我们默认准点：任务上写的就是「这时候提醒我」，提前得自己选。

**应用关了不响**（用户定的）：没有托盘、不开机自启。退出时把还挂在通知中心里的提醒收掉 —— 应用不在了，按钮点了没人接。
刚打开应用时，关着那段时间到点的不补。

**睡眠醒来。** 电脑睡着时到点的，醒来合成一条：「你不在的时候有 3 条到点了」，列出前几条，只响一声。只补 12 小时以内的。

**同一分钟到点好几条。** 每条一个通知（各自能点「完成」），只响一声；超过 3 条合成一条。

**通知长什么样（Windows）：**

```
Odea
交周报                                  ← 任务（去掉日期、标签那些记号）
18:00 · 这周要做的                       ← 几点 · 出处（那一篇的标题）
个人笔记                                 ← 开着好几个仓库时才有：哪个仓库
[ 完成 ]  [ 10 分钟后 ]  [ 打开 ]
```

- 用 reminder 场景：一直停在屏幕上，点掉才走
- 「完成」：把那一行勾上（那一篇开在编辑器里就经编辑器改，和打字走同一条路）；「10 分钟后」：10 分钟后再响一次（应用关了就没了）；
  「打开」和点通知本身：窗口提到前面、打开那一篇、光标停在那一行
- 在别处勾掉了（编辑器里、日历里），还挂着的那条通知自己收掉
- 提前响的，第二行写「还有 10 分钟 · 18:00 · 这周要做的」

**设置**（命令面板「提醒设置…」）：开关、提前量、提示音（清泉 / 木铃 / 系统提示音 / 不响，每个都能试听）、「发一条试试」。
存在本机（数据目录的 `reminders.json`），不跟着仓库同步：通知是这台设备上的事。

### 1.3 怎么做

- **计时在 Rust 里**（日程插件 `plugins/journal/reminders.rs`），一个应用一个线程，每分钟的整点醒一次，按墙上的时钟算
  「上次看到这次之间有哪些到点了」。不靠网页里的定时器：窗口最小化了 WebView 的定时器会被节流，睡眠醒来也不准
- 每次查开着日程的每个仓库窗口的 task 表（日历「当日安排」查的就是它，已经有日期、几点、做没做完、在哪一篇哪一行）
- 去重：仓库 + 文档 id + 那一行的原文 + 响的时刻。行号会漂（上面加了一行），原文不漂；改了几点就是新的一条，该响还响
- **Windows 通知**：WinRT 的 `ToastNotification`（`windows` crate）。应用标识（AUMID）就是 tauri.conf.json 的 identifier：
  安装包给开始菜单的快捷方式登记了它（Tauri 的 NSIS 模板里有 `SetLnkAppUserModelId`），通知上显示「Odea」和图标；
  没装的（开发版、直接跑 exe）在 `HKCU\Software\Classes\AppUserModelId\<identifier>` 登记名字和图标
  （[微软：没打包的应用发通知](https://learn.microsoft.com/en-us/windows/apps/design/shell/tiles-and-notifications/send-local-toast-other-apps)）。
  按钮的回调在本进程里（`Activated` 事件），应用开着就接得到
- **声音**：见 §2.3
- 「完成」「打开」交给那个仓库窗口的前端（`ReminderAction` 事件），「10 分钟后」Rust 自己记着
- **macOS / Linux**：`notify-rust` 发通知（没有按钮），声音用系统自带的播放程序（`afplay`、`pw-play` / `paplay`）放。都没在真机上走过

## 2. 声音

### 2.1 调研

**什么让人觉得烦。**

- 尖锐度（高频成分多）是头号原因。Zwicker、Fastl 的《心理声学》里「感官愉悦度」和尖锐度反着走，也受粗糙度、响度、调性影响
  （[Springer](https://link.springer.com/chapter/10.1007/978-3-662-09562-1_9)）；
  一套 129 种声音的评分里，除了响度，尖锐度对「烦」的贡献最大（r²=0.72），粗糙度（0.04）、调性（0.08）都不显著
  （[publisso](https://journals.publisso.de/en/journals/zaud/volume7/zaud000073)）
- 电动车提示音的实验：断续的纯音，频率越高越烦，350 Hz 平均 3/10，2 kHz 约 7/10；纯音（5.4）比断续音、复合音（4.8）更烦
  （[arXiv 2509.16901](https://web3.arxiv.org/pdf/2509.16901)）
- 起音、衰减明显影响冲击声有多烦（[密歇根理工的论文](https://digitalcommons.mtu.edu/cgi/viewcontent.cgi?article=1558&context=etds)）

**紧迫感从哪来**（Edworthy 1991、Hellier 1993 一路下来的研究，[综述](https://www.mcgill.ca/mpcl/files/mpcl/suied_2008_jepappl.pdf)）：
音越高、越快、重复越多、泛音越不规则，听着越急；速率最管用。车载提示音的实验里，脉冲长短、间隔、占空比、音色对紧迫感的影响
比对「烦」大得多 —— 两者可以分开调（[Marshall 等](https://www.researchgate.net/publication/245417108_Annoyance_and_Urgency_of_Auditory_Alerts_for_in-Vehicle_Information_Systems)）。
任务提醒是不急的那一类：慢、少、规则。

**旋律。** RMIT 2020 年的研究（PLOS ONE，50 人自评）：被评为有旋律的闹铃和更少的起床昏沉有关，「哔哔」那种中性的声音反而相关更多
（[RMIT](https://www.rmit.edu.au/news/all-news/2020/feb/melodic-alarms)）。样本小、是自评，只当方向。
另有专利认为彼此协和的音不容易留下不好的印象；贝尔实验室早年发现太好听的电话铃没人接（[同一篇综述](https://medium.com/@fivepointseven/how-to-design-a-pleasant-alert-sound-2ddf7a9724de)）—— 好听和听得见之间要拿捏。

**平台的说法。** 苹果 HIG：自定义提示音要短、好认、做得精（[Notifications](https://developer.apple.com/design/human-interface-guidelines/notifications)）。
Material：声音的分量要和它在界面里的分量相称；什么时候不出声和什么时候出声一样要设计（[About sound](https://m2.material.io/design/sound/about-sound.html)）。

**Windows 11 自带的几声**（实测 `C:\Windows\Media`，`scripts/sound/analyze.mjs`）：

| 文件 | 长 | 峰值 | 最响 400ms 的 RMS | 频谱重心 | 能量分布 | 起音 |
|---|---|---|---|---|---|---|
| Windows Notify Calendar | 1.36 s | -16.5 dBFS | -24.9 dBFS | 400 Hz | 86% 在 300–700 Hz | 约 250 ms |
| Windows Notify Email | 1.32 s | -13.3 | -23.0 | 301 Hz | 63% 在 300 Hz 以下 | 约 120 ms |
| Windows Notify System Generic | 1.14 s | -11.8 | -21.1 | 250 Hz | 99% 在 300 Hz 以下 | 约 9 ms |
| Windows Proximity Notification | 1.13 s | -11.3 | -23.2 | 838 Hz | 300 Hz–2 kHz | 约 660 ms |

很低、很软、慢慢涌上来。好处是一点不刺耳；毛病是在笔记本的小喇叭上（300 Hz 以下基本放不出来）、在别的声音里容易听漏。

**Windows 上声音怎么放。** 通知的 `<audio src>` 只认 `ms-appx:///`、`ms-resource`，不认 `ms-appdata`、网址、`C:\` 这种绝对路径
（[Custom audio on toasts](https://learn.microsoft.com/en-us/windows/uwp/design/shell/tiles-and-notifications/custom-audio-on-toasts)）。
没打包的应用没有 `ms-appx`，自己的声音只能「通知不出声 + 应用自己放」。代价是「勿扰」得自己判断：
`SHQueryUserNotificationState` 只报全屏、演示、忙这些，`QUNS_QUIET_TIME` 不是勿扰（是新用户第一次登录后的那一小时）；
用户开的勿扰只能读没公开的 WNF 状态（[微软文档](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ne-shellapi-query_user_notification_state)、
[notification-state-ffi](https://npmjs.com/package/notification-state-ffi) 的说明）。

### 2.2 设计

两个声音，都用加法合成算出来（`scripts/sound/reminder.mjs`，生成 `src-tauri/sounds/*.wav`，16 位单声道 32 kHz，各 90 KB 左右）：

| | 清泉（默认） | 木铃 |
|---|---|---|
| 音 | D5 → A5，上行纯五度，隔 150 ms | C5 → E5 → G5，大三和弦往上走，各隔 110 ms |
| 音色 | 近乎谐和的分音（0.5、1、2、3 倍）加一条 4.2 倍的玻璃味，很快就没了：像碰了一下玻璃杯 | 马林巴的分音 1 : 3.93 : 9.2，高的两条 50 ms、20 ms 就没了：木头味 |
| 起音 | 6 ms（升余弦） | 4 ms |
| 衰减 | 基频按指数走，时间常数 0.42 s | 0.3 s，最后一个音 0.42 s |
| 混响 | 一点点房间感（Schroeder，湿声 16%，先过低通） | 12% |
| 长 | 1.41 s | 1.31 s |
| 峰值 / 最响 400ms 的 RMS | -14.7 / -23.0 dBFS | -12.4 / -23.0 dBFS |
| 频谱重心 | 743 Hz，2 kHz 以上几乎没有 | 730 Hz |

为什么这样：

- 基频 520–880 Hz：笔记本喇叭放得出来，又远低于开始烦人的 2 kHz；能量全压在 2 kHz 以下（尖锐度低）
- 不是纯正弦：几条很快衰减的分音给出「被敲了一下」的质感
- 起音 4–6 ms：有个清楚的头，不像 Windows 自带的慢慢涌上来那样容易听漏；又不是 0 ms 的「咔」
- 两三个音、协和、上行、慢：有旋律、不急，是「轻轻拍一下肩」，不是警报
- 响度和 Windows 自带的邮件提示音一个量级（RMS -23 dBFS），跟着系统音量走

**什么时候不响**（声音的留白）：

- 只响一次，不循环；同一分钟到点好几条只响一声；上一声还没完（3 秒内）不再响
- 选的是我们的声音时：Windows 开着勿扰、全屏（游戏、看视频）、在演示，都不响；通知照样按系统的规矩出
- 选「系统提示音」时，声音交给通知自己（`ms-winsoundevent:Notification.Reminder`），勿扰、各应用的「通知时播放声音」开关全由系统管
- 选「不响」：只有通知

## 3. 属性面板

### 3.1 别家怎么做

- **Obsidian**：属性类型是整个库一份，存在 `.obsidian/types.json`，只记手动选过的那些，别的按值猜（`true` / `false` 是勾选……）；
  值和选的类型对不上时提示「type mismatch」。类型有 text、multitext（列表）、number、checkbox、date、datetime，外加 tags、aliases 两个专用的
  （[Obsidian 帮助：Properties](https://obsidian.md/help/properties)、
  [types.json 只记手动选过的](https://forum.obsidian.md/t/not-all-properties-present-in-types-json/96646)）。
  设置里「文档中的属性」可选显示、隐藏、源码，默认显示（面板）

### 3.2 定下来的

**类型：按值猜，仓库里记着的优先，同名键看整个仓库。** 依次看：

1. 仓库里记着的：`.obsidian/types.json` 在就读它、在面板里改了类型也写它（同一个文件夹，Odea 和 Obsidian 打开一个样）；
   不在就记在 `.odea/types.json`（同样的格式）
2. 整个仓库里同名的键，值多半是什么类型
3. 这个值本身像什么：`2026-11-20` 是日期、`2026-11-20T15:30` 是日期时间、`[a, b]` 和下面一行一条 `- a` 是列表、`true` / `false` 是勾选、数字是数字，别的是文字

所以 `截止:` 空着、别的笔记里 `截止` 都是日期，它还是日期选择器 —— 只按值猜就做不到这一点。

**默认显示成面板。** 命令面板「属性显示成源码」「属性显示成面板」（本机偏好）；面板底下的「源码」临时打开一次。

> 动手时才发现（§6.1）：属性块根本没进编辑器 —— Rust 读文件时整个属性块拆掉了（`frontmatter::split`），
> 编辑器里只有正文，用户自己的 `tags`、`status` 在 Odea 里一直是看不见的（demo 里画成「一块灰底的源码」是错的）。
> 所以面板不是编辑器里的装饰，而是标题下面单独的一块，「光标挪进属性块露出源码」这一条不成立，换成上面的「源码」。

**改一项只重写那一项的那几行**，别的字节不动（注释、引号、键的顺序都留着）。嵌套的、多行字符串（`|`、`>`）那一项只读显示，点进去改源码。

**提示从整个仓库来**：加属性时提示仓库里出现过的键（按用得多少排），填值时提示这个键出现过的值（`status` 写过「进行中」，以后都提示）。

## 4. 视图文件

### 4.1 Obsidian 的 Bases

- 一个 `.base` 文件，YAML：`filters`（全局筛选）、`formulas`（公式算出来的属性）、`properties`（列的显示名）、`summaries`（汇总）、
  `views`（好几个视图）（[Bases syntax](https://obsidian.md/help/bases/syntax)）
- 筛选是 `and` / `or` / `not` 嵌套，叶子是表达式字符串：`'status != "done"'`、`file.hasTag("book")`、`file.inFolder("项目")`、
  `file.mtime > now() - "1 week"`。属性写 `note.status` 或直接 `status`，文件的写 `file.name`、`file.mtime`，公式的写 `formula.x`
- 视图：表格、卡片（1.9）、列表、地图（1.10）、看板（1.14，按 `groupBy` 分列、`groupOrder` 定列的顺序）。视图自己的键有
  `order`（哪几列）、`groupBy`、`groupOrder`、`limit`、`filters`、`summaries`
- 公式语言照 JavaScript 的行为，约 68 个函数和方法，日期格式是 Moment.js 的（[Functions](https://obsidian.md/help/bases/functions)）
- 能嵌进笔记：`![[项目.base]]` 用第一个视图，`![[项目.base#看板]]` 指定视图
- **改过的不兼容**：1.9.1（2025 年 5 月）内置函数从 snake_case 改成 camelCase；1.9.2（2025 年 6 月）大改公式和文件格式：属性名不再用反引号、
  改成 `note["属性 名"]`，日期运算从 `dateModify(date, string)` 改成 `date + string`，加了 `properties` 一节；1.9.5 去掉了 `String#icon()`
  （[1.9.2 更新日志](https://obsidian.md/changelog/2025-06-05-desktop-v1.9.2/)、[AlternativeTo 的报道](https://alternativeto.net/news/2025/6/obsidian-1-9-2-updates-bases-with-new-syntax-and-file-format-changes)）。
  之后 1.10–1.15 只加东西：2026 年 9–11 月的更新日志里没有 Bases 的不兼容改动，只有 `groupOrder` 必须是列表、筛选值里的引号存坏了这类修正

### 4.2 定下来的

**用 `.base`，不自己发明格式。**

- Odea 一直跟着 Obsidian 的文件约定走：属性块、`[[双链]]`、`![[嵌入]]`、callout、Tasks 的 `📅`，同一个文件夹两个应用都能开。
  自己弄一个 `.view` 就成了第三种谁都不认的格式，从 Obsidian 过来的人的 `.base` 打不开
- 不兼容的那几次都在它刚出来的头一个月（2025 年 5–6 月），之后一年半只加不改。我们要的那部分（筛选、表格和看板的键）是它最稳的部分
- 代价：它的公式语言很大。第一版只认一个子集，不认得的原样留着、界面上说清楚哪一列「Odea 还算不了」；写回时只改动过的那几个键

第一版认的：

- `filters`：`and` / `or` / `not`；比较 `== != > < >= <=`、`&&` `||` `!`；`file.inFolder()`、`file.hasTag()`、`file.hasProperty()`、`file.hasLink()`；
  `file.name`、`file.folder`、`file.mtime`、`file.ctime`；`now()`、`today()` 加减 `"1 week"` 这种时长；属性 `note.x`、`x`、`note["x"]`
- `views`：`table`、`cards`、`list`、`kanban`；`order`、`groupBy`、`groupOrder`、`limit`、`filters`；`properties` 里的 `displayName`
- 不认：`formulas`（列里显示「—」，悬停说 Odea 还算不了公式）、`summaries`、`map`

**第一版：表格和看板。** 卡片、列表跟着做（和表格同一份数据，排法不同）。日历视图不做：Bases 自己也没有，日程的日历已经按日期摆任务。

**智能文件夹先不并进来。** 智能文件夹是树上「一行字的筛选」，轻、快，很多人只要这个；视图文件是一个文件，能同步、能嵌。
以后可以在智能文件夹的菜单里加「存成视图文件」。

**顺序：先属性面板，再视图文件。** 视图里改的东西写回各篇的属性块，用的就是属性面板那一套读写。

## 5. 提醒的实现记录（2026-11-12）

**写法**（`plugins/journal/tasks.rs`）：任务行多认一个 `⏰`：`⏰ 2026-11-12 17:30`、`⏰ 17:30`（任务那一天），和后面的字可以连着写；
认不出的 `⏰` 照原样当字。只有 ⏰ 的任务，⏰ 那一天、那个时刻就是它的日期和时间（进日历）。task 表加一列 `remind_at`，
索引升到第 7 版（和下面属性的 `props` 列一起，0.8.0 的第 6 版直接重建一次）。

**计时**（`plugins/journal/reminders.rs`）：一个线程，睡到下一分钟整点后 0.3 秒、最多睡 20 秒，醒来按墙上的时钟看
`(上次, 现在]` 之间哪些到点了。隔了 3 分钟以上算睡醒，补 12 小时以内的；刚起来时 `上次 = 现在`，关着时到点的不补。
每次醒来还看一眼挂着的通知：那一条在别处勾掉了、那个仓库窗口关了，收掉。响的时刻 = ⏰，没有 ⏰ 是「日期 几点 − 提前量」；
上午、下午这种 `fire_time` 给 None。去重键是 `窗口 · 文档 id · 原文 · 响的时刻`，两天前的扔掉。
设置在数据目录的 `reminders.json`（开关、提前量 0/5/10/15/30/60、声音 chime/marimba/system/off），认不得的值回默认。

**通知**（核心的 `notify.rs`，不认识日程）：
- Windows：WinRT `ToastNotification`，`scenario="reminder"`（停在屏幕上），按钮「完成」「10 分钟后」后台激活、「打开」前台激活，
  点通知本身也是打开。`<audio silent="true"/>`，声音应用自己放；选了「系统提示音」才交给通知（`ms-winsoundevent:Notification.Reminder`）。
  回调在本进程的 `Activated` 事件里（通知对象留在 `LIVE` 里，点了、被划掉了才放）；退出时 `RunEvent::Exit` 里 `ClearWithId` 全收掉
- 应用标识就是 identifier。每次启动在 `HKCU\Software\Classes\AppUserModelId\<identifier>` 登记 `DisplayName`、`IconUri`
  （图标写到数据目录的 `notification-icon.png`），值没变不重写。**坑**：一开始「开始菜单里有 Odea.lnk 就不登记」，
  结果测试版（别的 identifier）被用户装的那个版本的快捷方式骗了，通知进了历史却登记不全
- 勿扰：`SHQueryUserNotificationState` 不是「可以接通知」（全屏、演示、忙、锁屏）就不出声；再读 WNF 的
  `WNF_SHEL_QUIETHOURS_ACTIVE_PROFILE_CHANGED`（ntdll 的 `NtQueryWnfStateData`，用 `windows-link` 导入），非 0 是开着勿扰。读不到当没开
- 放声音：`PlaySoundW(SND_MEMORY | SND_ASYNC)`，WAV 用 `include_bytes!` 编进去，外面包一层 `#[repr(align(4))]`（PlaySound 当 WCHAR 指针收）。
  同一分钟几条只响一声、3 秒内不重复
- macOS / Linux：`osascript` / `notify-send` 发（没有按钮），`afplay` / `pw-play`、`paplay`、`aplay` 放。没在真机上走过

**完成、打开**（`src/plugins/journal/reminders.ts`）：Rust 发 `ReminderAction` 给那个仓库窗口（日程的 Effects 里听着）。
「完成」：那一篇开在编辑器里就按原文找那一行（离原来的行号最近的那一条），经 `liveEditor().edit` 勾上；没开着调新命令
`task_complete`（Rust 按行号 / 原文找、只勾不取消，已经勾上了返回 false）。「打开」：`openDocument` 带行号。
原来的 `toggle_task` 和它共用 `edit_task_line`。

**设置**：命令面板「提醒设置…」（`ReminderSettings.tsx`）：开关、提前量、四种声音（点了就试听，旁边也有试听按钮）、
写法的三个例子（跟着提前量变）、「发一条试试」；开着勿扰时底下说一句「提示音先不响」。

**测试**：Rust `tasks.rs` 2 条（⏰ 的几种写法、只勾不取消）、`reminders.rs` 3 条（哪些响和提前量、通知上的字、设置文件）、
`notify.rs` 1 条（通知 XML 的转义和按钮）；前端 `reminders.test.ts` 5 条（只勾不取消、按原文找行、经编辑器 / 交给 Rust）。
桌面端（单独 identifier 的调试版，经 WMI 在 Claude 的 MSIX 容器外起）实测：到点的两条、⏰ 那一条都进了通知历史，字对
（「对一下官网的稿子 / 还有 85 分钟 · 23:59 · 这周要做的」）；「发一条试试」出来了；系统记下了用户点过两次。
**没验证到**：从容器里、容器外的 UI 自动化都找不到屏幕上的通知（找不到「完成」按钮），所以按钮的回调（尤其是后台激活的
「完成」「10 分钟后」在没打包的应用里走不走本进程的 `Activated`）没有亲手点过；声音放没放出来听不到；勿扰开着的情况没测。
- 坑：调试版启动时把绑定写到相对路径 `../src/lib/bindings.ts`，经 WMI 起时工作目录是 `System32`，写不进去就 panic（退出码 101）——
  启动脚本先 `cd /d src-tauri`
- 坑：从容器里起的进程登记 AUMID 写的是重定向的注册表，Windows 看不到

## 6. 属性面板的实现记录（2026-11-12）

### 6.1 数据怎么走

- Rust（`vault/properties.rs`）：属性就是 `FrontMatter::extra` 那几行原文。`doc_properties` / `doc_set_properties` 读写它，
  写回前核对：不能有单独一行 `---`、不能冒充应用的八个键；笔记写回时补上 `id`、`created`（和 `note_save` 一样，
  第一次被 Odea 写的笔记都会多这两行）。正文一个字不动，冲突判断只比正文（`keep_unseen_edits`），改属性不会另存冲突副本
- 索引 doc 表加 `props` 列（原文），`vault_property_catalog` 从这里现算：每个键几篇用了、常见的值（最多 40 个）、
  值多半是什么类型（空着的不算票）；归档的不算
- 记着的类型：仓库里有 `.obsidian/` 就读写 `.obsidian/types.json`，没有就是 `.odea/types.json`，`{"types": {...}}`，文件里别的键原样留着
- `Note` 多了 `properties`（来自 `props` 列），`noteGet` / `noteSave` 一回来就放进属性缓存（`properties/store.ts`）：
  面板第一帧就有，正文不会等它到了再往下跳。别的文档（某一天、目标）没走这条，第一次打开时异步取

### 6.2 前端

- `properties/yaml.ts`：认成一条条（键、所在的行、scalar / list / complex），改一条只换它那几行；列表照原来的写法
  （一行 `[a, b]` 还是一行一条），新加的照 Obsidian 一行一条；文字里会被认成别的（`2`、`true`、日期、`[[双链]]`、带 `: `）加引号；
  换类型时能留的值留着（日期 → 日期时间补 09:00、列表 → 文字用逗号连）
- `properties/PropertiesPanel.tsx`：在 `DocumentView` 的标题下面、分隔线上面。没有属性时不占地方；做客的那一篇不画；
  不能编辑时只读。一行：类型图标（点开换类型，记进 types.json）、键（点了改名）、值、删除（指到这一行才显出来，只淡颜色）。
  值：文字（下面提示这个键出现过的值，↑ ↓ 挑；双链只显示标题，Ctrl + 点打开）、数字、勾选、日期 / 日期时间（「11月20日 周五」，
  30 天内的写「还有 8 天」「今天」「过了 2 天」，点了是系统的日期选择器）、列表 / 标签 / 别名（小块，回车或逗号加一项，空着按退格删最后一项）、
  多行的（只读，「在源码里改」）。底下「添加属性」「源码」平时看不见，指到这一块才淡出颜色
- 「添加属性」：命令面板、Ctrl+;（正在写的那一篇接）；键名提示整个仓库用过的（带类型图标和次数），类型照记着的 / 仓库里多半的
- 写回一次一次排着，先改界面，Rust 写好了对一遍，失败了退回去、在面板里说为什么
- 字号、图标只用档位里的（`uiScale.test.ts` 管着），按键提示写 Cmd / Ctrl 不画 ⌘

### 6.3 测试

Rust `vault/properties.rs` 4 条（几种写法、一览的类型和次数、写回的核对、值的类型）、`vault/tests.rs` 2 条（只改自己那几行、
types.json 跟着 .obsidian 走）；前端 `properties/yaml.test.ts` 5 条。浏览器预览里点过：Ctrl+; 加一条、打字加标签、勾选、
「源码」、暗色；桌面端（WebView2）看过一篇照 Obsidian 写的属性块（文字、标签、日期、数字、勾选、双链都对），
在面板里勾「公开」后磁盘上属性这一块只变了那一行（另外多了 Odea 自己的 `id`、`created`）。
没做：某一天、目标的属性第一次打开是异步取的（会晚一帧出来）；类型菜单、键改名在桌面端没点过；L1 插件够不到属性。

## 1. 结论

| 问题 | 定了什么 | 为什么 |
|---|---|---|
| 双击图标打开什么 | **没在运行：打开上次开着的仓库；已经在运行（Windows / Linux）：弹启动器** | VS Code 在 Windows 上就是这样（`window.restoreWindows` 默认 `all`，`openWithoutArgumentsInNewWindow` 在 Windows / Linux 默认 `on`、macOS 默认 `off`）；Obsidian 在 Windows 上再启动一次也是弹库选择器 |
| 一个窗口能开几个仓库 | **一个窗口一个仓库**，同一个仓库只开一个窗口 | 两个窗口开同一个文件夹 = 两份监听、两个写入方、同一份索引，迟早互相覆盖 |
| P2（笔记 / 今日TODO / GOAL / 日历 / 归档）放哪 | **不单独做成一种「模式」，做成每个仓库都能开的「日程」功能** | 今日TODO、GOAL、日历本来就是仓库上的视图（日记 / 目标文件 + 全库扫出来的带日期任务）；单独成一个模式，日历就看不到别处笔记里的任务 |
| 启动器上的按钮 | 新建 / 打开文件夹 / 从同步仓库拉一份 / 加入协同编辑 | 「打开逻辑目录」和「打开本地目录」合成一个「打开文件夹」，文件夹里有 `.odea/tree` 就认成逻辑目录 |
| 逻辑目录的树记在哪 | **单独一份清单 `.odea/tree`，一行一个节点，按笔记 id 引用** | 写进每篇属性块会改文件的修改时间（「上次更新」就是它，技术方案 §5.2），拖一下排序要改一串文件，空文件夹也没处放 |
| 一篇能不能在树上放好几处 | **不能**，树不是图；以后要的话加「快捷方式」节点 | 一篇放多处，删除到底删什么、面包屑写哪条路都说不清 |
| 没被树引用的笔记 | 出现在固定的「未整理」里 | 延续「什么都不会消失」（技术方案 §5.2） |
| 逻辑目录同步撞车 | 这一个文件不出冲突副本，**按节点三方合并**，同一节点两边都改了用本机的 | 两棵树没法用；本机优先和 §5.9 一致 |
| 挂载别处的真实文件夹 | **第一期不做**，先做「导入」 | 索引、监听要跨多个根，仓库外的文件同步管不到 |

## 2. 现状和要解决的问题

现在应用只认一个仓库（`config.json` 的 `vaultRoot`），结构是固定的（技术方案 §5.2）：

```
笔记/   日记/   目标/   归档/   附件/   .odea/
```

- 「换仓库」只有命令面板里的「更换笔记文件夹…」，换完整页重载，同一时刻只有一个仓库开着
- 打开 Obsidian 的库也行（不认识的位置都当笔记），但左边看到的还是「笔记 / 今日TODO / GOAL / 日历 / 归档」这一套，文件树只列 `笔记/` 下面的
- 文件夹 = `笔记/` 下的真目录（§5.8），不能手动排序，不能和硬盘上的位置分开摆

要做到的：

1. 像 Obsidian、VS Code 那样有一个启动器，记着用过的仓库，双击图标的行为和它们一样
2. 打开任意文件夹，左边直接是它的文件和文件夹（Obsidian 那样）
3. 能建「逻辑目录」：树按自己的意思摆，和文件在硬盘上放在哪无关
4. 现在这套「日程」（今日TODO / GOAL / 日历 / 归档）不丢，老用户升级后看到的还是原来的样子

## 3. 启动器

### 3.1 双击图标的行为

| 情况 | 行为 |
|---|---|
| 没在运行，双击图标 | 打开上次关的时候还开着的那些仓库，各一个窗口。一个都打不开（列表是空的、文件夹都找不到了）时弹启动器 |
| 已经在运行，再双击（Windows / Linux） | 弹启动器；启动器已经开着就把它提到前面 |
| macOS 点 Dock | 有窗口就提到前面（系统默认）；一个窗口都没有时（`RunEvent::Reopen`）打开最近的仓库，没有就弹启动器 |
| 在启动器里选了一个已经开着的仓库 | 把那个窗口提到前面，不开第二份 |
| 上次的文件夹找不到了（移动硬盘没插、被删了、被改名了） | 不打开它，启动器里那一条标「找不到」。**绝不在原处新建一个空仓库**：以前 `prepare` 会 `create_dir_all`，看着就像笔记全没了（技术方案 §5.7） |
| 点 `odea://join/…` 链接 | 交给最近用过的那个仓库窗口；一个都没开着就先打开最近的仓库 |

**「上次开着」怎么记。** 一个仓库窗口关掉时：还有别的仓库窗口开着 → 记成「没开着」；它是最后一个 → 照旧记成「开着」，下次启动打开它。这样一个个关窗口，下次只回到最后关的那个；关应用（最后一个窗口）时开着的都回来。Obsidian 有个坑正好反过来：主窗口关了、副窗口还开着时整个应用退出，下次落到选择器上 —— 这里没有主次窗口，每个仓库窗口都一样。

**新装第一次打开**：弹启动器。以前是直接在「文档/Odea」建一个仓库，再用横幅告诉用户笔记放在哪、要不要换（§5.7「第一次打开时说一声」）；现在新建时位置就是用户自己选的（默认还是「文档/Odea」），那条横幅不要了。从更老的 OnTheWay（SQLite 时代）升上来、旧库里有东西的，照旧搬进「文档/Odea」直接打开，不弹启动器。

### 3.2 布局

参考 Obsidian 的库选择器：左边是用过的仓库，右边是 Logo、版本号和几个操作。窗口 800×560，不能改大小，无边框（右上角最小化、关闭），只淡入（CLAUDE.md 的动效规矩）。

**左边的列表**

- 一条：名字（文件夹名）+ 路径；逻辑目录前面一个小图标；正在别的窗口里开着的标「已打开」；找不到的灰掉、标「找不到」
- 按上次打开的时间排，最近的在上
- 单击打开；⋮ 菜单：在资源管理器中显示、从列表里移除（**不删文件**，菜单里写清楚）

**右边的操作**

| 操作 | 做什么 | 哪一期 |
|---|---|---|
| 新建 | 名字 + 位置（默认「文档」）→ 建文件夹、放使用指南、打开。P11.3 起建的是逻辑目录（§12） | P11.1 |
| 打开文件夹 | 系统的选择文件夹对话框 → 打开它。文件夹里有 `.odea/tree` 的是逻辑目录，否则是本地目录（按真实结构） | P11.1 |
| 从同步仓库拉一份 | 现有的「接入同步」（技术方案 §5.9.7）挪到这里：登录、选仓库、clone 到新文件夹、打开。换电脑时最常用（§13） | P11.4 |
| 加入协同编辑 | 粘贴邀请链接 → 交给最近用过的仓库窗口去加入（访客那篇本来就不落进仓库，[协同编辑.md](./协同编辑.md) §3）。P11.4 起开一个不用开仓库的访客窗口（§13） | P11.1 |

编辑器里打开启动器：命令面板「打开别的仓库…」；P11.2 左栏改版后左下角放「仓库名 ⌄」（Obsidian 也在这里）。

## 4. 多窗口：一个窗口一个仓库

### 4.1 后端的状态

现在 `AppState` 里只有一个仓库（`vault`、`watcher`、`sync`、`indexing`），所有命令都直接拿它。改成：

```
AppState
├─ workspaces: 窗口标签 → Workspace     每个仓库窗口一份
│     Workspace { vault, watcher, sync, indexing }
├─ data_dir、sync_login、update        全应用一份（账号、更新和窗口无关）
└─ collab                              全应用一份，记着会话属于哪个窗口（§4.3）
```

- **命令怎么知道是哪个仓库**：加一个注入参数 `Ws`（实现 Tauri 的 `CommandArg`），从调用它的窗口标签查出 `Workspace`；specta 生成前端类型时跳过它（和 `State` 一样实现 `FunctionArg` 返回 `None`）。前端的调用一个字不用改
- **事件只发给那个窗口**：`VaultChanged`、`IndexProgress`、`SyncStatusChanged`、`SyncNotice` 从 `emit` 改成 `emit_to(标签)`。别的窗口收到别的仓库的变化会去刷新根本不存在的笔记
- **后台线程认仓库不认窗口**：后台读索引（`spawn_backlog`）、文件监听、同步线程都拿着自己那份 `Arc<Mutex<Vault>>`，和现在一样
- 索引本来就是一个仓库一个文件（`index/<路径指纹>.db`），不用动

### 4.2 窗口

- 窗口都由 Rust 建（`tauri.conf.json` 里不再写窗口）：仓库窗口 1440×900、无边框、先藏着等前端 `ready`，和现在一样；启动器单独一种
- **标签**：老用户升级时迁过来的那个仓库用 `main`（窗口位置插件按标签记位置，升级后窗口还在原处）；别的用 `vault-<路径指纹>`，每个仓库记着自己的窗口位置。撞了（一个窗口换过仓库）加序号
- **前端怎么知道自己是哪种窗口**：启动器的地址带 `?launcher`；启动后再开的仓库窗口带 `?quiet`（不播开场动画 —— 开场的 sessionStorage 是一个窗口一份，新窗口每次都会播）
- **localStorage 是所有窗口共用的**：「上次停在哪」（`odea.session`）和「哪些文件夹展开着」（`odea.folders.expanded`）改成按仓库分开存（键后面接仓库路径）；按仓库存的没有时读旧的那个键，老用户升级后照旧回到上次那篇。主题、偏好、表情最近用过的仍然全应用一份
- **关窗口**：前端的关闭保护照旧（先存编辑器里的），`win_force_close` 只收这个窗口的：结束这个窗口的协作、这个仓库的同步推一次（最多等 3 秒）。窗口销毁后从 `workspaces` 里拿掉（停监听、停同步），按 §3.1 记「开没开着」
- **再双击**：`tauri-plugin-single-instance` 的回调里，参数里有 `odea://` 的交给 deep-link 处理，没有的弹启动器
- 最小化时让 WebView2 少占内存（`memory.rs`）原来用一个全局的开关记状态，改成按窗口记

### 4.3 协作

一次仍然只有一个会话（[协同编辑.md](./协同编辑.md) §11），会话属于开始它的那个窗口：

- 主持、加入、附近、继续上次的协作时，`CollabHub` 记下窗口标签；`CollabEvent` 只发给它，字节管道（`collab_pipe`）按窗口登记，只往它那条里塞
- 另一个窗口要开始会话时，前一个还在：报「另一个窗口正在协作」
- 主持人那边访客要附件、传附件，读写的是开始会话那个窗口的仓库（以前是全局唯一的那个）
- 关窗口只结束它自己的会话
- `odea://` 链接（应用开着时点的）：发给最近获得过焦点的仓库窗口；一个都没有就打开最近的仓库，链接存着等它取（`collab_pending_link`）

### 4.4 换仓库、搬仓库

命令面板「更换笔记文件夹…」照旧（搬过去 / 复制过去 / 只换文件夹），换的是**这个窗口**的仓库：

- 新文件夹已经在别的窗口开着：不换，报错
- 换完更新仓库列表：搬过去 → 这一条的路径改成新的；复制过去 / 只换文件夹 → 新文件夹加进列表（或者把已有的那条标成开着），原来那条标成没开着
- 第二台设备「接入同步」（clone 到新文件夹再换过去）同样走这里

## 5. 仓库列表

`config.json`（应用数据目录，每台机器一份）：

```json
{
  "vaultRoot": "C:\\Users\\Gred\\Documents\\Odea",
  "vaults": [
    { "path": "C:\\Users\\Gred\\Documents\\Odea", "window": "main", "lastOpened": 1760918400000, "open": true },
    { "path": "D:\\forGPT", "lastOpened": 1760832000000, "open": false }
  ]
}
```

- `window`：只有迁移过来的那一个写 `main`（§4.2），别的不写
- **迁移**（照 `old_name.rs` 的老办法「新版认旧的」）：`vaults` 是空的、`vaultRoot` 有值 → 把它变成第一条，`window: "main"`、`open: true`。升级后第一次打开直接进原来的仓库，体验不变
- `vaultRoot` 继续写（最近打开的那个仓库），降级回旧版时旧版还能找到笔记
- `ODEA_VAULT`（开发、测试用）：只打开它，不记进列表
- 名字就是文件夹名，不另存

## 6. 日程：仓库上的一组功能

**P2 不在启动器上单独做成「日常模式」。** 今日TODO = `日记/今天.md`，GOAL = `目标/` 下的文件，日历的「当日安排」是全库扫出来的 `@日期` 任务（技术方案 §5.4）——它们是建在仓库上的视图，不是另一种存储。单独成一个模式，要么另开一个仓库（日程和笔记分家，日历看不到笔记里的任务，而「任务写在哪篇文档里都会进日历」恰恰是卖点），要么同一个仓库两套界面来回切。Obsidian 也是这么拆的：日记、日历是插件，哪个库都能开。

做成仓库的一组功能，叫「日程」：今日TODO、GOAL、日历、归档。

- **开关存在仓库里**（`.odea/vault.json` 的 `features.journal`），跟着仓库走、跟着同步走
- **默认值**：新建的仓库开；打开一个已有的文件夹不开 —— 不往别人的文件夹里建 `日记/`、`目标/`。在左栏或命令面板「启用日程」。老用户的仓库（迁移过来的）开
- **文件夹可配**：`日记`、`目标`、`归档` 现在写死在 `vault/layout.rs`（`DAYS_DIR` 等），改成读 `vault.json` 里的值，没写就用现在的名字
- **团队仓库的日程是团队的**（2026-10-22，[协同编辑.md](./协同编辑.md) §22.6）：每天一篇团队的、团队的目标；个人的日程放在个人仓库。几个仓库都开着日程时，今日TODO、目标、日历那一行日期右边有日程切换器，点了跳到那个仓库的窗口、停在同一页
- **接 Obsidian 的日记**：打开一个 Obsidian 库时读 `.obsidian/daily-notes.json` 里设的日记文件夹，日期格式是 `YYYY-MM-DD` 的话，他原来的日记直接进今日TODO 和日历

**左栏**（P11.2）：最左边一条窄栏（Obsidian 的 ribbon、VS Code 的活动栏），固定有「文件」；开了日程才多出今日 / 目标 / 日历 / 归档。现在列表栏的位置换成文件树：本地目录是真实结构（整个仓库，不再只是 `笔记/`），逻辑目录是自定义的树。P2 现在的「全部笔记」（置顶 + 文件夹 + 笔记）就是文件树的一种样子，接着用。开着日程的本地目录，树的根还是 `笔记/`（日记、目标从窄栏进），老用户看到的和现在一样。（实际做的时候细化了：Odea 建的仓库树根是「笔记」，打开的文件夹开了日程树根还是整个文件夹，见 §11.2）

## 7. 逻辑目录

### 7.1 解决什么

树按自己的意思摆，不受文件在硬盘上放在哪的约束：手动排序，文件夹随便建、随便拖，改名、挪动文件夹不碰任何文件。Obsidian 的文件树不能手动排序是社区里的老需求，现在靠 Custom sort、Explorer Sort、书签分组这类插件补。

### 7.2 树记在哪

| 做法 | 例子 | 问题 |
|---|---|---|
| 每篇属性块里写位置（`folder: 交易/学习`） | Bear 的嵌套标签 | 挪一下就改文件，修改时间跟着变，按更新时间的排序全乱；拖一下排序要改一串文件；空文件夹没处记；不是 Odea 建的文件得先改了它才进得了树 |
| **单独一份清单** | VS Code 的 `.code-workspace`、Obsidian 书签分组、Scrivener | 同步时这一个文件容易撞车（§7.4） |
| 智能文件夹（存下来的筛选） | Apple 备忘录、Bear 标签 | 不能手动摆，只能当补充 |

清单当骨架，智能文件夹是树里的一种节点。

### 7.3 清单的样子

```
我的逻辑目录/
├─ 交易学习.md            ← 新建的笔记平放在根上，文件名 = 标题（和现在一样）
├─ 旧资料/数学建模流程.md  ← 放在哪都行：树按 id 找，不看路径
├─ 附件/
└─ .odea/
   ├─ vault.json          ← kind: "logical"，日程开没开
   └─ tree                ← 树
```

```
# .odea/tree —— 一行一个节点：节点 id、父节点、排序键、内容
d7k2  .     a0  folder 交易
n9x1  d7k2  a0  note 0199f3c2-…
n3p8  d7k2  a1  note 0199f3d0-…
q1m4  .     a1  query #复盘 updated:30d
```

- **按 id 引用**：笔记属性块里的 `id` 改名、挪位置都不变（技术方案 §5.2），所以笔记在仓库里放哪都不影响树
- **一行一个节点 + 分数排序键**（fractional indexing，Figma、Linear 用的）：拖一篇只改它自己那一行（父节点、排序键），插到两项中间不用给后面的重新编号
- 纯文本，人看得懂；节点 id 短（4–6 位），清单里不存标题（标题是文件名，存了就要两边对账）
- 本地目录「转成逻辑目录」：按现有文件夹结构生成清单，一个文件都不动

### 7.4 同步

两台设备各挪了不同的东西：改的是不同的行，git 逐行合并就合上了。两边动了同一个节点：这个文件**不走**「冲突一律变成冲突副本」（技术方案 §5.9.5；这条对笔记合适，对树不合适 —— 出两棵树没法用），同步时按节点做三方合并：

- 共同祖先那一版 libgit2 拿得到
- 每个节点各自比：只有一边改了用那一边；两边都改了用本机的（和「本机优先」一致）；一边删一边改，留改过的（和 §5.9 一样）
- 合并出环（两边把 A、B 互相挪进对方）：断开的那个挪到根上
- 引用的笔记不存在了（另一边删了）：节点去掉；笔记还在、节点没了：进「未整理」

不开同步、放进网盘的，网盘出了冲突副本（`tree (1)` 这类）：按同样的规则和原文合并，合完删掉副本。

### 7.5 规矩

1. **一篇只在一个位置**（树，不是图）。以后要的话加「快捷方式」节点，删它不删笔记
2. **「未整理」固定在树上**：没被清单引用的笔记都在这儿 —— 在资源管理器里直接扔进来的、清单坏了或合并丢了引用的
3. **挪出文件夹和删除是两回事**：右键「移到未整理」只改清单；「删除」照旧进回收站（技术方案 §5.2）
4. **新建笔记**：文件平放在根上，树上放在当前选中的文件夹里
5. **文件夹改名、挪动、拖动排序只改清单**，不碰任何 .md：修改时间不变，不触发笔记的同步
6. `[[双链]]` 照旧按标题找，和树无关。平放时同名的笔记靠现有的「 2」+ 属性块 `title` 那套处理
7. **退路**：「导出成真实文件夹」按树的结构复制一份，离开 Odea 时结构不丢

### 7.6 不做（第一期）

- **挂载别处的真实文件夹 / 引用仓库外的文件**（VS Code 多根工作区、Windows 7 的「库」）：索引和监听要跨多个根，仓库外的文件被改名了要靠 id 找回，同步只管得到仓库里面的。先做「导入」：从本地目录复制进来，树按原来的文件夹结构建好
- 一篇放多处

## 9. 风险

| 风险 | 怎么办 |
|---|---|
| 多窗口改动面大：一百多个命令都要换成按窗口找仓库 | 加注入参数 `Ws`，命令里只是 `state` 换成 `ws`，逻辑不动；事件改 `emit_to` 的地方集中在 `announcer`、`sync_hooks`、`spawn_backlog`、`forward_collab` |
| 两个窗口开了同一个文件夹（换仓库时撞上、路径大小写不同） | 打开前按规范化路径（`canonicalize`，Windows 上不区分大小写）查一遍 |
| 关最后一个窗口时退出，同步还没推完 | 照旧：窗口先藏、推一次最多等 3 秒再销毁（技术方案 §5.9.6） |
| WebView2 多窗口的内存 | 每个窗口一个 WebView，同一个浏览器进程；最小化的窗口按 `memory.rs` 降内存目标。实测在 §10 记 |
| 逻辑目录的清单被别的工具改坏 | 解析不了的行跳过、记日志；笔记都还在，没被引用的进「未整理」 |

### 10.4 坑

- **`emit_to(标签)` 到了前端，全局 `listen` 照样收**：Tauri 的 `match_any_or_filter` —— 订阅的目标是 Any 的不过滤。只收自己窗口的，订阅要挂在窗口上：`events.x(getCurrentWebviewWindow()).listen`（`lib/tauri.ts` 的 `thisWindow()`）
- **注入参数 `Ws` 和 specta**：specta 给 `FunctionArg` 有一条 `impl<T: Type>` 的通用实现，自己的类型只要不实现 `Type`，就能另外实现 `FunctionArg` 返回 `None`（Tauri 给 `State` 也是这么做的），生成的前端类型里没有它
- `tauri::Error → AppError` 的转换原来只在 `desktop-runtime` 下编，`typegen`（导出类型的 example）现在也用得到
- 从启动器打开已经开着的仓库会当场关掉启动器，那次调用的回复送不回去（窗口没了），开发版控制台里出一行 `PostMessage failed … 0x80070578`，无害
- 窗口位置插件按标签记：迁过来的仓库用 `main`，升级后窗口还在原处；启动器在 denylist 里，每次都在屏幕中间
- `cargo` 不在这台机器 bash 的 PATH 里：`/d/Dev/cargo/bin/cargo`（`launch.json` 里的几条是自己设的）

### 11.2 和设计不一样、或者设计里没写的

- **窄栏常驻**（2026-10-20 和用户确认）：240 宽带字的导航不要了，一直是 64 宽（就是以前收起后的样子），各项的字在悬停提示里。能收起的改成它右边那一栏（文件树 / 月历 / 归档列表），像 VS Code 的侧栏：窄栏左下角的开关、命令面板「收起侧栏」、点已经选中的那一项；点别的区、点正文上方的路径时顺手展开。偏好键 `panelCollapsed`，以前的 `navCollapsed` 不接着用
- 窄栏上的「正在读取笔记 1234 / 2000」「新版本 0.2.0」「已同步 · 3 分钟前」只剩图标，字在悬停提示里
- **仓库名 ⌄ 放在列表栏底下**（Obsidian 的位置）。今日TODO、目标没有列表栏，那两页看不到它；命令面板里「打开别的仓库…」「启用日程」照样在
- **开日程不改树根**：设计写「开着日程的本地目录，树的根还是 `笔记/`」，说的是 Odea 建的仓库。一个 Obsidian 库开了日程，树根还是整个库（它没有「笔记」，改成「笔记」树就空了），只是日记、目标、归档这几个文件夹从树上拿掉，里面不是日期的笔记算在树根这一层。树根记在 `folders.notes`：新建的仓库写「笔记」；老标记（没有 `features`）当它是「笔记」，关了日程再开回来还是「笔记」
- **日程关着时树根一律是整个仓库**：老仓库关了日程，树上是「笔记」「日记」「目标」「归档」「附件」几个文件夹 —— 什么都在，没有藏起来的
- **空文件夹按 Odea 的摆法**：「打开文件夹」打开一个空文件夹、「更换笔记文件夹」换到空文件夹，也开日程、树根「笔记」。设计说的是「不往别人的文件夹里建日记」，空文件夹不算别人的
- **Obsidian 的日记**：没有 `.obsidian/daily-notes.json` 按 Obsidian 的默认（库根上、YYYY-MM-DD）—— 日记核心插件默认开着，不改设置就不会有这个文件；`core-plugins.json` 里关了日记插件的不认；格式不是 YYYY-MM-DD 的（按年月分子文件夹、带星期）不认，照旧用「日记」。只在标记里没写 `folders.days` 时看它，Obsidian 里改了设置这边跟着变。新的一天平放进它的文件夹（Obsidian 就是这么建的），不按年分
- **开关日程后整页重载**（和换仓库一样）：日记、目标从笔记变成某一天 / 目标（或者反过来），缓存的哪一样都不对了。开的那一下落在今日TODO，关的那一下落在文件
- **别的设备开关了日程、同步过来**：这台下次打开仓库时按新的摆法（打开时和索引里记的比，不一样就清空重读）。开着的时候不跟着变 —— 用户可能正在打字，整页重载不合适
- 整个仓库当树根时「附件」就是一个普通文件夹（图片不在树上，只列 .md 和文件夹；Obsidian 会列图片）。Obsidian 自己的附件文件夹设置（`attachmentFolderPath`）还没接，粘贴的图片照旧进「附件」
- 浏览器预览（mock）的日程开关只管窄栏上有没有那几项，树根一直是「笔记」；整个仓库当树根的样子要在桌面版里看

### 12.2 和设计不一样、或者设计里没写的

- **属性块里没写 id 的笔记按路径引用（`file 路径`）**：设计说一律按 id。可别的工具建的、资源管理器里扔进来的文件没有 id，索引给它的是随机的、只在本机，换台设备、重建索引就对不上了；写进属性块又要改文件（修改时间变、和「一个文件都不动」冲突）。所以按路径记，应用自己给它改名、挪位置时（那一刻属性块里写上了 id）换成按 id（`tree_follow`）；属性块里后来有了 id 的，下次整理时也换过去。外面给它改了名就对不上了 —— 和本地目录一样，它进「未整理」
- **找不到的笔记，连着两次整理都找不到才从清单里去掉**：整理在打开仓库、后台读完索引时做，这一次没找到的记在索引的 meta 里。网盘常常是清单先到、笔记还在路上，一找不到就删会把别的设备刚放好的位置丢了。删除进回收站的笔记节点一直留着，撤销时回到原处
- **新建的文件夹、新建的笔记、拖进文件夹的笔记都排在那一层最前面**：就地起名的输入框本来就在最上面，起好名字原地不动；新的一篇在最上面看得见
- **「手动排序」是排序里的一项**，逻辑目录才有，默认还是「按更新时间」。只有手动排序时笔记能拖着排（按别的排时拖动排顺序没有意义）；文件夹在逻辑目录里一直是手动的顺序
- **删逻辑目录的文件夹 = 底下的笔记进回收站**（归档的不动），和本地目录一样；撤销时清单里拿掉的那几行原样放回去。只想拿出来的用「移到未整理」
- **「未整理」有东西才出现**，固定在根上文件夹的最后，不能改名、拖动、删；能往里拖笔记
- **转过来的老仓库，新建的笔记平放在「笔记」里**（原来的树根）；启动器新建的逻辑目录平放在仓库根上。转换前先弹确认框（Rust 里，和换仓库一样）
- **两边都改了清单就重合一遍，不管 git 合没合上**：两边各把未整理里的同一篇放进不同文件夹、互相挪进对方，逐行合并合得上，可结果是同一篇两处、成环。这一个文件不交给冲突副本
- **网盘副本合并**没有共同祖先：两边的节点都留下，同一个节点不一样用原文的；合完删掉副本。删掉的节点会回来（看不出是谁删的），和「什么都不会消失」一致
- 逻辑目录的文件夹菜单里没有「在文件夹中显示」（不在硬盘上）；底部的「在文件夹中显示」照旧定位那一篇的文件
- 文件监听原来整个忽略 `.odea/`，现在放行 `.odea/tree` 和 `tree (1)` 这类：不放行的话网盘改了清单这边不知道，应用只改了树、没改笔记时同步也不会被戳到

### 14.2 和设计不一样、或者设计里没写的

- **附件放哪跟着 Obsidian 走**，但只管新粘贴的；已经在正文里的路径不动。笔记旁边的子文件夹（`./附件`）按这篇所在的文件夹算
- **树上的图片、PDF 只在本地目录列**：逻辑目录的清单只放笔记（§7.3），文件在哪不重要。点了用系统的程序打开（Odea 不做 PDF 阅读器）
- **别的设备开关了日程不是马上换**：用户可能正在打字，底部问一句，点了才重新认文件、整页重载；同一次变化只问一回
- **导入的笔记不写 id**：清单里按路径引用（和转成逻辑目录一样，一个文件都不改）；以后应用改了这一篇时才写上
- **快捷方式不能进「未整理」**：那里放的是没放好的笔记，快捷方式本来就是「放好了的另一个位置」

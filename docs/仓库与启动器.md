## 1. 结论

| 问题 | 定了什么 | 为什么 |
|---|---|---|
| 双击图标打开什么 | **没在运行：打开上次开着的仓库；已经在运行（Windows / Linux）：弹启动器** | VS Code 在 Windows 上就是这样（`window.restoreWindows` 默认 `all`，`openWithoutArgumentsInNewWindow` 在 Windows / Linux 默认 `on`、macOS 默认 `off`）；Obsidian 在 Windows 上再启动一次也是弹库选择器 |
| 一个窗口能开几个仓库 | **一个窗口一个仓库**，同一个仓库只开一个窗口 | 两个窗口开同一个文件夹 = 两份监听、两个写入方、同一份索引，迟早互相覆盖 |
| P2（笔记 / 今日TODO / GOAL / 日历 / 归档）放哪 | **不单独做成一种「模式」，做成每个仓库都能开的「日程」功能** | 今日TODO、GOAL、日历本来就是仓库上的视图（日记 / 目标文件 + 全库扫出来的带日期任务）；单独成一个模式，日历就看不到别处笔记里的任务 |
| 启动器上的按钮 | 新建 / 打开文件夹 / 从同步仓库拉一份 / 加入协同编辑 | 「打开逻辑目录」和「打开本地目录」合成一个「打开文件夹」，文件夹里有 `.odea/tree` 就认成逻辑目录 |
| 逻辑目录的树记在哪 | **单独一份清单 `.odea/tree`，一行一个节点，按笔记 id 引用** | 写进每篇属性块会改文件的修改时间（「上次更新」就是它，技术方案 §5.2），拖一下排序要改一串文件，空文件夹也没处放 |
| 一篇能不能在树上放好几处 | **不能**，树不是图；以后要的话加「快捷方式」节点 | 一篇放多处，删除到底删什么、面包屑写哪条路都说不清 |
| 没被树引用的笔记 | 出现在固定的「未整理」里 | 延续「什么都不会消失」（技术方案 §5.2） |
| 逻辑目录同步撞车 | 这一个文件不出冲突副本，**按节点三方合并**，同一节点两边都改了用本机的 | 两棵树没法用；本机优先和 §5.9 一致 |
| 挂载别处的真实文件夹 | **第一期不做**，先做「导入」 | 索引、监听要跨多个根，仓库外的文件同步管不到 |

## 2. 现状和要解决的问题

现在应用只认一个仓库（`config.json` 的 `vaultRoot`），结构是固定的（技术方案 §5.2）：

```
笔记/   日记/   目标/   归档/   附件/   .odea/
```

- 「换仓库」只有命令面板里的「更换笔记文件夹…」，换完整页重载，同一时刻只有一个仓库开着
- 打开 Obsidian 的库也行（不认识的位置都当笔记），但左边看到的还是「笔记 / 今日TODO / GOAL / 日历 / 归档」这一套，文件树只列 `笔记/` 下面的
- 文件夹 = `笔记/` 下的真目录（§5.8），不能手动排序，不能和硬盘上的位置分开摆

要做到的：

1. 像 Obsidian、VS Code 那样有一个启动器，记着用过的仓库，双击图标的行为和它们一样
2. 打开任意文件夹，左边直接是它的文件和文件夹（Obsidian 那样）
3. 能建「逻辑目录」：树按自己的意思摆，和文件在硬盘上放在哪无关
4. 现在这套「日程」（今日TODO / GOAL / 日历 / 归档）不丢，老用户升级后看到的还是原来的样子

## 3. 启动器

### 3.1 双击图标的行为

| 情况 | 行为 |
|---|---|
| 没在运行，双击图标 | 打开上次关的时候还开着的那些仓库，各一个窗口。一个都打不开（列表是空的、文件夹都找不到了）时弹启动器 |
| 已经在运行，再双击（Windows / Linux） | 弹启动器；启动器已经开着就把它提到前面 |
| macOS 点 Dock | 有窗口就提到前面（系统默认）；一个窗口都没有时（`RunEvent::Reopen`）打开最近的仓库，没有就弹启动器 |
| 在启动器里选了一个已经开着的仓库 | 把那个窗口提到前面，不开第二份 |
| 上次的文件夹找不到了（移动硬盘没插、被删了、被改名了） | 不打开它，启动器里那一条标「找不到」。**绝不在原处新建一个空仓库**：以前 `prepare` 会 `create_dir_all`，看着就像笔记全没了（技术方案 §5.7） |
| 点 `odea://join/…` 链接 | 交给最近用过的那个仓库窗口；一个都没开着就先打开最近的仓库 |

**「上次开着」怎么记。** 一个仓库窗口关掉时：还有别的仓库窗口开着 → 记成「没开着」；它是最后一个 → 照旧记成「开着」，下次启动打开它。这样一个个关窗口，下次只回到最后关的那个；关应用（最后一个窗口）时开着的都回来。Obsidian 有个坑正好反过来：主窗口关了、副窗口还开着时整个应用退出，下次落到选择器上 —— 这里没有主次窗口，每个仓库窗口都一样。

**新装第一次打开**：弹启动器。以前是直接在「文档/Odea」建一个仓库，再用横幅告诉用户笔记放在哪、要不要换（§5.7「第一次打开时说一声」）；现在新建时位置就是用户自己选的（默认还是「文档/Odea」），那条横幅不要了。从更老的 OnTheWay（SQLite 时代）升上来、旧库里有东西的，照旧搬进「文档/Odea」直接打开，不弹启动器。

### 3.2 布局

参考 Obsidian 的库选择器：左边是用过的仓库，右边是 Logo、版本号和几个操作。窗口 800×560，不能改大小，无边框（右上角最小化、关闭），只淡入（CLAUDE.md 的动效规矩）。

**左边的列表**

- 一条：名字（文件夹名）+ 路径；逻辑目录前面一个小图标；正在别的窗口里开着的标「已打开」；找不到的灰掉、标「找不到」
- 按上次打开的时间排，最近的在上
- 单击打开；⋮ 菜单：在资源管理器中显示、从列表里移除（**不删文件**，菜单里写清楚）

**右边的操作**

| 操作 | 做什么 | 哪一期 |
|---|---|---|
| 新建 | 名字 + 位置（默认「文档」）+ 文件夹怎么摆（真实文件夹 / 逻辑目录，默认真实文件夹）→ 建文件夹、放使用指南、打开。P11.3 到 0.4.2 一律建逻辑目录（§12），2026-10-27 起让用户选（§15） | P11.1 |
| 打开文件夹 | 系统的选择文件夹对话框 → 打开它。文件夹里有 `.odea/tree` 的是逻辑目录，否则是本地目录（按真实结构） | P11.1 |
| 从同步仓库拉一份 | 现有的「接入同步」（技术方案 §5.9.7）挪到这里：登录、选仓库、clone 到新文件夹、打开。换电脑时最常用（§13） | P11.4 |
| 加入协同编辑 | 粘贴邀请链接 → 交给最近用过的仓库窗口去加入（访客那篇本来就不落进仓库，[协同编辑.md](./协同编辑.md) §3）。P11.4 起开一个不用开仓库的访客窗口（§13） | P11.1 |

编辑器里打开启动器：命令面板「打开别的仓库…」；P11.2 左栏改版后左下角放「仓库名 ⌄」（Obsidian 也在这里）。

## 4. 多窗口：一个窗口一个仓库

### 4.1 后端的状态

现在 `AppState` 里只有一个仓库（`vault`、`watcher`、`sync`、`indexing`），所有命令都直接拿它。改成：

```
AppState
├─ workspaces: 窗口标签 → Workspace     每个仓库窗口一份
│     Workspace { vault, watcher, sync, indexing }
├─ data_dir、sync_login、update        全应用一份（账号、更新和窗口无关）
└─ collab                              全应用一份，记着会话属于哪个窗口（§4.3）
```

- **命令怎么知道是哪个仓库**：加一个注入参数 `Ws`（实现 Tauri 的 `CommandArg`），从调用它的窗口标签查出 `Workspace`；specta 生成前端类型时跳过它（和 `State` 一样实现 `FunctionArg` 返回 `None`）。前端的调用一个字不用改
- **事件只发给那个窗口**：`VaultChanged`、`IndexProgress`、`SyncStatusChanged`、`SyncNotice` 从 `emit` 改成 `emit_to(标签)`。别的窗口收到别的仓库的变化会去刷新根本不存在的笔记
- **后台线程认仓库不认窗口**：后台读索引（`spawn_backlog`）、文件监听、同步线程都拿着自己那份 `Arc<Mutex<Vault>>`，和现在一样
- 索引本来就是一个仓库一个文件（`index/<路径指纹>.db`），不用动

### 4.2 窗口

- 窗口都由 Rust 建（`tauri.conf.json` 里不再写窗口）：仓库窗口 1440×900、无边框、先藏着等前端 `ready`，和现在一样；启动器单独一种
- **标签**：老用户升级时迁过来的那个仓库用 `main`（窗口位置插件按标签记位置，升级后窗口还在原处）；别的用 `vault-<路径指纹>`，每个仓库记着自己的窗口位置。撞了（一个窗口换过仓库）加序号
- **前端怎么知道自己是哪种窗口**：启动器的地址带 `?launcher`；启动后再开的仓库窗口带 `?quiet`（不播开场动画 —— 开场的 sessionStorage 是一个窗口一份，新窗口每次都会播）
- **localStorage 是所有窗口共用的**：「上次停在哪」（`odea.session`）和「哪些文件夹展开着」（`odea.folders.expanded`）改成按仓库分开存（键后面接仓库路径）；按仓库存的没有时读旧的那个键，老用户升级后照旧回到上次那篇。主题、偏好、表情最近用过的仍然全应用一份
- **关窗口**：前端的关闭保护照旧（先存编辑器里的），`win_force_close` 只收这个窗口的：结束这个窗口的协作、这个仓库的同步推一次（最多等 3 秒）。窗口销毁后从 `workspaces` 里拿掉（停监听、停同步），按 §3.1 记「开没开着」
- **再双击**：`tauri-plugin-single-instance` 的回调里，参数里有 `odea://` 的交给 deep-link 处理，没有的弹启动器
- 最小化时让 WebView2 少占内存（`memory.rs`）原来用一个全局的开关记状态，改成按窗口记

### 4.3 协作

同时可以有好几个会话（[协同编辑.md](./协同编辑.md) §25，2026-10-27 起；以前一次只有一个），每个会话属于开始它的那个窗口：

- 主持、加入、附近、继续上次的协作时，`CollabHub` 按（窗口，会话号）记下；`CollabEvent` 只发给那个窗口，字节管道（`collab_pipe`）按窗口登记，只往它那条里塞
- 几个窗口各开各的会话；端点（`collab::Node`）整个应用一个，第一个会话开始时起、最后一个结束时关
- 主持人那边访客要附件、传附件，读写的是开始会话那个窗口的仓库（以前是全局唯一的那个）
- 关窗口只结束它自己的会话
- `odea://` 链接（应用开着时点的）：发给最近获得过焦点的仓库窗口；一个都没有就打开最近的仓库，链接存着等它取（`collab_pending_link`）

### 4.4 换仓库、搬仓库

命令面板「更换笔记文件夹…」照旧（搬过去 / 复制过去 / 只换文件夹），换的是**这个窗口**的仓库：

- 新文件夹已经在别的窗口开着：不换，报错
- 换完更新仓库列表：搬过去 → 这一条的路径改成新的；复制过去 / 只换文件夹 → 新文件夹加进列表（或者把已有的那条标成开着），原来那条标成没开着
- 第二台设备「接入同步」（clone 到新文件夹再换过去）同样走这里

## 5. 仓库列表

`config.json`（应用数据目录，每台机器一份）：

```json
{
  "vaultRoot": "C:\\Users\\Gred\\Documents\\Odea",
  "vaults": [
    { "path": "C:\\Users\\Gred\\Documents\\Odea", "window": "main", "lastOpened": 1760918400000, "open": true },
    { "path": "D:\\forGPT", "lastOpened": 1760832000000, "open": false }
  ]
}
```

- `window`：只有迁移过来的那一个写 `main`（§4.2），别的不写
- **迁移**（照 `old_name.rs` 的老办法「新版认旧的」）：`vaults` 是空的、`vaultRoot` 有值 → 把它变成第一条，`window: "main"`、`open: true`。升级后第一次打开直接进原来的仓库，体验不变
- `vaultRoot` 继续写（最近打开的那个仓库），降级回旧版时旧版还能找到笔记
- `ODEA_VAULT`（开发、测试用）：只打开它，不记进列表
- 名字就是文件夹名，不另存

## 6. 日程：仓库上的一组功能

**P2 不在启动器上单独做成「日常模式」。** 今日TODO = `日记/今天.md`，GOAL = `目标/` 下的文件，日历的「当日安排」是全库扫出来的 `@日期` 任务（技术方案 §5.4）——它们是建在仓库上的视图，不是另一种存储。单独成一个模式，要么另开一个仓库（日程和笔记分家，日历看不到笔记里的任务，而「任务写在哪篇文档里都会进日历」恰恰是卖点），要么同一个仓库两套界面来回切。Obsidian 也是这么拆的：日记、日历是插件，哪个库都能开。

做成仓库的一组功能，叫「日程」：今日TODO、GOAL、日历、归档。（2026-10-27 起归档单独一个开关，日程只管今日TODO、GOAL、日历，§15）

- **开关存在仓库里**（`.odea/vault.json` 的 `features.journal`），跟着仓库走、跟着同步走
- **默认值**：新建的仓库开；打开一个已有的文件夹不开 —— 不往别人的文件夹里建 `日记/`、`目标/`。在左栏或命令面板「启用日程」。老用户的仓库（迁移过来的）开
- **文件夹可配**：`日记`、`目标`、`归档` 现在写死在 `vault/layout.rs`（`DAYS_DIR` 等），改成读 `vault.json` 里的值，没写就用现在的名字
- **团队仓库的日程是团队的**（2026-10-22，[协同编辑.md](./协同编辑.md) §22.6）：每天一篇团队的、团队的目标；个人的日程放在个人仓库。几个仓库都开着日程时，今日TODO、目标、日历那一行日期右边有日程切换器，点了跳到那个仓库的窗口、停在同一页
- **接 Obsidian 的日记**：打开一个 Obsidian 库时读 `.obsidian/daily-notes.json` 里设的日记文件夹，日期格式是 `YYYY-MM-DD` 的话，他原来的日记直接进今日TODO 和日历

**左栏**（P11.2）：最左边一条窄栏（Obsidian 的 ribbon、VS Code 的活动栏），固定有「文件」；开了日程才多出今日 / 目标 / 日历 / 归档。现在列表栏的位置换成文件树：本地目录是真实结构（整个仓库，不再只是 `笔记/`），逻辑目录是自定义的树。P2 现在的「全部笔记」（置顶 + 文件夹 + 笔记）就是文件树的一种样子，接着用。开着日程的本地目录，树的根还是 `笔记/`（日记、目标从窄栏进），老用户看到的和现在一样。（实际做的时候细化了：Odea 建的仓库树根是「笔记」，打开的文件夹开了日程树根还是整个文件夹，见 §11.2）

## 7. 逻辑目录

### 7.1 解决什么

树按自己的意思摆，不受文件在硬盘上放在哪的约束：手动排序，文件夹随便建、随便拖，改名、挪动文件夹不碰任何文件。Obsidian 的文件树不能手动排序是社区里的老需求，现在靠 Custom sort、Explorer Sort、书签分组这类插件补。

### 7.2 树记在哪

| 做法 | 例子 | 问题 |
|---|---|---|
| 每篇属性块里写位置（`folder: 交易/学习`） | Bear 的嵌套标签 | 挪一下就改文件，修改时间跟着变，按更新时间的排序全乱；拖一下排序要改一串文件；空文件夹没处记；不是 Odea 建的文件得先改了它才进得了树 |
| **单独一份清单** | VS Code 的 `.code-workspace`、Obsidian 书签分组、Scrivener | 同步时这一个文件容易撞车（§7.4） |
| 智能文件夹（存下来的筛选） | Apple 备忘录、Bear 标签 | 不能手动摆，只能当补充 |

清单当骨架，智能文件夹是树里的一种节点。

### 7.3 清单的样子

```
我的逻辑目录/
├─ 交易学习.md            ← 新建的笔记平放在根上，文件名 = 标题（和现在一样）
├─ 旧资料/数学建模流程.md  ← 放在哪都行：树按 id 找，不看路径
├─ 附件/
└─ .odea/
   ├─ vault.json          ← kind: "logical"，日程开没开
   └─ tree                ← 树
```

```
# .odea/tree —— 一行一个节点：节点 id、父节点、排序键、内容
d7k2  .     a0  folder 交易
n9x1  d7k2  a0  note 0199f3c2-…
n3p8  d7k2  a1  note 0199f3d0-…
q1m4  .     a1  query #复盘 updated:30d
```

- **按 id 引用**：笔记属性块里的 `id` 改名、挪位置都不变（技术方案 §5.2），所以笔记在仓库里放哪都不影响树
- **一行一个节点 + 分数排序键**（fractional indexing，Figma、Linear 用的）：拖一篇只改它自己那一行（父节点、排序键），插到两项中间不用给后面的重新编号
- 纯文本，人看得懂；节点 id 短（4–6 位），清单里不存标题（标题是文件名，存了就要两边对账）
- 本地目录「转成逻辑目录」：按现有文件夹结构生成清单，一个文件都不动

### 7.4 同步

两台设备各挪了不同的东西：改的是不同的行，git 逐行合并就合上了。两边动了同一个节点：这个文件**不走**「冲突一律变成冲突副本」（技术方案 §5.9.5；这条对笔记合适，对树不合适 —— 出两棵树没法用），同步时按节点做三方合并：

- 共同祖先那一版 libgit2 拿得到
- 每个节点各自比：只有一边改了用那一边；两边都改了用本机的（和「本机优先」一致）；一边删一边改，留改过的（和 §5.9 一样）
- 合并出环（两边把 A、B 互相挪进对方）：断开的那个挪到根上
- 引用的笔记不存在了（另一边删了）：节点去掉；笔记还在、节点没了：进「未整理」

不开同步、放进网盘的，网盘出了冲突副本（`tree (1)` 这类）：按同样的规则和原文合并，合完删掉副本。

### 7.5 规矩

1. **一篇只在一个位置**（树，不是图）。以后要的话加「快捷方式」节点，删它不删笔记
2. **「未整理」固定在树上**：没被清单引用的笔记都在这儿 —— 在资源管理器里直接扔进来的、清单坏了或合并丢了引用的
3. **挪出文件夹和删除是两回事**：右键「移到未整理」只改清单；「删除」照旧进回收站（技术方案 §5.2）
4. **新建笔记**：文件平放在根上，树上放在当前选中的文件夹里
5. **文件夹改名、挪动、拖动排序只改清单**，不碰任何 .md：修改时间不变，不触发笔记的同步
6. `[[双链]]` 照旧按标题找，和树无关。平放时同名的笔记靠现有的「 2」+ 属性块 `title` 那套处理
7. **退路**：「导出成真实文件夹」按树的结构复制一份，离开 Odea 时结构不丢

### 7.6 不做（第一期）

- **挂载别处的真实文件夹 / 引用仓库外的文件**（VS Code 多根工作区、Windows 7 的「库」）：索引和监听要跨多个根，仓库外的文件被改名了要靠 id 找回，同步只管得到仓库里面的。先做「导入」：从本地目录复制进来，树按原来的文件夹结构建好
- 一篇放多处

## 9. 风险

| 风险 | 怎么办 |
|---|---|
| 多窗口改动面大：一百多个命令都要换成按窗口找仓库 | 加注入参数 `Ws`，命令里只是 `state` 换成 `ws`，逻辑不动；事件改 `emit_to` 的地方集中在 `announcer`、`sync_hooks`、`spawn_backlog`、`forward_collab` |
| 两个窗口开了同一个文件夹（换仓库时撞上、路径大小写不同） | 打开前按规范化路径（`canonicalize`，Windows 上不区分大小写）查一遍 |
| 关最后一个窗口时退出，同步还没推完 | 照旧：窗口先藏、推一次最多等 3 秒再销毁（技术方案 §5.9.6） |
| WebView2 多窗口的内存 | 每个窗口一个 WebView，同一个浏览器进程；最小化的窗口按 `memory.rs` 降内存目标。实测在 §10 记 |
| 逻辑目录的清单被别的工具改坏 | 解析不了的行跳过、记日志；笔记都还在，没被引用的进「未整理」 |

### 10.4 坑

- **`emit_to(标签)` 到了前端，全局 `listen` 照样收**：Tauri 的 `match_any_or_filter` —— 订阅的目标是 Any 的不过滤。只收自己窗口的，订阅要挂在窗口上：`events.x(getCurrentWebviewWindow()).listen`（`lib/tauri.ts` 的 `thisWindow()`）
- **注入参数 `Ws` 和 specta**：specta 给 `FunctionArg` 有一条 `impl<T: Type>` 的通用实现，自己的类型只要不实现 `Type`，就能另外实现 `FunctionArg` 返回 `None`（Tauri 给 `State` 也是这么做的），生成的前端类型里没有它
- `tauri::Error → AppError` 的转换原来只在 `desktop-runtime` 下编，`typegen`（导出类型的 example）现在也用得到
- 从启动器打开已经开着的仓库会当场关掉启动器，那次调用的回复送不回去（窗口没了），开发版控制台里出一行 `PostMessage failed … 0x80070578`，无害
- 窗口位置插件按标签记：迁过来的仓库用 `main`，升级后窗口还在原处；启动器在 denylist 里，每次都在屏幕中间
- `cargo` 不在这台机器 bash 的 PATH 里：`/d/Dev/cargo/bin/cargo`（`launch.json` 里的几条是自己设的）

### 11.2 和设计不一样、或者设计里没写的

- **窄栏常驻**（2026-10-20 和用户确认）：240 宽带字的导航不要了，一直是 64 宽（就是以前收起后的样子），各项的字在悬停提示里。能收起的改成它右边那一栏（文件树 / 月历 / 归档列表），像 VS Code 的侧栏：窄栏左下角的开关、命令面板「收起侧栏」、点已经选中的那一项；点别的区、点正文上方的路径时顺手展开。偏好键 `panelCollapsed`，以前的 `navCollapsed` 不接着用
- 窄栏上的「正在读取笔记 1234 / 2000」「新版本 0.2.0」「已同步 · 3 分钟前」只剩图标，字在悬停提示里
- **仓库名 ⌄ 放在列表栏底下**（Obsidian 的位置）。今日TODO、目标没有列表栏，那两页看不到它；命令面板里「打开别的仓库…」「启用日程」照样在
- **开日程不改树根**：设计写「开着日程的本地目录，树的根还是 `笔记/`」，说的是 Odea 建的仓库。一个 Obsidian 库开了日程，树根还是整个库（它没有「笔记」，改成「笔记」树就空了），只是日记、目标、归档这几个文件夹从树上拿掉，里面不是日期的笔记算在树根这一层。树根记在 `folders.notes`：新建的仓库写「笔记」；老标记（没有 `features`）当它是「笔记」，关了日程再开回来还是「笔记」
- **日程关着时树根一律是整个仓库**：老仓库关了日程，树上是「笔记」「日记」「目标」「归档」「附件」几个文件夹 —— 什么都在，没有藏起来的
- **空文件夹按 Odea 的摆法**：「打开文件夹」打开一个空文件夹、「更换笔记文件夹」换到空文件夹，也开日程、树根「笔记」。设计说的是「不往别人的文件夹里建日记」，空文件夹不算别人的
- **Obsidian 的日记**：没有 `.obsidian/daily-notes.json` 按 Obsidian 的默认（库根上、YYYY-MM-DD）—— 日记核心插件默认开着，不改设置就不会有这个文件；`core-plugins.json` 里关了日记插件的不认；格式不是 YYYY-MM-DD 的（按年月分子文件夹、带星期）不认，照旧用「日记」。只在标记里没写 `folders.days` 时看它，Obsidian 里改了设置这边跟着变。新的一天平放进它的文件夹（Obsidian 就是这么建的），不按年分

### 12.2 和设计不一样、或者设计里没写的

- **属性块里没写 id 的笔记按路径引用（`file 路径`）**：设计说一律按 id。可别的工具建的、资源管理器里扔进来的文件没有 id，索引给它的是随机的、只在本机，换台设备、重建索引就对不上了；写进属性块又要改文件（修改时间变、和「一个文件都不动」冲突）。所以按路径记，应用自己给它改名、挪位置时（那一刻属性块里写上了 id）换成按 id（`tree_follow`）；属性块里后来有了 id 的，下次整理时也换过去。外面给它改了名就对不上了 —— 和本地目录一样，它进「未整理」
- **找不到的笔记，连着两次整理都找不到才从清单里去掉**：整理在打开仓库、后台读完索引时做，这一次没找到的记在索引的 meta 里。网盘常常是清单先到、笔记还在路上，一找不到就删会把别的设备刚放好的位置丢了。删除进回收站的笔记节点一直留着，撤销时回到原处
- **新建的文件夹、新建的笔记、拖进文件夹的笔记都排在那一层最前面**：就地起名的输入框本来就在最上面，起好名字原地不动；新的一篇在最上面看得见
- **「手动排序」是排序里的一项**，逻辑目录才有，默认还是「按更新时间」。只有手动排序时笔记能拖着排（按别的排时拖动排顺序没有意义）；文件夹在逻辑目录里一直是手动的顺序
- **删逻辑目录的文件夹 = 底下的笔记进回收站**（归档的不动），和本地目录一样；撤销时清单里拿掉的那几行原样放回去。只想拿出来的用「移到未整理」
- **「未整理」有东西才出现**，固定在根上文件夹的最后，不能改名、拖动、删；能往里拖笔记
- **转过来的老仓库，新建的笔记平放在「笔记」里**（原来的树根）；启动器新建的逻辑目录平放在仓库根上。转换前先弹确认框（Rust 里，和换仓库一样）
- **两边都改了清单就重合一遍，不管 git 合没合上**：两边各把未整理里的同一篇放进不同文件夹、互相挪进对方，逐行合并合得上，可结果是同一篇两处、成环。这一个文件不交给冲突副本
- **网盘副本合并**没有共同祖先：两边的节点都留下，同一个节点不一样用原文的；合完删掉副本。删掉的节点会回来（看不出是谁删的），和「什么都不会消失」一致
- 逻辑目录的文件夹菜单里没有「在文件夹中显示」（不在硬盘上）；底部的「在文件夹中显示」照旧定位那一篇的文件
- 文件监听原来整个忽略 `.odea/`，现在放行 `.odea/tree` 和 `tree (1)` 这类：不放行的话网盘改了清单这边不知道，应用只改了树、没改笔记时同步也不会被戳到

## 15. 归档单独一个开关、回收站、新建时选文件夹怎么摆（2026-10-27）

评审意见里和仓库有关的三条。

### 15.1 归档和日程分开

**问题。** 归档是笔记的生命周期（用完了、舍不得删），日程是今日TODO、目标、日历。以前归档算在日程里（`note_archive` 先 `require_journal`），只想写笔记、关了日程的人就归档不了；窄栏的「归档」也跟着日程一起没了，笔记菜单里却还有「归档」，一点就报「没开日程」。

**做法。**

- 仓库标记多一个 `features.archive`。**没写的跟着日程**：0.4.2 以前的仓库打开时和以前一样；没有 `features` 的老标记两样都开着
- `Layout.archiving`：开着时「归档」文件夹里的是归档的笔记、不在树上（`hidden_dirs`）；`classify` 先看归档、再看日程。`note_archive` 改成 `require_archive`
- 只改一个开关时（`marker_with_feature`），另一个没写的先按现在的意思写上：老标记关日程时，归档照旧开着，不会跟着关掉
- 新建的、空文件夹两样都开；打开有笔记的文件夹两样都不开 —— 别人文件夹里叫「归档」的可能只是个普通文件夹，开了以后里面的笔记才算归档的
- 命令面板「启用归档 / 关闭归档」、仓库菜单各一个开关（`vault_set_archive`，和开关日程一样重认文件、整页重载）；窄栏的「归档」、命令面板的「归档」跳转、笔记菜单里的「归档」都跟着它；`fitLayout` 把停在归档页、归档又关了的窗口带回文件
- 单测：layout 1 条（老标记跟着日程、只开归档、关日程不带走归档、只开日程不要归档），仓库 1 条（打开的文件夹默认不能归档、开了归档以后别人的「归档」文件夹算归档、日程照旧关着、关日程不带走归档）

### 15.2 回收站对话框

**问题。** 删除进 `.odea/trash/` 留 30 天，可唯一的反悔入口是底部 6 秒的「撤销」，还只记最近一次（后一次顶掉前一次）。笔记软件里误删常常是几分钟、几天以后才发现的。

**做法。**

- `trash_list`：回收站里的笔记（标题、原来的位置、摘要、什么时候删的、什么时候清掉），最近删的在前；退役共享仓库挪进来的文件夹不算。id 按属性块里的（对得上文件名才用，对不上用文件名），恢复照旧走 `note_undelete`
- `TrashDialog`：命令面板「回收站…」、仓库菜单「回收站…」、删除提示条上的「回收站」打开；能按标题、原来的位置、摘要搜；「恢复」放回原处（文件夹没了重新建上，逻辑目录的节点一直留着），恢复了的那一行换成「打开」。外壳和历史版本对话框一样；每打开一次重新取（关上的淡出没播完又打开时，AnimatePresence 用的还是那张卡片）
- 上面还列着协作时本机留的几份（[协同编辑.md](./协同编辑.md) §24.1）
- 「6 秒撤销」照旧是快捷入口；永久删除、清空回收站没做 —— 30 天自己清，什么都不会被立刻永久删掉

### 15.3 新建时选真实文件夹还是逻辑目录

**问题。** P11.3 起启动器「新建」一律建逻辑目录：用户在界面里整理出多层文件夹，硬盘上笔记却平放在根上，换别的编辑器打开，整理的结构得先「导出成真实文件夹」才带得走。逻辑目录适合要手动排序、随便拖的人，可这个取舍用户事先不知道。

**做法。** 「新建」里多一行「文件夹」，两个选项，区别直接写在选项上：

- **真实文件夹**（默认）：树就是硬盘上的文件夹，换别的编辑器打开也一样
- **逻辑目录**：文件夹只在 Odea 里，能手动排序；硬盘上笔记平放

`launcher_create(parent, name, logical)` → `Open.logical`。默认选真实文件夹：「普通 Markdown 文件夹，别的工具直接能用」是更不意外的那一个；想要手动排序的随时能「转成逻辑目录…」（一个文件都不动），反过来要「导出成真实文件夹」拷一份。使用指南里那一段跟着改了。

## 16. 界面顺滑的六处（2026-10-28）

用户的反馈：开关日程卡、会跳到今日TODO；启动器关的时候掉帧；今日TODO ↔ /GOAL 闪来闪去；侧栏开关在没有侧栏的页面上没用；编辑区的源码是闪出来的；文末那一行信息想像 Typora 一样贴在底下。

### 16.1 开关日程、归档就地换上

**问题。** `setJournal` 存完、调 `vault_set_journal` 以后 `window.location.reload()`，还先把停的那一页改成今日TODO（开）/ 文件（关）。重载那一下窗口空着、开场再播一遍，用户说的「整个页面会卡顿，会跳到今日TODO」。§11 当时整页重载的理由是「缓存的哪一样都不对了」：后端重新认文件时清空了索引（`index::sync_layout` 删掉 `doc`），属性块里没记 id 的笔记连 id 都换了。

**做法。** `data/store.ts` 的 `switchLayout`，开关日程、开关归档、别的设备改了摆法点「切换过去」三处共用：

- 先存掉编辑器里的；记下两个列表里选中那一篇的**路径**
- 后端换完以后重取：两个列表、日历记号、读索引的进度、文件夹（逻辑目录取树，本地目录取文件夹和树上的图片 PDF）
- 选中的按路径在新列表里找回来（id 换了也是那一篇）；它的正文 id 换了的话先取回来，换上的那一帧就是编辑器，不先闪一下「载入中…」
- 日程开关变了：某一天、目标、任务、命令面板里的日记标题这几份缓存作废。开日程以后 Shell 的 effect 照常取今天
- 这些在同一个同步块里放进 store（不 await），React 只画一次。停在哪一页不动，那一页没了（关日程时停在今日TODO）才由 `fitLayout` 回到文件
- 窄栏上多出来、没了的那几项撑开 / 收起（高 0 ↔ 38，起步就走、收尾短的曲线，CLAUDE.md 规矩 7）并淡入淡出，下面的「归档」跟着挪
- **主持着协作、团队仓库照旧整页重载**：会话认的是笔记 id，id 一换就对不上了

### 16.2 启动器关掉的那一下

**问题。** 启动器关掉（点了关闭、打开仓库以后新窗口画出来了）是 `window.destroy()`：WebView 先被拆掉，Windows 拿来播关窗淡出的是一块只剩底色的窗口；拆 WebView 还要在主线程上卡一下，这时新开的仓库窗口正在画第一屏。

**做法。** `workspace::close_launcher` 先 `hide()`（系统的淡出播的是完整的画面），400ms 以后再销毁。关闭按钮、Alt+F4 也走这里（`lib.rs` 拦下启动器的 `CloseRequested`）。退场中又被叫回来（`focus` 启动器）就不销毁了，用一个号码分清是哪一次退场。

**2026-10-29 用户还是说「关那个小窗口时掉了几帧」。** 桌面端逐帧抓屏（Desktop Duplication，180Hz，用真鼠标点 ×；启动器后面垫一块纯色底板，抓不到别的程序）：系统的关窗动画不只是淡出，还把窗口缩到约 0.95 —— 前 80ms 每帧收 2–3px，到 772px 宽时一帧跳到 761，之后不再动、只剩淡（三次都一样）。普通的 Win32 窗口也是这个套路，只是那一跳分在三帧里。缩放还把整窗当位图拉，字发虚。

- 退场改成自己淡：关掉这个窗口的系统过渡（`DWMWA_TRANSITIONS_FORCEDISABLED`），改成分层窗口，按合成器的节奏（`DwmFlush`，60Hz、180Hz 都是一帧一步）把整窗透明度 150ms 从 255 降到 0（ease-out cubic），淡完再 `hide()`。分层窗口的透明度对 WebView2 画的内容一样有效（50% 时实测正好一半）。淡的时候点击穿过去（`WS_EX_TRANSPARENT`）。只淡不缩放，CLAUDE.md 规矩 1
- 淡到一半、淡完藏起来又被叫回来：`focus` 先把透明度、样式、系统过渡还回去（tao 藏窗口时会按它记的样式重设扩展样式，藏起来以后已经不是分层窗口了）
- 改完再抓：宽一直是 799，每帧亮度降 16、14、10、10、9、7……平滑到底，最后没有闪回不透明的一帧
- 打开仓库那一下另外有个毛病：新窗口在上面淡入、启动器在它底下同时淡出，两个各淡各的，中间后面的桌面透出来，启动器那一块先亮、再暗（244 → 239）、再亮。现在新窗口显示出来以后启动器等 250ms（新窗口的淡入约 75ms）、整个被盖住了再退场（`close_launcher_behind`），那一块一路单调变亮。新窗口自己的系统淡入开头偶尔少一两次刷新（180Hz 下约 11ms，时有时无），trace 里页面主线程、GPU 进程都没有长任务，是系统动画自己的，没动它

### 16.3 今日TODO ↔ /GOAL 不再闪

**问题。** 三件事叠在一起：

1. Shell 的主内容按区重挂：旧的一屏 140ms 淡出还往旁边挪 12px，新的一屏 220ms 淡入；分隔线从 0 再展开一次，状态栏再晚一拍淡进来
2. 旧的退得比新的进得快，中间一段两份都只剩一半 —— 整块字先变浅、再变深
3. 换篇的快照（`SwapFade`）挪出了正文的尺寸容器，里面 `@min-[480px]` 的大标题从 38px 掉回 30px，标题以下整篇往上缩 10px：换的第一帧旧内容整块跳一下（换笔记时一直有，以前被 4px 的上飘和淡出盖住了）

**做法。**

- 主内容按「版面」换，不按区换：这一区有没有列表栏（`frame`）。版面一样的两页之间是同一个 DocumentView，只是换了一篇文档，和在列表里换一篇笔记一样走 `SwapFade`。版面变了才换一屏
- `SwapFade` 从交叉淡化改成**溶解**：旧内容的快照铺着底色、盖满宿主，从不透明退到透明；新内容一直是不透明的、不动，没有「两份都半透明」的那一段，新内容也不会淡完再被提出图层重画一次。快照不再上飘。快速连切时新的快照垫在还在退的那一份底下，画面不跳
- 快照层自己是尺寸容器（`container-type: inline-size`，和宿主一样宽）
- 版面变了那一下也是溶解：新的一屏挂上就不透明，旧的一屏（popLayout 冻住）盖在上面退掉。旧的一屏得画在上面：新的一屏的根是 relative、DOM 里又在后面，会盖住它 —— Motion 在退场那一刻、画之前给它挂上 `data-motion-pop-id`，`.odea-frame[data-motion-pop-id]` 抬高一层
- /GOAL 这一期的目标和今天一起先取：第一次点过去不先空着一页「载入中…」
- 专注模式的按钮在笔记 ↔ 日历时淡入淡出（以前跟着整屏换）

用户问「是不是因为没有侧栏」：不是。没有列表栏的两页之间切，以前整屏只有这一个淡入淡出，所以那一下最显眼。

### 16.4 侧栏开关挪到状态栏最左端

窄栏左下角那颗开关收起 / 展开的是它右边那一栏，今日TODO、目标没有那一栏，在那两页按它什么都不发生。挪到正文底下状态栏的最左端（Typora 的位置），紧挨着它收起的那一栏；只有文件、日历、归档有，专注模式、访客窗口没有。命令面板里「收起侧栏 / 展开侧栏」同样只在这几页出现。点窄栏上已经选中的那一项照样收起 / 展开。

### 16.5 源码标记不淡入

光标进到一段语法里，`**`、`#`、`[[` 这些标记以前淡入 160ms：标记一出来就占了位置、后面的字当场让开，标记本身却是透明的、过一会儿才浮出来 —— 字先跳、源码后到，就是「闪出来」；每个标记还各提成一层，淡完放回页面重画一次。改成和 Obsidian 一样一帧之内出来、收起（`.cm-odea-syntax-marker` 去掉 `animation`）。

### 16.6 状态栏贴在底下

## 17. 列表栏改成一棵树（2026-10-28）

**问题。** 列表栏同时是两样东西：P2 的笔记列表（卡片带摘要、点文件夹进去、面包屑）和 P11 以后的文件树（就地展开、一行一个标题）。§6 写的是「P2 现在的『全部笔记』就是文件树的一种样子，接着用」—— 旧列表直接当了树，样子没按树重新设计；未整理、智能文件夹、快捷方式、图片 PDF 后来又各自按「再加一组」挂上去。看得到的：

- 同一篇笔记三种样子：树根上的是 63px 的卡片，文件夹里展开出来的是 32px 一行，置顶又是带底色的卡片；点进那个文件夹，它又变回卡片
- 层级读反了：树根上的笔记和文件夹是同一层，却排在最下面一组，展开的文件夹越多被推得越远
- 一行上两种导航：点图标（悬停才出现的 20px 箭头）是展开，点名字是进去、整列换掉
- 「文件夹」「笔记」两个组标题和分隔线是在补救行长得不一样；本地目录最多五组
- 置顶去重不一致：这一层的置顶从「笔记」组里拿掉了，展开的文件夹里却没拿，一篇出现两次
- 「全部笔记」列的只是树根这一层，不是全部

**做法。** 一条规矩：有层级的用行，平铺的用卡片。

- **文件夹视图**（树根和任何一层）：上面一组置顶，下面是这一层的树。子文件夹、笔记、快捷方式、图片 PDF 都是同一种 34px 的行（图标 + 名字 + 右边一格），深度只体现在缩进上；顺序是文件夹（逻辑目录的根上最后是未整理）、笔记、快捷方式、图片 PDF。列表栏这一层和展开出来的子树是同一个组件（`FolderContents`），不再分组，也就没有组标题
- **平铺的列表还是卡片**（标题、所在文件夹、摘要）：搜索结果、聚焦到智能文件夹、聚焦到未整理。这时没有层级，摘要才有地方放
- **点文件夹整行是展开 / 收起**（按住 Alt 连子文件夹一起），Enter / 空格一样。空文件夹没什么可展开，点了是进去 —— 那里的空状态说怎么往里放东西；搜索结果里的文件夹也是进去
- **「进去」降成次要**：文件夹「…」第一项「聚焦到这里」、点标题打开的文件夹切换器、正文上方的路径。面包屑留着
- 文件夹「…」多一项**「新建笔记」**：右上角的 + 建在列表栏这一层，要建在某个子文件夹里不用先进去。建好以后展开那个文件夹、选中新的一篇、光标在标题里
- **置顶的每篇只出现一次**：在最上面那一组 —— 这一层和下面各层的（以前进了文件夹只列直接放在里面的），不在这一层的名字后面淡淡写上文件夹；树上它那个位置不列（`notesByFolder` 跳过置顶的）。文件夹的篇数照旧连置顶的一起算。智能文件夹是筛选，筛到置顶的照样列
- 树上的笔记行有和卡片一样的「…」菜单（`useNoteMenu`；以前展开出来的那几行没有菜单）。置顶的静止时右边一格是图钉，悬停换成「…」
- **「显示摘要」开关**（同一天，用户看了以后要的）：排序菜单分隔线下面一项，记在本机（`odea.prefs` 的 `noteExcerpts`），默认关。开着时树上**每一篇**笔记都是两行 —— 标题、底下一行摘要，52px，哪一层、置顶那一组、智能文件夹展开出来的都一样；文件夹、快捷方式、图片 PDF 还是一行 34px。图标和右边一格对齐标题那一行（顶上 7px + 行高 20px，和单行时标题落的位置一样）。没把摘要默认放回树里：300px 宽、每深一层缩 16px，摘要剩十几个字，原来的毛病也不是有摘要，是同一篇在不同位置样子不一样
- **智能文件夹展开出来的那一篇选中时淡淡地亮**（`bg-accent-wash/60`、不加粗，同快捷方式）：智能文件夹是筛选，同一篇在树上还有它本来的位置，两处一样亮看不出哪一处是它真正在的地方
- **树根叫什么**：它在仓库里的文件夹名，Odea 建的仓库是「笔记」（`folders.notes` 改过的照改过的）；整个仓库当树根时也叫「笔记」（`data/folders.ts` 的 `rootLabel`）。面包屑、正文上方的路径、「已移到「…」」跟着换。不用仓库名：列表栏底下就是「仓库名 ⌄」，一栏两个一样的名字、点了做不同的事
- **动效**（CLAUDE.md 规矩第 3 条：一排很多个的不进合成层）：文件夹图标 ↔ 箭头、篇数 ↔「…」、图钉 ↔「…」淡的都是颜色；箭头转的是 SVG 里的 `<path>`（和右侧目录树的收起箭头一样，`Twisty`）。`RowMenu` 的「…」也从淡 opacity 改成淡颜色（只有列表栏在用）。以前行尾那个「进去」的小箭头去掉了

### 17.1 验证（2026-10-28）

- lint、tsc、前端 1157 条过
- 浏览器预览（`odea-browser-v4`，本地目录和 `?logical`）：所有行 34px；「…」、篇数、图钉在同一列（篇数的字和「…」右边差 0.5px，图钉和「…」同一个中心）；点 OTW 原地收起、列表不换；展开「交易」不列已经在置顶里的那篇、篇数还是 3；空文件夹点了进去、面包屑「‹ 笔记」；文件夹「…」新建笔记 → 展开、新的一篇在它底下第一行、光标在标题里；聚焦到 OTW 是同样的行；搜索、聚焦到智能文件夹是卡片；未整理点了原地展开

## 19. 窄栏不掉帧、固定标题栏、窗口打开就最大化（2026-10-28）

接着 §16 的三条反馈。

### 19.1 开关日程时窄栏的图标不掉帧

**问题。** §16.1 让多出来 / 没了的那几项动高度（0 ↔ 38）。高度只能在主线程上一帧一帧算，可开关的那一下主线程正忙着按新的列表把整个应用重画一遍：4 倍降速的开发版里一下 106ms，动画进行到一半今天那一篇取回来又是 53ms —— 头几帧和中间都卡。

**做法。** `Sidebar` 的 `useNavRows`：排版只变一次，动的都是合成器上的 opacity / transform（Web Animations），主线程再忙也照常走。

- 多出来的：挂上就占好格子，晚 70ms 淡入；下面的「归档」从原来的位置滑过去（FLIP，240ms，起步就走、收尾短的曲线）
- 拿掉的：先留在原来的格子里淡出（140ms，点不到、读屏器不念），淡完撤掉，下面的再滑上去
- 动之前对齐到整物理像素（1.25 倍屏上奇数格落在半个像素上），每一格一直待在自己的图层上（CLAUDE.md 规矩 3）

**验证。** 4 倍降速、1.25 倍屏的无头 Chrome，tracing 里窄栏的 24 个动画事件没有一个带 `compositeFailed`（都在合成器上）；同一段时间主线程照样有 68–128ms 的长任务，挡不住它们。关日程：三项淡出、「归档」从 232 滑到 118；开日程反过来。

### 19.2 正文上方固定的一条（已撤回，见 §20）

**问题。** 标题上方那一行（笔记的文件夹路径；某一天的日期和日程切换器；分段控件）跟着正文滚走，用户想让它像底下的状态栏一样固定。

**做法。** `DocumentView` 的 `DocHeader`：从滚动的正文里挪出来，放在正文上方。

- 位置和以前那一行一样：中线 62px（和右边目录树的标题齐），标题照旧从 80px 开始 —— 今日TODO、/GOAL、笔记的标题在同一个高度，切换时不跳。最上面 38px 还是无边框窗口的拖动区，这一条在它下面，点得到
- 和正文一样居中、一样跟着专注模式 / 收起列表栏滑（`CenteredColumn` 拿 className 区分两处），往左 chrome 底下多铺一截；它自己是尺寸容器，窄的时候分段控件照样换成一个字
- 左边那截换篇时跟着正文溶解（自己的 `SwapFade`）；分段控件不在里面 —— 切周 / 月 / 年时它的滑块在动，快照盖上去会重影
- 正文滚进它底下时在 20px 里淡掉；在顶上时不画（滚动时直接给宿主挂 `data-scrolled`，不重渲染），不然大标题的上沿也被淡掉一截
- 专注模式的按钮挪到同一条中线上（top 46）

### 19.3 仓库窗口打开就最大化，关的时候什么样下次就什么样

**问题。** 窗口位置以前交给 `tauri-plugin-window-state`。用户机器上它的记录停在 10 月 20 日：插件只在应用正常退出那一刻（`RunEvent::Exit`）写盘，自动更新走的是 `app.restart()`，很可能走不到那一步；所以每次都按那天记的 1440×900、不最大化开，最大化过也记不住。另外它还原「可见」「最大化」是在窗口刚建好的时候：上次关时是可见的，它就当场 `show()`；最大化（tao 里是 `ShowWindow(SW_MAXIMIZE)`）也会把藏着的窗口直接显示出来 —— 都比前端画好第一帧早，`ready` 里「等首帧画完再显示」形同虚设。

**做法。** 仓库窗口不再交给插件（`with_filter` 把 `main`、`vault-…` 排除；访客窗口还交给它，只记位置大小），自己记在 `config.json` 这个仓库的那一条里（`placement`）：

- 关之前（`CloseRequested`）用 `GetWindowPlacement` 记下是不是最大化、不最大化时的位置大小 —— 最大化着、最小化着也拿得到原来那个（最小化之前是最大化的，`WPF_RESTORETOMAXIMIZED`）
- 建窗口时（还藏着）摆好：记过的用 `SetWindowPlacement(SW_HIDE)` 摆回去（那块屏幕拔掉了系统自己挪回来）；要最大化的先撑满它那块屏幕的工作区，前端第一帧就按最终的尺寸排
- `ready` 时一步显示：`SetWindowPlacement(SW_SHOWMAXIMIZED)` 最大化显示、同时把不最大化时的位置记回去，再让 tao 走一遍 `maximize()`（标题栏的「还原」图标按它）
- **没记过的按最大化开**（像 Obsidian），所以升级以后第一次打开就是最大化；日程切换器给了位置的照它
- 别的系统上只记是不是最大化和位置大小，显示时再最大化

- 前端 1157 条、Rust 306 条过（boot 加了 2 条：旧配置没有 `placement` 读成「没记过」、记下的存进去读回来只记它自己的；哪些标签算仓库窗口）；lint、tsc、cargo check
- 桌面端（单独的 identifier 和数据目录，见 19.5）：
  - 没记过：开出来就是最大化，页面 2560×1392 = 屏幕可用区域；点「还原」回到屏幕正中 1440×900
  - 还原着关掉：记下 `maximized: false` 和位置；再开是不最大化、在原处
  - 最大化着关掉：记下 `maximized: true`，不最大化时的位置还是原来那个；再开是最大化，点「还原」回到原处
  - 重开时一连上就量页面尺寸：编辑器挂上之前已经是 2560×1392（建窗口 52ms 时还是 1440×900，219ms 撑满）—— 第一帧就按最大化的尺寸排，显示时不重排
  - 固定标题栏：路径在 y 52–72，拖动区到 38 为止，路径那里最上层就是它自己（点得到），标题从 80 开始
- 浏览器预览：笔记、今日TODO、日历、窄窗口、滚下去以后的截图；今日TODO 和 /GOAL 的标题都在 80
- **没测到**：多块屏幕、记下的那块屏幕拔掉以后（系统会把窗口挪回来，没实测）；macOS；正式版里点一遍

### 19.5 坑

- tao 在 Windows 上最大化是 `ShowWindow(SW_MAXIMIZE)`：藏着的窗口会被直接显示出来。要「藏着、但已经是最大化的大小」只能先把窗口撑满工作区，显示时再 `SetWindowPlacement`
- `GetWindowPlacement` 的 `rcNormalPosition` 带着系统看不见的边框（1440×900 的页面记成 1456×909），是「工作区坐标」：原样交回 `SetWindowPlacement` 才对得上，别拿去 `set_position`
- window-state 插件只在 `RunEvent::Exit` 写盘；它的还原和保存用同一组开关，没法「记最大化、但建窗口时先别最大化」
- 用户的 Odea 开着时，同一个 identifier 的开发版起来就退（单实例把参数转给了用户那个，那边可能弹一下）：`pnpm tauri dev --config <只写了 identifier 的 json 文件>` 换一个 identifier 就能并排跑
- 用 `ODEA_VAULT` 打开的仓库不进 `config.json` 的列表，记不了 `placement`：测「记住」要先在列表里放一条

## 20. 标题栏里的「路径 / 标题」（2026-10-28）

**问题。** §19.2 把标题上方那一行固定在正文上方，加上最上面 38px 的拖动区，顶上一直占着 80px，用户嫌太挤、
太占编辑区，问能不能像 Typora 那样贴着顶，或者有更好的办法。

**调研。** Typora 把菜单和标题栏合成顶上一条，只淡淡地写文件名；Obsidian 顶上是标签页一行、路径一行，
和 §19.2 一样重，所以设置里能关掉标签页那一行，论坛上一直有人要「往下滚时把顶栏收起来」；iA Writer、
Ulysses 打字、滚动时把工具栏收起；苹果的大标题在顶上时是大标题，一滚动就缩进导航栏变成一行小字。
微软的标题栏规范允许把内容放进标题栏，只要空着的地方还能拖、双击能最大化。

**做法（苹果大标题那一种）。** `DocumentView` 的 `TitleStrip`：

- 在顶上时和最早一样：路径（日期、分段控件）在标题上方，跟着正文滚，顶上一点不多占，标题从 80px 开始
- 往下滚到标题那一块（连同上面那一行）整个钻进窗口最上面那条（38px 的拖动区）底下，那条里淡进来一行
  「路径 / 标题」：笔记是 `📁 文件夹 / 标题`，某一天是 `日期 / 标题`，目标只有标题。点标题滑回顶上，
  点路径的一段在列表栏里打开那个文件夹
- 什么时候出来看的是 IntersectionObserver（根是滚动容器、上沿往里收 38px），滚动时不用每帧算。
  没用 CSS 滚动时间线（滚多少淡多少）：换篇时正文先拨回顶上、再滚回上次看到的地方，跟着滚动走的话
  这一行会灭一帧再亮
- 状态记着「这是哪一篇的结论」：换篇时新那篇的结论回来之前，字留着刚才那一篇的；结论是显示才换字，
  换字时跟着正文一起溶解（自己的 `SwapFade`）。两篇都滚在中间来回切，这一行一直亮着
- 两层：底色（这一栏宽、下沿 16px 渐隐，盖住滚上来的正文）在标题栏（z-40）底下，窗口按钮照样在上面；
  字那一层在标题栏上面（z-41），整层不接指针，只有路径的几段和标题接 —— 空着的地方照样拖窗口。
  底色比 chrome（z-30）高，不能像正文画布那样往左多铺一截，不然盖住窄栏的 Logo
- 出来 220ms、收起 180ms，只淡 opacity，一直待在自己的图层上；收起时淡完再 `visibility: hidden`，
  看不见的按钮不挡拖窗口
- 给鼠标用的复本：`aria-hidden`、按钮 `tabIndex -1`（`NotePath` 多了这个参数），读屏器和 Tab 键走正文里那一行

**验证（2026-10-28）。**

- 浏览器预览（1.5 倍屏无头 Chrome）：在顶上藏着；滚到 60（标题底边还在 68）也藏着；滚到 120 出现
  「笔记 / 欢迎使用 Odea」；点标题回到顶上、藏起来；滚在中间换到一篇在顶上的，淡出时字还是刚才那篇的；
  两篇都滚在中间来回切，透明度一直是 1，字溶解约 200ms
- 逐帧（`scripts/perf/fade-frames.mjs` 加了 `strip` 场景）：淡入一路收敛，171ms 起和终帧完全一致，没有平台
- 桌面端：滚下去以后，路径和标题那里最上层是这一行（点得到），标题右边空着的地方、窗口按钮那里最上层是
  拖动层；窄栏的 Logo、列表栏顶上没被盖住
- 前端 1157 条过，lint、tsc

**坑。**

- 比 chrome 层级高的东西不能往左多铺：§19.2 的固定顶栏、正文画布都往 chrome 底下多铺了一截，那是因为它们
  比 chrome 低
- 两层要分开：底色要在窗口按钮底下、字要在拖动层上面，一层做不到

## 1. 结论

| 问题 | 定了什么 | 为什么 |
|---|---|---|
| 做哪一种「多窗口」 | **窗口里的标签页 + 分屏**，最后再做「弹成独立窗口」 | 仓库级的多窗口已经有了（一个窗口一个仓库，仓库与启动器 §4）；缺的是同一个仓库里同时开着几篇 |
| 哪些页有标签 | **只有笔记**。今日TODO、/GOAL、日历、归档照旧，切过去标签栏不显示，切回笔记还在 | 日程那几页本来就是「一页一篇、跟着日期走」，开成标签反而要解释「今日」这个标签明天是哪一篇；和用户确认过（2026-10-29） |
| 点列表里的一篇 | **在当前标签里打开**（像 Obsidian），这一篇已经开在别的标签里就切过去 | 笔记应用常在列表里一篇篇点着看，每点一下多一个标签（VS Code 不开预览模式时）很快就乱了 |
| 怎么开新标签 | Ctrl / ⌘ + 点击、中键点击、行菜单「在新标签页打开」；双链 Ctrl+Shift+点击 | 和浏览器、Obsidian 一样；行菜单是给不知道快捷键的人找得到的入口 |
| 只开着一篇时 | **和现在一模一样**：没有标签栏，最上面那条还是空的拖动区、滚下去出「路径 / 标题」 | 不用标签的人一点感觉不到；开了第二篇标签栏才淡出来 |
| 标签栏放哪 | **窗口最上面那条 38px 的拖动区里**（Chrome、Arc 那样），正文不往下挪 | 仓库与启动器 §20：用户嫌顶上多占 80px；Obsidian 标签一行 + 路径一行正是被嫌的那种 |
| 背后的标签留什么 | 不留 DOM、不留编辑器，只留 `EditorState`（开着的标签不被挤出缓存）和视图记忆 | 一个窗格同时只挂一个编辑器（VS Code 的做法）；Obsidian 后台标签加载过就一直挂着，内存跟着标签数涨 |
| 怎么分 | **只左右分，最多三栏**（§12） | 标签栏长在最上面那条拖动区里；上下分的话下面那个窗格的标签栏没处放，得在正文里另起一行 |
| 分屏用什么库 | **自己写**，不用 dockview / FlexLayout | 它们的落点提示会缩放、把面板挪到别处会重挂编辑器、样式要整套覆盖，和 §10 动效规矩、§11.5「祖先在动时不能挂编辑器」都冲突；布局本身就是一棵「横竖分割 / 窗格」的树，几百行 |
| 弹出成独立窗口 | **`window.open` 拿到同一个 JS 环境里的子窗口，窗格 portal 进去**（§16）；一个弹出窗口一个窗格，关掉标签回到主窗口 | 共用 store 和编辑器缓存、不变成第二个开同一仓库的窗口。WebView2 上验证过行（§16.1），代价是写死了全局 `document` / `window` 的地方要改成按所在的窗口 |

## 2. 调研：VS Code 和 Obsidian 怎么做

### 2.1 VS Code

- 编辑区是一张网格（`SerializableGrid`），格子叫编辑器组，每组一排标签
- **一组只有一个编辑器控件**，切标签是给它换文档模型（`ITextModel`）；光标、滚动、折叠按「组 + 文件」记着（`EditorMemento`），切回来恢复
- 同一个文件开在两组里共用一份模型，两边各有自己的视图状态
- 单击文件是「预览」标签（斜体），下一次单击会被替换；改了或双击才固定下来 —— 为的就是不让单击浏览开出一堆标签
- 1.85 起编辑器能拖出成独立窗口（auxiliary window），和主窗口是同一个渲染进程

### 2.2 Obsidian

- 工作区是一棵树：分割（WorkspaceSplit）→ 标签组（WorkspaceTabs）→ 叶子（WorkspaceLeaf），左右侧栏也是标签组
- 在文件列表里点一篇，是在当前标签里打开；Ctrl+点击开新标签，Ctrl+Alt+点击开在右边分屏；每个标签有自己的前进 / 后退
- 每个叶子一个视图、一个 CodeMirror。1.7.2 起后台标签在第一次被看到之前不加载（「deferred views」，[更新说明](https://obsidian.md/changelog/2024-09-19-desktop-v1.7.2)、[插件指南](https://docs.obsidian.md/plugins/guides/defer-views)），加载过就一直挂着
- 设置里能关掉标签栏那一行（标签 + 路径两行太重，见仓库与启动器 §20）；0.15 起有弹出窗口

### 2.3 Tauri 里的弹出窗口

- Tauri 2.12 的 `WebviewWindowBuilder` 有 `on_new_window`：页面里 `window.open` 时由 Rust 决定，返回 `NewWindowResponse::Create { window }` 就用自己建的窗口接住，`window_features(features)` 带上页面要的那些特性（[docs.rs](https://docs.rs/tauri/latest/tauri/webview/struct.WebviewWindowBuilder.html)）
- WebView2 那一层：宿主在 `NewWindowRequested` 里给一个同一个 Environment、还没导航过的 WebView，`window.open` 返回给页面的就是它的窗口，两边能互相访问（[NewWindowRequested](https://learn.microsoft.com/es-es/microsoft-edge/webview2/reference/win32/icorewebview2newwindowrequestedeventargs)）
- 成立的话，React 直接 portal 进子窗口，store、编辑器缓存、IPC 都是同一份。**没找到 Tauri 在 WebView2 上接住 opener 的确切说法**，P12.3 先花半天验证：`window.opener`、样式怎么带过去、CodeMirror 的 `root`、键盘事件、Motion 用的是哪个 window（验证结果在 §16.1：成立）

### 2.4 现成的分屏库

dockview（React，标签、网格、浮动组、弹出窗口都有）、FlexLayout、react-mosaic、golden-layout、allotment（VS Code 分割条的移植）。不用的原因见 §1。

## 3. 范围：只有笔记有标签

- 标签里只放**笔记**（`DocumentSaveTarget` 的 `note`）。归档里的那篇、某一天、某个周期的目标照旧由 `openDocument` 切到它那一区去看
- 切到今日TODO / 日历 / 归档：标签栏不显示，标签都还在；切回笔记，原样回来
- 专注模式：标签栏收起（这一刻只想写这一篇），Ctrl+Tab 照样能切
- 做客（协作时正文区换成别人的那一篇）：标签栏收起，协作结束回到当前标签
- 访客窗口（不开仓库）：没有标签

## 4. 交互

### 4.1 打开

| 操作 | 结果 |
|---|---|
| 单击列表里的一篇（树上的行、卡片、快捷方式） | 当前标签换成这一篇；它已经开在别的标签里就切过去（一个窗格里不重复） |
| Ctrl / ⌘ + 单击、中键单击 | 在当前标签右边开一个新标签并切过去；已经开着就切过去 |
| 行菜单「在新标签页打开」 | 同上 |
| 双链：Ctrl / ⌘ + 点击 | 当前标签（和现在一样） |
| 双链：Ctrl / ⌘ + Shift + 点击 | 新标签 |
| 新建笔记、全局搜索、命令面板打开一篇 | 当前标签 |

### 4.2 关、切、排

| 操作 | 结果 |
|---|---|
| 标签上的 ×、中键点标签 | 关掉；关的是当前的，切到它右边那个，没有就左边那个 |
| Ctrl / ⌘ + W | 关掉当前标签；只剩一个时什么都不做（不关窗口） |
| Ctrl / ⌘ + Shift + T | 重新打开最近关掉的那个（这次会话里，最多记 20 个；那一篇已经不在了就跳过） |
| Ctrl + Tab / Ctrl + Shift + Tab | 下一个 / 上一个，到头绕回来 |
| Alt + 1…8（macOS ⌃ + 1…8） | 第几个；Alt + 9 是最后一个。Ctrl + 数字编辑器里是「设成几级标题」，不占 |
| 点已经是当前的那个标签 | 正文滚回顶上（和点「路径 / 标题」那一行的标题一样） |
| 按住标签左右拖 | 换顺序；别的标签让位（只动 transform） |

快捷键只在笔记区生效；对话框、命令面板开着时不管。

### 4.3 笔记没了

- 在这里删除、归档正在看的那篇：开着别的标签就**关掉这个标签**（切到旁边的标签）；只有这一个标签时照旧挪到列表里的下一篇（`selectNeighbor`）
- 别处删掉、归档的（资源管理器、同步、别的标签里开着的那篇被删）：笔记列表一更新，指着它的标签都关掉。列表还没取回来（启动时）不动
- 撤销删除不把标签开回来

## 5. 界面

### 5.1 位置

- 标签栏是窗口最上面那条（38px，无边框窗口的拖动区）里、正文区那一截：左边从列表栏右缘往里 12px 起，右边让出窗口按钮（桌面端约 128px）
- 和「路径 / 标题」（`TitleStrip`）同一种叠法：底色那一层（正文区宽、下沿 16px 渐隐，盖住滚上来的正文）在标题栏（z-40）底下，标签那一层在它上面（z-41）；整层不接指针，只有标签接 —— 标签之间、右边空着的地方照样拖窗口、双击最大化
- 标签栏显示着的时候，「路径 / 标题」改在标签栏底下一行（§18）。~~不出，当前标签就是标题，路径在标签的悬停提示里~~：开着第二个标签、分屏、弹出窗口里，滚下去就不知道这一篇在哪个文件夹了
- 列表栏收起 / 展开：标签栏跟着列表栏的右缘滑（和列表栏同一个 `tween.base`，怎么对齐见 §11.3），不然列表栏还没滑走，标签已经跳到了它上面

### 5.2 样子

- 高 28（控件高度 24 / 28 / 32 那一档），字 13，左边内边距 10，圆角 8；**按字数排宽**，最宽 200、最窄 72，多了先一起变窄，再多就横着滚（滚轮竖滚转横滚，切过去的那个滚进视野）。一样宽的话，没有底的标签之间字和字的空一段大一段小
- 不是当前的：一行 `muted` 的字，没有底、没有框；悬停 `raised/35` 的底、字变 `body`
- 当前的：`raised` 的底，字 `ink`（字重不变：中文换字重一帧十几毫秒，宽度也会变）；底色那一块在标签之间滑过去（`layoutId`，和分段控件的滑块同一种写法；它没有字，可以缩放）。悬停和当前的底色要差得开：最早是 `/40` 和 `/70`，截图里分不清哪个是当前的
- 关闭的 ×：14px（按钮 18×20），当前的和悬停的才看得见；淡的是 `color`（一排很多个，CLAUDE.md 规矩 3），不进合成层。按钮的悬停底是 `ink/10`：当前标签的底已经是 `raised` 了
- 这一篇有修改没存进去（保存失败、`drafts` 里有它）：× 的位置是一个 `warning` 色的小圆点，悬停变回 ×
- 悬停提示：`文件夹 / 标题`

### 5.3 动效

- 标签栏出现 / 收起（第二个标签开出来、关到只剩一个、进出专注模式、切到别的区）：只淡 opacity，出来 220ms、收起 180ms；一直待在自己的图层上（`will-change: opacity`），开始淡之前 `snapToDevicePixels`。收起的那一段里字留着收起之前的样子
- 新标签：挂上就在最终位置，淡入 160ms；右边的标签从原处滑过去（FLIP，transform，ease-out cubic 200ms）
- 关标签：先原地淡出 120ms（点不到），淡完撤掉，右边的滑过来
- 拖着排：被拖的那个跟着指针走，别的让位（同一条曲线）
- 切标签：正文的溶解和在列表里换一篇一样（`SwapFade`）
- 减少动效：都直接换

## 6. 状态和数据

### 6.1 store

`app/store.ts` 的 `useApp` 加一组：

```ts
noteTabs: NoteTab[];        // { id, noteId }，从左到右
activeTab: string;          // 当前标签的 id
openNoteTab(noteId, at?);   // 新标签（已经开着就切过去）
switchTab(id) / closeTab(id) / moveTab(id, index) / reopenTab()
```

- **不变式：当前标签的 `noteId` 就是 `selectedNoteId`。** `selectNote` 改的是当前标签（已经开在别的标签里就切过去）；切标签改 `selectedNoteId`。这样 P12.1 里「现在显示哪一篇」的全部逻辑（`useCurrentDocument`、列表高亮、`selectNeighbor`、团队视图、命令面板里的「这一篇」）一行不用改 —— 同一时刻还是只显示一篇
- 永远至少有一个标签。一个都没开过时（新仓库）就是 `[{ noteId: selectedNoteId }]`
- 关掉的标签记一个栈（20 个，只在这次运行里）给 Ctrl+Shift+T

### 6.2 记在本机

- 记在「上次停在哪」那一份里（`odea.session:仓库路径` 的 `tabs`，按仓库分开）：标签的 noteId，当前那个就是原来的 `noteId`；只有一个标签时不写。和选中的那篇写在一起，不会一份新一份旧
- 打开应用时恢复；指着已经不在的笔记的，笔记列表取回来以后去掉

### 6.3 缓存

- 编辑器状态缓存（技术方案 §11.6）：**开着的标签不被挤出去**。普通的还是最近 12 篇；开着的标签另算，总数到 24 再按最久没用的挤（一篇长文的状态有几 MB）。开着的标签有哪些，由一个不进编辑器分包的小模块（`editor/statePins.ts`）告诉缓存
- 笔记正文（`bodies`，24 篇）：开着的标签的正文也不挤掉（只是字符串）
- 视图记忆（`lib/viewMemory.ts`）照旧按篇记滚动、光标、收起的标题，切回来回到原处

## 7. 性能

- 开一个标签 = 现在在列表里换一篇：缓存里有的 66KB 长文约 58ms，第一次约 124ms（技术方案 §11.6）
- 背后的标签不挂 DOM、不挂编辑器；同一时刻挂着的编辑器 = 窗格数（P12.1 是 1）。perf 脚本的「切完笔记还活着的编辑器」照样该是 1
- 内存：开着的标签多留的是 `EditorState`（上限 24 个）和正文字符串
- 启动：只挂当前标签那一篇；别的标签只有标题（相当于 Obsidian 的 deferred views）
- 分屏（P12.2）最大的风险是拖分割条：宽度每帧变，开了自动折行的 CodeMirror 逐帧重新折行（技术方案 §8.8、§13.2 踩过的坑）。缓和的一点：正文列最宽 860，窗格比它宽时拖动不改折行。要先量（4 倍降速），超了再想办法
- perf 脚本要加的场景：开 20 个标签 Ctrl+Tab 轮一遍、关掉再开、切到别的区再回来；P12.2 加分屏打字、拖分割条的逐帧耗时

## 8. 和现有机制的交界

| 现有的 | P12.1 | P12.2 起 |
|---|---|---|
| `useCurrentDocument()`（全局的工作区 + 选中项 → 一篇） | 不动（当前标签就是选中项） | 正在写的窗格照旧用它（做客时它换成共享的那一篇）；别的窗格用 `usePaneDocument(noteId)`（笔记那一支抽出来的 `useNoteDocument` + 团队那一层） |
| `selectNeighbor`（删除、归档前挪选中） | 开着别的标签时改成关标签 | 窗格里只剩这一个标签、又有别的窗格：关这个窗格 |
| `TitleStrip`（「路径 / 标题」） | 标签栏显示着时出在它底下一行（§18） | 分屏时每个窗格都有标签栏，各在各的标签栏底下 |
| 目录树（右边 180） | 不动 | **改了**：每个窗格自己的，窗格 1060 宽以上才有（§12）。抽出来做成跟着正在写的窗格的一栏，要把目录从 DocumentView 里搬出来，先不做 |
| 状态栏 | 不动 | **改了**：每个窗格一条（字数、历史、删除都是那一篇的），侧栏开关只在最左边那一栏 |
| `pendingAnchor` / `focusRequest`（按 docKey） | 不动 | 只有正在写的窗格接（两个窗格开着同一篇时不两边都抢） |
| `setTeamView`（团队：我在看哪一篇） | 不动 | **还是只报正在写的那一篇**：团队的「我在看」是一篇，改成几篇要动协议，没做 |
| 编辑器状态缓存 | 开着的标签不挤 | 同一篇开在两个窗格：主视图留撤销历史，另一个转发事务（CodeMirror 的 split 例子）；协作中的两边都绑同一份 Loro |
| 专注模式 | 标签栏收起 | 只留正在写的那个窗格 |

## 9. 分阶段

### 11.2 和设计不一样、或者设计里没写的

- **当前标签就是 `selectedNoteId`**，P12.1 只有一个窗格，「显示哪一篇」的逻辑一行没动：`useCurrentDocument`、列表高亮、团队视图、命令面板都照旧只看它。直接 `useApp.setState({ selectedNoteId })` 会破坏这条，现在只有 `restoreVaultSession`（连标签一起换）和测试这么写

- 整条正在淡入淡出时，里面的标签不各自播动画：收起再出来时上一次那几个不会留着淡出（`wasShown`）
- 按下就切过去（和浏览器一样），拖过 4px 才算排顺序；松手时看得见的位置记成「上一次的位置」，挪到新格子从那里接着滑，不跳回原处

- 关闭按钮的 × 和保存失败的圆点在同一个 SVG 里，换的是 stroke / fill 的颜色

### 11.3 标签栏怎么跟着列表栏滑

列表栏是 Shell 里 Motion 的 `x`，在主线程上逐帧算。三种做法逐帧量过（无头 Chrome、1.5 倍屏，每一帧在 Motion 更新完之后读第一个标签的左缘和列表栏的右缘，对齐时前者 = 后者 + 12）：

| 做法 | 结果 |
|---|---|
| Motion 的 `layout="position"` | 要等量完下一帧才起步：展开时开头约 100ms 标签落后，压在正在滑出来的列表栏上 |
| 合成器上的 Web Animations | 不跟着主线程顿：列表栏一顿（开关的那一下主线程有 20ms 的帧）就差出几十个像素；把 `startTime` 设成这一帧又反过来超前 |
| **Motion 的 `animate(x)`，在同一次提交里起步** | 第二帧起每一帧都正好 +12。Motion 在一次同步执行里给的「现在」是同一个，两条的进度一样，顿也一起顿 |

第一帧还差一点，是列表栏自己的：AnimatePresence 退场的第一帧它没动，下一帧直接跳到进度上。推迟到下一帧再起步（`frame.update`）试过，落后得更多。

## 12. 分屏：只左右分、最多三栏

（2026-10-29 做 P12.2 时定的，细化 §9）

**只左右分。** 标签栏长在窗口最上面那条拖动区里（§5.1），左右分时每一栏的标签栏正好在它自己头顶上；上下分的话下面那个窗格的标签栏没处放，只能在正文里另起一行 —— 就是 Obsidian 那种「标签一行、路径一行」又重又挤的样子（仓库与启动器 §20 用户嫌过的）。所以布局不是一棵树，就是一排窗格（`app/panes.ts`）。

**最多三栏。** 窗口 1440、列表栏开着时正文区 1076 宽，三栏一栏 358；再多一栏正文一行放不下几个字。拖分割条时一栏最窄 320。

**每个窗格：**

- 一条标签栏（`NoteTabs`），在这一栏的正上方。分屏时每一栏都显示标签栏（哪怕只有一个标签），一眼看得出每一栏是哪一篇；最右边那一栏让出窗口按钮
- 一个 DocumentView。最左边那一栏的画布往左 chrome 底下多铺、状态栏最左端有侧栏开关；专注模式的按钮在最右边那一栏
- 自己的状态栏（字数、历史、在文件夹中显示、删除都是这一篇的）
- 目录树：只有一栏时照旧（窗口 1280 以上）；分屏时这一栏 1060 宽以上才有（正文 860 + 目录 180 + 留白）

**正在写的那个窗格。** 在哪一栏按下鼠标、焦点进了哪一栏，它就是正在写的（`activePane`）。列表里点一篇、命令面板、全局搜索、新建都作用在它上面；列表的高亮跟着它。别的栏的当前标签字淡一档（`body` 不是 `ink`）、底色浅一档（`raised/55`），换的是颜色。

**分割条。** 1px，和别处的分隔线同色（`line-strong`），从窗口顶一直到底，标签栏那一截也有，看着是几栏。能按的地方左右各 4px，从拖动区下面开始（最上面 38px 还是拖窗口的）；悬停 300ms 才变主色，划过去不闪；拖的时候整个窗口的指针都是左右箭头、正文不被选上。双击：几栏一样宽。焦点在上面时按左右键一次挪 24px。

**拆出、关掉一栏是溶解，还在的窗格不重挂。** 整排拍一张快照（SwapFade，和换篇同一个溶解）盖在上面退，还在的那一栏在快照底下变宽变窄、重新折行，只有新的那一栏挂上来。笔记 ↔ 日历（只有一栏时）照旧是同一个 DocumentView 换一篇。（最早是窗格的 id 进 Shell 的版面键、整屏换掉，每个编辑器都重建，卡，§15.6）

**做客时只有一栏。** 正文区换成别人的那一篇时（`useCurrentDocument` 给的是共享的那一篇），只画正在写的那一栏，标签栏收起（§3）。

## 13. 停靠和右键菜单

**拖标签。** 按住标签：

- 左右拖过 4px：排顺序（P12.1）
- 上下拖出 24px：停靠。标签回到原处、淡一档，一个小签跟着指针走（挨着窗口边就往里收），指针底下那个窗格亮出落点：左右各四分之一是「拆到这一边」（落点是那半边），中间是「挪进这个窗格」（落点是整个窗格）。到了三栏、或者把一个窗格里唯一的标签拖到自己边上，两边也算「挪进去」；挪进自己所在的窗格等于没动，不亮
- 松手：拆出一栏（标签挪过去，原来的窗格空了就关掉、地方给旁边的），或者挪进那个窗格的最后（那个窗格里已经开着这一篇就切过去）

落点只淡入淡出；换了一块，位置、大小滑过去（140ms，它没有字）；第一次出现直接摆在那里再淡入。小签和落点的坐标都对齐到整物理像素。

**右键菜单。** 关闭（Ctrl+W）、关闭其他标签、关闭右侧的标签、向右拆分（Ctrl+\，同一篇在右边再开一栏）。做不了的不列（只有一个标签时没有「关闭其他」，到了三栏没有「向右拆分」），不放灰掉的。样子和行菜单一样，只淡入。

**往回走。** 每个标签记着在它里面看过的（最多 50 步）：在列表里点一篇换掉当前标签里的那一篇时，原来那篇进「往回」。Alt+← / Alt+→（macOS ⌘+[ / ⌘+]，Option+← 是编辑器里按词移动）、鼠标侧面的后退 / 前进键。删掉了的、这个窗格别的标签里开着的跳过。

## 14. 同一篇开在两个窗格

「向右拆分」最常见的用法就是同一篇的两处对着看（上面看目录、下面写），所以允许同一篇开在两个窗格里（一个窗格里还是不重复）。

**两个编辑器，互相转发。** 每个窗格一个编辑器（各自的光标、滚动、撤销历史）。一边打的字原样转给另一边（CodeMirror 的 split 例子那样转事务，`mirrorSync`）：

- 转过去的不进那边的撤销历史：右边撤销只撤右边自己打的
- 转过去的不由那边存盘：打字的那一边存（两边的正文一样，存的都是整篇）
- 转过去的不算那边「和磁盘对上了」：对没对上还看存盘回来的那一版（`syncedMarkdownRef`）。不然左边连着打字、存盘回来的是早半秒的一版，右边以为自己是干净的，拿那一版回填 —— 刚转过来的字就没了，接下来转过来的改动位置也全错
- 后挂上的那个用先挂着的那个现在的正文建，不用 store 里的（那一版可能还差着没存的几个字）
- 编辑器状态缓存：还有一个开着时不缓存，最后一个卸载时缓存它的

**协作中的不行。** 协作的绑定是一个编辑器一份，两份绑同一个会话，一份提交时另一份当成自己的（origin 一样）不理 —— 两边对不上。所以协作中的那一篇只在一个窗格里编辑（正在写的那个，不是的话最左边那个），另一个窗格里说一声「这篇正在协作」，不挂编辑器。

| 1 倍速 | 5.6ms | 5.7ms | 11ms | 2ms |
| 4 倍降速 | 28–44ms | 55–72ms | 110–230ms（第一帧过了正文区的容器查询档位） | 9ms（拆外壳以前 576ms） |

4 倍降速下每一帧约 35ms 都是浏览器自己的：重新排版（约 9ms）、容器查询带来的样式重算（约 6ms）、绘制（约 10ms），CodeMirror 量尺寸约 4ms，React 几乎没有。这是两栏实时折行的代价；VS Code、Obsidian 拖分割条也是实时折行。

想过的替代：拖的时候正文列冻在原来的宽度、松手再折一次（变窄的那一栏字被切掉一截）；只挪分割线、松手才改宽度（线和正文对不上）。都比卡几帧难看，没做。1 倍速很顺，用户机器上要是明显卡，再按「慢了就降成每两帧改一次」这个方向试。

**没测到的**：桌面端（三栏时标签栏让开窗口按钮、分割条最上面 38px 还能拖窗口、WebView2 里 Alt+← 和鼠标侧键会不会被拿去做页面后退）；协作中的那一篇开两处（单测覆盖不到协作的绑定，靠窗格那边只让一个窗格编辑）；三栏时拖分割条；暗色下的落点和分割条；perf 脚本里加分屏打字、拖分割条的场景

### 15.5 坑

- 拖动时跟着指针的小签取标签的字：当前标签里第一个 `span` 是底色那一块（`layoutId` 的），取到的是空的。给标题的 `span` 加了 `data-tab-title`
- Bash 的 heredoc 遇到带反引号、反斜杠的 TypeScript 会出错（`unexpected EOF`），大段代码改用 Write 写成文件再拼进去
- 窗格的 `style.flex` 是 React 给的，拖的时候改了 `flexGrow`：松手只清掉不行，React 只改它觉得变了的，没变的那个 `flex-grow` 就没了、窗格塌成 0（§15.2）

### 15.6 拆出、关掉一栏卡一下（2026-10-29 修）

用户说「分屏动画开启和关闭感觉是卡顿的」。不是动画的问题：溶解本身每一帧 6ms（合成器上淡的），卡的是按键以后、溶解开始之前的那一帧。

**原因。** 窗格的 id 在 Shell 的版面键里，拆出、关掉一栏等于换一屏：新的一屏里**每个**窗格都重新挂 —— 还在的那一栏的编辑器也销毁重建（长文要重新解析）、整页重新算样式和排版，旧的一屏还冻在 DOM 里退。都挤在按键那一个任务里。

**改法。**

- 版面键不带窗格 id，窗格按 id 留着不重挂；整排的溶解挪到 DocumentPanes 里，用 SwapFade 拍快照
- SwapFade 拍完快照当场盖上（`getSnapshotBeforeUpdate` 里），React 再在它底下改：子组件 layout effect 里量尺寸时快照已经在页面上，跟着一起排；以前改完才盖，快照那一块到帧末还要再排一遍
- 向右拆分的第二个编辑器从另一边的状态接着用（语法树、装饰不重来），撤销历史换成空的（`historySlot`：先拿掉再装回来）
- 窗格数变的那一次拦掉 Motion 的布局动画（`useInstantLayoutTransition`，在 DocumentPanes 渲染时）：带 `layoutId` 的元素一卸掉（变窄的那一栏收起目录、关掉的那一栏的标签底色）Motion 就要量一遍位置，那时 React 改 DOM 改到一半，整页排版被逼着算一遍、帧末再算一遍。反正盖在快照底下，不需要滑
- 两份目录的指示条 `layoutId` 用 `LayoutGroup` 分开（以前两个窗格的目录共用一个 `outline-indicator`，Motion 当成同一个，在两份目录之间飞）

**量的。** 无头 Chrome、生产构建，Ctrl+\ 拆出同一篇、Ctrl+W 关掉，各三次，按键以后最长的那一帧（`perf.mjs` 的 `split` 场景，4 倍降速、2 倍屏；不降速的是同一个做法、1.5 倍屏）：

| | 改之前 | 改之后 |
|---|---|---|
| 长文（语法全览）拆出，不降速 | 95–111ms | 约 45ms |
| 长文关掉，不降速 | 67–106ms | 约 28ms（偶尔 60） |
| 普通笔记拆出，不降速 | 44–84ms | 17–39ms |
| 普通笔记关掉，不降速 | 22–55ms | 11–17ms |
| 长文拆出，4 倍降速（中位数） | 462ms | 194ms |
| 长文关掉，4 倍降速（中位数） | 396ms | 182ms |

剩下的（长文、4 倍降速）：快照的克隆要算样式，变窄 / 变宽的那一栏重新折行的排版要算两遍（标签栏淡入淡出前对齐像素时读了一次位置，逼着先排一遍；新编辑器挂上、帧末再排一遍），新编辑器约 30ms。再往下要么快照只克隆看得见的那几行，要么把对齐像素挪到下一帧开头，没做。逐帧（`fade-frames.mjs` 的 `split` / `unsplit`）：一路收敛到最终帧，没有平台。

## 16. 弹出窗口

（2026-10-29 做 P12.3 时定的，细化 §9）

### 16.1 技术验证：WebView2 上成立

Tauri 2.11.5、wry 0.55、WebView2 151，仓库窗口建的时候接上 `on_new_window`，在 DevTools 里试的：

| 问题 | 结果 |
|---|---|
| `window.open('about:blank')` 拿到的是不是同一个 JS 环境 | 是。Rust 里建一个同一个 Environment 的窗口（`window_features` 带上 opener 的），wry 在 `NewWindowRequested` 里 `SetNewWindow`；页面拿到的子窗口同源、`opener` 就是主窗口，主窗口直接改它的 DOM |
| 什么时候能往里写 | `window.open` 一返回就能写，之后不会换成别的文档。Tauri 的窗口标签（子窗口的 `__TAURI_INTERNALS__.metadata.currentWindow.label`）约 20ms 后才有 |
| 子窗口一开始多大 | `window.open` 刚返回时视口是 0×0，下一帧才是要的大小（§17.2 第 3 条） |
| 窗口藏着（`visible(false)`）时 | 页面照样是 visible、rAF 照跑、能排版：可以画好再显示 |
| 主窗口最小化以后 | 主窗口的页面还是 visible，计时器、rAF 都不节流。Motion 用的是主窗口的 rAF，自动保存用的是主窗口的计时器，弹出窗口里不受影响 |
| 关窗口 | `w.close()` 只关得掉页面，Tauri 的窗口还在：要经 Rust `destroy` |
| 观察器 | 主窗口的 ResizeObserver 看不见子窗口里的元素（一次都不报），IntersectionObserver 照常报（§17.2 第 1 条） |
| 代价 | 同步的 `window.open` 约 150–190ms（建一个 WebView2），只在拆出去的那一下 |

### 16.2 怎么开、怎么关

- **拆出去**：右键标签「在新窗口中打开」；或者按住标签往下拖成停靠（§13），拖出主窗口、或者贴着窗口边（最外面 2px）松手 —— 窗口最大化时指针出不了屏幕，也就出不了窗口。拖到那里时小签换成「在新窗口中打开「标题」」。新窗口开在松手的地方（指针落在新窗口的标签上），宽度和原来那一栏差不多（720–1100），收进主窗口所在的那块屏幕
- **一个弹出窗口一个窗格**：一排标签、一个 DocumentView。不分屏：标签栏在窗口最上面，分屏在主窗口里做
- **跨窗口拖标签不做**：指针一出窗口就不归原来那个窗口管了。往回挪用右键「移回主窗口」（回到主窗口正在写的那个窗格并切过去，那里已经开着就切到那个）
- **关窗口**（标题栏的 ×、Alt+F4、任务栏的「关闭窗口」）：标签回到主窗口正在写的那个窗格的最后，**不切过去** —— 关一个窗口，另一个窗口里正看着的不该跟着换。主窗口只剩一个空标签（唯一的标签被拖出去了）就换掉它
- **关掉弹出窗口里最后一个标签**（×、Ctrl+W）：窗口没了，标签不回去（像浏览器）
- **主窗口关了**：弹出窗口跟着关，里面的东西是主窗口的页面画的。关之前照旧先存盘（编辑器的 flush 是同一份登记）
- **不记**：下次打开应用，弹出窗口里的标签在主窗口里（和关掉弹出窗口一样）

### 16.3 正在写的是哪个窗口

`activePopout`：在弹出窗口里按下、它拿到焦点，就是它；主窗口拿到焦点、在主窗口里按下，回到 null。主窗口那一排和 selectedNoteId 的不变式（§6.1）不变，弹出窗口的窗格不在 `notePanes` 里。

- 从正文里打开一篇（双链、反向链接）开在正在写的那个窗口里；Ctrl+Shift+T 开回正在写的那个窗口
- 列表栏在主窗口里：点它之前主窗口先拿到焦点，所以照旧开在主窗口
- 团队视图（「我在看哪一篇」）报正在写的那个窗口的那一篇
- 弹出窗口里的快捷键：Ctrl+W、Ctrl+Tab、Alt+数字、Alt+← / →、鼠标侧键、Ctrl+Shift+T 作用在它自己身上；没有 Ctrl+\（不分屏）
- 弹出窗口里点「历史版本」：对话框在主窗口里开，主窗口提到前面

### 16.4 同一篇两个窗口、协作

- 同一篇开在主窗口和弹出窗口里：和分屏一样，两个编辑器互相转发（§14）
- 协作中的那一篇主窗口里也开着（当前标签）：在主窗口里编辑，弹出窗口里说一声「这篇正在协作」

### 16.5 样子

- 无边框，最上面 38px 是标签栏和窗口按钮（主窗口的 TitleBar，操作的是弹出窗口）；标签之间、右边空白处拖窗口、双击最大化。只有一个标签也显示标签栏：没有列表栏，靠它认出是哪一篇
- 没有专注模式、没有侧栏开关；窗口 1060 宽以上才有目录树（和分屏时一样）
- 窗口标题跟着当前那一篇（任务栏、Alt+Tab 里看到的）
- 样式、主题跟着主窗口：`<head>` 里的样式抄一份过去，`<html>`、`<body>` 上的属性（主题、减少动效、拖分割条时的指针）变了跟着变

### 17.2 坑

1. **主窗口的 ResizeObserver 看不见子窗口里的元素。** CodeMirror、滚动条、目录树都靠它，弹出窗口里的编辑器不知道自己变宽了。第一次开弹出窗口时把全局的 `ResizeObserver` 换成分派的：已经挂在页面上的元素，用它所在窗口的 ResizeObserver；还游离着的（CodeMirror 先建好、开始观察，再挂上去）每个开着的窗口都看一份 —— 元素只画在一个窗口里，只有那一个会报。第一版按 `winOf(元素)` 找构造函数，主窗口的已经换成了这个类，无限递归
2. **CodeMirror 在游离的 DOM 里建**（建完再挂，省掉挂着时设 contenteditable 的那一遍）：`root` 认的是主窗口的文档。挂进弹出窗口以后 `hasFocus` 一直是 false、读写的是主窗口的选区 —— 光标画不出来，打的字落到行首。挂上以后 `view.setRoot(那个文档)`，焦点、选区、窗口事件、样式都换过去
3. **子窗口一开始是 0×0。** 编辑器在 0 宽的时候量了第一次，按一行十个字估出一篇两万像素高；滚动位置落到正文外面，它看自己不在窗口里就再也不量了。等窗口有了大小再往里画
4. 挂在全局 `document.body` 上的浮层（补全、右键菜单、悬停卡片、停靠的小签）、`window` 上的监听、按 `window.innerWidth` 摆的位置，都跑到主窗口去了：一个个改成按所在的窗口。`navigator.clipboard` 也是：主窗口的文档没有焦点，写剪贴板会被拒
5. 开发时改了导出非组件的模块，Vite 整页刷新主窗口，弹出窗口跟着关（`pagehide`）。不是 bug，测的时候别以为是它自己关的
6. 驱动脚本：主窗口最小化着时 `Page.captureScreenshot` 一直不回来；点会让窗口没了的按钮（×、Ctrl+W）时 `Input.dispatchMouseEvent` 也不回来，要套个超时

## 18. 标签栏底下的「路径 / 标题」（2026-10-29）

**问题。** 只开着一篇时，往下滚到大标题钻进最上面那条，那条里淡进来「📁 文件夹 / 标题」（[仓库与启动器.md](./仓库与启动器.md) §20）。
§5.1 定的是标签栏显示着时不出：那条已经是标签了，当前标签就是标题。结果一开第二个标签、一分屏、一弹出窗口，
这个效果就没了 —— 标签只写着标题，读到一半不知道这一篇在哪个文件夹（悬停提示要停住才出来）。

**做法。** 同一个 `TitleStrip` 多一处 `underTabs`：标签栏显示着时，「路径 / 标题」出在标签栏底下一行。

- 一行 26 高（字那一行 20，上下各 3），从 38 起；和最上面那条一样跟着正文那一列居中（`CenteredColumn`），
  路径的第一个字和正文左缘对齐，不跟标签左对齐 —— 它是这一篇「收起来的大标题」，不是标签栏的一部分
- 什么时候出：大标题整个钻进「标签栏 + 这一行」（64px）底下。在顶上时还是一点不多占，滚下去时顶上是 64 + 16 的渐隐，
  比 §19.2 撤回的那种一直占 80px 少，而且只在读到一半时才占

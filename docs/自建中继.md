# 自建协作中继

> 给想和**不在同一个网络**的人一起编辑的团队。Odea 不提供中继：团队里有一个人照这一篇架一台，把「中继码」发给大家，每人添加一次。
> 设计和实测数字见 [协同编辑.md](./协同编辑.md) §6；这一篇只讲怎么架。

---

## 1. 要不要架

| 情况 | 用不用中继 |
|---|---|
| 同一个 Wi-Fi、办公室、手机热点 | 不用：局域网直接连 |
| 主持人那边有公网 IPv6、或者路由器给了端口映射（分享框的自检里看得到 ✓） | 多半不用：链接里带着能连进来的地址 |
| 一方连不进来、另一方能 | 不用：连不上的那位生成「回连链接」发过去，反过来拨 |
| 两边都在手机网络、公司网络、运营商级 NAT 后面 | **要**：没有第三台机器帮忙，任何软件都连不上 |

分享框里那一行写着「现在只有同一网络里的人能加入」、访客那边说「你们不在同一个网络里」，就是该架中继的时候。

中继做两件事：打洞时当介绍人（告诉双方各自的公网地址），打不通时转发。它转发的是端到端加密过的内容，**看不到也改不了你们写了什么**；它看得到的是双方的 IP、哪两台设备在通信、流量大小和时间。

## 2. 要一台什么样的机器

- **有公网 IP**：云主机、VPS、NAS、家里常开又有公网地址的电脑都行
- **1 核 1G 就够**：本机实测 2 核每秒转发 2000 个包时延迟还在几毫秒（设计 §6.3）。先吃紧的是带宽：选按流量计费、或者带宽 ≥ 10Mbps 的套餐（便宜套餐常只给 1–5Mbps）
- **离用户近**：中继夹在两个人中间，离双方越近越快。团队分布在几个大洲的话，每个大洲放一台小的，比一台大的好；Odea 会自动挑延迟最低的那台

## 3. 端口

| 端口 | 协议 | 做什么 | 不开会怎样 |
|---|---|---|---|
| 443 | TCP | 中继本身（HTTPS / WebSocket） | 用不了 |
| 80 | TCP | 强制门户检测；用 Let's Encrypt 时签证书 | 用 Let's Encrypt 的话签不了证书 |
| 7842 | UDP | QUIC 地址发现（打洞的介绍人） | 转发照样能用，但打洞没人介绍，更多连接只能一直经中继转发 |

云主机记得在控制台的「安全组 / 防火墙」里也放行这几个端口。

## 4. 安装

用官方的 `iroh-relay`（1.x，和 Odea 用的 iroh 1.x 线协议一致），不用装我们写的任何东西。在服务器上：

```bash
# 没有 Rust 的话先装：https://rustup.rs
cargo install iroh-relay --features server --version "^1"
```

## 5. 配置

### 5.1 有域名（推荐）

域名的 A / AAAA 记录指到这台机器，证书由 Let's Encrypt 自动签、自动续。

```toml
# relay.toml —— 改好域名、邮箱和令牌
enable_relay = true
enable_quic_addr_discovery = true        # 默认是关的；打洞要靠它告诉客户端自己的公网地址

# 只让拿着令牌的人用（可以写好几个，换令牌时先加新的、大家都换完再删旧的）
access.shared_token = ["换成一长串随机字符"]

[tls]
cert_mode = "LetsEncrypt"
hostname = "relay.example.com"
contact = "you@example.com"

# 每个客户端 256KB/s：打字绰绰有余，防止有人拿它传大文件
[limits.client.rx]
bytes_per_second = 262144
max_burst_bytes = 1048576
```

令牌可以这样生成：

```bash
openssl rand -base64 32
```

### 5.2 没有域名：自签名证书

用 IP 地址也行，证书自己签，Odea 那边按**证书指纹**认它（只认这一张）。

```bash
# 把 203.0.113.10 换成服务器的公网 IP
openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 -nodes -days 3650 \
  -keyout relay.key -out relay.crt -subj "/CN=203.0.113.10" \
  -addext "subjectAltName=IP:203.0.113.10"
# 证书指纹（SHA-256），添加中继时填它
openssl x509 -in relay.crt -noout -fingerprint -sha256
```

`relay.toml` 里 `[tls]` 那一段换成：

```toml
[tls]
cert_mode = "Manual"
manual_cert_path = "/etc/iroh-relay/relay.crt"
manual_key_path = "/etc/iroh-relay/relay.key"
```

### 5.3 访问控制的其他写法

`access.shared_token` 之外，官方程序还支持（同一时间只能用一种）：

- `access.allowlist = ["<设备公钥>", …]`：只让这几台设备用，固定的小团队最省心。设备公钥在 Odea 的「协作中继…」最底下，点「复制」
- `access.denylist = [...]`：除了这几台都能用
- `access.http`：每个连接问一次你自己的接口

不配 `access` 就是谁都能用 —— 别这样：任何拿到地址的人都能蹭你的流量。

## 6. 跑起来

```bash
iroh-relay --config-path relay.toml
```

常驻的话用 systemd（`/etc/systemd/system/iroh-relay.service`）：

```ini
[Unit]
Description=iroh relay for Odea
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/root/.cargo/bin/iroh-relay --config-path /etc/iroh-relay/relay.toml
WorkingDirectory=/etc/iroh-relay
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now iroh-relay
```

- 中继不存任何东西：挂了重启就行，客户端自动重连；换机器不用迁数据
- 9090 端口有指标（连接数、流量），**别对公网开**
- 想知道这台机器扛得住多少人：仓库里的 `scripts/perf/relay-load` 有压测程序（[协同编辑.md](./协同编辑.md) 附录 A.3）
- Let's Encrypt 的证书存在 `WorkingDirectory` 里（`cert_dir` 可以改），续期自动

## 7. 在 Odea 里添加

架的人自己：命令面板（Ctrl+K）→「协作中继…」→ 填地址（`relay.example.com`，自签名的填 `203.0.113.10`）→ 再填令牌（自签名的还有指纹）→ 添加 →「测试」：

- 「连上了 · 35ms · UDP 7842 通」：好了
- 「UDP 7842 不通」：转发能用，但检查一下 7842/UDP 有没有放行
- 「令牌被拒」：令牌和 `relay.toml` 里的对不上
- 「连不上：…」：看端口、证书（指纹对不对、域名解析对不对）
- 「中继的版本和 Odea 不配套（它只认 …）」：中继和 Odea 不是同一代 iroh（见下面「升级」）。也可能是中继前面放了 nginx 这类反向代理、没把 WebSocket 升级请求转过去 —— 那样的话这里说的是「连不上：… got status code 400」

然后点那一行的「中继码」，复制出来的 `odea://relay/…` 发给团队里的人。他们点开（或者在「协作中继…」里粘贴）以后会被问一句「添加中继 relay.example.com？」，确认就行。中继码里带着令牌，只发给自己人。

之后：

- **主持的人配了中继**：邀请链接里自动带上它（和令牌），被邀请的人不用配也能经它进来；加入前会提示「这次经由 relay.example.com 转发」，访客可以选「只直连」
- **只有访客配了**：访客连不上时生成的回连链接里带着它，主持人经它拨过去
- 令牌会随邀请链接发出去：被邀请的人之后也能用这台中继，靠限速兜着；需要时在 `relay.toml` 里换令牌，再给大家发新的中继码

## 8. 升级

iroh 承诺 1.x 之间线协议不变：中继跟着 1.x 升就行（`cargo install iroh-relay --features server --version "^1" --force`）。Odea 哪天换到 iroh 2，会在更新说明里说，到时中继也得跟着升。版本对不上时 Odea 会直接说「中继的版本和 Odea 不配套」，不会只说连不上。

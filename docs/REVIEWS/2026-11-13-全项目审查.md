- 只做交给你的那一段，做完更新 0.2 的清单、停下。别顺手做下一段
- 确认一条、写一条：发现一经确认就写进 §4（或 §5、§6），看过什么写进 §3。不要攒在脑子里

- 读代码：先 `Grep` 定位，再用 `Read` 的 `offset` / `limit` 读那一段；整篇读只限几百行以内的文件。
  `TODO.md`、`技术方案.md`、上一份审查记录、`语法全览.md` 一律不整篇读，按标题找到那一节再读

- 命令的输出截短：`pnpm test`、`cargo test`、构建只看末尾的汇总和失败的那几条（`| tail -n 30`）；
  性能脚本的结果写到系统临时目录的文件里，只读汇总
- 浏览器：先用 `find`、带 `ref_id` / `depth` 的 `read_page`、返回一小段 JSON 的 `javascript_tool`（DOM 测量）；
  截图只在要留证据、或者文字工具判断不了的时候截，带 `scale`（0.4 左右）或者用 `zoom` 只截那一块。
  不对整个应用 `get_page_text`、不读整棵无障碍树
- `git diff` 只看具体的文件，别反复打整份 diff
- 不再往下开子代理
- Browser 面板藏着时（`tabs_context` 会说 hidden）页面是后台页：发完按键先在 `javascript_tool` 里等几帧再量，
  动效和焦点先后的结论不算数（`PITFALLS/环境.md` 最后一节）

### 4.1 【缺陷·崩溃】属性值里有六个以上的汉字，取属性一览时整个应用退出

- **位置**：`src-tauri/src/vault/properties.rs` 的 `kind_of_value`（修之前 160–163 行）
- **怎么触发**：仓库里任何一篇没归档的笔记，属性块里有一条不是纯 ASCII、又有 16 个字节以上的值
  （`摘要: 这是一篇关于发版的笔记`，六个汉字就够）。鼠标移到属性面板上、焦点进去、点「添加属性」、按 Ctrl+;
  都会取属性一览（`vault_property_catalog` → `catalog` → `kind_of_value`）
- **根因**：判断「是不是日期时间」时按字节切片 `&value[..10]`、`&value[11..16]`。第 10、16 个字节落在一个汉字中间，
  Rust 直接 panic。release 是 `panic = "abort"`（`Cargo.toml`），不是这一条命令失败，是进程没了
- **证据**：新加的测试 `long_values_that_are_not_ascii_are_just_text`，修之前：
  `panicked at src\vault\properties.rs:161:23: end byte index 10 is not a char boundary; it is inside '篇' (bytes 9..12 of string)`
- **修**：换成 `value.get(..10)`、`value.as_bytes().get(10)`、`value.get(11..16)`，切不到整字就不是日期时间
- **验**：上面那条测试过（另含 `2026-11-20 下午三点开会`、全角数字 `2026-11-2０ 15:30`、经 `catalog` 走一遍）
- **为什么以前没撞上**：原有的测试 `values_have_kinds` 里最长的中文值是「进行中」（9 个字节），不到 16

### 4.2 【缺陷·数据】属性面板会写下自己读不回来的属性块，属性变成正文开头的几行字

- **位置**：`src-tauri/src/vault/properties.rs` 的 `set_doc_properties`
- **怎么触发**（两条路）：
  1. 今日TODO、目标（没有标题的那种，属性块里没有应用的键）里加一条中文名字的属性：Ctrl+; → `截止` → 回车
  2. 任何一篇里属性块超过 58 行（比如一行一条的标签加到五十多条）
- **根因**：属性块是照 `frontmatter.rs::find_block` 认的 —— 60 行以内收尾、中间至少一行**英文字母或下划线开头**的键。
  写的时候不查这两条。写下去以后整块认不出来，被当成正文：编辑器里开头多出 `---`、`截止: 2026-11-20`、`---` 三行，
  属性面板空了；第 2 条路还连带丢了置顶（`pinned` 也在那一块里）
- **证据**（探针测试的输出，修之前）：
  ```
  (a) set => Ok(DocProperties { text: "", editable: true })
  (a) file => "---\n截止: 2026-11-20\n---\n\n- [ ] 买菜"
  (a) day body => "---\n截止: 2026-11-20\n---\n\n- [ ] 买菜"
  (c) set => Ok(0)          ← 70 条标签，写成功了，读回来属性是空的
  (c) body starts => "---\nid: 01a1d47c-…\ncreated: 2026-1"
  ```
- **修**：写之前把要写的内容再认一遍（`frontmatter::split(render(..))`），属性那几行、正文有一样对不上就不写，
  说为什么（「属性太多了：属性块最多 58 行……」「属性名都不是英文字母开头的……先加一条英文名字的」）。
  笔记不受第 1 条影响：属性块里总有 `id`、`created`
- **验**：`properties_that_would_not_read_back_are_not_written`（某一天只有中文键被拒、文件没动；加一条英文键就行；
  笔记的中文键照常；70 行被拒、56 行正好到上限能写、正文都没动）
- **第二条路**（接着查出来的）：起了标题的那一天，属性块里有 `title:`，只有中文名字的属性写下去是认得出来的 ——
  直到标题被清空（`save_typed` 把 `title:` 那一行拿掉）、或者这一篇被另存成冲突副本（副本不带标题），
  剩下的又认不出来了。存正文的那条路不能拒绝，所以在加属性的地方先拦住：某一天、目标的属性那几行得自己认得出来
  （至少一条英文名字的），不指望 `title:`。同一条测试里加了这一段（起了标题的那一天只有中文名字的被拒；
  加上英文名字的、再清空标题，属性和正文都还在）
- **代码里对应的名字**（2026-11-14 接手时对过一遍，正文和代码一致）：行数上限是 `MAX_BLOCK_LINES`（58）；
  「属性那几行自己认不认得出来」是 `recognisable(extra)`（空的算认得出，否则至少一行过 `frontmatter::is_yaml_key` ——
  为这个把它从私有改成了 `pub(super)`，这是 `frontmatter.rs` 唯一的改动）；提示语是 `NEEDS_ASCII_KEY`；
  `set_doc_properties` 里先后两道：不是笔记的先查 `recognisable`（第二条路），再把 `render` 的结果 `split` 回来比
  属性那几行和正文（第一条路），对不上时 `unreadable_block` 挑一句原因（太多行 / 没有英文名字的 / 其它）
- **没解决的那一半**：只有中文名字的属性块认不出来，这条规矩本身要不要改，见 §6.1。别的工具手写的
  「`title:` 加只有中文名字的属性」的某一天，清空标题时照旧会坏，没有拦的地方

### 4.4 【缺陷】属性面板里按 Esc 不是「不改了」，是把打了一半的字存下去

- **位置**：`src/properties/PropertiesPanel.tsx` 的 `TextValue`、`ListValue`（修之前 764–767、887–890 行）
- **怎么触发**：点进一条属性的值，打几个字，按 Esc。标签那种列表：在「加一项」里打几个字，按 Esc
- **根因**：Esc 的处理是 `setDraft(原来的值)` 再 `blur()`。`blur()` 当场触发 `onBlur`，那时这次渲染里的 `draft`
  还是打的字（`setDraft` 要到下一次渲染才生效），`onBlur` 就把它存了
- **证据**（浏览器预览，真的按键，修之前）：Ctrl+; → `status` → 回车 → 打 `draft-one` → Esc，
  `localStorage` 里是 `"status: draft-one"`；标签里打 `abc` → Esc，成了 `tags:\n  - abc`
- **修**：按 Esc 时记一笔（`cancelled`），失焦的那一下看到这一笔就不存、把框里的字改回去。键名、日期、
  「添加属性」那一行原来靠「输入框被卸掉时不触发 blur」正好是对的，现在走同一条路
- **验**：`PropertiesPanel.dom.test.tsx`（`Esc leaves a value as it was, Enter saves it`、
  `Esc does not add the half-typed list item`）；浏览器预览里重走：值里打 `XX` 按 Esc，存的还是 `draft-one`；
  新加的 `prio` 打 `high` 按 Esc，存的是空的 `prio:`

### 4.5 【体验】属性面板里用完键盘，焦点落在 body 上

- **怎么触发**：在正文里按 Ctrl+; 加一条属性，填完值回车（或者中途按 Esc）

### 4.6 【体验】值正好是某条提示的一截时，用键盘存不下来；「添加属性」打了已有的名字，光标哪也没去

- **位置**：`PropertiesPanel.tsx` 的 `useSuggestions`、`AddRow`
- **怎么触发**：
  1. 别的笔记里 `status` 写过「进行中」，这一篇想写「进行」：打完回车，存下的是「进行中」（提示列表的第一条一直是选中的，

### 4.7 【风险 → 修了】连着改两条属性，前一次写回来的结果把界面换回旧的

- **位置**：`PropertiesPanel.tsx` 的 `commit`、`refetch`
- **怎么推出来的**：写回是排着队一次次写的，界面先改（乐观更新）。第一次写完时 `setDoc(saved)` 不管后面还排没排着：
  第二次还没写完，界面就被换回只有第一处改动的那一版，等第二次写完才对回来。自己那次写引出的 vault-changed
  → 重取，也会在中间插进来一版旧的。窗口期是一次 IPC 加一次落盘（`write_atomic` 要 `sync_all`），慢盘上几十毫秒
- **证据**：测试里把两次写回的先后控制住，修之前 `an earlier write coming back does not put the older text on screen` 失败
  （第一次回来以后值变回「草稿」）。真人手速下没在浏览器里看到过
- **修**：记「排到第几次、写完到第几次」。后面还排着的时候，前一次的结果、半路重取到的都不拿来换界面；
  写失败时退回磁盘上的那一版（重取一次），不是退回这次改之前界面上的那一版

### 4.9 【缺陷·安全】静态渲染器：块级 HTML 里的图片地址能把净化过的属性变成 `onerror`

- **位置**：`src/render/staticHtml.ts` 的 `htmlBlock`（修之前 618–621 行）。导出 HTML / PDF 和 `![[笔记]]` 的嵌入卡片都用它
- **怎么触发**：正文里一块 HTML：
  ```html
  <div><abbr title="onerror=alert(1) ">x</abbr><img src="https://e.com/a$`"></div>
  ```
- **根因**：块级 HTML 先净化成 DOM、`<img>` 的 `src` 换成记号 `@@IMG0@@`，序列化以后再用
  `html.replace("@@IMG0@@", 地址)` 换回来。`String.replace` 的第二个参数是字符串时，里面的 `` $` ``、`$'`、`$&`
  有特殊含义（记号前面的那一段、后面的那一段、记号本身）。地址里写 `` $` ``，记号前面那一段 HTML 就整个进了 `src` 的引号里；
  那一段里别的属性（`title` 的值不限）的引号把 `src` 提前收尾，`title` 里的字成了 `<img>` 自己的属性
- **证据**（探针测试的输出，修之前）：
  ```
  html: <div class="html-block"><div><abbr title="onerror=alert(1) ">x</abbr><img src="https://e.com/a<div><abbr title="onerror=alert(1) ">x</abbr><img src="" decoding="async"></div></div>
  withHandlers: [ "IMG.onerror=alert(1)" ]
  ```
- **能造成什么**：
  - 导出成网页的那个文件以前不带 CSP：在浏览器里打开就执行。笔记可能是别人的（团队仓库、协作、下载来的 .md）
  - 应用里的嵌入卡片、打印用的那一页有 CSP（`script-src 'self'`、`default-src 'none'`）挡着，内联的事件属性跑不了 ——
    第二层接住了，第一层是破的。浏览器预览（开发服务器）没有 CSP
- **修**：
  - 换记号时给函数、不给字符串；记号带上这一次渲染的随机数（正文里写 `@@IMG0@@` 也只是字）
  - 存成网页的也带上和打印那一页一样的 CSP（`default-src 'none'; img-src data: https: http:; style-src 'unsafe-inline';
    font-src data:`）：导出的页面里本来就只有字、样式和图
- **验**：`staticHtml.dom.test.ts` 的 `puts an image address into an HTML block as plain text, whatever it contains`
  （修之前失败：`expected [ Attr{…} ] to deeply equal []`）。原有的那条 XSS 测试只按字符串找 `onerror`，这种情况下
  `title` 里合法地有这几个字，新的一条把输出解析成 DOM、查有没有 `on*` 属性

### 4.10 【缺陷·安全】页眉页脚的 `{标题}` 里写 `</style>` 能在导出的页面里插标签

- **位置**：`src/export/pageSetup.ts` 的 `cssString`
- **怎么触发**：页面设置里页眉或页脚写了 `{标题}`（不是默认，是给的选项之一），导出一篇标题里有 `</style>` 的笔记

### 4.11 【缺陷】点块级 HTML 里的链接，整个窗口跳到那个网址去

- **位置**：`src/editor/widgets.ts` 的 `HtmlBlockWidget`（修之前 1215–1223 行）
- **怎么触发**：正文里一块 HTML，里面有链接，比如 README 里常见的
  `<div align="center"><a href="https://example.com">…</a></div>`。光标不在这一块上时点那个链接
- **根因**：这里的 `<a href>` 是净化后重建的真链接。点它的处理写在 `mousedown` 里：`preventDefault()`、用系统浏览器打开。
  但 `mousedown` 的 `preventDefault` 拦不住随后那一下 `click` 的默认动作 —— 链接照样被点了，页面自己跳走。
  结果是系统浏览器开了一次，应用的窗口也跳到了那个网址；Rust 那边没有 `on_navigation` 拦主框架的跳转
  （`on_new_window` 只管新窗口）
- **证据**（浏览器预览，真的鼠标点击；在 `window` 上记下冒泡到头的 `click` 有没有被拦，记完自己拦掉免得真跳走）：
  修之前 `{ href: "https://example.com/odea-review-probe", preventedByApp: false }`，`window.open` 被调了一次
- **修**：`mousedown` 只管不切回源码；打开挪到 `click` 里，那里 `preventDefault`。链接聚焦时按回车也是一次 click，一样走这里
- **验**：`markdownAdvanced.dom.test.ts` 的 `opens a link in an html block outside the app instead of letting the window navigate`；
  浏览器预览里重点一次：`preventedByApp: true`、`window.open` 一次、这一块没切回源码
- **顺手**：嵌入卡片（`editor/embed.ts`）里的链接本来就在 `click` 里拦了，但按着 Ctrl 点时先返回了、没拦。
  实测按着 Ctrl 点会先在 `mousedown` 里打开嵌的那一篇、卡片跟着换掉，那一下 click 落不到链接上；Ctrl+Shift（开在新标签）
  时卡片还在。把「是链接就拦」挪到判断修饰键之前
- **没验的**：桌面端（WebView2）里没点过；HTML 表格格子里的 `<a href>` 实测点了是进格子编辑、不跳走（没有打开它的办法，
  Ctrl+点只认 `data-href`，见 §7）
- **建议的第二层**：见 §6.3

### 4.21 【缺陷·数据】仓库文件夹一时打不开（移动硬盘拔了、网络盘断了），扫一遍就把索引清空，回来以后外来的笔记都换了 id

- **位置**：`src-tauri/src/vault/mod.rs` 的 `plan_rescan`；根子在 `fsio::walk`：哪个目录 `read_dir` 失败就当它是空的

  `walk` 一篇都没找到 → 「先删消失的」把索引里每一篇都 `forget`，发给前端「这些都变了」，列表空了。盘回来以后再扫一遍：
  应用写过的笔记 id 在属性块里，还是原来的；**不是应用写的**（从 Obsidian 搬来的、别的工具建的，id 只在索引里）全部换了新 id ——
  开着的标签、最近打开、按 id 记的东西都对不上。拔的是移动硬盘时监听本身也死了，盘插回来不重启就一直是空列表
- **证据**：探针测试（仓库目录改名挪走再挪回来，模拟拔掉）：挪走时 `rescan_and_announce` 返回 `Ok`、`note_list` 0 篇、发了一次 2 篇的变化；
  挪回来以后「外来」那篇 `id == 原来的` 是 false
- **修**：`plan_rescan` 先 `read_dir` 仓库根，打不开就报错（`仓库文件夹现在打不开: …`），索引一行不动、什么都不发。
  子目录打不开的没管：那多半是真的被删、被挪了，或者一直没权限，照旧
- **验**：`a_vault_folder_that_is_gone_for_a_while_keeps_its_index`（挪走时报错、索引里还是 2 篇、没发通知；挪回来两篇的 id 都是原来的）。
  真的拔一次移动硬盘没试
- **补**（第二个 B 会话）：上面只堵了整扫。探针：仓库挪走以后 `rescan_paths_and_announce(["笔记/外来.md"])` 返回 `Ok`、索引剩 0 篇，
  挪回来「外来」换了 id；后台读（`index_backlog` → `index_file`）同样把它 `forget` 了。文件监听这一批只有几篇 .md（盘断的时候网盘正在写）、
  启动后台还没读完时盘没了，都走得到。改成一个 `check_root`：整扫、只重读几篇的开头，`index_file` 要因为「文件不在」forget 之前，都先问一句，
  打不开就报错、不动索引。回归测试同一条，加上了这两条路（挪走时两条都不删、挪回来「外来」是外面改过的那一版）

### 4.22 【缺陷】别的程序正占着一个文件，文件监听这一批整个作废：后面的文件进不了索引，已经认出的删除不通知前端

- **位置**：`src-tauri/src/vault/mod.rs` 的 `rescan`、`rescan_paths_and_announce`（读文件那一句是 `?`）
- **怎么触发**：Windows 上网盘客户端、杀毒、别的编辑器不共享地打开着仓库里的一个 `.md`（`os error 32`）。文件监听的这一批里有它：
  - 只重读几篇的那条路：在它这里返回错误，排在它后面的文件不读；前面已经从索引里删掉的那几篇（外面删了的）`forget` 了却没 `announce`，前端还列着
  - 整个扫一遍的那条路：只要它还被占着，**每一次**整扫都在它这里失败，按路径排在它后面的新文件一直进不了索引
  - 同步合并完调的 `absorb_merge` 最后也是整扫：失败了这一轮报错，「另存为冲突副本」的提示发不出去（副本已经写在盘上了）
- **证据**：探针测试（`share_mode(0)` 打开 `乙.md` 不放）：`rescan_paths_and_announce` 返回 `Io("另一个程序正在使用此文件…(os error 32)")`、

- **修**：扫描时读文件改成 `read_for_index`：读不了的记一笔、跳过，这一个在索引里还是旧的（修改时间、大小对不上），下次扫描再读；
  别的照常读、照常通知。和后台分批建索引（`index_backlog`）本来的做法一致
- **验**：`a_file_another_program_holds_does_not_stop_the_rest_of_the_scan`（Windows 上 `share_mode(0)`；Unix 上去掉读权限，用 root 跑读得了就不测）：
  只重读几篇、整扫都不报错，「甲」进了索引、「要删的」通知了前端；放开以后再扫，「乙」也进来了。
  还留着的：放开以后要等下一个文件事件或者整扫才补读，监听不会自己回头再试（见 §5.4）

### 4.23 【缺陷·数据】名字长的笔记：Linux 上 80 个汉字的标题存不进去；冲突副本另存失败，同步合并时对方那一版只剩在历史里

- **位置**：`src-tauri/src/vault/fsio.rs` 的 `write_atomic_bytes`（临时文件叫 `.{原名}.{pid}-{n}.tmp`）；`vault/mod.rs` 的
  `write_conflict_copy`、`conflict_copy_rel`、`legacy_backup_rel`（原名后面接「 (冲突 …)」「 (GBK 原文)」）
- **怎么触发**：文件名的上限是 255（ext4 按 UTF-8 字节，NTFS、APFS 按字符）。应用起文件名时卡的是 80 个字（`MAX_STEM_CHARS`），
  80 个汉字 + `.md` 是 243 字节，在 ext4 上放得下；可临时文件的名字比原名多 13–16 字节，**新建、保存、改名都过不了临时文件那一步**。
  标题 80 个汉字以上（截到 80）的笔记在 Linux 上新建不了、存不进去。Windows 上要原名本来就有 240 个字左右（别的工具建的）。
  冲突副本另接 22 个字（UTF-8 25 字节），门槛更低：
  - 保存：磁盘上那一版不是编辑器照着改的（`keep_unseen_edits`）→ 另存冲突副本失败 → `note_save` 报错，这一篇一直存不进去
  - 同步合并：两边都改了这一篇 → 合并提交已经做了（原处留本机的）→ `absorb_merge` 另存对方那一版失败、整个返回错误，
    同一批排在后面的冲突也不另存了，对方的那几版只剩在 git 历史里，状态是「同步出错」
- **证据**：探针（Windows，原名 230 个「长」）：`absorb_merge` 返回 `Io("文件名、目录名或卷标语法不正确。 (os error 123)")`，
  仓库里只有两个原文件、一份副本都没有（排在后面的「短.md」也没另存）；`note_save` 同样报错。原名 240 个 `a` 时连
  `write_atomic` 本身都失败（临时文件 259 个字符）。Linux 上 80 个汉字那一条是按字节数算出来的，这台机器上没法建 ext4，没实测
- **修**：`fsio::fit_stem(原名, 后面要接的字节数)`：接上以后超过 255 字节就从原名后面按整字截。临时文件、冲突副本、GBK 原文的备份
  三处起名都过它。截过的副本名字里认不出原文（`conflict_of` 按名字找不到），但另存下来了、正文是全的
- **验**：`fsio::tests::a_name_close_to_the_limit_can_still_be_written`（250 字节的名字写得进去、不留临时文件）、
  `a_stem_is_cut_by_whole_characters_to_leave_room_for_what_follows`、`vault::tests::a_conflict_copy_of_a_long_named_note_still_gets_written`
  （240 个 `a` 的原名：同步合并两份副本都另存下来、外面改过以后照样存得进去、每个文件名 ≤ 255 字节）。把修复拿掉（`git stash` 那两个文件）
  这条测试在建文件那一步就失败

### 4.25 【缺陷·安全】Windows 上路径里的一段 `D:` 过得了校验，拼出来落在仓库外面：协作的访客能在主持人的 D 盘上建文件

- **位置**：`src-tauri/src/vault/layout.rs` 的 `folder_dir`、`clean_dir`；`vault/mod.rs` 的 `tree_file_path`、`note_undelete`（`trashed-from` 不查）、
  `absorb_merge`；根子在 `fsio::abs` 逐段 `PathBuf::push` —— Windows 上 push 一个带盘符的段（`D:`）会把前面的整条路径换掉
- **怎么触发**：校验只挡了空段、以点开头（含 `..`）、反斜杠，`D:` 是个合法的「段」。
  - 协作：访客（有编辑权限）在范围里新建一篇，交给主持人的文件夹是原样转给前端的（`collab/store.ts::answerCreate` 只去两头的斜杠，
    文件夹范围的会话拼成「范围/访客给的」），前端调 `note_create(folder)` → `existing_folder_dir("D:")` 认为在（`D:` 是 D 盘的当前目录，
    没设过就是 D 盘根）→ 笔记写在 `D:\` 下；再用 `ATTACH_PUT` 往这一篇的附件位置交文件，扩展名照访客给的（`.exe`、`.bat` 都行），
    附件文件夹不在会自己建 —— 访客能往主持人别的盘上任意一个文件夹里放可执行文件。只读的访客建不了（host.rs 先挡了）
  - 同步、网盘带过来的配置和文件：`.obsidian/app.json` 的 `attachmentFolderPath`、`.odea/vault.json` 的 `folders.*`（都走 `clean_dir`）写 `D:/…`，
    附件、新笔记就写到仓库外面；归档的 `archived-from` 写 `笔记/D:`，恢复时整篇挪出去。回收站文件里的 `trashed-from` 连 `..` 都没挡，

### 4.30 【缺陷】几个仓库同时续 GitHub 令牌：后到的那个被当成「登录失效」

- **位置**：`src-tauri/src/sync/account.rs` 的 `access_token`
- **怎么触发**：GitHub 的令牌 8 小时过期，到期前 10 分钟内或者推拉被拒时，用刷新令牌换一对新的。GitHub 的规矩是刷新令牌用一次就作废、
  旧的访问令牌也跟着作废（官方文档 Refreshing user access tokens：用过的刷新令牌和旧的访问令牌都不再能用；Odea 用的是开了令牌过期的 OAuth App，走同一个接口）。
  `access_token` 读钥匙串 → 换 → 存，没有任何互斥：开着两个都同步到 GitHub 的仓库（或者一个仓库窗口加团队成员面板的 `with_token`），
  隔夜再打开应用，几个窗口一起恢复、令牌都过期了，各自的第一轮同步同时拿同一个刷新令牌去换 —— 先到的成了，后到的收到 `bad_refresh_token`，
  `refresh_result` 把它当成 `SyncError::Auth`，那个窗口的同步状态变成「需要重新登录」，要等下一轮（`PULL_EVERY`）读到别人换来的才自己好；用户多半已经去点了重新登录
- **证据**：探针测试（照 GitHub 的规矩写的假刷新：给的不是当前那一个刷新令牌就回 `Auth`，中间睡 100 毫秒当网络），两个线程同时续：`[Ok("ghu_1"), Err(Auth)]`
- **修**：续期拿一把进程里的锁；拿到锁以后重读钥匙串，等锁期间别人已经换好了（访问令牌变了、没快过期）就直接用他的。换的那一步抽成 `access_token_with`，测试里能换掉联网的那一步
- **验**：回归测试 `sync::account::tests::two_syncs_finding_the_token_expired_at_once_refresh_it_once`（两个都拿到 `ghu_1`，只换了一次，钥匙串里是新的刷新令牌）；`sync::` 52 条全过。
  真 GitHub 上没试（要等令牌过期，还要两个同步到 GitHub 的仓库）

### 4.32 【缺陷】存盘还在路上时把刚打的字删了（或者撤销了），存盘一回来删掉的字又回来，光标跳走（C 段）

- **位置**：`src/editor/MarkdownEditor.tsx` 回填外部正文的那个 effect（`initialMarkdown` 变了的时候）
- **怎么触发**：打一个字，停 400ms 自动存盘发出去；存盘回来之前按退格（或 Ctrl+Z）。store 换成刚存的那一版，`initialMarkdown` 跟着变；
  编辑器判断「本地有没有没同步的编辑」只比 `现在的正文 !== 上次对上的那一版`，而删掉以后正文正好又等于上次对上的那一版，
  于是把回音当成别处来的新正文整篇换上：删掉的字回来、光标跳走。随后存的是删过的那一版，400ms 后回音再把它换回去；
  这 400ms 里接着打字的话，存下的是「复活的字 + 新打的」，删掉的那个字就永远回来了。窗口是一次存盘的来回（IPC + 写文件 + 改索引），
  后端忙（建索引、同步）时更长
- **证据**：探针（happy-dom，真的 `MarkdownEditor`）：`A` 打 `x`、存盘挂起、删 `x`、放行并把 `initialMarkdown` 换成 `Ax`，
  编辑器里是 `"Ax"`（应为 `"A"`）
- **修**：编辑器记下自己交给 `onSave` 的每一版（`unconfirmedSaves`，一个编辑器一份，最多 16 版）；`initialMarkdown` 换成其中一版、
  又不是外部改动时，是自己的回音：只记「和 store 对上了」，正文不动（编辑器里的总比它交出去的新）。同一篇开在两个窗格里时，
  一边交出去的也记进另一边的，后挂上的抄一份先挂着的；编辑器拆了跟着没了（重新挂上的是照 store 建的，那时到的回音照旧换上）。
  外部改动（`externalRevision` 变了）不认回音，正好等于以前存过的那一版也照样换上
- **验**：回归测试 `editor/saveEcho.dom.test.tsx`（删了的不回来、别处的改动照样换上、外部改动正好是旧版也换上、另一个窗格也认得回音）；

### 4.38 【缺陷·数据】冲突副本「用这一版替换原文」：副本上最后几个字没带过去；点「撤销」只回来副本，原文被替换前的那一版找不回来（C 段）

- **位置**：`src/data/store.ts` 的 `resolveConflict`（`ConflictBanner.tsx` 的「替换」「删掉这份副本」都走它）
- **怎么回事**：
  1. 不先 `flushAllEditors`（恢复历史版本、换新版指南、挪笔记、换摆法都先存）。横幅就在副本的标题上方，用户常常是在副本里手动并一两句、
     再点「替换」：编辑器 400ms 的防抖还没到（或者那次存盘还在路上），取到的是副本上一次存的那一版；接着副本进回收站，
     编辑器晚到的那次保存找不到这篇（`saveDocument` 的 `source` 为空，返回「没加载」），那几个字两头都没有。原文开在另一个窗格、小窗里刚打的字同理
  2. 替换完提示条是删除的那条「已删除「笔记 (冲突 …)」 撤销」：撤销只把副本从回收站拿回来，原文已经是副本的内容，
     横幅随即说「两版内容一模一样，可以直接删掉」。没开同步的仓库没有历史版本，原文替换前的那一版就没了 —— 撤销只撤了一半，
     撤的还是不要紧的那一半
  3. 小的：副本在归档里时走另一条路直接 `noteDelete`，不记 `lastDeleted`，删了没有撤销（注释说「deleteNote 只管笔记列表」，早就不是了）
- **证据**：探针测试（`store.dom.test.ts`，注册一个编辑器的 flush，里面存「另一台的，又改了一句」）：`noteSave` 只被调了一次 `["n-1","另一台的"]`，
  flush 没被调；提示条是 `lastDeleted = copy`、`undoable` 为空；`undoDelete` 以后原文的正文还是「另一台的」，「本机的」没了
- **修**：先 `flushAllEditors`；删副本一律走 `deleteNote`（归档里的也有撤销）；真的替换了原文时，提示条换成「已用冲突副本替换了「原文」」，
  撤销是整个撤：先存编辑器、原文写回替换前的那一版（当成一次外部改动，开着的编辑器换上）、副本从回收站拿回来、回到副本那一篇
- **验**：见 §3.5 第四个 C 会话那几行

## 5. 风险（读代码推出来、没复现的）

### 5.1 录音、视频正放着，往下滚远了就停（**修了**，2026-11-15 随 §6.5，见 `技术方案.md` §11.4.6）

`![[录音.m4a]]` 的卡片是编辑器里的一个替身。CodeMirror 只画视口附近（上下各约 1000px）的内容，卡片滚出去 DOM 就拆了；
媒体元素从文档里拿掉，内核把它暂停；滚回来是一张新卡片，从头。「一边听录音一边在下面记」正是这个功能的用法。
两样各自量到了：浏览器预览里光标停在文末时，2540px 以上的那张卡片不在 DOM 里；一个正在放的 `<audio>` `remove()` 以后
`paused` 从 false 变成 true。合起来的那一步（真的放着一段录音往下滚）没走：预览里没有音频文件，桌面端没起。
**怎样复现**：桌面端一篇长文开头放 `![[录音.m4a]]`，点播放，滚到两屏以外。怎么修要定，见 §6.5

### 5.2 页眉页脚里的 `{标题}` 很长时折成几行

`export/pageSetup.ts` 的页边框盒子（`@top-left` 这些）没限行数。标题五十多个汉字（A4、标准页边距、9pt 一行放得下的上限）
以上会折行，再长会从页边距那一条里溢出来压到正文。默认没有页眉；要自己在页眉里写了 `{标题}`、标题又很长才会遇到。
**怎样复现**：页眉填 `{标题}`，导出一篇标题 100 个字的笔记成 PDF。没试（页边框盒子里 `text-overflow` 管不管用要在
PrintToPdf 里实测，这一段没起桌面端）

### 5.3 小的，记一笔

  两次写文件的先后也没有保证。一次 IPC 加一次写文件是一毫秒上下，人手点不出来，没处理

  （`TODO.md` 导出那一条的「没做」里已经写了没量过）
- 属性面板里给一条文字属性填 `2026-11-20`，存下的是带引号的 `due: "2026-11-20"`（当文字存的），面板随后按值把它认成日期；
  之后经日期选择器改会不会变成不带引号的没看。文件两种写法都读得回来，没深究
- 旧库搬家（B 段）：`plugins/journal/legacy.rs::import` 里一天的 `date` 不合法时 `day_path(&date)?` 让整个搬家失败（目标那一段是跳过的），
  搬家失败仓库不打开、下次启动重来、又失败。旧版写入时校验过日期，「理论上不会有」，没改

### 5.4 被占着跳过的文件，放开以后不会自己补读（B 段）

§4.22 修完，读不了的那一篇跳过、下次扫描再读。可「下次」要等下一个文件事件（或者重启）：别的程序存完、放开文件时多半还会发一次修改事件，
那样就补上了；只是打开着不改（有的同步客户端会长时间不共享地占着）放开时没有事件，这一篇的外部改动就一直进不了索引，
列表、搜索里是旧的，打开它拿到的也是旧的（`note_get` 给的是索引里的正文）；在旧的上面改了再存，
版本对不上，磁盘上那一版另存成冲突副本（`keep_unseen_edits`），不丢字，但多一份副本。
**怎样复现**：外面改一篇、马上用不共享的方式占住它几秒再放开，看那一篇在列表里的摘要。要修就在 `watch.rs` 里把这一批读失败的路径留到下一批再试（定时器），没做

### 5.5 同步合并：先提交合并，后另存对方那一版（B 段）

`sync/engine.rs::try_round` 在仓库锁里依次 `merge_fetched`（合并提交已经做了，原处留本机的）→ `absorb_merge`（把对方那一版另存成冲突副本）。
另存那一步只要失败（盘满了、没权限；§4.23 修掉了确定会失败的「名字太长」），这一轮报错，对方那几版不在工作区里，
下一轮合并已经做过、不会再冲突 —— 只剩在 git 历史里（「历史版本」里应该翻得到，没核实），用户看到的是「同步出错」，不知道有一版没另存。
**怎样复现**：两台设备改同一篇，合并前把那个文件夹设成只读，看另存和提示。要修得把「另存」挪到合并提交之前、或者失败时
回退合并提交，动的是同步的流程，没做

### 5.6 经人转来的访客，同时要的附件不限个数（B 段）

`collab/host.rs::forwarded_stream` 的 `ForwardStream::Attach` 每条流 `let open = AtomicU32::new(0)` 一个新计数器，交给 `serve_attachment_counted`，
`ATTACH_STREAMS` 的上限对它永远不触发；直连的访客是一条连接一个计数器。每条附件帧最多 50 MB 多一点、要读完才处理，
一位经人转的有编辑权限的访客同时开几十条 `ATTACH_PUT`（直连的最多 8 条），主持人这边就要先收下几 GB。要有恶意的成员，也受 QUIC 每条连接的并发流数限制。
**怎样复现**：三台设备 A 主持、B 转、C 经 B 同时发 100 条 50 MB 的 `ATTACH_PUT`，看 A 的内存。要修就把计数器按成员号放进 `State`，没做

### 5.7 主持人组字时攒着远端改动，编辑器正好被拆掉：存下去的是缺了那几个字的一版（C 段）

`collab/binding.ts`：组字期间碰到组字那一行（Markdown 里一整段就是一行）的远端改动先攒在 `deferred`，会话的正文里有、编辑器里还没有，
组字结束才派发。编辑器在这之前被拆掉（关窗口、Ctrl+W 这类不经失焦的换篇），`destroy` 只是丢掉 `deferred`；可主持人的编辑器自己也存盘
（`DocumentView` 的 `onSave`，和 `watchHosted` 存会话的正文是两条路），卸下时 `flushQuietly` 存的是编辑器的那一版。`watchHosted` 400ms
的防抖要是已经存过，磁盘上就是缺了对方那几个字的一版；之后会话结束不再存，下次「继续协作」时这段差别会被当成外部删掉的字合进来。
窗口很窄：要在 compositionend 和最后一次组字改动读进来之间（通常是同一个微任务）拆掉编辑器，鼠标点别处都先失焦、先放行了。
**怎样复现**：`binding.dom.test.ts` 的组字辅助：A 在一行里组字、B 在同一行打字（A 那边进了 `deferred`），超过 400ms 后直接 `view.destroy()`，
看 A 的编辑器最后交给 `onSave` 的那一版。要修，协作中主持人的编辑器不该再存一份（存盘只走 `watchHosted`），动的是两条存盘路线，没做

**2026-11-15 复现、修了（丁包）**：`collab/editorEdges.dom.test.tsx`「主持人组字时攒着对方的字、编辑器正好被拆掉」—— 真的 `MarkdownEditor` 挂着会话，组字时对方在同一行打了「【」，

又攒着别人的字的那种没处理（解绑那一下派发会打断输入法），写进了 `协同编辑.md` §27.5

### 5.8 历史版本的「恢复」不认协作：团队里别人主持的那篇，恢复写进了自己的磁盘、正文不动、提示却说恢复了（C 段）

`HistoryDialog` → `data/store.ts::restoreVersion`：先 `flushAllEditors`，`saveDocument(旧版)`，再把 `externalRevisions` 加一当外部改动。
自己主持（邀请协作的 `watchHosted`、团队的 `startHosting`）时外部改动会合进会话，没问题。可团队仓库里**别人主持**这一篇时：
编辑器在会话里不认外部回填（`MarkdownEditor` 的约定：外部改动由主持人合进会话），这台的 controller 只在主持时盯外部改动 ——
于是旧版只写进了这台的磁盘（违反「只有主持人写盘」），编辑器、会话、别的成员都不变，提示条却是「已恢复到 … 的版本」。
等 git 下一轮同步，这台磁盘上的旧版作为本机的改动提交、和主持人推上去的三方合，可能把别人后来的改动合没一部分、或者出冲突副本。
另外「撤销」是整篇换回恢复之前的那一版：恢复以后接着打的字，点撤销会一起没了（提示条还在的那几秒里）。
**怎样复现**：`team/store.dom.test.ts`「别人在主持这一篇」那一套，绑上以后调真的 `useData.getState().restoreVersion(noteRef("n1"), "旧版", "…")`，
看对面的磁盘、会话的正文、这边的 `saveDocument`。要修得定恢复在协作里怎么走（把差别当成本地的一次改动写进会话；或者别人主持时不给恢复、说一声），
算产品行为，没做

**2026-11-15 复现、修了（丁包，§6.0 定的：写进会话）**：`team/store.dom.test.ts`「别人在主持这一篇：历史版本「恢复」写进会话」，修之前
`saved` 是旧版、会话没动、提示「已恢复到 昨天 的版本」。现在 `restoreVersion` 先问 `team/store.ts::restoreInTeam`：别人主持时把「现在 → 旧版」
当一个从会话现在的版本分叉出去的协作者合进会话（`mergeExternal`，大家都看到、主持人存），不写自己的磁盘；提示条的「撤销」从恢复后那一刻分叉、
把「恢复后 → 恢复前」合进去，只撤恢复那一下，恢复以后别人打的字留着（测试里断言了）。恢复这一下不进编辑器的 Ctrl+Z（是远端改动）

### 5.9 同步对话框、冲突横幅里小的几处（C 段，没修）

- 开同步那几步：验令牌、看云端（`syncInspect`）、新建仓库的时候「换个托管方」还能点；点了回到选托管方，那件事做完结果照样把人拽到下一步
  （登上了到仓库列表、看完云端到确认那一步）。按钮都禁用的话网慢时连回都回不去，只能关对话框，两头都不好；后果只是多点一下，没改
- 代理那一行「保存」：`syncSetProxy` 只在写 `config.json` 失败时报错，这时是一个没人接的 rejection，输入框不收起、什么都不说。很少见，没改
- 冲突副本替换以后的「撤销」（§4.38 加的）和 §5.8 说的恢复历史版本一样是整篇换回：替换以后在原文里接着打的字，提示条那几秒里点撤销会一起没。
  三处（恢复历史版本、换新版指南、替换冲突副本）一个做法，要改一起改
- 协作中继的「删除」（`RelayDialog.tsx` 的 `RelayRow`）：不确认、没有撤销，手滑删掉的那台带着令牌和证书指纹，要找给中继码的人再要一次。
  应用里别的删除都有撤销，这里要不要加看用户；低频，没改
- 启动器的「新建」「拉一份」：`api.defaultParent()`、`api.pickParent()` 没接 `catch`。取默认位置失败（「文档」文件夹被重定向到不存在的盘之类）时位置一栏空着、
  「创建」一直灰着，什么都不说；选位置的对话框出错是一个没人接的 rejection。很少见，没改

### 5.10 紧贴表格的那一行打字、粘贴，还是进表格（D 段，§4.43 没覆盖到的；桌面端复现了，见 [2026-11-15 桌面端验证](./2026-11-15-桌面端验证.md) §4.2、§5.1）—— 做了，见 `表格.md` §13

§4.43 只管「刚放进来一张表」和「走出表格时下面没有现成的空行（文末）」。表格在中间、下面是一个空行再一段字时，走出表格落在那个空行上（为了不在只是路过时改正文）；

### 5.11 双链 `[[` 的提示里，两篇同名的笔记是两行一模一样的字（D 段，没修）

### 5.13 切到长文：一次切换里排版、样式重算二十来次，几处强排版（E 段，没做）

- **量到的**（§3.7，4 倍降速、生产构建、带 sourcemap 拆账）：切到 `语法全览` 点列表 248ms、Ctrl+Tab 256–350ms，是常用操作里最重的。主线程上 >3ms 的排版 / 样式重算一次切换里有二十来次，
  最大的一次排版 465ms（第一次给新挂上的长文排版，躲不掉），前后还有 148、68、40、47ms 的几次
- **候选，按把握排**：
  1. `src/components/NoteTabs.tsx` `useFollowList`：layout effect 没有依赖，每次渲染都 `host.getBoundingClientRect()`，可只有 `panelCollapsed` 变了才用得上。改法：收没收没变就不量；
     平时左缘的变化（拖分隔条、拆栏）用 `ResizeObserver` 记（排完版以后回调，读它不多排版）。同一个文件里「切过去的那个滚进视野」的 effect 也在提交里读 `offsetLeft`
  2. Motion 投影的快照：列表的 `note-selection`、标签的 `note-tab-pill`、目录指示条这几个 `layoutId`，每次提交前 `willUpdate` 量一遍整棵投影树（`measureScroll` 读 `documentElement.scrollLeft`），
     这时 DOM 若是脏的就强排一次（每轮 86ms）。要先查是哪一次提交把 DOM 弄脏的（点击以后是不是连着两次提交）
  3. CodeMirror 量完读 DOM 选区（`readSelectionRange`）强排：库里的行为，只能看能不能少让它量几轮（替身挂上以后高度变了又量）
- **为什么没做**：第一次排版躲不掉，挪走一处强排版可能只是换个调用者付，得改了以后在同样的条件下交替量 INP 和最长一帧才知道省没省；E 段的上下文不够了。下一个做性能的会话从 1 开始，
  用 `perf.mjs --only switch,tabs` 交替量（`tools/prof.mjs` 那一套在审查收工时删了，做法写在 §3.7）

### 5.14 逻辑目录删文件夹，进回收站半路失败：内存里的树已经摘了、磁盘上的清单没写（F 段，没修）

§4.24 修完，`vault/logical.rs::tree_delete` 先在拷贝上摘、底下有不是 UTF-8 的就一点不动 —— 确定会失败的那种挡住了。剩下的是 `trash` 自己半路出错（文件被别的程序独占着、盘满了）：
`self.tree = Some(rest)` 已经换上了，前面几篇进了回收站、发给了前端，出错就返回，`save_tree` 没跑。这时内存里的树没有这个文件夹，还没进回收站的那几篇不在树上（落进「未整理」，
不丢）；磁盘上的 `.odea/tree` 还是旧的，下一次改树时才写下去 —— 在那之前重启，文件夹又回来了，里面是剩下的几篇和几个指向回收站的节点。前端拿不到 `FolderDeletion`，前面进了回收站的那几篇撤销不了
（和非逻辑目录的 `folder_delete` 半路失败一样）。**怎样复现**：逻辑目录里一个文件夹放三篇，Windows 上用 `hold_exclusively`（`vault/tests.rs`）独占第二篇，删这个文件夹，
看 `vault.tree` 和磁盘上的清单。要修就在出错时也 `save_tree`（或者把已经进了回收站的那几篇连同节点一起算进一个能撤销的 `FolderDeletion` 返回），低频，没改

### 6.0 定下来的方案（2026-11-14，用户交给主会话调研后定）

用户的话：「等我定的 8 条由你调研后然后再派 opus5.5xhigh 去做」。下面每条写：定了什么、做法、验收标准。
实现分五个包，一个包一个新会话，按这个顺序串行：**甲**（6.6 → 6.1）、**乙**（6.8、6.2）、**丙**（6.3、6.4）、**丁**（6.7）、**戊**（6.5）。
6.6 必须在 6.1 前面：6.1 要升索引版本，不先保住 id，升级的用户正好吃 §6.6 的亏。
每个包动手时先把这里的方案抄进对应功能文档的「设计」，做完写「实现记录」；做的和这里不一样，停下来报告。

**6.6　索引重建保住 id（甲）。定了：索引里加一张不跟着清的表，不往用户的文件里写 id。**
- 做法：`index.rs::prepare` 里和 `meta` 一样 `CREATE TABLE IF NOT EXISTS kept_ids (rel_path TEXT PRIMARY KEY, id TEXT NOT NULL)`，不升 VERSION、不进 `DROP` / `DELETE` 的名单。
  两处清空之前（`prepare` 版本不对、`sync_layout` 摆法变了）把 `doc` 里 `kind = 'note'` 的 `(rel_path, id)` 抄进去（旧版本的 `doc` 表先 `PRAGMA table_info` 看有没有这三列，没有就不抄）。
  `note_id_for` 的顺序改成：属性块里的 id → 这个路径原来那一行的 → `kept_ids` 里这个路径的（没被别的文件占着）→ 新分配。用掉的那一行删掉；
  一次完整的重扫走完以后还剩的（文件已经不在了）清掉，免得以后同一个路径上新建的另一篇捡到旧 id。连着清两次（先升版本、紧接着摆法又变）不能把第一次抄的丢了
- 验收：回归测试 —— 外来笔记（属性块里没有 id）建好索引，①把 `user_version` 改小再打开、②换摆法触发 `sync_layout`、③两样连着来，三种之后 id 都和原来一样；
  删了索引文件才换 id（写进文档，这是说好的边界）；文件不在了的旧记录不留；`cargo test`、clippy 过。桌面端：造一个带外来笔记的临时仓库，开着几个标签，改 `user_version` 重开，标签都还在

**6.1　键是中文的属性块也认（甲）。定了：认。键的第一个字是 Unicode 字母或下划线，后面是字母、数字、`_`、`-`，再是 `:`（半角）。**
- 做法：三处同一条规矩一起改 —— `vault/frontmatter.rs::is_yaml_key`、`domain/search.rs::is_yaml_key`（Rust 的 `char::is_alphabetic` / `is_alphanumeric`）、
  `editor/frontMatter.ts::KEY_RE`（`/^[\p{Alphabetic}_][\p{Alphabetic}\p{N}_-]*\s*:/u`，和 Rust 那两个属性是同一组）；`Grep` 一遍有没有第四处（`properties/yaml.ts`、`data/mock.ts`）。
  全角冒号 `：`、带空格的键照旧不算键（YAML 本来就不认）。`index.rs` 的 VERSION 升到 8（已经读进索引的要重新认）。
  §4.2 加的 `recognisable` / `NEEDS_ASCII_KEY` 跟着改：只有中文键的块现在认得出来了，「先加一条英文名字的」这句话和它的测试要换
- 已知留下的：以前被 Odea 存过一次的那种笔记（前面是 Odea 加的一块、正文开头还留着原来那块）不自动合并，原来那块还是正文，写进文档
- 验收：三处各有测试，同一组样例（`标签: 旅行`、`截止: 2026-11-20`、`_x: 1`、`タグ: a`、`标签：旅行` 不算、`1a: x` 不算、`- 列表项` 不算）三处结论一致；
  一篇只有中文键的外来笔记：属性面板里看得到、改一条只动那一行、正文一个字不动；一篇以分隔线开头、后面没有 `键: 值` 的普通笔记不被当成属性块；
  升版本以后外来笔记的 id 不变（靠 6.6）。前端三项、`cargo test`、clippy 过

**6.8　属性换类型不改值（乙）。定了：照 Obsidian —— 换类型只记 `types.json`，文件里的值一个字不动；值和类型对不上的那一行显示原来的字，带一个「类型不符」的标记。**
- 做法：`PropertiesPanel.tsx::changeKind` 不再 `convertValue` 写文件，只 `setPropertyType`。显示那一头：记着的类型读不了这个值时（日期读不了「草稿」），
  这一行画成原文 + 标记（图标加提示「类型不符：这个值不是日期」），点进去按文字改；改成读得了的值标记就没了。读得了的（日期当日期时间、单个值当列表）照新类型的控件显示，用户动了值才按新的样子写回。
  别的工具写的对不上的值（`types.json` 说是日期、值是 `soon`）走同一条路 —— 现在它是什么样先量一下，记进实现记录。`convertValue` 没人用了就删
- 验收：「草稿」换成日期 / 数字 / 勾选再换回文字，文件里那一行始终没变（测试断言文件内容）；对不上的行有标记、键盘走得到、读屏有名字；深浅色、800 宽各看一眼；
  `docs/提醒与属性.md` §6.2「换类型时能留的值留着」那句改掉。前端三项过

**6.2　属性的提示列表，回车存什么（乙）。定了：分开 —— 键名、标签照旧（第一条默认选中，回车选它）；文字值不默认选中，按 ↓ 才选，回车存的就是打的字。**
- 理由：键名和标签多半是复用；文字值多半是新写的，默认选中会让「打了 Bob、存下去的是 Bobby」—— 存的不是打的字，比多按一下 ↓ 严重
- 做法：提示列表的那个 hook（`active` 现在从 0 起）加一个「不默认选中」的开法，文字值的输入框用它：`active` 从 -1 起，↓ 进第一条，↑ 从第一条回到「没选」；
  没选中时 Enter 不归列表管。§4.6 的「Esc 先收列表」留着
- 验收：测试 —— 文字值打一截已有的值按回车，存的是打的字；↓ 再回车存的是那一条；键名、标签的行为没变。前端三项过

**6.3　窗口只许去应用自己的地址（丙）。定了：加。**
- 核实过的事实：tauri 2.11 的 `WebviewWindowBuilder::on_navigation(|url| -> bool)`；wry 在 WebView2 上接的是 `NavigationStarting`（只有主框架，`wry/src/webview2/mod.rs`），
  插件的 iframe 不经过它。**实现时在锁定的那个版本（`Cargo.lock`：tauri 2.11.5、wry 0.55.1）的源码里再核一遍**，并看 macOS / Linux 那两头是不是连子框架也回调 —— 是的话名单里要放行 iframe 用的地址
- 做法：一个纯函数判断「这种窗口能不能去这个地址」，七处建窗口的地方都挂上（`workspace.rs` 的仓库窗口、启动器、访客窗口，`quick_capture.rs`，`popout.rs`，`print.rs` 两处）。
  放行：应用自己的源（打包后 Windows 是 `http(s)://tauri.localhost`、别的平台 `tauri://localhost`；开发时是配置里的 devUrl）、`about:blank`（弹出窗口）、
  打印窗口只放行它自己那一页 `file://`。别的一律不去，记一行日志；不在这里替用户开浏览器（外链照旧走前端的 `openExternal`）
- 验收：纯函数的单测（每种窗口放行什么、挡什么，含 `https://tauri.localhost.evil.example`、`http://127.0.0.1:1420@evil.example` 这类）；
  **桌面端每种窗口都真的开一遍**（仓库、启动器、速记、访客、弹出、导出 PDF 的打印窗口、带 iframe 的插件），都打得开、能用；
  在每种窗口里经 CDP 执行 `location.href = 'https://example.com'`，窗口不走。`cargo test`、clippy 过

**6.4　插件的命令能说自己开的是哪个对话框（丙）。定了：加一个可选字段。**
- 做法：`plugins/registry.ts::PaletteCommand` 加可选的 `dialog`；`app/store.ts::PaletteDialog` 收 `plugin:${string}`；`CommandPalette.tsx` 跑插件的命令时照核心命令的做法记 `paletteBack`；
  `ReminderSettings.tsx` 用 `usePaletteBack`，`DialogLead` 不再写死 `back={null}`。只是内置插件的贡献点，不动沙箱里装的插件的协议
- 验收：测试 —— 从命令面板开「提醒设置…」，标题栏左边是「←」，Esc 回到面板、面板里还是刚才打的字；从别处开的不带返回。`docs/插件与跨端.md` 的贡献点那一节补上。前端三项过

**6.7　编辑器带着刚打的字挂上一份会话（丁，连带修 §4.36）。定了：做法 1 —— 会话记着自己是照哪一版建的，挂上时把编辑器多出来的改动映射过去，不丢字、不挡人。**
- 做法：会话上带一个只用一次的 `origin`（建这份会话时拿的本机正文：`team/controller.ts::join` 里的 `local`、`becomeHost` 里的那一版、`collab/store.ts::hostDoc` 里磁盘上的那一版）。
  `binding.ts` 构造时，编辑器 ≠ 会话、而且编辑器 ≠ `origin`：算 `origin → 编辑器`、`origin → 会话` 两份字符级的 `ChangeSet`（用仓库里现成的 diff，`mergeExternal` 用的那个；要的是细的改动，不是掐头去尾的一整段），
  本机那份映射过会话那份写进会话、发出去，编辑器收另一半，两边对到同一个结果（和组字时 `deferred` 同一条恒等式）。`origin` 用完就清；没有 `origin` 的照旧以会话为准。光标跟着映射，这一步不进撤销历史
- 一起查清并处理：`team_base` 是 null、本机和对方又不一样时，本机那一版最后去了哪 —— 不许悄悄没了（会话结束把会话的正文存回本机时会不会盖掉它）。要丢的话照冲突副本的办法另存一份。
  §5.8（别人主持的那篇点「恢复」）一起做：恢复写进会话（大家都看得到），不是只写自己的磁盘
- 验收：把 §4.36 的探针重搭成回归测试（真的 `TeamController` × 2、真的 CodeMirror + `collab()`，加入期间每 5ms 打一个字）：有 base、没 base 两种，打的字一个不少，两边正文一致；
  `becomeHost`、`hostDoc` 各一条；同一行上对方也在打字时两边的字都在；组字（输入法）进行中挂上不丢字。`docs/协同编辑.md` 记设计和实现。前端三项过。两台真机不在这次范围

**6.5　录音、视频滚远了不停（戊）。定了：做 —— 「一边听录音一边在下面记」是这个功能的用法，滚远了就停等于不能用。媒体元素不跟着卡片拆，卡片不在眼前时编辑器底部出一条小播放条。**
- 先做实验确认（技术事实）：Chrome / WebView2 里，一个正在放的 `<audio>` / `<video>` 在同一个任务里从一个父节点挪到另一个父节点（都在文档里）不会停；CodeMirror 拆替身时 `destroy(dom)` 的时机够不够把它挪走。不成立就停下来报告
- 做法：每个编辑器一个「媒体保管处」，按附件路径存媒体元素。`AttachmentWidget.toDOM` 向它要元素（没有才新建），放进卡片；替身被拆时元素正在放（或者放到一半暂停着）就挪到保管处藏着，
  滚回来的新卡片接回去，进度不变。有元素在保管处而且正在放：编辑器这一栏的底部出一条播放条 —— 名字、播放 / 暂停、进度、「回到卡片」（滚过去）、关掉（停下、放回去）。
  样子和动效照 `技术方案.md` §9、§10，按钮有名字、键盘走得到。换篇、关这一栏时全部停掉、清掉（写进文档：换篇会停）。视频在保管处只出声音，播放条同一个
- 验收：测试 —— 卡片被拆、重画，同一个元素、`currentTime` 没变、没有被暂停；播放条的出现、消失、各按钮。无头 Chrome 里用一段生成的音频真的放着滚两屏、再滚回来，量 `paused` 和 `currentTime`；
  **桌面端用真的 m4a、mp4 再走一遍**。性能：不放东西时不多一个监听、不多一次排版（`perf.mjs` 的滚动那几项和之前一样）。`docs/提醒与属性.md`（附件嵌入那一节）或 `技术方案.md` §11 记设计和实现。前端三项过

### 6.1 只有中文名字的属性块认不出来

`frontmatter.rs::is_yaml_key`、`domain/search.rs::is_yaml_key`、`editor/frontMatter.ts::KEY_RE` 三处是同一条规矩：
属性块里至少要有一行英文字母或下划线开头的键，不然当成「开头一条分隔线」。从别处搬来的、键全是中文的笔记
（`标签: 旅行`），属性块一直被当正文显示；Odea 第一次存它时在前面再加一块自己的。属性面板出来以后这条更显眼：
面板自己的文档拿 `截止`、`优先级`、`公开` 举例。

改成也认中文（Unicode 字母）开头的键要动三处、索引要升一版（已经读进索引的那些得重新认，不然存的时候正文里的
那一块会被再写一遍），是识别规则的改动，没自己做。§4.2 先堵住了「写下去读不回来」。

### 6.2 属性面板的提示列表：回车要不要默认选第一条

现在光标一进值、键名、标签的输入框，提示列表的第一条就是选中的，回车选它（Obsidian 也这样）。复用已有的值快，
代价是想存的字正好是某条提示的一截时回车存下的不是打的字（§4.6 加了「Esc 先收列表」这条出路）。
另一种做法是按 ↓ 才选中、回车默认存打的字。两种各有道理（标签、键名多半是复用，文字值多半是新写），没动，等定。

### 6.3 应用的窗口不该能跳到别的网址：Rust 里加一道 `on_navigation`

§4.11 是在出事的那个控件上修的。更稳的是在建窗口的地方（`workspace.rs`、启动器、速记小窗、访客窗口）加
`on_navigation`，主框架只许去应用自己的地址（开发时 `http://127.0.0.1:1420`，打包后 `tauri.localhost`），别的一律不去 ——
以后哪个新控件又放了真的 `<a href>`、忘了拦，窗口也不会跳走。要动每一种窗口的创建，判断写错了窗口就打不开
（弹出窗口是 `about:blank`、打印窗口是 `file://` 的临时页、插件是 `odea-plugin:` 的 iframe），得在桌面端三种窗口都走一遍，
没自己做。

### 6.4 「提醒设置…」不能回到命令面板，和别的从面板开的对话框不一样

2026-10-28 定的规矩（`components/PaletteBack.tsx`）：从命令面板打开的对话框，标题栏左边是「←」，Esc 回到面板、面板里还是刚才打的字。
查找、历史版本、回收站、同步、更新、协作、团队、中继、导出、速记快捷键都是这样。P15 新加的「提醒设置…」不是：
`DialogLead` 写死了 `back={null}`，Esc 整个关掉（浏览器预览里量的：同样从面板打开，「PDF 页面设置…」按 Esc 回到面板、输入框里还是 `pdf`；
「提醒设置…」按 Esc 以后一个对话框都没有，焦点在 `BODY`）。

原因是这个对话框在日程插件里：面板里的一条命令靠 `dialog: PaletteDialog` 说自己开的是哪个对话框，`PaletteDialog` 是核心
（`app/store.ts`）里一个写死的联合类型，插件的命令（`plugins/registry.ts` 的 `PaletteCommand`）没有这个字段。
要接上得动插件的贡献点：`PaletteCommand` 加一个可选的 `dialog`，`PaletteDialog` 收插件自己起的名字（比如 `plugin:${string}`），
`ReminderSettings.tsx` 用 `usePaletteBack`。改动不大（三处、十几行），但是插件接口的事，没自己做，等定。

### 6.5 录音、视频滚远了就停：要不要一个不跟着视口拆掉的播放器

§5.1。在替身上修不了（DOM 是 CodeMirror 拆的）。几种做法：正在放的那个媒体元素挪到编辑器外面一层留着、卡片滚回来再接回去；
或者放着的时候在文档底部出一个小播放条（名字、进度、暂停，点一下滚回卡片）；或者不管，写进文档说明「滚远了会停」。
前两种是新的界面和行为，等定。

### 6.6 索引重建一次，不是应用写的笔记就全换一遍 id（B 段）

属性块里没写 id 的笔记（从 Obsidian 搬来的、别的工具建的；应用没改过它们就一直不写），id 只在索引里。索引是缓存，
两种时候整个清掉重建：`index.rs` 的 `VERSION` 升了（应用升级，到现在升过 7 次，P15 刚升到 7），`sync_layout` 发现摆法变了
（开关日程、归档，别的设备开关了同步过来，`relayout`）。重建时 `note_id_for` 找不到「这个路径原来的那一行」，每一篇都新分配一个 id。
前端按 id 记的东西就对不上了：上次开着的标签和分屏（`odea.session`）、选中的那一篇、协作里按 id 引用的 —— 升级完打开，从 Obsidian 搬来的笔记的标签一个都不在了。
探针：`open_quick` 建好索引、把 `user_version` 改成 6 再打开，那一篇 `id == 原来的` 是 false。

和 §4.21 是同一种伤害，但不是 bug 修得了的：要改「id 从哪来」的规矩。一种做法：清空之前把 `(rel_path, id)` 记进索引里一张不跟着清的小表，
`note_id_for` 在没有前一行、属性块里也没写时先查它（几行代码，索引还是缓存、删了照样重建，只是删了索引才会换 id）；
另一种是第一次认出一篇外来的笔记就把 id 写进它的属性块（改用户的文件，Obsidian 那边会看到多了一行，和「一个文件都不改」的规矩冲突）。
动的是 id 的来源，没自己做

### 6.7 编辑器带着自己刚打的字挂上一份会话：怎么对齐（§4.36，C 段）

现在的规矩是「编辑器是拿会话的正文建的，万一不一样以会话为准」（`binding.ts` 构造函数），可团队的加入、接手主持、协作主持文件夹里的一篇，
都是「编辑器早就开着、会话从磁盘上某一版建」，中间这段时间编辑器里打的字没处去。几种做法：

1. **会话记着自己是从哪一版建的**（`session` 上一个只用一次的 `origin` 文本，`join` 里是 `local`、`becomeHost` 里是 `text`、`hostDoc` 里是 `disk`），
   绑定挂上时编辑器和会话不一样、编辑器也不等于 `origin`：把 `origin → 编辑器` 的改动（字符级，CodeMirror 的 `ChangeSet`）映射过
   `origin → 会话` 的改动（`ChangeSet.map`，和组字时的 `deferred` 同一个办法）写进会话、发出去，编辑器对齐到结果。不丢字、不挡人，
   改动在 `binding.ts` 加一段、三个建会话的地方各记一下。我倾向这个
2. **加入、接手的那一会儿编辑器只读**（controller 的快照带一个「正在加入」，`adapter` 交 `readOnly`）：改动小，但打的字当场被拒，
   加入经中继要一两秒，同事一开同一篇我这边就卡一下
3. 照旧，写进 `docs/协同编辑.md` 的「不做的」

另外 `join` 在 `team_base` 是 null 时整个不合本机的改动（探针里 27 个字一个不剩），要不要退回「拿会话建之前的那一版当 base」一起定

### 6.8 属性换类型：换不过去的值当场扔掉，没有撤销（D 段）

属性面板点类型图标换类型（`changeKind` → `yaml.ts::convertValue`）：文字「草稿」换成数字、日期、日期和时间，值变成空的（`status:`），
换成勾选变成 `false`；写进文件、记进 `types.json`，Ctrl+Z 管不到属性（不走编辑器的事务），换回「文字」也回不来。
无头 Chrome 里点一下就复现（菜单里「数字」「日期」挨着，键盘 ↓ 多按一下就是另一个）。这是 `docs/提醒与属性.md` §6.2 写明的
「换类型时能留的值留着」，能不能留之外的就扔 —— 而同一份文档调研那一节记的 Obsidian 是**不动文件里的值**，只在值和类型对不上时标一个「类型不符」。
几种做法：

1. **照 Obsidian：换类型只记 `types.json`、不改值**，对不上的那一行显示原来的字和一个「类型不符」的标记，用户自己改。不丢东西；要给对不上的状态画一种样子
2. **能换的照换，换不过去的先问**（「草稿」不是日期，换了这个值会清空）
3. **换完给一个「撤销」的提示条**（和冲突副本替换一样），撤销写回原来那一行、`types.json` 退回去
4. 照旧

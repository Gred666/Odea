## 1. 调研

`提醒与属性.md` §4.1 已经把 Obsidian Bases 的来龙去脉、哪几次不兼容查过了，这里补动手要的细节。资料：
[Bases syntax](https://obsidian.md/help/bases/syntax)、[Views](https://obsidian.md/help/bases/views)、[Kanban](https://obsidian.md/help/bases/views/kanban)、
Obsidian 的作者维护的 [obsidian-skills 里的 obsidian-bases](https://github.com/kepano/obsidian-skills)（`SKILL.md` 写了完整的键、`FUNCTIONS_REFERENCE.md` 列了函数）。

### 1.1 文件长什么样

```yaml
filters:                      # 整个文件的筛选：一行表达式，或者 and / or / not 套着的一组
  and:
    - file.inFolder("项目")
    - 'status != "完成"'
formulas:                     # 公式：名字 → 表达式，用的时候写 formula.名字
  剩几天: '(date(截止) - today()).days'
properties:                   # 列的显示名；笔记的属性要写 note. 前缀，不然不认
  note.status:
    displayName: 状态
summaries:                    # 自定义汇总（不是视图里那个 summaries）
  x: 'values.mean()'
views:
  - type: table               # table / cards / list / map / kanban（kanban 1.14 起）
    name: 进行中
    filters: 'priority > 1'   # 这个视图自己的，和上面的 AND
    order: [file.name, status, 截止]     # 显示哪几列 / 卡片上哪几项（看板、卡片的第一项是卡片标题）
    sort:                     # 一条条：property + ASC / DESC（必须大写，别的写法被忽略）
      - property: 截止
        direction: ASC
    groupBy:                  # 只能一个属性
      property: status
      direction: ASC
    groupOrder: [计划, 进行中, null]   # 只显示这几组、按这个顺序；null 是没写这个属性的那一组
    limit: 50
    columnSize:               # 表格的列宽（Obsidian 写的，文档里没写）
      file.name: 240
    summaries:
      预算: Sum
```

- 筛选里的属性写 `status`、`note.status`、`note["带 空格"]` 都行；文件的写 `file.name`、`file.folder`、`file.mtime`、`file.ctime`、`file.tags`、`file.links`、`file.ext`、`file.path`、`file.size`；
  `this` 在主区打开时就是这个 `.base` 文件自己
- 表达式照 JavaScript：`== != > < >= <=`、`&& || !`、`+ - * / %`；`now()`、`today()`、`date("2026-11-20")`，日期加减 `"1 week"` / `"7d"` 这种时长字符串，两个日期相减是一段时长（`.days`）
- 一个文件默认是整个仓库的所有文件（附件也算），靠筛选收窄；没有 `from`
- 看板：按 `groupBy` 分列，没写这个属性的在「None」一列；拖卡片到别的列改的是那一篇的这个属性（只有笔记能拖；按 `file.folder` 分的拖了是挪文件夹；按公式、别的 `file.*` 分的拖不了）；
  列的顺序拖列头改，存在 `groupOrder`；卡片在列里的顺序没有手动的，跟着排序
- 视图里认不得的键原样留着：地图视图的经纬度、卡片的 `image`、`cardSize`、插件自己加的
- 能嵌进笔记：`![[项目.base]]`、`![[项目.base#看板]]`；也能写成 ```` ```base ```` 代码块

### 1.2 写回

Obsidian 在界面里改了以后整份重写（YAML 的格式化是它自己的）。手写的注释、引号风格它不保。我们比它保守：**只换改了的那个键**，别的字节尽量不动（§3.2）。

## 2. 现有的能用什么

| 要的 | 现有的 | 结论 |
|---|---|---|
| 树上认出 `.base` | `vault/folders.rs::scan` 已经在列树上的文件（图片、PDF，`TreeFile`，`仓库与启动器.md` §11），整个仓库当树根时、Odea 的「笔记」里都列；逻辑目录不列 | 加一种 `base`。逻辑目录的树是清单（`.odea/tree`），第一版不列（§3.1） |
| 每篇的属性 | 索引的 `doc.props` 列（属性块里用户自己的那几行，原文）、`doc.tags`（属性块里的标签）；前端 `properties/yaml.ts` 认成一条条 | Rust 一条命令把所有文档的这几列给前端，前端用 `yaml.ts` 认 |
| 改一篇的一个属性 | `properties/yaml.ts`（`entryLines` / `replaceEntry` / `appendEntry`：只换那几行）+ `doc_set_properties`（核对、正文不动） | 直接用。值的编辑器（文字带提示、日期、勾选、列表）是 `PropertiesPanel.tsx` 里的 `ValueCell`，导出来给表格的格子用 |
| 属性是什么类型 | `vault_property_catalog`（整个仓库每个键多半是什么类型、常见的值）+ `types.json` | 一样用：列的类型、提示、空着的格子按什么编辑器 |
| 标签页 | 只放笔记（`标签页与分屏.md` §3），标签里存的是笔记 id | 视图文件也要能开在标签里（和 Obsidian 一样），§3.5 |
| 读写一个 YAML 文件、保住注释和顺序 | 没有。`yaml.ts` 只认属性块那一层 | 加 [`yaml`](https://eemeli.org/yaml/)（2.9.1，零依赖），跟着视图那一包用到时才加载（§2.1） |

### 2.1 为什么加 `yaml`，不用 `properties/yaml.ts`

照 `ENGINEERING.md`「依赖」：先看现有的能不能解决、多多少体积和传递依赖、重的用到时再加载。

- **`properties/yaml.ts` 解决不了**：它认的是属性块那一层 —— 一行一个「键: 值」，值是一行的标量、`[a, b]`、下面一行一条的 `- a`；
  嵌套的、多行的整块当「complex」只读，不往下认（`提醒与属性.md` §6.2）。`.base` 正好全是嵌套的：`views` 是一列映射，映射里有 `sort`（一列映射）、
  `groupBy`（映射）、`filters`（`and` / `or` / `not` 套着的列表，可以套好几层）、`properties`（两层映射）。要用它就得把它扩成一个通用的 YAML 解析器，
  还要能「只换一个键、别的字节不动」地写回 —— 这就是 `yaml` 这个库的 Document API 做的事（解析成带原文位置、注释、引号风格的节点树，改一个节点、其余照原样输出）。
  自己写一份：块 / 流两种集合、单双引号和转义、多行标量（`|`、`>`）、锚点和别名、注释挂在哪个节点上，几百行、还得自己测；写坏了丢的是用户的视图文件
- **Rust 那边也不合适**：`serde_yaml` 已经不维护了，而且只出值、不保注释和顺序；改了一个排序就把用户手写的注释、键的顺序全冲掉
- **代价**：`yaml` 2.9.1 没有任何依赖（`pnpm view yaml dependencies` 是空的），2026-09-11 发布；只有视图文件那一包引它（`src/bases/`，`BaseView` 用到时才加载），
  启动、开笔记都不加载它。生产构建里它进了视图那一个分包，大小见 §4 的实现记录
- `properties/yaml.ts` 照旧管属性块（视图里改一篇的属性用的还是它，§3.7）：属性块要的是「只动那一行」，比通用的 YAML 写回更保守，两样不合并

## 3. 方案

### 3.1 范围

第一版做：

- 树上认出、打开 `.base`（单击开在当前标签，Ctrl / 中键开新标签，行菜单「在新标签页打开」「在文件夹中显示」）；弹出窗口里也能开
- 表格、看板，卡片、列表跟着（同一份数据，换个排法）；地图、日历不做（`提醒与属性.md` §4.2）。认不得的视图类型（`map`、插件的）在视图切换里列着，点开说「Odea 还不会画这种视图」
- 筛选（整个文件的、这个视图的）、排序、分组（`groupBy` / `groupOrder`）、`limit`、`order`、`properties` 的 `displayName`
- **公式也算**（和 `提醒与属性.md` §4.2 不一样）：筛选和公式是同一种表达式，求值器写了就都能算；用了还不认得的函数的那一格显示「—」，悬停说哪个函数还算不了
- 表格里直接改属性（只改那一篇属性块里那一行）；看板拖卡片改分组的那个属性；看板列的「+」新建一篇带着这一列的值
- 在界面里改筛选、排序、分组、显示哪几列、加视图、改视图名、删视图，写回 `.base`；「源码」直接改整个文件
- 新建视图文件：命令面板「新建视图文件」、文件夹「…」菜单「新建视图」（在那个文件夹里建，筛选默认是「在这个文件夹里」）
- 文件在别处改了（Obsidian、同步、手改）：开着的视图跟上

不做（第一版）：

- **行里只有 Markdown 文档**。Obsidian 连附件、别的文件也列（只有 `file.*` 属性）。Odea 的仓库里附件在「附件」文件夹，列进来多半是噪音；
  真要按文件筛的写 `file.ext == "pdf"` 在 Odea 里是空的 —— 视图里说一句。归档的、日程的某一天也是 Markdown 文件，照 Obsidian 都算（同一个 `.base` 两边列出来一样），要排掉写 `!file.inFolder("归档")`
- `summaries`（汇总）、`file.backlinks`、`file.embeds`、嵌进笔记（`![[x.base]]`、```` ```base ````）：原样留着，界面上不画
- 逻辑目录的仓库：树是清单里摆的，`.base` 文件不在树上（磁盘上照样在、照样同步）；以后在清单里加一种节点
- 拖列头改列的顺序、拖边改列宽（读 `columnSize` 定宽）、看板拖列头改列的顺序（在「分组」菜单里排）
- 视图文件改名、删除（在资源管理器里做，树会跟上）

### 3.2 文件：读和写

- Rust 只管文件：`base_read` 给全文和指纹；`base_write` 带着读的时候的指纹写回，**磁盘上的已经不是那一版就不写**，回「别处改过了」，前端重读、把这一次的改动在新的那一版上再做一遍（改动都是「某个视图的某个键换成某个值」，重做一遍不会错）
- 前端用 `yaml` 的 Document 读：认成 `BaseConfig`（筛选、公式、显示名、视图）；改的时候在 Document 上 `setIn` 那一个键，`toString()` 写回 ——
  没碰的键、注释、键的顺序、引号都留着。认不得的键（`summaries`、`columnSize`、`image`、插件的）原样留着
- 写的格式跟着 Obsidian：`sort` 一条条 `property` / `direction`（大写）；表达式能不加引号就不加（`- file.inFolder("项目")`），以 `!` 这类开头、不加读不回来的才加，有双引号的用单引号括（`'!file.hasTag("x")'`）；一行的列表 `[a, b]` 括号里不加空格；键用前缀（`note.status`）还是不用，跟着文件里本来的写法
- 文件写坏了（YAML 读不出来、`views` 不是列表）：视图里说哪一行不对，给「源码」改；不往回写
- 新建的：

```yaml
filters:
  and:
    - file.inFolder("项目")
views:
  - type: table
    name: 表格
    order:
      - file.name
      - file.mtime
```

  筛选里写从仓库根起的路径（Obsidian 的 `file.inFolder` 认的就是它）：Odea 建的仓库的树根是「笔记」，在根上建的是 `file.inFolder("笔记")`；整个仓库当树根（打开的文件夹、Obsidian 的库）时在根上建就没有 `filters`

### 3.3 数据：在哪算

**每篇的属性由 Rust 一次给齐，筛选、排序、分组、公式在前端算。**

- Rust `base_docs(withBody)`：索引里每篇 Markdown 文档的 `DocumentRef`、相对路径、标题、建 / 改的时间、大小、属性原文（`props`）、属性块里的标签；
  `withBody` 时再给正文里的 `#标签` 和 `[[双链]]` 目标（要读正文，筛选里用到 `file.tags` / `hasTag` / `file.links` / `hasLink` 才要）
- 前端每篇认一次属性（`yaml.ts::parse`，按「这一篇的属性原文」缓存，没变不重认），再按视图算
- 为什么不在 Rust 算：表达式语言要两份（浏览器预览的 mock 也得能用）；界面上改筛选、拖卡片、改一格都要立刻看到结果，来回一趟 IPC 不如本地重算一遍；
  几千篇的比较是微秒级的事，重的是「认属性」，缓存以后只认一次。**量了再说**（§3.9），慢了再挪
- 什么时候重取：打开时；`vault-changed`（别处改了笔记）；笔记多了少了（`useData.notes` 里的 id 变了）。标题、修改时间每次算的时候从 `useData.notes` 里接最新的，不为了这个重取。
  这个窗口里改了属性（表格、属性面板）：两边经 `properties/store.ts` 的一个通知互相告诉，不等 Rust

### 3.4 表达式

自己写一个小的（`bases/expr.ts`）：词法 → 语法树 → 求值，值有 null、布尔、数字、字符串、日期、时长、列表、双链、文件、对象。

- 运算：`|| && !`、`== != < > <= >=`、`+ - * / %`、一元 `-`、括号、`a.b`、`a["b"]`、`a[0]`、`f(x)`、`a.m(x)`；字面量 `"…"` `'…'` 数字 `true` `false` `null`
- 全局函数：`now() today() date() duration() if() list() number() link() min() max() file()`
- 方法：字符串 `contains containsAll containsAny startsWith endsWith isEmpty lower upper title trim slice split replace repeat length toString`；
  数字 `abs ceil floor round toFixed`；列表 `contains containsAll containsAny isEmpty join length reverse slice sort unique flat filter map`（`value` / `index`）；
  日期 `year month day hour minute second date format relative isEmpty`；时长 `days hours minutes seconds milliseconds`；
  文件 `hasTag hasLink hasProperty inFolder asLink name basename path folder ext size ctime mtime tags links properties`；任何值 `isTruthy isType toString`
- `format()` 认 Moment 常用的那几个记号（`YYYY YY MM M DD D HH H mm ss dddd ddd`），别的原样输出
- 属性的值怎么认：`types.json` 记着的类型优先，再照值像什么（`yaml.ts::kindOfValue`）—— 日期、日期时间认成日期，数字、勾选认成数字和布尔，列表是列表，`[[x]]` 是双链
- 认不得的函数、语法写错了：那一条筛选不算（视图顶上说「这一条 Odea 还算不了：…」，结果里不因为它少东西）；那一格公式显示「—」
- 比较：日期和像日期的字符串能比；`==` 列表对列表逐项比；null 和 null 相等

### 3.5 打开：标签里放的不只是笔记

标签里存的是一个字符串（`NoteTab.noteId`）。视图文件存成 `base:` + 相对路径（`bases/ids.ts` 的 `baseTabId` / `baseOfTab`）。

- 为什么不给标签加一个「种类」：标签、窗格、往回走、弹出窗口、记在本机、对账，全是按这一个字符串走的（`app/panes.ts` 几十个纯函数），加字段要动一大片；
  笔记 id 不会以 `base:` 开头、以 `.base` 结尾（id 是应用生成的 UUID，外来笔记的 id 是属性块里的字，真有人写成那样两个都要中）
- 碰到的地方：正文区（`DocumentPanes`、`Popouts`）看到 `base:` 就画视图、不画编辑器；标签的标题是文件名（不带 `.base`）；
  列表里那一行亮；「选中的那篇没了就挪到第一篇」「笔记没了关掉标签」「取正文」这几处跳过 `base:`；文件没了视图里说「这个视图文件不在了」，标签留着让人自己关
- 别的区（日历、归档）照旧没有标签

### 3.6 界面

一页从上到下：

1. **页头**（跟着正文那一列的左缘）：文件名（大标题的样子，不能就地改）；下面一行是视图的切换（一个视图一个小签：图标 + 名字，当前的有底色；最后一个「+」加视图，菜单里选表格 / 看板 / 卡片 / 列表）。
   小签右键（或「…」）：改名、复制、删掉（只剩一个时不能删）
2. **工具条**（一行，靠右）：「n 篇」、筛选（有条件时写着条数、颜色深一档）、排序、分组（看板叫「分列」）、属性（显示哪几列 / 卡片上哪几项）、「源码」。点开是贴着按钮的小面板（`RowMenu` 那一套的样子）
3. **正文**：撑满这个窗格的宽度（不是正文那一列的 860），自己滚

**表格**：表头一行固定在顶上（滚的时候不走）；第一列是标题（点了开这一篇，Ctrl / 中键开新标签）；行高 36，只画看得见的那些行（几千行也只有几十个 DOM）；
分组时每组一个组头（值、篇数，点了收起）。表头点一下按这一列排序（升 → 降 → 不按它），写进 `sort`。
格子：笔记的属性能改 —— 点一下进编辑器（就是属性面板里那个：文字带提示、数字、勾选直接点、日期、列表的小块），Enter / 点别处存，Esc 不改；
`file.*`、公式只能看。没写这个属性的格子空着，点进去写就是给那一篇加这一条（按记着的 / 仓库里多半的类型）。键盘：↑ ↓ ← → 在格子间走，Enter 进编辑，Esc 回到格子

**看板**：一列一组（`groupOrder` 的顺序，没写的按值排在后面，「没有」一列放最后），列头是值和篇数；卡片上第一行是 `order` 的第一项（多半是标题），下面几项小字。
拖卡片（指针事件，和树上拖笔记同一套手感：按住移 4px 才算拖、跟手的是卡片的一张图、落点处空出一张卡片的位置）放到别的列，改那一篇的分组属性；
按 `file.*`、公式分的不能拖（卡片不跟手，说一句为什么）。列底下「+ 新建」：在视图文件所在的文件夹里建一篇，带着这一列的值，开在新标签里

**卡片**：等宽的格子排开（宽 220），卡片里标题 + 几项；有 `image` 键、值是图片的放一张封面。**列表**：一行一篇，标题后面跟着几项，「·」隔开

**筛选面板**：两段 —— 「所有视图」（文件的 `filters`）、「这个视图」。每段最上面「全部满足 / 任一满足」（就是 `and` / `or`），下面一行一个条件：
「属性 ⌄ 怎么比 ⌄ 值」三格（等于、不等于、包含、不包含、大于、小于、为空、不为空；属性的候选是仓库里的键加上文件的几项），改了马上生效、写回；
不是这种简单样子的条件（嵌套的组、函数）原样显示成一行表达式，能直接改字、能删。底下「添加条件」。写错了的那一行标红、说为什么

动效照 `技术方案.md` §10：面板、菜单直接出现或者只淡入；拖卡片只动 transform；换视图交叉淡化（`SwapFade`）。深浅色都走 token

### 3.7 改属性

- 一格改完：`yaml.ts::parse` 那一篇的属性原文 → 有这一条 `replaceEntry`、没有 `appendEntry`（`entryLines` 按类型写，列表照原来的写法）→ `docSetProperties`。
  先改界面上的数，Rust 写好了换成它回的原文，失败了退回去、在顶上说为什么（同属性面板）。改完告诉属性面板（同一篇正开着的话跟着换）

- 为什么不另写一套：属性块的规矩（只动那几行、读不回来的不写、应用的键不许碰）都在这两样里，另写一套迟早不一样

### 3.8 别处改了

### 4.2 和方案不一样、或者方案里没写的

- **别处改了 `.base` 没加 `bases` 字段**（§3.8 改了）：写的时候发现 `.base` 是树上的文件，现成的整扫本来就比树上文件的修改时间、变了发 `folders`。开着的视图看自己那个文件的修改时间
- **表达式写回不强加引号**：方案写「有双引号就用单引号括」。实际让 `yaml` 自己挑：能不加就不加（`- status != "完成"`、`- file.inFolder("项目")`，Obsidian 的文档里两种都有），不加读不回来的才加，有双引号的挑单引号
- **`flowCollectionPadding: false`**：`yaml` 默认把一行的列表写成 `[ a, b ]`，没碰的键也被改了（浏览器预览里点了一下表头，`order: [file.name, status]` 跟着变）。踩坑记进 `PITFALLS/数据.md`
- **新建时的筛选**：Odea 建的仓库树根是「笔记」，在根上建的写 `file.inFolder("笔记")`；整个仓库当树根时在根上建才没有筛选（§3.2 改了）
- **性能目标改了**：方案写的「4 倍降速 100ms 以内打开」量下来做不到 —— 同一个仓库里换一篇笔记本身就要 300ms（4 倍降速）。改成「不比换一篇笔记慢」，量的数在 §4.4
- **为了快加的两样缓存**（量过再加的，§4.4）：认属性的缓存只在记着的类型（types.json）变了时清 —— 一览晚一拍取回来是新对象，以前整个重认一遍；行对象按「属性原文、标题、修改时间……」复用，表格的行是 memo 的，重取数据只重画变了的。视图文件的全文按路径记着最后一版，换标签回来先画它

- 改视图名：双击小签、或者「…」里「改名」，就地变成输入框（不用 `window.prompt`）

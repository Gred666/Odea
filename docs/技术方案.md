> 个人效率与复盘桌面应用 —— 笔记 / 今日TODO / GOAL / 日历 一体化
>
> | | |
> |---|---|
> | 版本 | v2.1 |
> | 日期 | 2026-09-27 |
> | 状态 | **与代码同步**（以 `src/`、`src-tauri/` 现状为准；v1.0 是开工前的设计稿） |
> | 目标平台 | Windows 10+ / macOS 13+ / Linux（二等公民） |

> 与 v1.0 相比的主要偏离，先列在最前面，免得读旧文档的人带着错误预期看代码：
>
> | v1.0 设计 | 实际实现 | 原因 |
> |---|---|---|
> | Milkdown（ProseMirror）所见即所得 | **CodeMirror 6 + Typora 式「藏标记」装饰** | Milkdown 在 P6 实机接入后被换掉：AST ↔ Markdown 互转造成输入跳行、内容漂移；CodeMirror 文档始终是 Markdown 源文，没有往返损耗 |
> | TanStack Query + Router + Virtual | **只有 Zustand**，两个 store | 五个视图共用一个 `DocumentView`，没有路由；数据量级不需要虚拟列表；乐观更新直接写在 store 里 |
> | Temporal polyfill | `lib/date.ts` 基于 `Date` + ISO 字符串 | 只做本地日期运算，Temporal 是多余的 5KB+ |
> | 行动项 = 嵌在文档里的 task 实体 | **行动项已迁回 Markdown 的 `- [ ]`**（迁移 0003） | 两个编辑面（正文 + 独立行动项区块）让用户搞不清在编辑什么 |
> | 「今日TODO」是一篇特殊笔记 | **就是今天这一天的 `day_doc`**（迁移 0004） | 今日TODO 和日历里的今天本来就该是同一篇 |
> | GOAL 是带层级 / KR / 进度的目标实体 | **一个周期一篇 Markdown**（周 / 月 / 年） | 先把「写目标」做顺，KR / 进度环等表结构保留但未接 UI |
> | SQLite 是唯一真相来源 | **文件是真相**（v2.1）：每篇文档是仓库文件夹里的一个 .md，SQLite 只是随时能删了重建的索引 | 数据归用户：能在文件夹里定位、用别的编辑器打开、放进网盘同步；索引改结构不再需要迁移 |
> | 提醒调度器、每日自动备份、更新器 | 未实现 | 见 §16 |

## 1. 产品范围与设计约束

### 1.1 核心命题：一切皆文档

笔记、今日TODO、GOAL、日历的某一天、归档项 —— 全部是**同一种结构**：

```
（可选横幅）大标题 +（可选分段控件）
正文 Markdown（所见即所得编辑）
右侧目录树 + 底部状态栏
```

五个模块不是五套 UI，是同一个 `DocumentView` 的不同数据源。新增内容类型 = 在 `data/adapter.ts` 里多映射一个 `DocumentModel`，**不写新视图组件**。这是整个前端最重要的约束，守住它。

数据层同样是「一切皆文档」：每篇文档就是仓库文件夹里的一个 Markdown 文件（§5）。

```
日记/2026/2026-09-26.md  ──就是──> 今日TODO / 日历的那一天
目标/2026/2026-W39.md    ──周/月/年──> /GOAL、日历右侧分段
笔记/*.md、归档/*.md      ──[[双链]]──> 按标题找到另一篇
任何文档里的 `- [ ] 事情 @2026-09-30` ──> 那一天的「当日安排」
.ontheway/activity/*.jsonl（append-only 日志，写入中，尚无读侧）
```

### 1.2 硬性约束

| 约束 | 说明 |
|---|---|
| 本地优先 | 所有文档都是本机文件夹里的 Markdown 文件，无网络也 100% 可用 |
| Markdown 为唯一文本格式 | 笔记正文、某天的备注、目标全文都是 Markdown 文件；**没有富文本 AST 落盘** |
| 动效密度高但克制 | 参考 Telegram：短（80–320ms）、可打断、只跑合成器 |
| 中文优先 | jieba 分词搜索、中文排版、IME 输入不能卡顿吞字 |
| 单人可维护 | 不引入需要专职维护的基础设施 |

### 1.3 明确不做（v1）

- 协作、分享。多设备同步原先也在这里（当时的说法是「仓库是普通文件夹，放进网盘就能同步」），2026-10-07 起改为内置 git 同步，见 §5.9
- 移动端（数据模型已预留：UUIDv7、软删除、`updated_at`）
- AI 功能
- 「扩展」目前只有目录页和本地导入，**没有运行时**，见 §12.6

### 2.2 选型理由（一句话版）

| 选择 | 理由 | 放弃的替代 |
|---|---|---|
| Tauri 2 | 安装包小、常驻内存低；Windows 上 WebView2 = Chromium，动画性能与 Electron 等价 | Electron、Flutter |
| React 19 | Motion / Radix / CodeMirror 绑定最完整 | Solid、Svelte |
| Motion | layout 动画 + spring 物理 + 可打断 | GSAP、纯 CSS |
| Tailwind v4 | CSS-first，design token 就是 CSS 变量，动效 token 与样式 token 同源 | CSS Modules |
| 文件为真相 + SQLite 索引 | 数据是用户看得见、带得走的 Markdown 文件；索引拿 FTS5 / 自定义分词做搜索，坏了删掉重建 | SQLite 为真相（v2.0，已换掉）、CRDT 存储 |
| rusqlite 直连 | FTS5 / 自定义分词 / PRAGMA 的完全控制权 | tauri-plugin-sql |
| **CodeMirror 6** | 文档永远是 Markdown 源文；装饰层只做「藏标记 + 加样式」，光标进入范围标记原位出现，**不存在 AST 互转** | Milkdown（已试过并移除）、Tiptap |
| Zustand（仅此一个状态库） | 两个 store（UI / 数据）够用；没有路由、没有服务端缓存失效问题 | TanStack Query / Router |

## 3. 架构总览

### 3.1 进程与线程

```
┌─────────────────────────────────────────────────────────┐
│ WebView 进程 (WebView2 / WKWebView)                      │
│  主线程：React + Motion + CodeMirror + 两个 Zustand store  │
│  合成线程：transform / opacity 动画                       │
└───────────────────────┬─────────────────────────────────┘
                        │ Tauri IPC（tauri-specta 生成的类型安全调用）
┌───────────────────────┴─────────────────────────────────┐
│ Rust 主进程                                              │
│  #[tauri::command] → spawn_blocking → Mutex<Vault>       │
│  阻塞线程池：读写 .md 文件、SQLite 索引、jieba 分词        │
│  vault-watch 线程：监听仓库文件夹，攒 300ms 再增量重扫     │
│  setup：旧库搬家 / 放示例 → 打开仓库（增量扫描）→ 起监听   │
└─────────────────────────────────────────────────────────┘
                        │
              仓库文件夹（默认 文档/OnTheWay）+ 应用数据目录里的索引
```

没有 Web Worker，没有后台定时任务。**所有可能超过 1ms 的计算都在 Rust**（分词、搜索、扫描、摘要 / 字数派生）。

### 3.2 数据流

```
用户操作
   │
   ├─► useApp（UI 状态：工作区、选中项、主题、专注模式）—— 同步
   │
   └─► useData（数据状态：notes / goals / dayDocs / tasks）
          │
          ├─► 乐观更新 state ──► UI 立即变化 + 动画
          ├─► backend().xxx() ──► Tauri IPC ──► Rust ──► 写 .md 文件 ──► 更新索引（+ activity 日志）
          ├─► 成功：用返回值覆盖乐观值
          └─► 失败：回滚 + 写 error / saveError 让状态栏显示

别的程序改了仓库里的文件 / 一次操作连带改了别的文档
   └─► Rust 发 vault-changed 事件 ──► useData.applyVaultChange ──► 重取受影响的文档
```

`backend()` 在 Tauri 里走 IPC，在浏览器（`pnpm dev` 直开 1420）走 `data/mock.ts`（localStorage 持久化），语义尽量贴近 Rust 实现。视图和 store 只认 `Backend` 接口。

### 3.3 启动序列（`src/main.tsx`）

1. `initPreferences()`：把主题 / 减少动效落到 `<html>`（`index.html` 里的内联脚本已在首帧前落过一次，防暗色闪白）
2. **并行**：`preloadEditor()`（编辑器分包）+ `useData.initialize()`（笔记全文 + 归档 + 标记日期，并订阅 `vault-changed`）
3. `installCloseGuard()`：接管 Tauri `onCloseRequested`，关窗前 flush 所有编辑器
4. `createRoot().render(<Shell/>)`
5. 双 `requestAnimationFrame` 后 `signalReady()` → Rust `window.show()`

窗口在 `tauri.conf.json` 里是 `visible: false`，所以第 2 步多等的时间用户看不到，换来首帧就是编辑器而不是占位预览。

## 5. 数据层：仓库文件夹

### 5.1 存储决策

**文件是唯一的真相。** 每篇文档就是「仓库」文件夹里的一个 Markdown 文件；SQLite 只是从文件派生出来的索引，删了下次启动会从文件重建。

（v2.0 是反过来的：SQLite 是真相，正文是字段里的字符串。换掉的原因：数据锁在库里，用户没法在文件夹里找到一篇笔记、没法用别的编辑器打开、没法放进网盘；「一切皆文档」只在界面上成立。）

两个位置：

| 位置 | 内容 | 同步 / 备份 |
|---|---|---|
| **仓库**（默认 `文档/OnTheWay`，可以换，见 §5.7） | 所有文档 + `.ontheway/`（回收站、行为日志、仓库标记） | 用户自己的文件夹，放进网盘就同步 |
| **应用数据目录**（`app_data_dir`） | `config.json`（仓库在哪）、`index/<仓库路径指纹>.db`（索引）、旧版 `ontheway.db` | 每台机器一份，不同步 |

索引刻意**不放在仓库里**：仓库可能在网盘同步的文件夹下，一个正在写的 SQLite（还有 -wal / -shm）被同步程序来回拷，迟早出冲突副本。

### 5.2 仓库里的文件

```
笔记/秋季项目复盘.md          笔记（笔记/ 下任意深度，以及仓库里其它不认识的位置）
笔记/工作/周报/第 40 周.md      笔记/ 下的子目录就是界面上的文件夹（§5.8），空的也留着
归档/第一版信息架构草稿.md      归档的笔记（归档 = 挪进这个文件夹）
日记/2026/2026-09-26.md       某一天；今日TODO 就是今天这一篇
目标/2026/2026-W39.md          周目标（ISO 周，放在 ISO 周所属年份下）；2026-09.md 月；2026.md 年
附件/                          粘贴 / 拖进来的图片和文件，正文里用相对路径引用（§11.4.4）
.ontheway/vault.json           仓库标记：有它就不再搬旧库、不再放指南
.ontheway/trash/<id>.md        回收站（删除 = 挪进来，撤销 = 挪回去，30 天后清掉）
.ontheway/activity/2026-09.jsonl  行为日志，一行一条，append-only
```

以点开头的文件和目录一律不管（`.ontheway`、`.git`、`.obsidian`、应用写到一半的临时文件）。
日记文件夹里不是日期的文件、目标文件夹里认不出周期的文件，都当普通笔记 —— 什么都不会「消失」。
同一天 / 同一周期有两个文件时（比如手动拷了一份），第一个是那一天，其余当笔记。

**笔记的属性块**（YAML front matter，`vault/frontmatter.rs`）：

```markdown
---
id: 0199f3c2-…            # 稳定的 id：改名、挪位置都不变
title: "周报: 第 3 期"     # 只在文件名表达不了标题时写（非法字符、太长、重名加了序号）
created: 2026-08-28T11:59:00+08:00
pinned: true              # 只在置顶时写
archived: 2026-09-01T…    # 归档时间（在「归档」文件夹里时）
category: "工作笔记"       # 归档分类
archived-from: "笔记/工作" # 归档前所在的子文件夹，恢复时放回去（§5.8）
tags: [旅行]              # ← 别的工具写的键，一字不改地留着
---

正文
```

- 应用只认 `id / title / created / pinned / archived / category / archived-from / trashed-from`；认不出来的行原样保留，写回时放在后面。不是完整的 YAML 解析器，也不打算是：认不出来的最坏情况是某个键没被识别，而不是丢数据
- **标题 = 文件名**。文件系统不允许的字符换成外观相近的全角字符（`:` → `：`），最多 80 个字，去掉结尾的点和空格，避开 `CON` / `LPT1` 这类设备名；同一文件夹里重名加「 2」「 3」。文件名和标题不一样时完整标题写进 `title`
- 改标题 = 改文件名（同一个文件夹里）；改大小写也行（Windows / macOS 不区分大小写，`unique_rel` 不把文件自己算作占用）
- 没有 `id` 的文件（别的工具建的）扫描时临时分配一个，应用第一次写这个文件时写进属性块。拷贝出来的文件带着同一个 id 时，后一个另分配一个
- 某一天只有 `title`（有标题才写）；目标没有属性块。标题和正文都清空的某一天 / 目标会删掉文件
- 时间：`created` / `archived` 写在属性块里（本地时间带偏移）；**「上次更新」就是文件的修改时间**
- 正文的换行统一成 `\n`；属性块和正文之间空一行，读的时候吃掉这一行，往返不变

### 5.3 写入与索引

- 写入一律「先写同目录的隐藏临时文件、再改名覆盖」（`fsio::write_atomic`）：改名是原子的，断电时文件要么旧要么新
- 顺序永远是：先写文件，再更新索引。命令和文件监听都在同一把锁（`Mutex<Vault>`）里执行
- 改元数据（置顶、归档、恢复）时读磁盘上的当前内容，只改属性块 / 位置，正文用磁盘上的
- 索引里每个文件记着修改时间、大小和内容指纹（FNV-1a）：扫描时修改时间和大小都没变的不读；读了指纹没变的只更新文件状态 —— 应用自己写的文件因此永远不会被当成外部改动
- 挪位置（改名、归档）先在索引里改路径、清掉指纹，再按新路径写：否则旧路径那一行占着同一个 id；标题来自文件名、归档与否来自位置，内容一样也得重新解析

索引表（`vault/index.rs`，存在应用数据目录）：

```sql
doc  (id PK, kind note|day|goal, rel_path UNIQUE, day, horizon, period_start,
      title, content_md, excerpt, word_count, is_pinned, is_archived,
      archive_category, archived_at, created_at, updated_at,
      mtime, size, hash)                         -- 同一天 / 同一周期各自唯一
task (id = 文档id#行号, doc_id, line, raw, title, done, due_date, time_label, category)
doc_fts USING fts5(id UNINDEXED, title, tokens)  -- 只有笔记；jieba 预切分
```

表结构改了就升 `VERSION`：版本不对时整个索引清空，下次扫描从文件重建。**不需要迁移脚本** —— 这就是「文件是真相」换来的。

### 5.4 带日期的任务（`vault/tasks.rs`）

日历「当日安排」的唯一来源是正文里带日期的 `- [ ]`，写在任何文档里都行：

```markdown
- [ ] 完成编辑器专注模式原型 @2026-09-04
- [ ] 力量训练 @2026-08-29 18:30 #健康
- [x] 回顾第 35 周目标 📅 2026-08-29 下午 #GOAL      ← Obsidian Tasks 的写法也认
```

- 日期 `@YYYY-MM-DD` 或 `📅 YYYY-MM-DD`；紧跟的时间 `HH:MM` 或 上午 / 中午 / 下午 / 晚上 / 全天；第一个 `#标签` 是分类（纯数字的 `#1` 不算）；围栏代码块里的不算
- 只有日期（和时间、标签）、没写事情的不算：周计划模板（§11.4.3）给每一天留的 `- [ ] @2026-09-28 ` 在填上之前不进日历，日历上一条空白的安排什么也说明不了
- 某一天的「当日安排」= 别的文档里那一天的任务（那一天自己文档里写的就在正文里，不再列一遍；归档笔记里的不算），按一天里的先后排（上午算 9 点、下午 14 点…）
- 灰色小字：分类 · 时间 · 出处（笔记标题 /「9月26日」/「第 39 周目标」）
- 在日历里勾选 = 改原文件里的那一行：行号对得上就用它，对不上（文件在索引之后被改过）就找原文一样的那一行，只有唯一一行时才动 —— 宁可报错，也不勾错。勾完发 `vault-changed`，前端手里那篇的正文跟着刷新
- 以前的独立 task 表没有了（v2.0 里它也只服务「当日安排」）

### 5.5 外部改动与冲突

- **文件监听**（`vault/watch.rs`，notify）：事件攒 300ms 再处理一批；一批里全是 .md 文件就只重读这几个，有目录或别的东西（整个文件夹被挪走）就整个仓库增量扫一遍；有变化发 `vault-changed { notes, days, goals, tasks, conflicts }`
- 外部改名：新文件带着同一个 id，扫描时先删消失的、再加新的，前端看到的是「同一篇改了标题」
- **冲突副本**：两种情况下不覆盖别人的改动，先把磁盘上那一版另存成「标题 (冲突 2026-09-27 1030).md」（放在原文件旁边，去掉 id 和属性块里的标题，是一篇新笔记），再写编辑器里的：
  1. 保存时发现磁盘上的版本比索引新（监听还没来得及处理）—— 后端自己发现（`keep_external_edits`）
  2. 外部改动到达时编辑器里正有没存的修改 —— 前端发现（§11.6），下次保存前调 `vault_keep_conflict_copy`
- 冲突副本一出现，底部提示「别处改动了正在编辑的文档，那一版另存为「…」」（`NoticeToast`）
- **网盘的冲突副本**：两台机器都改了同一篇、同步时撞上，网盘把其中一版另存一份。认法（`Vault::conflict_of`，查询时现算，不怕扫描顺序）：
  1. 属性块里的 id 被另一个文件占着 —— 网盘连属性块一起拷了一份。索引多存一列 `file_id`（文件里写着的 id），和分到的 id 不同就是拷贝；能认出 iCloud 的「周报 2」、OneDrive 的「周报-机器名」这类光看名字分不清的
  2. 文件名是冲突副本的样子、而且同一个文件夹里真有那篇原文（`layout::conflict_originals`）：Dropbox「周报 (张三's conflicted copy …)」「(…的冲突副本 …)」、Syncthing「周报.sync-conflict-…」、Google Drive / 百度网盘「周报 (1)」、本应用自己的「(冲突 …)」。光看名字不算 ——「方案 (1)」可能就是正经起的名
  - 扫描时名字像副本的排到最后：拷贝带着原文的 id，谁先被索引谁拿到它；「周报 (1).md」按字节序排在「周报.md」前面，不挪的话原文反倒换了 id
  - `Note.conflictOf` = 原文 id。原文也可以是某一天（`day:2026-10-07`）或某个周期的目标（`goal:week:2026-09-21`）：副本「2026-10-07 (冲突 …).md」名字不是日期，落在「日记」里当一篇笔记，靠名字认出原文（`conflict_of` 第 2 条线索不限原文的种类）。两台设备都改了今日TODO 是同步里最常见的冲突（§5.9.5）。前端在 `data/conflicts.ts` 里把它认成原文：列表标题「10月7日」「第 41 周目标」（和反向链接的出处一样），横幅挂上时按需取那一天 / 那个周期的正文来对比，「打开原文」跳到今日TODO / 日历，「用这一版替换」先取回原文再写（当天的标题不动）。列表里摘要前面打「冲突副本」小标签；打开是冲突横幅（`ConflictBanner`）：查看差异（`lib/lineDiff.ts` 逐行 LCS，两边乘起来超过 400 万格就不比）、打开原文、用这一版替换原文（二次确认；原文写成副本的正文、副本进回收站）、删掉这份副本（进回收站，撤销提示条照常能撤）。两版一模一样时只给「删掉」
  - 新出现的（监听到的）副本发 `vault-changed { foundCopies }`，底部提示「网盘同步时两边都改过，留下了冲突副本「…」」

### 5.6 时间与时区约定

| 场景 | 存储 |
|---|---|
| 创建 / 归档时间 | 属性块里的本地时间带偏移（`2026-08-28T11:59:00+08:00`），读进来是 UTC 毫秒 |
| 上次更新 | 文件的修改时间（UTC 毫秒） |
| 任务日期、某一天、周期起点 | 本地日期 `YYYY-MM-DD`（文件名 / 正文里） |
| 行为日志 | UTC 毫秒 + 本地日期 |

前端所有日期运算经过 `src/lib/date.ts`（`ISODate` 字符串 + 少量 `Date` 封装）：`periodStartOf(horizon, date)` 算周一 / 1 号 / 1 月 1 日；`isoWeekNumber`；`monthGrid` 固定 6×7；中文格式化函数一组。**业务代码里不直接 `new Date()` 做加减。** Rust 侧目标文件名和标题（`layout::goal_path` / `goal_title`）与前端的 `goalTitle` 一致，单测守着。

### 5.7 启动、搬家与换仓库（`boot.rs`）

启动：`data_dir`（可用 `ONTHEWAY_DATA_DIR` 覆盖）→ 仓库位置（`ONTHEWAY_VAULT` > `config.json` > `文档/OnTheWay`）→ `prepare` → `Vault::open`（增量扫描，清 30 天前的回收站）→ 起监听。

`prepare` 只在仓库没有 `.ontheway/vault.json` 时做事：

- 旧版 `ontheway.db` 里有东西、仓库是空的 → **搬家**（`vault/legacy.rs`）：db / wal / shm 三个文件拷到临时目录，在拷贝上用 `db/migrate.rs` 迁到最新结构再读，**原文件一个字节都不碰**，搬完留在原地当备份。搬：没删的笔记（归档的进「归档」，id / 置顶 / 分类 / 归档时间都保留）、写过东西的每一天、每个周期的目标、带日期的任务（写进它那一天末尾的「## 当日安排」）、行为日志。更新时间设成文件的修改时间，列表的排序和「上次更新」和搬之前一样。软删除的笔记不搬。中途失败就删掉已经写出来的文件，下次启动从头再来；**搬家失败不带着空仓库启动**（会被当成笔记全没了）
- 否则仓库是空的 → 放使用指南（`vault/seed.rs` → `vault/guide.rs`）：置顶的「欢迎使用 OnTheWay」和「语法全览」两篇笔记。以前放的是原型图那一套示例笔记、日记和目标，2026-10-13 去掉了
- 最后写仓库标记，`config.legacyImported = true`：旧库只搬一次

**换仓库**（命令面板「更换笔记文件夹…」，`vault_change_root`）：系统的选择文件夹对话框 → 新文件夹是空的、现在的仓库有东西时问「复制过去 / 只换文件夹」（复制时原来的不动，跳过写到一半的临时文件）→ 新仓库不搬旧库、不放示例 → 停旧监听、换 `Vault`、起新监听、存配置 → 前端整页重载。新文件夹不能在现在的仓库里面或者包着它。每个仓库有自己的索引文件，换来换去缓存都在。

**在文件夹中显示**（`vault_reveal`）：定位到文件并选中；还没写过的某一天 / 周期没有文件，打开它将来所在的、已经存在的最近一层文件夹。

### 5.8 笔记的文件夹（`vault/folders.rs`）

**文件夹就是「笔记」下面的子目录**，不是写在属性块里的虚拟分组 —— 资源管理器、网盘、别的编辑器看到的是同一套结构；在资源管理器里建的文件夹，应用里直接就有。前后端都用相对「笔记」的路径（`工作/周报`），空串是「笔记」本身；落盘时 `layout::folder_dir` 拼成 `笔记/工作/周报`，并逐段检查（不能空、不能是 `.` / `..`、不能以点开头）。一篇笔记在哪个文件夹由它的 `relPath` 决定（前端 `data/folders.ts::folderOf`），不在「笔记」底下的（仓库根上、别的工具建的目录）都算在最上面一层。

- **空文件夹也是文件夹**：以前挪走 / 删掉最后一篇会顺手删掉空了的目录（`日记/2026/` 这种空壳），现在「笔记」底下的除外（`Vault::prune`）
- **文件夹名**和笔记文件名同一套规矩（`layout::folder_name`：非法字符换成相近的全角字符、去掉开头的点和结尾的点 / 空格），同一层重名加「 2」「 3」
- **改名**：一次 `rename` 整个目录，索引里底下每篇的路径换前缀（`index::rename_dir`，内容和修改时间没变，指纹留着），id 不变；发 `vault-changed` 让前端刷新这些笔记（正文里的图片以文件夹为基准）
- **删除**：底下（任意深度）的笔记逐篇进回收站（和单篇删除同一条路，记着原来的位置），再自下而上删掉空了的目录；目录里还有图片、PDF 之类别的文件就留着它（`kept`）。返回的 `FolderDeletion` 原样交回 `folder_undelete` 就能撤销：目录（含空的子文件夹）重新建上，笔记从回收站放回原处
- **移动笔记**（`note_move`）：文件名不变，目标里重名加序号（标题照旧，写进属性块）。**正文里相对路径的链接跟着改**（`folders::relink`）：笔记从 `笔记/` 挪到 `笔记/工作/周报/`，`![图](../附件/图.png)` 要变成 `../../../附件/图.png` 才指向同一个文件。只改 `](…)`、`[引用]: …`、`src="…"` 里在仓库中真找得到目标的相对路径；网址、锚点、绝对路径、找不到的不动；围栏代码块和行内代码里的不碰。归档 / 恢复同样会换文件夹，走的是同一段代码（`rewrite_note_meta`）。正文因此变了时照常发 `vault-changed`，前端那边移动前先把编辑器里没存的存掉、移动后让编辑器换上新正文 —— 不然一次晚到的自动保存会把旧链接写回去
- **归档再恢复回原处**：归档前在哪个子文件夹记在属性块 `archived-from: "笔记/工作"`，恢复时放回去；那个文件夹这期间被删了就重新建上
- **外部改动**：文件监听遇到目录事件本来就整库增量扫描；扫描时顺带比一下文件夹列表（`Vault.folders` 缓存），变了就在 `vault-changed` 里带 `folders: true`，前端重取列表。应用自己建 / 改 / 删的先更新缓存，扫描时不当成外部变化

#### 5.9.1 范围

- **整个仓库**都同步，包括附件和 `.ontheway/`（回收站、写到一半的临时文件除外，见 5.9.3）
- **单个文件超过上限的不同步**（GitHub 100 MB、Gitee 50 MB，见 5.9.3），并告诉用户是哪个文件
- 只有一条分支 `main`。没有分支、协作，也没有手动解决冲突的界面：合不上的一律变成冲突副本（5.9.5），沿用 §5.5 的冲突横幅
- 只走 HTTPS + 令牌。不支持 SSH、Git LFS、子模块
- **和网盘二选一**：仓库在网盘同步的文件夹里时不让开启，因为网盘来回拷 `.git/` 迟早会把它弄坏（5.9.7）

#### 5.9.2 选型：内置 libgit2

| 方案 | 结论 |
|---|---|
| **git2-rs（libgit2）** | ✔ 采用。编译进应用，用户不用装 git。HTTPS 在 Windows 上走 WinHTTP、在 macOS 上走系统 TLS，不带 OpenSSL。能编译到 iOS / Android（Android 要带 OpenSSL），以后的移动端用同一套代码 |
| 调用系统 git | ✘ 默认用户没装 git |
| 打包 MinGit | ✘ Windows 多 37 MB，macOS 没有官方便携版 |
| gitoxide（gix） | ✘ 纯 Rust，但到 2026-10 还不能 push，合并流程也没有 |
| isomorphic-git（前端 JS） | ✘ 慢；github.com 的登录接口不支持跨域 |

```toml
git2 = { version = "0.21", default-features = false, features = ["https", "vendored-libgit2"] }
```

原型（2026-10-07，Windows，release 配置和本项目相同）验证过：
- 文件和规则：中文路径；`.gitignore` / `.gitattributes` 生效
- 推送与合并：落后时推送被拒，再来一轮就推上去了；两边改了同一行时，本机留原文、对方那版存成副本；不冲突的改动自动合并；一边删一边改时留下改过的那版；行为日志用 `merge=union` 合并
- 网络：经代理用 HTTPS 连 GitHub，直连 Gitee
- 体积：可执行文件 **+1.2 MB**
- 2000 篇笔记的仓库：没改动时检查一遍 7 ms；改一篇再提交 0.14 s；**第一次全量提交约 10 s**（系统 git 约 3 s，慢在逐个写对象文件；已提速，见 5.9.8）

libgit2 和命令行 git 不一样的地方，下面各处要自己补：
- 不做 `gc`（5.9.8）
- 不读 Windows 的系统代理（5.9.4）
- 没有 `pull`，要自己拼成 fetch + merge（5.9.5）
- 推送被拒的报法不同：本地远端是返回错误，HTTPS 远端是 `push_update_reference` 回调里的状态，两种都要认

#### 5.9.3 仓库里多出来的文件

```
.git/            git 自己的；文件监听本来就不管以点开头的路径（§5.5）
.gitignore       应用维护其中一段，用户可以在这一段外面加自己的
.gitattributes   同上
```

`.gitignore` 里应用维护的那一段：

```gitignore
# >>> OnTheWay（这一段由应用维护）
.ontheway/trash/
.*.tmp
.DS_Store
Thumbs.db
desktop.ini
# <<< OnTheWay
```

- `.*.tmp` 必须有：原子写入的临时文件叫 `.周报.md.123-4.tmp`（`fsio::write_atomic`），提交时正好撞上就会被带进去
- 回收站不同步：删除就是挪进回收站，同步到别的设备上就是「删除」。撤销在本机做，撤销回来的文件照常同步

`.gitattributes`：

```gitattributes
* -text
*.md text eol=lf
.ontheway/activity/*.jsonl text eol=lf merge=union
```

- 附件一个字节都不改（`-text`）。Markdown 统一用 LF，Windows 上取出来不会变成 CRLF：应用自己写的本来就是 `\n`，别的编辑器写的 CRLF 在进库时规整掉
- 行为日志只追加不修改，`merge=union` 让两台设备追加的行都留下，不会冲突

**超限的文件**：
- 提交时 `add_all` / `update_all` 的回调按文件大小跳过超过上限的（回调返回正数就是跳过）
- 新文件一直不进库。**已经同步过、后来变大的文件，停在上一次同步的版本**：不能把它从索引里删掉，那等于在别的设备上删了它
- 上限按托管方定：GitHub 100 MB（它的硬上限）；Gitee 50 MB（免费版的单文件上限，超了整个推送都会被拒）
- 每个超限文件只提示一次（按路径 + 大小记）；同步状态里一直列着

**仓库体积**：
- git 历史只增不减，删掉的附件仍然留在历史里
- 每次推送后估算本地 `.git/objects` 的大小
- Gitee 免费仓库上限 500 MB，**超了推、拉都会被锁**，所以到 400 MB 就提醒
- GitHub 建议 1 GB 以内，到 1 GB 提醒

#### 5.9.4 账号、令牌与网络

| | GitHub | Gitee |
|---|---|---|
| 登录 | OAuth App 的**设备码**登录：界面上显示一串码，用户在浏览器里确认。应用里只放 client_id，不需要 secret | 第一版用**私人令牌**：用户在 Gitee 的「设置 → 私人令牌」里生成（勾 `projects`），粘贴到应用里。OAuth 登录的情况见表下 |
| 权限 | scope `repo`，能读写这个账号的所有仓库。GitHub App 能把权限限制到单个仓库，但新建的仓库还要另外授权，第一版不用 | 私人令牌的 `projects` |
| 令牌期限 | 2026-08-14 起新注册的 OAuth App 默认令牌会过期（注册时勾了「Expire user access tokens」）：访问令牌 8 小时，另给一个刷新令牌，**6 个月不用才失效**。用 `POST /login/oauth/access_token`（`grant_type=refresh_token`）换新的一对；设备码登录来的**不需要 client_secret**。同步每 10 分钟就跑一轮，刷新令牌一直在用，实际上只有半年没开应用才要重新登录 | 私人令牌不过期（除非用户自己删了） |
| git 凭据 | 用户名 = 账号 login（`GET /user`），密码 = 令牌 | 用户名 = 账号 login（`GET /v5/user`），密码 = 令牌 |
| 新建仓库 | `POST /user/repos`，`private: true` | `POST /v5/user/repos`，`private=true` |
| 列出仓库 | `GET /user/repos?affiliation=owner&sort=updated` | `GET /v5/user/repos` |

Gitee 的 OAuth 授权码登录先不做，**等用真实账号验证过 Gitee 接受 OAuth 令牌当 git 密码之后再加**。已经查清楚的几点限制：
- 不支持设备码，也不支持 PKCE
- 回调地址要和注册的完全一致，所以本机回调只能用固定端口：`http://127.0.0.1:<固定端口>/callback`
- client_secret 只能随应用一起分发
- access_token 一天就过期，要用 refresh_token 续

其他几点：
- **认证的交互方式**（实测 libgit2 + WinHTTP）：两家都是在收到 401 时调 `credentials` 回调，要 `USER_PASS_PLAINTEXT`。令牌不对时 libgit2 会**反复**调这个回调，所以第二次被调时就返回错误，当成「登录失效」处理
- **令牌**存在系统钥匙串里（`keyring` crate：Windows 凭据管理器 / macOS 钥匙串），键是 `github:<login>` / `gitee:<login>`。仓库地址里不带令牌
- **GitHub 令牌续期**：钥匙串里存访问令牌、刷新令牌和到期时间。每轮同步前，离到期不到 10 分钟就先刷新；推送或拉取时仍然报登录失效，就刷新一次再试；刷新也失败了（刷新令牌过期或被撤销），状态变成「登录失效」，给「重新登录」
- **同步配置跟着仓库走**，写在 `.git/config` 里（这个文件不会被推上去）：`remote.origin.url`、`ontheway.provider`、`ontheway.login`、`ontheway.autosync`。换仓库（§5.7）时，同步状态自然跟着换
- **代理**：libgit2 在 Windows 上用的是 WinHTTP 的默认代理设置（`netsh winhttp`），**读不到 Clash 这类工具设的系统代理**。所以应用自己按下面的顺序找，再显式传给 `ProxyOptions::url` 和 HTTP 客户端。不支持 PAC
  1. 应用里填的代理
  2. 环境变量 `HTTPS_PROXY` / `ALL_PROXY`
  3. 系统代理：Windows 读 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 里的 `ProxyEnable` / `ProxyServer`，macOS 读 `scutil --proxy`
  4. 都没有就直连
- **OAuth 和 API 请求**用 `ureq`（同步库，跑在同步线程里）。github.com 的设备码接口不支持跨域，不能从前端调
- **GitHub OAuth App**「OnTheWay」2026-10-07 注册（开了 Device Flow 和令牌过期，没有 client secret）。client_id 是 `Ov23lieFMfGc95fA5QQs`，写在 `sync/provider.rs`（它不是机密）；开发时可以用环境变量 `ONTHEWAY_GITHUB_CLIENT_ID` 换成别的 App

#### 5.9.5 一轮同步

同步在自己的 `sync` 线程里跑，同一时间只有一轮。**联网的步骤不持仓库锁**（`Mutex<Vault>`），否则网络一慢或者断网，所有命令都会卡在锁上；改工作区的步骤持锁，只要几十毫秒。

1. **提交**（持锁）
   - 按文件大小过滤之后做 `add_all` + `update_all`；树没变就不提交
   - 提交信息用改动的文档标题，比如「更新 周报、10月7日 等 5 篇」；作者是「OnTheWay (<设备名>)」
2. **fetch**（不持锁）
3. **合并**（持锁）
   - 先再提交一次：第 1 步之后用户可能又存过
   - 用 `merge_analysis` 判断：已经是最新的就跳过；能快进就 `checkout_tree`（safe 模式）再移动分支
   - 否则用 `merge_commits` 在内存里做三方合并（默认带改名识别），冲突按下表处理，再用 `checkout_tree`（safe）写进工作区，然后提交合并（两个父提交）
   - 最后**直接**拿新旧两棵树的差异调 `rescan_paths_and_announce`（有目录增删就整个仓库增量扫一遍），不等文件监听。监听随后看到的事件指纹都对得上，不会再报一遍
4. **push**（不持锁）：被拒说明别的设备刚推过，回到第 1 步，最多 3 轮
5. 发 `sync-status` 事件给前端

冲突怎么处理：

| 情况 | 结果 |
|---|---|
| 两边改了同一篇的不同地方 | 三方合并自动合好，不出副本 |
| 两边改了同一处，或两边新建了同名文件 | 原文 = **本机**的版本；对方的版本存成冲突副本（`write_conflict_copy`：去掉 id 和属性块里的标题，起名「标题 (冲突 时间)」），打开时出冲突横幅（§5.5） |
| 附件两边都改了 | 同上，副本叫「名字 (冲突 时间).png」，内容原样 |
| 一边删、一边改 | 留改过的版本，不丢东西 |
| 行为日志 | `merge=union`，两边追加的行都在 |

「本机优先」的意思是：后同步的那台设备上，原文是它自己的版本，先同步那台的版本在副本里。两台设备上最后都能看到两个版本。

编辑器里没存的改动不用特别处理。合并改到正在编辑的文档时，走的是 §5.5 / §11.6 的外部改动流程：本地有没同步的编辑，就把外部那一版另存成冲突副本。

#### 5.9.6 什么时候同步

| 时机 | 做什么 |
|---|---|
| 启动时，或刚开启同步 | 同步一轮。启动时**等前端 `ready`**（窗口显示、事件已订阅）再开始，最多等 30 秒：第一轮就可能出冲突副本，提示发早了没人收 |
| 最后一次写入后安静 1 分钟（一直在写的话，最多等 10 分钟） | 先提交；有新提交或没推的才联网同步。「写入」来自文件监听：每处理完一批就戳一下同步线程，应用自己写的、外部程序写的、合并检出的都算（合并检出的那次提交时什么都没有，不会白连一次云端） |
| 窗口获得焦点，距上一轮至少 1 分钟 | 同步一轮。第一轮之前的焦点不算：窗口一建出来（还藏着）就会收到一次 |
| 应用开着时，每 10 分钟 | 同步一轮，主要为了拉别的设备的改动 |
| 关闭窗口 | 提交 + 推送，最多等 3 秒（`win_force_close` 里先把窗口藏起来再等）；没推完就下次启动再推，上次提交到一半留下的 `index.lock` 启动时清掉 |
| 命令面板「立即同步」 | 同步一轮 |

断网时，fetch / push 报网络错误，状态显示「离线，改动都在本机」，按 1、2、5、10 分钟退避重试；窗口获得焦点时也会试一次。

#### 5.9.7 开启、接入、断开

**第一台设备**：从命令面板「开启同步…」进入
1. 选 GitHub 或 Gitee，登录
2. 新建一个私有仓库（默认名 `ontheway-notes`），或者选一个已有的空仓库
3. 在仓库根目录上 init，写 `.gitignore` / `.gitattributes`
4. 第一次全量提交（在同步线程里成批放进包，不持仓库锁，状态显示「同步中」，见 5.9.8），然后推送

仓库文件夹本来就是用户自己建的 git 仓库时，沿用它，只加远端。

**第二台设备**（云端仓库里已经有东西）：
- 不在本机现有的仓库上硬合。新装的应用放过示例内容，合进去就会被推到云端
- 改成 clone 到一个新的空文件夹（默认「文档/OnTheWay」，那里不空就用「文档/OnTheWay (同步)」），再走 §5.7 的换仓库流程切过去；原来的文件夹不动
- 原来的仓库里有用户自己写的东西时，问要不要「也合并进来」：拷进新仓库（id 不同不会撞，重名的加序号），下一轮同步推上去

**断开同步**：删掉钥匙串里的令牌，停掉同步线程，清掉 `.git/config` 里的 `ontheway.*`。`.git` 留着，历史都在，之后还能重新连上。

**网盘检测**：仓库路径在常见的网盘同步目录下时（OneDrive（`%OneDrive%`）、iCloud Drive、Dropbox、坚果云等），不让开启，并说明原因。

#### 5.9.8 仓库维护

- **打包零散对象**：libgit2 不会自动 `gc`。每次自动提交都留下几个零散的对象文件，一年下来是几万个，检查状态和磁盘占用都会越来越差。零散对象超过 1000 个时（一天最多一次，在同步线程里做，不持仓库锁），用 `packbuilder` 把所有能从引用走到的对象打成一个包，再删掉零散对象和旧包
- **一下子要进库很多文件**（第一次开启同步、把本机笔记合并进来、拖进来一大批附件）：逐个来在 Windows 上很慢，2000 篇十几秒，而且整个提交都持着仓库锁，这期间保存都在排队。慢在两处，都是等文件系统：每个对象写一个零散文件；libgit2 每写一个 blob 都要从头查一遍属性（一个文件两次，每次约 2 ms）。所以每轮提交前先 `stage_bulk`（不持锁）：
  - 用 `statuses()` 找新的、改过的文件（只比 stat，不像 `add_all` 那样给每个新文件生成 diff）；不到 200 个就什么都不做
  - 只收 ≤ 1 MB 的文件，按 64 MB 一批。每批分给最多 8 个线程：各自开一个 Repository，挂一个空的内存索引和 mempack，`add_path` 算出对象（按 `.gitattributes` 转换、stat 都是 libgit2 自己做的），自己用 packbuilder 落成一个包（mempack 的 `dump` 只收提交能走到的对象，这时还没有提交）
  - 主线程把这些索引项原样放进真正的索引；包都落了盘才写索引，中途断电也不会指着不存在的对象
  - 剩下的（大文件、删除、提交本身）照常由 `commit_all` 在锁里做。真实应用里 2000 篇 + 附件：锁外 1.4 s，持锁 0.23 s（debug 构建）；一次留下最多 8 个包，打包（上一条）时并成一个
- **只改大小写的改名**：Windows / macOS 上 `core.ignorecase` 为真，libgit2 识别不到这种改名。提交时拿索引里的路径和磁盘上的真实大小写比一下，不一样就删掉旧路径、加上新路径

#### 5.9.11 单篇的历史版本

同步用的 git 仓库里，每次改过这篇的提交就是一版。停笔一分钟同步一次，差不多一分钟一版；没开同步时没有历史。

- **找版本**（`sync/history.rs`）：从 HEAD 按时间倒着走提交（最多看 5 万个），这次提交里它的内容和上一版（合并提交是任何一边）不一样就算一版。两台设备各改各的再合并：两边的提交各算一版，合并出来的内容和两边都不一样时合并提交也算
- **改名、挪位置**：笔记改标题会改文件名，挪文件夹、归档会挪位置。在上一版里按已知的路径找不到它时，看这次提交删掉的 .md 里属性块 id 一样的那个，就是它原来的路径，往前接着按它找。全程拿 id 核对，旧路径后来被另一篇新笔记占了也不会认错。某一天、目标的路径由日期定，按路径找
- 只读，另开一个 Repository，不持仓库锁，不和同步线程抢
- **命令**：`doc_history(target)` 返回最近 200 版（时间、哪台设备 —— 提交署名「OnTheWay (设备名)」里的设备名，是不是这台、当时的标题），没开同步时 `unavailable` 说明原因；`doc_version_text(blob)` 取某一版的正文
- **界面**（`HistoryDialog.tsx`，状态栏的时钟按钮、命令面板「历史版本…」）：外壳和同步对话框一样。左边版本列表，新的在前：「今天 09:15」、哪台设备（这台的写「这台电脑」）、笔记改过名的写「当时叫「…」」；和现在正文一样的那版标出来。打开时默认选中和现在不一样的最近一版。右边是那一版和现在的差异（`DiffView`，和冲突横幅共用），也能切到全文。「恢复这一版」就地确认后把正文换成它（编辑器里没存的先存掉），底部提示条可以撤销。没开同步时说明一下，给「开启同步…」的入口
- 恢复只换正文，标题不动：当时的标题写在列表里，要改回去手动改

## 6. 中文全文搜索

### 6.1 为什么不能直接用 FTS5

`unicode61` 不切中文（整句一个 token）；`trigram` 按 3 字符切，中文双字词（「笔记」「目标」）直接搜不到。

### 6.2 方案：jieba 预分词 + unicode61（`domain/search.rs`）

- 写入：`tokenize_for_index` 用 `cut_for_search` 产生**重叠细粒度切分**（「季度目标」→ `季度` `目标` `季度目标`），过滤掉不含字母数字汉字的标点 token，空格拼接存进索引的 `doc_fts.tokens`（标题另切一份进 `doc_fts.title`）
- 查询：`build_match_query` 同样切词，每个 token 双引号包裹 + 转义 + 前缀 `*`（单字「笔」能命中「笔记」），隐式 AND；纯标点 / 空查询返回 `None` → 命令直接返回空结果而不是全表
- 高亮：**不用** SQLite `snippet()`（作用在分词串上，中文会显示成「今天 开会 讨论」）。`query_tokens` 把 token 按长度降序去重传回前端，由前端在原始正文上高亮
- `JIEBA` 是 `once_cell::Lazy`，首次初始化 ~50ms，`setup` 里 `std::thread::spawn(search::warm_up)` 预热

### 6.3 查询 SQL

```sql
SELECT d.*, bm25(doc_fts, 0.0, 10.0, 1.0) AS score   -- id 列不算分，标题权重 10x
FROM doc_fts JOIN doc d ON d.id = doc_fts.id
WHERE doc_fts MATCH ?1 AND d.kind = 'note'
ORDER BY score LIMIT ?2;                              -- bm25 越负越相关
```

`search_notes` 命令、`Backend.searchNotes`、`useData.searchNotes` 都在，**但当前没有任何界面调用它**：笔记列表只按标题本地筛选（原因见 `NotesView.tsx` 注释 —— 全文匹配的结果和标题栏对不上，且异步回填会闪一次），归档列表按标题 + 正文本地筛，命令面板的「笔记」组也是本地过滤。2026-10-06 确认现在这样就够用，不再单独做全文搜索的入口。

## 7. IPC 契约

### 7.1 类型生成：tauri-specta

三个 crate 版本锁死（`=2.0.0-rc.22` / `=0.0.9` / `=2.0.0-rc.21`），RC 之间不兼容。

生成时机有两条：

1. **debug 启动时**：`lib.rs::run()` 在 `#[cfg(debug_assertions)]` 下写 `../src/lib/bindings.ts`
2. **不起 app**：`cargo run --example export_bindings --features typegen --no-default-features`，用 `tauri::test::MockRuntime` 收集同一份命令列表

导出配置：`bigint(Number)`（时间戳远低于 `MAX_SAFE_INTEGER`）、文件头加 `// @ts-nocheck`。`biome.json` 忽略该文件。事件也由它生成：`events.vaultChanged.listen(...)`（`collect_events![VaultChanged]`，事件名 `vault-changed`）。

```ts
export const commands = {

  async ready(): Promise<void> { ... },   // 窗口命令没有 Result 包装
  ...
};
export type AppError =
  | { kind: "Db"; message: string } | { kind: "NotFound"; message: string }
  | { kind: "Invalid"; message: string }
  | { kind: "DbTooNew"; message: { found: number; supported: number } }
  | { kind: "Io"; message: string } | { kind: "Internal"; message: string };
```

`data/backend.ts` 里 `unwrap()` 把 `Result` 拆开：`status === "error"` 就 `throw result.error`，store 的 `messageOf()` 再把 `{kind, message}` 拆成人能读的字符串。

### 7.3 「延续」语义（`Vault::day`）

请求「今天」而今天还没写过时，把之前最近写过的一天（标题 + 正文）延续过来，`carried_from` 指向那天。**延续的内容不建文件**，用户一编辑才以今天的身份 `calendar_day_save`；昨天那篇原样留在昨天。翻到昨天之前的空白日期就是空白。前端 `forgetCarriedDays()` 在跨过零点时丢掉缓存里所有延续来的文档。

## 8. 前端架构

### 8.1 两个 store

| store | 文件 | 内容 |
|---|---|---|
| `useApp` | `app/store.ts` | 工作区与切换方向、各区选中项、`todayDate`（零点翻页信号）、日历分段 / GOAL 尺度、搜索框文本、主题、减少动效、命令面板开关、专注模式 |
| `useData` | `data/store.ts` | `notes` / `archived`（含全文）、`tasks`（按 id 索引）、`goals`（按 `horizon:periodStart`）、`dayDocs`、`markedDates`、加载 / 保存中 / 错误状态 |

**编辑器内容不进 React state。** CodeMirror 持有文档，`updateListener` 里防抖 400ms 才调 `onSave`；目录树用的实时正文另走一条 250ms 防抖，且只在标题集合真的变化时才 `setState`。

### 8.2 `useData` 的加载策略

- `initialize()`：并行取 `noteListFull(false)` / `noteListFull(true)` / `calendarMarked(2000..2100)`，并订阅 `vault-changed`（只装一次）。**不取目标和某天** —— 切到哪个周期 / 哪一天再 `loadGoal` / `loadDay`，已缓存的不重复取
- `applyVaultChange(change)`：重取变了的笔记（没了的从列表里去掉，归档状态变了就挪到另一个列表）、缓存里有的某一天 / 目标（没打开过的不管，下次切过去自然会取）；只是任务变了时只换某一天的 `tasks`、不动正文（编辑器那边可能正有没存的修改），再刷新日历墨点。正文真的变了的文档给 `externalRevisions[saveKey]` 加一（§11.6 用它区分外部改动和自己的保存）
- 外部改动撞上没存的修改：`markConflict(target)`，下一次 `saveDocument` 先调 `vaultKeepConflictCopy` 再写
- `Shell` 里两个 effect 负责按需加载：今天这一篇一进应用就取（今日TODO 用）；日历 / GOAL 按当前分段和选中日期取
- 保存：`saveDocument(target, contentMd)` 三种 `DocumentSaveTarget`（note / goal / day）各自判重后写库。**未加载完不写**（`source` 为空直接返回），否则空编辑器一输入会把已有内容整篇覆盖 —— 这是修过的 P0

### 8.3 乐观更新（示例：`toggleTask`）

```ts
const optimistic = { ...current, status: done ? "todo" : "done" };
set((state) => patchTask(state, id, optimistic));      // tasks 表和 dayDocs 里同步替换
try {
  const saved = await (await backend()).taskToggle(id);
  set((state) => patchTask(state, id, saved));
} catch (error) {
  set((state) => ({ ...patchTask(state, id, current), error: messageOf(error) }));
}
```

`togglePin` / `archiveNote` / `restoreNote` / `deleteNote` 同款。`createNote` 例外：id 由后端分配，等一个来回。

自动保存**刻意不重排列表**：每 400ms 刷一次 `updatedAt`，按它排序会让正在编辑的笔记当着用户的面往上跳；顺序在下次加载 / 置顶 / 归档时自然更新。

### 8.4 统一文档模型

```ts
interface DocumentModel {
  key: string;                       // React key + 滚动位置
  title: string;
  banner?: { icon: "archive"; text: string };
  segments?: { group; options; active };   // 标题右侧分段（GOAL 周月年 / 日历四段）
  bodyMd: string;
  dayTasks?: Task[];                 // 日历某一天的「当日安排」（别的文档里写着这一天的任务）
  eyebrow?: string;                  // 「今天 · 9月16日 周三」
  statusParts: string[];
  deletable?: boolean;
  editor?: { target: DocumentSaveTarget; titleEditable?: boolean };  // 没有 = 只读占位
}
```

`data/adapter.ts::useCurrentDocument()` 是唯一的映射点：

| 工作区 | 数据源 | 标题可编辑 |
|---|---|---|
| 笔记 | `notes[selectedNoteId]`，找不到退到第一篇 | 是 |
| 今日TODO | `dayDocs[todayDate]` | 是 |
| /GOAL | `goals[goalHorizon : periodStartOf(today)]` | 否，由周期算 |
| 日历 · 日TODO | `dayDocs[selectedDate]` | 是 |
| 日历 · 周/月/年 GOAL | `goals[scope : periodStartOf(selectedDate)]` | 否 |
| 归档 | `archived[selectedArchiveId]`，带横幅 | 是 |
| 扩展 | 不走 DocumentView | — |

数据还没回来时 `editor` 为 `undefined`，`DocumentView` 渲染 `DocumentPreview`（`renderMarkdown`）作为占位 —— 此时 `bodyMd` 通常是空串。**这不是一个「只读模式」**，`renderMarkdown` 现在只服务于占位和空状态文案。

### 8.5 `DocumentView` 的职责

标题（可编辑时是 `EditableDocumentTitle`：随内容长高的 `textarea`，长标题折行，回车 = 写完，粘贴的换行去掉）、分段控件、编辑器或占位、日历的当日安排（`DayTasks`）、右侧 `Outline`、底部状态栏（`statusParts` + 保存中 + `saveError`）、右下删除按钮、专注模式按钮（仅笔记区）。编辑器分包在模块求值时就开始 `import()`，`preloadEditor()` 让 bootstrap 能 await 它。

### 8.6 保存链路

```
CodeMirror updateListener ──► createDebouncedSaver(save, 400)
                                   │ schedule()：重置计时
                                   │ flush()：串行写链，失败版本放回队列
                                   ▼
                              useData.saveDocument()
                                   │
registerEditorFlush(saver.flush) ──► saveBus.flushAllEditors()
       触发点：Mod-S、失焦、切换文档（卸载）、Tauri onCloseRequested
```

关窗保护（`saveBus.installCloseGuard`）：`preventDefault` → `flushAllEditors()` → `win_force_close`。保存失败时**不锁死窗口**：把原因写进 `saveError`，并放行下一次关闭请求（再点一次 = 放弃未保存内容）。浏览器里退化为 `beforeunload`。

### 8.7 零点翻页

`startTodayTicker()`：`setTimeout` 对准下一个 00:00:00.500，醒来（`visibilitychange`）再对一次表。`todayDate` 变了就更新，日历选中若停在旧的今天则一起带过去。

### 8.8 专注模式（zen）

只在笔记区。左侧 chrome（导航 240 + 列表 300 = `RAIL_WIDTH` 540）切成 `absolute` 后用 `x: -540` 的 tween（460ms）滑出；正文画布往左多铺 540px 负外边距，让进出两个方向都是「chrome 在白色画布上滑动」。Esc 退出；离开笔记区自动退出。刻意**不**动画化 width / marginLeft —— 开了 lineWrapping 的 CodeMirror 会逐帧重新折行。

## 10. 动效规范

### 10.1 三条铁律

1. **只动 `transform` 和 `opacity`。** 需要「宽度动画」时用 Motion 的 `layout` 或 transform 补偿。唯一的例外是盖在正文上、带字的小浮层（表情 / 模板选择器）：缩放会让字先糊后抖，只能动 fixed 面板自己的 `height`（§11.4.2）
2. **绝不动画化 `backdrop-filter` 和 `box-shadow`。** 命令面板的毛玻璃是静态的，只动 opacity
3. **时长 80–320ms，且可打断。** spring 天然可打断；确定时长的 tween 只用在「必须在某个点之前结束」的场景
4. **带字的元素不缩放。** 缩放（以及合成器上跑的位移，比如 CSS 的 transform 关键帧）会让整层字被当成位图重采样、改用灰度抗锯齿：动画里字是虚的，结束那一帧回到正常绘制，字一下变清楚还挪一点 ——「先糊、再抖一下」。盖在内容上的面板用 `popoverCard` 从一条边展开（表情 / 模板选择器、命令面板），菜单、悬停卡片、「今天」这类小东西只淡入；缩放只留给图标、圆点、勾选框这些没有字的。位移用 spring 时给 `restDelta: 0.01`：默认差半个像素就直接跳到终点。验证办法：1.5 倍屏无头 Chrome，把页面的 `performance.now` 和文档时间线一起放慢 10 倍逐帧截图，和最终帧逐像素比（`popupMotion.test.ts` 守着这些组件不再出现 scale）
   - 淡入本身在 Chrome 里也有一次很轻的切换：淡入那几帧文字是灰度抗锯齿，到 1 的那一帧换回 ClearType。所有网页都这样，程度远轻于缩放，不用为它去掉淡入
5. **`popoverCard` 展开的面板，第一帧就得是最终的样子。** 它只在第一帧量一次 `height: auto`，之后内容再变高变矮，展开到头那一下就会跳（同步对话框的代理那一行、账号那一行、历史版本都出过）。从后端来的内容要么先取再打开（历史版本：取到了再开，超过 250ms 先开），要么所有状态（转圈、提示、列表）用同一个固定高度，要么先把那几行的位置占住、记下上次读到的值（同步对话框）。展开的面板里不放高度不一样的「正在…」占位。浏览器里的 mock 回得太快、内置浏览器的截图跟不上动画，看不出来：改了这类面板，用无头 Chrome 把 mock 的接口拖慢 300–600ms，逐帧记卡片高度，「展开到头那一下」和「之后又变」都得是 0

### 10.2 预设（`lib/motion.ts`）

```ts
spring.snappy  { stiffness: 520, damping: 34, mass: 0.7 }  // 按钮、勾选
spring.smooth  { stiffness: 320, damping: 30 }             // 列表重排、指示器（默认）
spring.gentle  { stiffness: 190, damping: 26 }             // 面板滑入
spring.bouncy  { stiffness: 420, damping: 17 }             // 完成、达成（少用）
spring.layout  { stiffness: 380, damping: 34, mass: 0.9 }  // layout 重排专用

tween.instant / fast / base / slow = 80 / 140 / 220 / 320ms，ease-out-quint（slow 用 expo）
stagger(index, step = 22ms, cap = 10)
layoutIds = { navIndicator, listSelection, outlineIndicator, segmentThumb(group), calendarDay }
```

### 10.3 场景对照（现状）

| 场景 | 技术 | 参数 | 备注 |
|---|---|---|---|
| 工作区切换 | `AnimatePresence mode="popLayout" anchorX="right"` | 进场纯 opacity `tween.base`；退场 `x: dir * -12` + opacity `tween.fast` | **进场不带 transform**，编辑器才能在第一帧直接挂上（§11.5）。popLayout 把退场那屏冻结在原尺寸上交叉淡出，列表栏进出引起的收窄不会让它重新折行；`anchorX="right"` 是因为它的定位父级左边缘会挪 300px，钉右边才原地不动 |
| 列表栏出现 / 消失 | `x: -300 → 0`，整块从导航栏（z-20）底下抽出 | `tween.base`（220ms） | 挂载瞬间就以完整宽度进 flex 流，布局只变一次；之后纯 transform。以前动画化 `marginLeft`，220ms 里每帧重排、CodeMirror 逐帧折行，头几帧稳定 28ms 一帧 |
| 列表栏内容切换 | `AnimatePresence mode="wait"` | `tween.base` | key 只跟「有没有列表栏」走，笔记 → 日历不整条收起再展开 |
| 专注模式 | `x: -540`，chrome 层切 absolute | 460ms 自定义 ease-out | §8.8 |
| 导航活动项 / 列表选中 / 目录活动条 | `layoutId` | `spring.smooth` | |
| 切换文档 | `components/SwapFade.tsx`：`getSnapshotBeforeUpdate` 里克隆旧内容，挂在不滚动的 `[data-swap-host]` 上原地淡出；新内容 WAAPI 纯 opacity 淡入 | 旧 140ms + 上飘 4px，新 220ms，ease-out-quint | 正文列和目录树各一份。新内容只动 opacity（§11.5①）；快照里的 CSS 动画、光标、查找面板全关掉；连切时上一份快照直接换掉；减少动效时直接硬切。标题、分隔线、目录条目不再各自播入场 |
| 标题下分隔线 | `scaleX 0→1` | 450ms | 只在进工作区时播，换篇不重播 |
| 任务勾选 | SVG `pathLength` + 圆环 scale 脉冲 + 文字色 | `spring.snappy` | 三层同时，约 380ms |
| 命令面板 | 遮罩静态 backdrop-blur + opacity；面板从输入框那一栏往下展开 | `popoverCard` | 面板不缩放、不淡入（§10.1 第 4 条） |
| 下拉菜单 / 悬停卡片 | CSS 关键帧，只动 opacity | 140ms 进 / 100ms 出 | 以前带 scale + 位移，字先糊后跳 |
| 提示条（撤销删除、出错、通知） | 上滑 12px + 淡入，不缩放 | `tween.slow` | 不用 spring：收尾会跳半个像素 |
| 日历切月 | `AnimatePresence`，方向感知 | `tween.base` | 事件块只淡入，不 stagger |
| 主题切换按钮 | 图标旋转交叉淡入 | | |
| 悬停反馈 | 纯 CSS transition | 80ms | 极短的用 CSS |

### 10.4 减少动效

- `Shell` 上 `<MotionConfig reducedMotion={reduceMotion ? "always" : "user"}>`
- 应用内开关存 `localStorage.otw.prefs`，同时落 `<html data-reduce-motion>`（CSS 动画据此关闭，如 Logo 的笔画描边停在「写完」态）
- 组件里判断系统偏好用 `lib/motion.ts::usePrefersReducedMotion()`（直接问 `matchMedia`），**不要用** motion 自带的 `useReducedMotion()` —— `MotionConfig` 只要设过一次 `"always"`，它之后就一直返回 true，直到刷新页面

## 11. 编辑器（CodeMirror 6）

### 11.1 原理

文档**始终是 Markdown 源文**。装饰层对「光标不在的语法范围」隐藏标记（`Decoration.replace`）并施加排版样式（`Decoration.mark` / `Decoration.line`），光标一进入，标记在原位置重新出现。`#`、`**`、链接 URL 都能直接改，不存在富文本 AST 与 Markdown 互转导致的输入跳行。

解析器（`editor/markdownParser.ts`）：在 `commonmarkLanguage` 上自己拼 GFM + Superscript + Emoji，再加两个自定义 lezer 扩展 —— `$…$` / `$$…$$` 公式节点（必须在解析阶段整块认下来，否则 `$a*b$ 和 $c*d$` 里的 `*` 会配成强调）和单个 `~` 的删除线（按 GitHub 规矩，一个或两个波浪线都是删除线，不再是 Pandoc 下标；下标改走 `<sub>`）。`codeLanguages: languages`（`@codemirror/language-data`）让围栏代码按语言名懒加载对应解析器；配色由 `editor/codeHighlight.ts` 的 `HighlightStyle` 发类名、`globals.css` 的 `--code-*` 变量上色，只覆盖代码里的 tag，Markdown 自己的 tag（heading / emphasis / processingInstruction…）刻意不碰，免得和装饰层打架。

### 11.2 两层装饰（`MarkdownEditor.tsx`）

拆成两层是因为成本量级完全不同：

| 层 | 类型 | 负责 | 遍历范围 |
|---|---|---|---|
| 块级 | `StateField` | 折叠围栏行 / Setext 下划线行 / 分隔线行 / front matter 围栏行 / `[TOC]` 行，把表格、`$$` 公式块、块级 HTML、HTML 注释块、```mermaid / ```csv 围栏、收起的 callout 正文换成 widget —— 这些改变行结构，CodeMirror 要求必须来自 StateField；顺带收集引用标签、脚注正文（悬停预览用）、`*[缩写]: 全称` | 全文，但只下探 `Document / BulletList / OrderedList / ListItem / Blockquote`，`Paragraph` 只扫行不下探 |
| 行内 | `ViewPlugin` | 标记隐藏、加粗斜体、任务勾选框、列表符号（自动编号 / 按深度换符号）、语言名标签、图片、callout 徽章、脚注、双链、Emoji / 实体 / 硬换行替身、行内公式、行内 HTML 标签配对、`<br>` / `<img>` / 注释替身、定义列表、缩写提示、智能标点、`==` 源码规则 | 只处理 `view.visibleRanges`，成本与文档长度无关 |

拆分前一个 StateField 深度遍历全文，53KB 文档每次按键 5.3ms；拆分后 0.57ms。块级层给行内层一个 `foldedLines` 集合，被整行折叠的行不再渲染行内装饰。

块级层拿的是**全文**的语法树：CodeMirror 建状态时只同步解析开头约 3000 字符，剩下的交给空闲时的后台解析。以前块级层直接用 `syntaxTree(state)`，长文档刚打开时 `[TOC]` 只列出开头几节、后面的表格公式还是源码，要点一下（选区变化触发重建）才「展开」。现在先 `ensureSyntaxTree` 同步解析全文（80ms 预算，超大文档解析不完退回现有的那半棵），并且两层都在语法树换了一棵（后台解析推进）时重建。已解析完的树直接返回，40KB 文档上每次按键 / 移动光标的开销和改前一样（约 2–4ms，含 DOM 更新）。

块级替身还要报**估计高度**（`OtwWidget.estimatedHeight`）：CodeMirror 只画视口附近，没画过的块级替身默认按一行估 —— 一张 mermaid 图 300px、一张表几百 px 都被当成 24px，跳到远处时先按估计滚过去，上面的替身一画出来整页下沉。现在表格按行数、目录按条数、公式按 `\` 行数、代码块封口 / 分隔线 / 属性块封口按固定尺寸给估计；画过一次的按内容记住量到的真实高度（ResizeObserver，最多 400 条），切走再切回这篇直接用真值。

`selectionTouchesRange` 决定「光标在不在这个范围里」：空选区看 `head`，非空选区看是否相交。

### 11.3 注册表（`markdownStyleRegistry.ts`）

新增纯样式语法只需在这里加一行：

- `markdownStyleRules`：语法树节点名 → 类名，`kind: "mark"`（行内）或 `"line"`（整行）
- `hiddenMarkerNodes`：需要藏起来的标记节点（`HeaderMark`、`EmphasisMark`、`CodeMark`、`QuoteMark`、`LinkMark`…）
- `widgetByNode`：需要 DOM 表现的（`TaskMarker` → 勾选框、`HorizontalRule`、`Image`、`Table`、`Emoji`、`Entity`、`HardBreak`、`InlineMath`、`HTMLTag`、`Comment`）
- `markdownSourceStyleRules`：CommonMark 树不会合并成单节点的自定义行内语法，目前只剩 `==…==`，源码级匹配；配对不能跨段落、不能落在代码字面量里，对称标记还要求内容非空且首尾不是空白，免得 `a == b == c` 被当成高亮。（`<u>` 以前也在这里，现在所有行内 HTML 标签统一走语法树里的 `HTMLTag` 节点配对。）

方括号家族（callout 标签、脚注、双链、`[TOC]`）不走注册表：CommonMark 把没有定义的 `[文字]` 一律解析成短引用 `Link`，得在行内层按内容分流 —— `[!标签]` 在引用块首行是 callout，`[^id]` 是脚注，外面再套一层方括号的是双链，都不是的话看块级层收集的 `referenceLabels`：有定义才当链接，否则就是普通的方括号文本（以前任何 `[x]` 都被染成链接色并藏掉括号）。

所有 widget 在 `editor/widgets.ts`（公式和图表的替身单独在 `editor/math.ts` / `editor/diagram.ts`，因为它们要懒加载 KaTeX / mermaid）；表格单元格和 `[TOC]` 条目里的行内格式由 `editor/inlineDom.ts` 渲染成真实 DOM（不走 innerHTML）；HTML 的标签白名单、样式白名单和块级净化重建在 `editor/html.ts`；Emoji 短码表在 `editor/emoji.ts`，实体表在 `editor/entities.ts`，callout 的标签分类与图标在 `editor/callout.ts`，front matter 识别在 `editor/frontMatter.ts`，链接目标解析与打开在 `editor/links.ts`。

**HTML 的安全边界**：用户写的字符串永远不进 innerHTML。行内标签只是映射成装饰类（`<b>` 和 `**` 同一个类，`<span style>` 只放行颜色 / 字号 / 粗细那几个属性）；块级 HTML 先用 `DOMParser` 解析到惰性文档，再按白名单一个节点一个节点重建 —— 脚本、`on*` 事件属性、`javascript:` 地址、iframe / 表单 / 媒体整棵丢掉。KaTeX 的输出和 mermaid 的 SVG 是库自己生成的（用户原文都经过转义 / 净化），前者走 innerHTML，后者 DOMParser 解析后只收 `<svg>` 节点。

### 11.4.1 动效

编辑区里的动画只动 opacity / transform / stroke，从不改尺寸（CodeMirror 靠 `getBoundingClientRect` 量高度）；减少动效由全局规则统一收掉。

| 时机 | 动画 |
|---|---|
| 光标进入语法范围、标记重新出现 | 标记 160ms 淡入 |
| 光标离开、替身出现（列表符号、Emoji、徽章、封口、分隔线） | 140ms 淡入 |
| 表格 / 目录 widget 出现 | 淡入 + 向上 3px 落定（220ms） |
| 勾选任务 | 盒子 `scale 0.82 → 1.1 → 1` 弹一下，对勾 `stroke-dashoffset` 描边画出；悬停亮边 + 光晕，按下微缩 |
| 复制代码 | 按钮平时半透明，悬停封口时实起来；复制成功图标切成对勾描边 + 「已复制」1.4s |
| 图片 | 加载完成后 320ms 淡入，失败时显示 alt |
| 标题 | 悬停时左侧 `H2` 提示淡入并右移 4px 归位 |
| 链接 / 双链 / 目录条目 | 下划线色、底色、位移的 140ms 过渡 |
| 动态表情 | 露出视口就一直循环（一轮动作 + 700ms 停顿），滚出去停回静止帧；同时循环最多 48 个（见下）；单击从头再来；从选择器插入时先整个弹出来再做动作 |

### 11.4.2 动态表情

**为什么是 SVG + Web Animations，不是 GIF / Lottie。** GIF 只有 1 位透明（暗色主题下带白边）、256 色、位图在高分屏发虚、JS 控制不了播放。这套表情是自己画的线稿，SVG 就能表达：矢量、颜色走 CSS 变量跟主题变、能精确控制「看得见就循环 / 滚出去就停 / 减少动效时停在静止帧」，不用引 WASM、不用改 CSP。以后要接第三方的彩色动画表情再上 Lottie。

**源文。** Markdown 里只是短码 `:otw_<id>:`（lezer 的 Emoji 语法只认字母数字下划线，所以前缀用下划线）。别的编辑器打开看到短码；列表摘要、目录、表格单元格的 `textContent` 里换成对应的 Unicode（`lib/emojiText.ts`，和设计稿一一对应，单测守着）。

**设计规矩**（`animatedEmojiSet.ts` 文件头，`animatedEmoji.test.ts` 逐条守着）：24×24 画布，1.7 圆头描边 + 同色系淡彩（淡彩 = 色相 22% 混进纸色，暗色下自动变深）；要动的部件带 `data-a`，身上不许写 `transform` 属性；只动 transform / opacity / stroke-dashoffset；每段动画的最后一帧等于静止态（只在视觉上无缝的对称旋转可以例外，且要声明 `seamless`）；平时隐藏的粒子（`fx`）最后一帧必须回到透明；一轮不超过 2.5 秒。

**排版。** 外框只占一个汉字的位置（1em 高、落在基线下 0.12em），图画成 1.3em 绝对定位压在上面 —— 多出来的只是视觉溢出，行盒子永远不会被撑高。以前按 1.3em 做外框时，正文行高 1.4 的行会多 0.5px、标题多 4px，CodeMirror 的高度图就歪了（e2e 逐行比对过带 / 不带表情的行高）。

**编辑器行为。**
- `eq` 只比短码不比位置：在它前面打字时复用 DOM，动画不会从头再来
- 选区规则 `selectionEntersRange`：光标严格在短码内部、或选区只切到一部分时才展开源码；贴在两边、整个被选中都保持表情
- 插入时，前面紧挨着 `:词`（`12:30`）或 `]`（行首 `[标签]:` 是引用定义）先垫一个空格
- 一直循环，但只在看得见的时候：全局一个 `IntersectionObserver`（上下各多看 64px），露出来开始循环、滚出去 `stop()` 回到静止帧。自动开始的随机晚 0–700ms（停在静止帧上等），同屏同时露出来的一排不会齐步走
- 循环怎么省：每轮用一个计时器从头播一遍（各部件自己的时长、delay、重复次数），`fill` 只有 `backwards`。做完的部件回到底下的静止样式（等于最后一帧，单测守着），结束了的动画不再每帧参与样式计算 —— 设计稿里部件平均约 1/3 的时间是停着的（等 delay、等别的部件、两轮之间的停顿），这段时间不占帧。试过把「一轮 + 停顿」折成一条 `iterations: Infinity` 的动画，停着的时候照样每帧重算：无头 Chromium（软件渲染）同屏 39 个表情时每帧重算样式的元素 301 → 186，主线程占用 46% → 39%。也试过把动画烘进静止帧那张图里（CSS `@keyframes`，同款共用一张图），结果每个实例每帧都要重绘整张 SVG 图，绘制反而从 8% 涨到 26%，放弃
- 同时循环的上限 48 个，超出的停在静止帧排队，前面有滚出去的就依次补上；悬停排队中的、单击、刚插入的不受限。无头 Chromium 上 308 个表情铺满一屏：上限 80 时 p95 帧间隔 33ms，48 时稳定 60 帧（主线程 55%）；「减少动效」随时拨动都会跟着停 / 恢复
- **静止时是一张图**：替身的成本几乎全在浏览器给新 SVG 算样式（一个表情约 10 个元素，和 `color-mix` / `var()` 无关，只和元素数量有关）。静止帧改成 `<svg viewBox="0 0 24 24"><image href="data:…"/></svg>`：同一份 SVG 连同当前主题解析好的颜色（`--ae-*`、画布、墨色）和 `EMOJI_PART_CSS` 序列化成 data: 图，每个表情每套主题生成一次，所有实例共用；只在循环时把活的 SVG 叠上去（静止帧 `display: none`，不卸载），停下时摘掉。切换主题时 `MutationObserver` 盯着 `data-theme`，把页面上所有静止帧换成新颜色。拿不到主题颜色（样式表未加载、测试环境）时退回活的 SVG
- 为什么是 `<image>` 不是 `<img>`：`<img>` 的落点吸附到整设备像素，行内 SVG 按亚像素绘制，表情在一行字里的位置几乎总是小数 —— 用 `<img>` 时静止帧和动起来的第一帧差半个像素，一播就「抖」。外框也必须保持原来的尺寸和 viewBox（1.3em、`0 0 24 24`，图自己的画布扩到 `-3 -3 30 30` 放在 (-3, -3)）：换成数学上等价的更大外框，像素吸附会让整个表情挪一个设备像素
- 画质验证（新旧两版并排逐像素比较，当时的 24 个表情 × 静止 + 8 帧，亮暗两套；之后新增的表情同样核对了静止帧图片和活 SVG 的一致性）：所有动画帧逐像素一致（最大差 0）；静止帧与原来的矢量渲染最大差 8–12/255，只在抗锯齿边缘，任何一个像素都不超过 16/255（正文 17px 1x / 2x、H1 38px、H2 30px 都测过）
- 成本（无头 Chromium 实测，优化前 → 后）：一屏 400 个表情首次渲染 217ms → 103ms（样式重算 150 → 49ms）；一屏 30 个 11.4 → 9.0ms；每个表情的 DOM 元素 10.5 → 5.4（其中 2.4 个是 CodeMirror 给行内 widget 加的占位）；400 个在屏时打字中位数 4.4 → 3.8ms；连续滚动 2000 个表情的长文档，超过 20ms 的帧 16–29 → 12–16，样式重算 760 → 650ms（关掉动效时 510 → 300ms）

**选择器（`Mod-e`）。** 贴着光标弹出，下面放不下翻到上面、左右夹在窗口里；宽度量面板的 `offsetWidth`、高度量里面的内容（面板自己挂上时还是入场第一帧那一窄条）。最上面一行是最近用过的（`localStorage.otw.emoji.recent`，读写都兜住异常），下面八组（心情、干劲、在路上、日常、打工人、吃瓜、表态、小动物）各一行；网格限高 322px 滚动，键盘走到看不见的格子时滚过去（只在键盘移动时滚，悬停不滚，免得边上的格子一碰就跳）；上下都放不下完整面板时（矮窗口、光标在中间），挑空间大的一侧、把网格压矮到正好放得下（`placePicker`，最少留 120px）；方向键按行列走、回车插入、Esc 关闭并把焦点和原选区还给编辑器；输入框里打字就是搜索（中文、近义词、拼音、英文、Unicode 本身都行），输入法组字时的回车不算。当前格循环播放，其余静止（一屏几十个在同一个小面板里一起动太吵）。格子里的静止帧**不用图**（`mount(host, { image: false })`，直接是活的 SVG）：每张不同的 `data:` SVG 图浏览器都要同步建一个隔离的 SVG 文档，48 个一起建，以前 4 倍降速 + 2x 屏上首次打开主线程卡 0.75–0.94 秒、之后每次 0.2 秒以上；现在首次约 0.3 秒、之后约 0.1 秒。底栏的回车画成图标不写 ↵ —— 界面字体里没有这个字，第一次画它要把系统字体找一遍（`popupGlyphs.test.ts`）。入场动画（`popoverCard`，模板选择器同款）：卡片从贴着光标的那条边展开，第一帧露出贴光标的那一栏（往下开是搜索栏，往上开是底栏），280ms、`cubic-bezier(0.32, 0.72, 0, 1)`；动的是面板的 `height`（§10.1 的例外），里面的内容钉在最终位置上，不缩放、不变透明。两种做法都踩过：整块从透明淡入，半透明的那 100ms 里表情格子和正文叠在一起，看着像正文跳了一下；实心卡片 `scale 0.97 → 1`，带字的层被当位图拉伸，前 200ms 字发虚，撤掉 transform 那一帧字一下变清楚还挪一点（「先糊、再抖一下」）。往上开的面板用 `bottom` 定位，内容 `justify-end` 贴着下边排，展开时那条边不动；位置对齐到物理像素（`pinnedEdge`），半个像素上的边框和字会发虚。面板用 `overflow: clip` 不用 `hidden`：hidden 仍是滚动容器，展开途中键盘走到还没露出来的格子，`scrollIntoView` 会把整块内容卷上去。往上开还是往下开在挂载那一帧就定：面板尺寸是定的（292 × 398），先按常量算位置，挂上后再按量到的尺寸校正。两个 CodeMirror 的坑：
- 光标带折行方向（`assoc`，按 End 或点在折行处）时，编辑器一失焦 CodeMirror 就会在下一次测量里 `enforceCursorAssoc`，改写 DOM 选区顺手把焦点抢回正文。打开前先把方向清掉，Esc 关闭时还原
- 打开走 `requestMeasure`：坐标在读阶段量，并且排在上一个按键留下的测量之后
退场 200ms：折回贴光标的那条边，剩不到 10px（只剩空白边、没有字）时才淡掉，最后不留一条带阴影的细线。退场中不接点击、不再监听外部事件（否则会把紧接着新开的选择器关掉）；每次打开换一个 key，上一个没退完时再按快捷键得到的是全新的实例。

### 11.4.3 模板（`/模板`）

只在某一天（今日TODO、日历某天）和 GOAL（周 / 月 / 年）里有，笔记不接（`DocumentView` 按保存目标算出 `TemplateContext` 传给编辑器，只 import 类型，模板本身留在编辑器分包里）。空文档显示占位「…或输入 /模板 从模板开始」。

**触发。** 一行里只写着触发词、光标在它末尾：`/模板`，也认 `/model` `/template` `/mb` `/muban` `/tpl`（不分大小写），以及 `、模板` —— 中文输入法下 `/` 键打出来的是顿号。只认打字（`input.type`，含输入法上屏），撤销回来的、外部回填的不算，否则撤销一次模板又弹出来；引用、列表里的（`> /模板`、`- /模板`）不算。

**选择器（`TemplatePicker.tsx`）。** 焦点一直留在正文里，像自动补全：接着打字、退格、光标挪走、点到别处、滚轮、窗口失焦，触发词不在了就收起。方向键 / Tab、回车、Shift+回车、Esc 由编辑器 `Prec.highest` 的按键转过来（比列表续行、缩进先拿到），**输入法组字时不转**（`view.composing`）。面板上 `mousedown` 一律 `preventDefault`，否则点一下正文失焦、选择器就收了。只列这篇文档能用的模板（某一天 4 个、周 3 个、月 2 个、年 2 个）；右边是当前那个的缩略预览：按这篇的日期现算出来，用占位渲染器排成一页纸再 `scale(0.6)`，底部渐隐。定位复用表情选择器的 `placePicker`（`nudge` 让面板对齐行首）。

**插入。** 回车：用模板换掉触发词那一行，和上下文之间各留一个空行（表格、列表别粘到前后的段落上），光标停在模板里 `‸` 的位置。Shift+回车（正文里除了触发词还有东西时才给）：替换全文 —— 开头的属性块留着，原文里还没勾掉的 `- [ ]` 统一成顶层任务、去重，收进最后的「## 待续」，一条不丢。今天延续了之前某天的内容时，早上 `/模板` + Shift+回车就是「用模板开始新的一天，没做完的带上」。两种都是一次普通编辑（`userEvent: "input.template"`），撤销一下回到 `/模板`，自动保存照常。

**模板是按日期现算的 Markdown**，和日历打通：

| 文档 | 模板 | 要点 |
|---|---|---|
| 某一天 | 今日计划 / 时间块 / 晚间复盘 / 三行日记 | 主线 callout + 三件要事；时间块是「计划 / 实际」对照表；复盘是 1–5 打分表 + 四句 |
| 周 | 周计划 / 周复盘 / 习惯打卡 | 周计划「每天一件事」是这一周七天带日期的空任务 `- [ ] @2026-09-28 `（日期在前、末尾留空格：点在行尾接着打就行），写上事情就进日历；打卡表列头是这一周的日期 |
| 月 | 月度目标 / 月度复盘 | 按月里的每一周（截在月内）拆「每周节奏」；复盘是继续 / 停止 / 开始 |
| 年 | 年度目标 / 年度复盘 | 六个方面表 + 季度拆解 |

计划类模板把复盘写成带日期的任务（周日 20:00 周复盘、月末月度复盘、季度末 / 年末回顾），会出现在日历的那一天；已经过去的节点不写。只有日期、没写事情的任务不进日历（§5.4）。写法上的约定：一个模板只在主标题上放一个动态表情；表格分隔行用 `:---`（占位渲染器要三个 `-`，预览靠它）；表格是主体的模板，光标停在标题末尾（光标在表格里时表格显示成源码）。`templates.test.ts` 守着每个模板恰好一个 `‸`、每张表格子数一致、预览里认得出表格。

### 11.4.4 附件（粘贴截图、拖文件进来）

- 粘贴：剪贴板里有文件（截图、从浏览器复制的图）就存成附件；剪贴板里同时有文字的按文字粘 —— 从 Excel 复制单元格会顺带一张截图
- 拖放：浏览器里是 HTML5 drop；桌面端窗口开着 `dragDropEnabled`，系统拖进来的文件 WebView 收不到 drop，走 Tauri 的 drag-drop 事件（路径 + 物理像素坐标，落在这个编辑器上才接）。拖到正文上方时画一条主色竖线标出插入位置（零宽，正文不挪）
- 存法（`Vault::attach`）：仓库根下的「附件/」；文件名去掉文件系统和 Markdown 链接里有特殊含义的字符、空白换成 `-`（`![](a b.png)` 会被空格截断）；剪贴板图片统一叫 image.png，换成「粘贴-时间」；同名同内容直接用已有的，同名不同内容加 `-2`；上限 50 MB。粘贴的内容以 base64 过 IPC（一字节一个数字的 JSON 数组太大）
- 插法：`![名字](../附件/名字.png)`，路径相对**文档自己所在的文件夹**（和 Typora、Obsidian、VS Code 一样，搬到别的编辑器里照样能看）；不是图片的插普通链接。图片自己占一行、光标落到下一行 —— 光标挨着图片时显示的是源码，插完就该直接看到图
- 显示：编辑器的 `imageBaseDir` facet = 仓库根 + 文档所在的文件夹（`Note / DayDoc / Goal` 都带 `relPath`，没写过的日子 / 周期是它将来的位置；仓库根来自启动时的 `vault_info`）。相对路径在 `resolveImageSource` 里拼上它、消掉 `..`，再转 asset 协议。改名挪了位置、仓库路径晚到时只换这个 facet，图片重画
- 浏览器预览没有仓库文件夹：mock 把粘贴的图片直接写成 `data:` 地址

### 11.5 编辑器与动画的关系

CodeMirror 靠 `getBoundingClientRect` 定位光标和测量 widget 高度，两条硬规则：

1. **祖先不得跑 layout / transform 动画时挂载**。工作区进场因此是纯 opacity；专注模式的动画在 chrome 层而不是正文层
2. **块级 widget 的留白必须在边框盒里（padding），不能用 margin** —— margin 不在 `getBoundingClientRect` 里，高度图比真实布局短，点击会定位到错误的行。`CodeFenceWidget`、`TableWidget`、`HorizontalRuleWidget`、`ImageWidget` 都遵守；`widgetSpacing.test.ts` 用正则守着 CSS
3. **光标进出时，折起来的替身和露出来的源码行一样高** —— 否则点进一个块，它上面那一行一变高矮，整块内容连同刚点的那一行一起跳。代码块 / 属性块的围栏封口和 ``` / `---` 源码行共用一组尺寸变量（`--fence-*`、`--frontmatter-*`），源码行用 `::before` 画出同样的圆角框（以前源码行比开头封口矮 15px、比结尾封口高 3px，框也露着口）；分隔线露出的 `---` 行高等于分隔线；整行注释的小标记等于一行源码；等宽的源码标记（短码、实体、脚注、callout 标签、行内 HTML、行内公式）`line-height: 1`，不再把所在行撑高 0.6–1px。逐行比对（光标放到「语法全览」每一行，量周围 ±10 行的高度）：会改变别的行高度的从 211 行降到 25 行，剩下的是 Setext 下划线露出、折叠的 callout 展开（都是设计如此），以及 [TOC] 和几张在无网络的测试环境里加载失败的外链图片
4. **正文区的鼠标指针一律是 I 形**，替身（列表符号、表格、代码块封口、HTML 块、图表、目录、动态表情）和块之间的留白也是 —— 以前替身是箭头、表情是手形，滚动时内容从静止的鼠标底下滑过，指针来回跳，看着一闪一闪。只有真正能点的控件（勾选框、复制按钮、目录条目、折叠按钮、脚注徽章）是手形；通用规则用 `:where()` 压到最低优先级，不盖它们

### 11.6 持久化

- `createDebouncedSaver(save, 400)`：串行写链；保存中继续输入不会覆盖正在写的版本；失败版本放回队列，下次 flush 重试
- 外部回填用 `externalSync` annotation 标记，不触发保存；**只在本地没有未同步编辑时回填**（P0：某天备注异步到达时不能覆盖用户已输入的内容）
- `externalRevision`：`initialMarkdown` 变了而它没变，是自己的保存回来了；它也变了，才是别的程序改了文件。这时本地还有没同步的编辑 → 编辑器里的留着，回调 `onExternalConflict`，上层在下次保存前把外部那一版另存成冲突副本（§5.5）
- **按文档缓存编辑器状态**：卸载时把 `EditorState` 存进一个 12 篇的 LRU（键 = `saveKeyOf`），同一篇再挂上来且正文一字不差时直接用它建视图 —— 解析好的语法树、块级装饰、撤销历史都在，不再跑 `ensureSyntaxTree`。握着上一个实例闭包的那一截配置（保存器、Mod-S / Mod-E、双链点击、目录联动）放在 `session` compartment 里，复用时 `reconfigure` 成新实例的；光标回到开头，开着的查找面板关掉。生产包里 66KB 的「语法全览」切回来 160–220ms → 约 58ms（第一次打开仍要解析，约 124ms）
- 目录树通过 `EditorOutlineHandle` 直接用行号 `scrollIntoView`，不依赖 DOM 锚点
- 中文 IME：`spellcheck="false"`；CodeMirror 自身处理 composition，没有额外门控

### 11.7 占位预览（`lib/markdown.tsx::renderMarkdown`）

只在 `doc.editor` 为空（数据未到）或空状态文案时渲染，返回真实 React 节点（无 `dangerouslySetInnerHTML`）。它的语法覆盖比编辑器窄（无 Setext、无图片、无 `<u>`、无引用链接），但因为几乎只渲染空串，实际不影响体验。`buildOutline`（ATX / Setext / callout 标签）是真正在用的部分；摘要和字数在 `lib/plainText.ts`。

## 12. 各模块现状

### 12.1 笔记

- 列表：标题本地筛选（不走全文搜索，见 §6.3）、三种排序（更新 / 创建 / 标题，单选菜单）、置顶分组、选中高亮 `layoutId` 滑动、`+` 新建（等后端分配 id，建在当前文件夹里）
- **文件夹**（§5.8，`views/NotesView.tsx` + `views/notes/`）：列表栏是「当前文件夹」的视图 —— 置顶、这一层的文件夹、直接放在这一层的笔记。「全部笔记」里的置顶包括所有文件夹里置顶的笔记，摘要前带上所在文件夹；搜索标题时搜所有文件夹，结果同样带文件夹
  - **就地展开**：文件夹的图标位悬停时变成箭头（有东西可展开的才变），点开在原地列出子文件夹和里面笔记的**标题**（一行一篇，不带摘要），子树左边一条淡竖线对着上一层图标；Alt + 点箭头 / Alt + → 连子文件夹一起展开；← → 收起展开。展开了哪些记在本机（`localStorage: otw.folders.expanded`）。展开 / 收起只动高度，里面的行原地不动
  - **进出**：点文件夹的其余地方是进去（展开出来的任何一层都能直接进）；列表整列朝进出的方向挪一小段，动的是 `left` 不是 transform（合成层上位移的字在动画里是灰阶抗锯齿，停下那一帧才变清楚）。进了文件夹，搜索框下面一行面包屑回上层 —— 不放在标题上方：顶上 38px 是自绘标题栏的拖窗口带（z-40），列表栏在 z-30 的层里，放那儿的按钮点下去是在拖窗口。退回上层时刚出来的那个文件夹闪一下
  - **标题是切换器**（`FolderPicker`）：点开是全部文件夹的树，打字筛选，↑↓ / 回车，平级文件夹之间直接跳；和行菜单里的「移动到…」是同一个组件。盖在列表上，实心、按高度从顶上展开（`popoverCard`），里面的字不动
  - **拖笔记**（`views/notes/noteDrag.ts`）：指针事件自己做 —— 窗口开着 `dragDropEnabled`（拖文件进来当附件），Windows 上 WebView 里的 HTML5 拖放会被它吃掉。挪过 5px 才算拖；能放的地方带 `data-drop-folder`（文件夹行、面包屑）；停在收起的文件夹上 0.8 秒它就地展开，接着往子文件夹里放；影子卡片写着「移到「…」」，位置走 `left/top`；Esc 取消；松手那一下的 click 吞掉
  - 新建文件夹（标题右侧的按钮，或文件夹「…」→ 新建子文件夹）、改名都是就地一个输入框：回车确定、Esc 取消、点别处也算确定。文件夹「…」：新建子文件夹 / 重命名 / 在文件夹中显示 / 删除文件夹（连同里面几篇写在菜单上）
  - 起名回车那一下：store 先按后端的规矩（`cleanFolderName` / `uniqueChild`，和 `layout::folder_name` 一致）把结果放进列表，输入框和文件夹同一帧换过来，不等 IPC 那一个来回；后端给的路径不一样再改正，失败退回。输入框往左多出 7px，框里的字和起好名之后的名字同一个位置、字号、字重。新名字落在输入框那一格就原地换，字不挪；排到别处去了，输入框那一行按高度收起、新行在它的位置按高度展开（`entryMotion`，下面的行跟着平滑挪，不是瞬间跳），再闪一下
  - 文件夹切换器里的列表 `shrink-0`：卡片按高度展开的那几帧要是把它压扁，会冒出滚动条、列表窄一条滚动条宽，右边的数字往左挪 10px，展开完一下跳回去（逐帧量过）
  - 移动、删除文件夹和删除笔记共用底部那条「撤销」提示（`UndoToast`，后发生的顶掉前一条）；东西放进了哪个文件夹，那一行闪一下
- 行菜单 `RowMenu`：置顶 / 移动到… / 在文件夹中显示 / 归档 / 删除（Radix DropdownMenu + Motion）
- 正文：编辑器；标题可编辑（随内容长高的 textarea，长标题折行）；右下「历史版本」（§5.9.11）、「在文件夹中显示」和删除（每种文档都有前两个）；专注模式入口
- 双链 `[[标题]]`：编辑器内按标题显示，Mod + 点击跳转（`app/navigate.ts::openDocument`，归档里的也行）
- **改标题时改别处的链接**（`Vault::relink`，`vault/links.rs::retarget`）：标题框写完（回车 / 失焦）存好之后，别的文档（笔记、某一天、目标，归档的也算）里链到旧标题的 `[[…]]` 改成新标题：只换标题那一段，`|别名`、`#小节`、`^块` 和两头空白原样留着，代码里的、转义的不动，自己链自己的不动（它正开在编辑器里）。正文按磁盘上的改，属性块原样留着。底部提示条「已把 2 篇里的 [[周报]] 改成 [[月报]]」可以撤销：每篇换回改之前的全文，改完之后又被改过的那篇不动。三种情况不改，提示一句为什么：新标题里有 `[ ] | # ^`（写进双链会被拆成别名、小节）；还有别的笔记叫旧标题（那些链接本来就指着它）；新标题已经有别的笔记在用（改了就分不清链到哪篇）。只改了大小写不算改名。刚新建、还是占位标题「无标题笔记」的那篇不改。不在每次保存时改：标题只在写完时存一次，中途的样子不会碰巧和别的笔记撞名
- **反向链接**（`Backlinks.tsx`，正文后面、状态栏前面，只在笔记上）：后端 `Vault::backlinks` 扫索引里正文含 `[[` 的所有文档（`vault/links.rs`：`[[标题]]` `[[标题|别名]]` `[[标题#小节]]` `[[标题^块]]`，标题去空白不分大小写，围栏代码和行内代码里的不算，自己链自己不算），没打开过的某一天、目标也算。每条：图标（笔记 / 某一天 / 目标）+ 标题 + 已归档 + 「N 处」，下面最多三行上下文（去掉列表符号、任务框、引用、井号，太长截出链接附近一段），双链画成小块、链到这一篇的用主色。点标题打开那一篇，点某一行打开并滚到那一行、光标放在行尾（`pendingAnchor.line` → `EditorOutlineHandle.scrollToLine`）。任何文档存了半秒后重取；没取回来、或者一条都没有时整块不画（以前没有时也画一段「还没有别的文档链接到这里…」，每篇笔记底下挂着同一段说明，只是噪音）
- 空状态：一篇都没有时正文区是插画 + 「新建笔记」，列表栏只留一行小字；搜不到时列表栏是放大镜插画（`EmptyArt.tsx`）

### 12.2 今日TODO

就是今天这一天的文档 `日记/YYYY/YYYY-MM-DD.md`（§7.3）。标题可编辑，空标题显示占位「无标题笔记」。状态栏会写明「延续自 9月14日，还没有今天自己的记录」或「今天的内容会延续到明天，直到你改动它」。一行里输入 `/模板` 选模板（§11.4.3）；Shift+回车替换全文时，延续来的没做完的事收进「待续」。

### 12.3 /GOAL

一个周期一篇（`目标/2026/2026-W39.md` 等）。分段「周 / 月 / 年」；标题由 `goalTitle(horizon, periodStart)` 算出，不可编辑；没写过的周期是空白编辑器，第一次保存才建文件。状态栏：周期范围 + 字数 + 上次更新。一行里输入 `/模板` 选这个尺度的模板（§11.4.3），日期、周数、复盘节点按这个周期算好。

### 12.4 日历

- 月历面板：固定 6×7 网格、ISO 周数列、每周自成一个 grid 行（整行高亮用 `inset-0`）、方向感知切月、「今天」按钮只在离开今天时出现
- 两套颜色语义：主色 = 时间光标（今天、选中圈）；墨色 = 有没有写（`markedDates` 的日子数字加深 + 墨点）
- 右侧分段「日TODO / 周·月·年 GOAL」：日 = 选中那天的文档 + 「当日安排」（别的文档里写着那一天的 `- [ ] … @日期`，§5.4；`ActionItem` 勾选走 `task_toggle`，改的是原文件）；周月年 = 选中日期所在周期的 GOAL
- `calendarMarked` 一次取 2000–2100 全范围，保存后本地增删

### 12.5 归档

列表按 `archived_at` 降序；分类 · 日期；悬停旋转的恢复按钮；正文带「已归档 · 日期」横幅，仍可编辑，正文后面同样有反向链接。归档空了是盒子插画。

### 12.6 扩展

整页视图，不走 `DocumentView`。`extensions/catalog.ts` 定义 `ExtensionManifest`（schemaVersion 1、id 正则、≤2MB 包）和 `ExtensionCatalogProvider` 接口；当前实现 `localExtensionCatalog`：官方占位条目（数学公式、Mermaid、增强 Callout…，全部 `downloads: 0`）+ 本地导入的清单存 localStorage。**没有扩展运行时**，「下载」不做任何事。接口留给以后的审核服务 / CDN。

### 12.7 命令面板

`Mod-k`，自绘浮层（Motion `AnimatePresence`，非 Radix）。四组：跳转（六个工作区）、笔记（本地按标题 / 摘要过滤）、文件（在文件夹中显示当前文档、打开笔记文件夹、更换笔记文件夹…）、外观（亮 / 暗 / 跟随系统 / 减少动效）。方向键 + 回车；捕获阶段处理 Esc 并 `preventDefault`，专注模式的 Esc 在冒泡阶段看 `defaultPrevented`，两者不打架。

### 12.8 提醒卡片（已移除）

原型右下角有一张提醒卡片，文案是写死的两套（笔记 / GOAL），背后没有任何提醒调度，还压着目录树的底部，已经删掉。要做提醒得先有调度，见 §16。

## 14. 构建与发布

### 14.1 `tauri.conf.json` 要点

- 窗口：1440×900（最小 940×620），`decorations: false`，`visible: false`，`backgroundColor: #F1F1ED`（和 rail 同色，show 前不闪白）
- CSP：`default-src 'self'; img-src 'self' asset: http://asset.localhost data:; style-src 'self' 'unsafe-inline'; connect-src 'self' ipc: http://ipc.localhost`
- 打包目标：`nsis`（`installMode: currentUser`，中英文）、`dmg`（macOS ≥ 13）、`appimage`、`deb`；WebView2 用 `downloadBootstrapper`；`createUpdaterArtifacts: true`（安装包旁边多出 `.sig`，见 §14.4）
- 不写 `version`：用 `Cargo.toml` 的。版本号只在 `package.json` 和 `Cargo.toml`（连同 `Cargo.lock`）两处，`pnpm bump 0.2.0` 一起改，`src/content/changelog.test.ts` 对它们是不是一样
- `plugins.updater`：`pubkey`（更新签名的公钥）、`endpoints`（GitHub Releases 上的 `latest.json`）、Windows 用 `passive` 安装（只有一个进度条）
- capabilities：`core:default`、`core:window:allow-start-dragging`、`opener:default`、`window-state:default`（在文件夹中显示、选择文件夹对话框、检查和安装更新都在 Rust 命令里调，前端不需要额外权限）

### 14.2 插件

`single-instance`（二次启动拉回已有窗口）、`window-state`（记忆位置大小）、`opener`、`dialog`（只在 Rust 里用：选择仓库文件夹、确认是否拷贝）、`updater`（只在 Rust 里用，§14.4）。**没有** notification、global-shortcut、autostart。

updater 停在 2.12（`~2.12`）：2.13 起要 tauri 2.12，这里还是 2.11。只开 `native-tls`（和 ureq 一样用系统 TLS，不带 rustls / ring），不要 `zip`（那是给 Tauri v1 的压缩包格式的）。

macOS 上 `openssl-sys` 用 `vendored`（`Cargo.toml` 里只对 macOS）：git2 的 `https` 在所有 unix 上都带着它，可 macOS 上 libgit2 走 SecureTransport、HTTP 走 Security.framework，没人调 OpenSSL。不 vendored 的话，在 Apple 芯片的 CI 机器上交叉编 Intel 版找不到 OpenSSL、编不过；Apple 芯片版会动态链上 Homebrew 的 libssl，没装 Homebrew 的 Mac 打不开。发版 CI 用 `otool -L` 查 macOS 的程序有没有链 Homebrew 的库。Linux 照旧链系统的 OpenSSL（CI 装 `libssl-dev`）。

### 14.3 未做

代码签名（Windows Authenticode、macOS 公证）：不做的话第一次安装会被 SmartScreen / Gatekeeper 拦一下，之后经 updater 装的不会。发版的 CI、Gitee 镜像见 TODO。

### 14.4 自动更新（`src-tauri/src/update.rs`）

**发版**：版本号 + `src/content/changelog.md` 最上面写这一版的更新说明 → CI 打包、用私钥给安装包签名、生成 `latest.json`（版本、更新说明、每个平台的下载地址和签名）→ 放到 GitHub Releases。私钥只在 CI 的 Secrets 和发版人自己手里，丢了的话已经装上的用户就再也收不到自动更新。

发版流程在 `.github/workflows/release.yml`（发版的事归 Claude，更新说明也是它写）：`pnpm bump 0.2.0` → 写 changelog 那一节 → 提交 → `git tag v0.2.0 && git push origin master v0.2.0` → CI 检查版本和更新说明（`scripts/release-notes.mjs`）、跑测试 → 四个打包任务（Windows、macOS 两种芯片、Linux）签名、传进草稿 Release → 四个都成了才镜像到 Gitee → Gitee 也成了才把 GitHub 的草稿转成正式发布。两边一起上线，哪一步挂了都不上线，修好重跑失败的任务就行。Actions 页面手动 Run workflow 是试打包：安装包在 Artifacts 里，不建 Release、不查 changelog，顺带检查 Gitee 令牌能不能推。

**Gitee 镜像**（`scripts/gitee-release.mjs`，仓库 `hyxzs111111/on-the-way`，令牌在 Secret `GITEE_TOKEN`）：代码和 tag 推过去，建同名发行版、传安装包（不传 `.sig`，签名在 latest.json 里），latest.json 的下载地址换成 Gitee 的，放进固定的发行版 `updater` —— Gitee 没有 `releases/latest/download/`，应用查的是 `…/releases/download/updater/latest.json`。Gitee 的规矩（2026-10 实测）：公开仓库的附件不登录就能下；单个附件不超过 100 MB（超的跳过，latest.json 里它还指向 GitHub）；一个仓库的附件一共不超过 1 GB，所以只留最近两版。Linux 的 AppImage（八十多 MB）不传 Gitee：0.1.0 第一次发版时就挂在传它这一步，AppImage 的安装和更新走 GitHub。上传断了（连接被掐、超时、5xx）会重试，出错写成 `::error::` annotation，不登录也能从 `check-runs/<job id>/annotations` 读到原因。

**两个地址**：tauri.conf.json 的 `endpoints` 是 Gitee 在前、GitHub 兜底。`update.rs` 一个地址一个地址试，从取 latest.json 到下载、验签哪一步不行，整条换下一个地址 —— 插件自己只管「latest.json 取不到就换」，可国内常见的是 GitHub 的页面打得开、安装包下不动。本机用一个安装包是 404 的 latest.json 在前、正常的在后走过一遍：先失败、记一行，再从第二个地址下好，导航栏出现「新版本」。

`createUpdaterArtifacts` 开着，`tauri build` 打完包就要签名：要 `TAURI_SIGNING_PRIVATE_KEY`（私钥内容或文件路径，tauri-cli 2.11 不认 `_PATH`）和 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`，没有就报「A public key has been found, but no private key」、退出码 1（安装包已经生成，只是没有 `.sig`）—— 公钥空着的时候也一样。有的话安装包旁边多一个 `.sig`（本机用测试密钥打过 debug 包确认过）。

**查**：窗口出来（`ready`）以后 20 秒查第一次，之后每 6 小时；连不上半小时后再试，不报错（离线是常态）。请求走同步的代理（应用里填的 > 环境变量 > 系统代理，§5.9.4），每个地址最多等 20 秒。公钥没填就不查；开发时（debug 构建）也不查，除非设了 `ONTHEWAY_UPDATER_ENDPOINT`。

**下**：查到新版就在后台下载（最多 15 分钟），下完先验签，对不上就当没查到、下一轮再来。下好了才发 `update-ready` 事件 —— 用户看到提示时新版已经在本机了，点了只等重启。Linux 的 deb / rpm 要 root 才能装，不下载，只提示，「去下载」打开下载页（`UpdateInfo.manual`）。

**提示**（`components/UpdateDialog.tsx`、`Sidebar.tsx` 的 `UpdateRow`）：导航栏同步那一行上面多出一行「新版本 0.2.0」，图标是强调色的 `CircleFadingArrowUp`，出现时只淡入、箭头往上探两下；收起导航栏时只剩图标。不弹窗、不标红（红色在这里是出错）、不挨着 Logo（收起时 Logo 只剩一个「O」）。点开是新版本卡片：版本号、发布日期、更新说明，「稍后」和「重启并更新」。「稍后」只是关上卡片，那一行留着直到装上；没有「跳过这个版本」。命令面板「帮助」里是「检查更新」，有新版时换成「更新到 0.2.0…」。

**装**（`update_install`）：前端先把看到哪、编辑器里的、存失败留下的草稿都写盘（和关窗口一样），存不上就不装。Rust 记下窗口位置（window-state 平时退出时才存）、藏起窗口、开着同步就推一轮（最多 3 秒），再交给安装包：Windows 上安装包接手后进程直接结束（`process::exit`，不经过关窗保护，所以上面那些得先做），装完由安装包把应用拉起来；macOS / Linux 换好文件后 `restart()`。装不上就把窗口拿回来、重新开起同步，卡片里说原因。

**升级后的更新说明**：`config.json` 记着上一次启动的版本（`lastVersion`，`boot::note_version`）。比它新就是刚升级上来：开场动画落地后弹一次「更新说明」卡片，内容是 `changelog.md` 里旧版之后、到这一版为止的几节；新装的（之前没有配置文件）、同一版、降级回去的都不弹，这一版没写说明也不弹。更新说明随安装包带，不写进用户的笔记仓库。命令面板「这一版的更新说明」随时能再看。

**本机把整条路走一遍**：`pnpm tauri signer generate` 生成一对测试密钥，用 `pnpm tauri signer sign` 给一个随便什么 exe 签名，写一份 `latest.json` 用 `python -m http.server` 放出来；启动时设 `ONTHEWAY_UPDATER_ENDPOINT=http://127.0.0.1:端口/latest.json`、`ONTHEWAY_UPDATER_PUBKEY=<测试公钥>`（只在 debug 构建里认），再配上 `ONTHEWAY_VAULT` / `ONTHEWAY_DATA_DIR` 指向临时文件夹，不碰真实笔记。

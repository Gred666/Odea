# 桌面端实测

在这台机器上把桌面端真的跑起来验的做法和坑。环境的问题（cargo、MSIX 容器、127.0.0.1）在 `环境.md`。

## 用户自己的 Odea 一直开着

用户的 Odea 在 `E:\Odea\odea.exe`，别动它，也不用请用户关。

- 同一个 identifier 的开发版一起来就退出（退出码 0：单实例把参数转给了用户那个，那边可能弹一下）。换一个 identifier 并排跑：
  `pnpm tauri dev --config <只写了 {"identifier":"dev.odea.xxx"} 的 json 文件>`；构建用 `TAURI_CONFIG='{"identifier":"dev.odea.xxx"}' cargo build`
- 测的时候会在用户屏上弹窗口、动鼠标、弹通知：先跟用户说一声；测完把开发版的进程（`target\debug\odea.exe`）停掉

## 拿不同的前端打两个 exe 来比

量启动这类「只差前端」的比较（2026-11-12，`1110审查与研究.md` §5.3.1）：两份前端各 `vite build` 到一个目录，
`pnpm tauri build --no-bundle --config <json>`，json 里写单独的 identifier 和 `build.frontendDist`、`"beforeBuildCommand": ""`。

- `frontendDist` 写 `C:/…` 这种绝对路径会被当成 scheme 是 `c` 的网址：前端根本没嵌进 exe（两个 exe 一样大），
  窗口去开 `file:///…/index.html`。要写 `\\?\C:\…`（JSON 里转义成 `"\\\\?\\C:\\…"`）
- 为了快：`CARGO_PROFILE_RELEASE_LTO=false`、`CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16`、`CARGO_PROFILE_RELEASE_INCREMENTAL=true`，
  `CARGO_TARGET_DIR` 放 `%TEMP%`（别碰 `target/debug`，可能正有人在用）。冷编 3 分半，换一份前端再编 40 秒到 1 分钟。测完把那个目录删了（3 GB 多）
- 量的时候数据目录、`WEBVIEW2_USER_DATA_FOLDER` 都放 `%TEMP%`（`环境.md` 的 MSIX 那一条），经 DevTools 协议连上、关缓存、刷新

## 给用户的测试包别覆盖

- **出过的事**（2026-10-18）：重打协作测试包时，脚本开头 `rm -rf src-tauri/target/collab-test` 把用户正在主力电脑上运行的测试版的
  exe、仓库、配置删了（MSYS 的 `rm` 连运行中的 exe 都能删），只剩被锁住的索引
- **根因**：用户自己按步骤测，测试包就是他们正在用的东西，不是临时文件
- **怎么办**：新版本的包放进新的文件夹（collab-test-2、-3……），不覆盖、不删旧的；要删旧的先用 `Get-Process` 查有没有从那里运行的进程，
  有就让用户先关

## 起两个实例（协作、团队仓库）

做法在 `协同编辑.md` §19.2、§23.5，这里只记容易踩的：

- A = `launch.json` 的 `odea-team-a`（tauri dev，调试端口 9333），B = `odea-team-b`（release，
  `--config '{"identifier":"dev.odea.collab-b"}'` 构建，端口 9334）
- 用 `ODEA_VAULT` 打开的仓库不进 config.json 的 vaults 列表：要测跟着仓库记的东西（比如窗口 `placement`），
  先往临时数据目录的 config.json 里放一条
- 驱动脚本走 WebView2 的 DevTools 协议（`/json/list` 找页面，`Input.insertText` 真的打字），读编辑器用 `.cm-content` 的 `cmTile.view`
- tauri dev 里页面加载的模块带着 `?t=` 时间戳：自己 `import('/src/xxx.ts')` 拿到的是另一份 store，
  要从 `performance.getEntriesByType('resource')` 里找页面用的那个地址
- release 版里没法 import 模块：用 `window.__TAURI_INTERNALS__.invoke('命令名', 参数)` 直接调命令
- 团队设备密钥在设了 `ODEA_DATA_DIR` 时是数据目录里的 `collab/team-key`（种子的十六进制），可以事先生成、算出公钥写进 `.odea/devices`
- 加中继会写系统钥匙串（`collab-relay:地址`）：测完用 `collab_relay_remove` 删掉
- 窗口最小化着时 DevTools 的 `Page.captureScreenshot` 一直不回来；页面 JS 没有 unminimize 权限，用 PowerShell 的 EnumWindows
  按标题找到窗口 `ShowWindow(h, 9)`
- 弹出窗口（P12.3）在 `/json/list` 里是 url 为 `about:blank` 的页面；发 WM_CLOSE 等于 Alt+F4
- Node 24 的 WebSocket：脚本结尾 `process.exit` 偶尔报 `UV_HANDLE_CLOSING` 断言、退出码 127，输出已经打完，不影响结果
- 驱动脚本一律写成文件再跑，别用 heredoc（`环境.md`）

## 窗口级的动画要抓屏幕，照用户的原样操作

- **出过的事**（2026-10-29）：用户第三次说「启动器关掉时掉帧」才抓到。前两轮，一轮只看了 DWM 合成计数和亮度
  （系统的关窗动画其实边淡边缩，最后一帧跳 11px），一轮用 JS 调关闭、还当成了「打开仓库那一下」
- **根因**：窗口级的动画 WebView 里量不到；不照用户的原样操作（真鼠标点 ×、悬停）就会量错场景；只量亮度会漏掉缩放
- **怎么办**：
  - 用户说某个动效不对，先确认是哪个动作、哪个窗口，再用同样的操作复现，位置和亮度两样都量
  - 工具是 `scripts/perf/window-frames.py`（dxcam 抓屏，文件头写了怎么起单独 identifier 的开发版）
  - 抓屏会抓到用户别的程序：抓之前垫纯色的置顶底板、只抓要看的那一块；万一抓到了别的程序，图当场删掉，不细看

## 系统通知（提醒）

2026-11-12 做到点提醒时摸出来的：

- 应用要在 Claude 的 MSIX 容器外起（经 WMI `Invoke-CimMethod Win32_Process Create` 跑一个 .cmd），不然它登记的应用标识
  （`HKCU\Software\Classes\AppUserModelId`）进了重定向的注册表。从资源管理器起 .cmd 那条路没起来
- 调试版启动时往相对路径 `../src/lib/bindings.ts` 写绑定：WMI 起的进程工作目录是 System32，写不进去就 panic（退出码 101）。
  .cmd 里先 `cd /d D:\OnTheWay\src-tauri`
- 屏幕上的通知 UI 自动化找不到（容器里外都一样），按钮点不了。看结果用
  `[Windows.UI.Notifications.ToastNotificationManager]::History.GetHistory(<标识>)` 读内容；
  `HKCU:\...\Notifications\Settings\<标识>` 的 PeriodicInteractionCount 是用户点过几次
- 按钮的回调要人点

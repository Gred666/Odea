# 桌面端实测

在这台机器上把桌面端真的跑起来验的做法和坑。环境的问题（cargo、MSIX 容器、127.0.0.1）在 `环境.md`。

## 用户自己的 Odea 一直开着

用户的 Odea 在 `E:\Odea\odea.exe`，别动它，也不用请用户关。

- 同一个 identifier 的开发版一起来就退出（退出码 0：单实例把参数转给了用户那个，那边可能弹一下）。换一个 identifier 并排跑：
  `pnpm tauri dev --config <只写了 {"identifier":"dev.odea.xxx"} 的 json 文件>`；构建用 `TAURI_CONFIG='{"identifier":"dev.odea.xxx"}' cargo build`
- 测的时候会在用户屏上弹窗口、动鼠标、弹通知：先跟用户说一声；测完把开发版的进程（`target\debug\odea.exe`）停掉
- `launch.json` 的 `odea-desktop-temp` 以前只换了数据目录和仓库，identifier 还是默认的 `dev.odea.editor`，和用户那个一样，用户的 Odea 开着时起不来。
  2026-11-21 起它自己写一份 `%TEMP%\odea-dev\tauri-temp.json`（`{"identifier":"dev.odea.temp"}`）带着 `--config` 起，WebView2 的配置目录也指到 `%TEMP%\odea-dev\webview2`：
  用户的开着也能直接起（只重编 app 这个 crate，一分多钟）。`dev.odea.temp` 是固定的，`%APPDATA%`、`%LOCALAPPDATA%` 下它那份目录留着下次接着用，不用删。
  别的几个配置（`odea-desktop`、`odea-team-a`）还是默认 identifier，起之前照旧 `Get-Process odea` 看一眼。关它用 `CloseMainWindow()`（等于点 ×），`tauri dev` 跟着自己退出，索引的 WAL 也合回去了，
  这时再用 `node:sqlite`（Node 22.5+ 自带）改索引。**例外**：这一次起来以后搜过正文（全局搜索、命令面板）的话 WAL 不合 ——
  搜正文的只读连接是个 `static`，退出时不关，主连接就不是最后一个（`REVIEWS/2026-11-15-桌面端验证.md` §4.8）。改索引之前看一眼有没有 `-wal`，有就照样能读、能改（`node:sqlite` 开的时候会读进来）。
  2026-11-17 起只读连接跟着 `Vault` 一起关（§4.8 修了），搜过正文也合回去了
- `%TEMP%\odea-dev\data`、`vault` 是这几个配置写死的位置，可能留着以前别的会话的东西：要一个干净的仓库就先改名挪开，测完删掉自己的、改回来
  （或者照 `odea-desktop-temp` 那几个环境变量，指到一个新建的 `%TEMP%` 目录，测完整个删掉，原来的不用动）
- 1420 上已经开着项目的 Vite（浏览器预览）时，`--config` 里再加 `"build": { "beforeDevCommand": "" }` 复用它，不然 `pnpm dev` 抢不到端口（strictPort）
- 换了 identifier 起过的，`%LOCALAPPDATA%`、`%APPDATA%` 下会多出以它命名的目录（`.window-state.json` 这些，实际在容器的 `LocalCache` 里）：测完连同容器里那份一起删

## 测音视频（2026-11-15，`技术方案.md` §11.4.6）

- **机器上没有 ffmpeg**：用 Windows 自带的 Media Foundation，PowerShell 5.1 调 WinRT（`System.WindowsRuntimeSystemExtensions.AsTask` 等异步）：
  `MediaTranscoder` 把 WAV 编成 m4a（AAC 编码器只收 44.1k / 48k 的采样率），`MediaComposition` 加 `MediaClip.CreateFromImageFileAsync`（一张彩条图）
  和 `BackgroundAudioTrack` 编成 mp4。坑：.ps1 不带 BOM 时 5.1 按 ANSI 读，中文文件名乱掉、`CreateFileAsync` 直接失败（先用英文名，放进仓库时再改名）；
  `composition.Clips.Add` 报没有 Add 方法，要经 `[System.Collections.Generic.ICollection[Windows.Media.Editing.MediaClip]].GetMethod('Add').Invoke(...)`
- 放：CDP 的 `Runtime.evaluate` 带 `userGesture: true`，`play()` 才让放，不用改 WebView2 的自动播放策略。电脑真的出声：音量 0.02
- 没放过的卡片滚远了，播放器是被放掉的（去掉 `src`，设计如此），滚回来是新画的一个：脚本里先拿着的那个元素已经死了，对它 `play()` 永远不回 —— 每次要放之前重新 `querySelector`
- asset 协议支持 Range（中间一段回 206）；几百 KB 的文件播放器一次 `bytes=0-` 就全拿到了，拖进度看不出 Range，要验就直接 `fetch` 带 `Range` 头

## 每种窗口都开一遍（2026-11-15，审查 §6.3）

- **按地址找 CDP 目标会找错窗口**：仓库、启动器、访客、速记小窗的地址都是 `http://127.0.0.1:1420/…`，访客窗口一开就排在 `/json/list` 的最前面，
  拿「地址里有 1420」去找，命令打到了访客窗口上（`note_list` 报「窗口「guest」没有打开仓库」）。用 `/json/list` 的 id，或者带上 `?launcher`、`?guest`、`?capture` 去找
- **自己建的临时仓库日程是关着的**（打开别人的文件夹不开日程）：命令面板里没有日程插件的命令。先「启用日程」；打「提醒」直接回车选中的是「新建笔记「提醒」」
- **几种窗口怎么叫出来**：启动器 `invoke('launcher_show')`；访客窗口在启动器里 `invoke('launcher_join', { link: 'odea://join/随便什么' })`（加不进去，窗口照样开、能用）；
  弹出窗口：开两个标签（`useApp.getState().openNoteTab(id)`，单个标签时没有标签栏）再在标签上发 `contextmenu`、点「在新窗口中打开」；
  速记小窗只认全局快捷键：开之前在临时数据目录的 `config.json` 里写 `"quickCapture": { "enabled": true, "shortcut": "Ctrl+Alt+Shift+F9" }`
  （没人用的键，不碰用户那个 Odea 的 Ctrl+Alt+N），再用 `keybd_event` 按一下
- **导出 PDF 的窗口看不见、印完就销毁**：要在它开着的时候经 CDP 去试，给那篇放一张本机慢服务器上的图（十几秒才回 404），窗口等页面 load 就多开十几秒
- **系统的「另存为」在 Claude 的容器里用 UI 自动化看，里面的控件全是 Pane**：没有 Value、Invoke 模式。按 AutomationId + 类名找文件名框（`1001`、`Edit`）
  和保存按钮（`1`、`Button`），拿 `NativeWindowHandle` 发 `WM_SETTEXT`、`BM_CLICK`。
  2026-11-15 那次 UIA 连对话框本身都找不到（`RootElement` 的子元素里没有 `#32770`，`EnumWindows` 看得到「另存为 HTML」）：
  直接用 Win32 —— `EnumWindows` 按进程号和类名 `#32770` 找对话框，`EnumChildWindows` 按类名加 `GetDlgCtrlID`（Edit 是 1001、Button 是 1）找控件，同样发那两条消息

## 拿不同的前端打两个 exe 来比

量启动这类「只差前端」的比较（2026-11-12，`REVIEWS/2026-11-10-审查与竞品调研.md` §5.3.1）：两份前端各 `vite build` 到一个目录，
`pnpm tauri build --no-bundle --config <json>`，json 里写单独的 identifier 和 `build.frontendDist`、`"beforeBuildCommand": ""`。

- `frontendDist` 写 `C:/…` 这种绝对路径会被当成 scheme 是 `c` 的网址：前端根本没嵌进 exe（两个 exe 一样大），
  窗口去开 `file:///…/index.html`。要写 `\\?\C:\…`（JSON 里转义成 `"\\\\?\\C:\\…"`）
- 为了快：`CARGO_PROFILE_RELEASE_LTO=false`、`CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16`、`CARGO_PROFILE_RELEASE_INCREMENTAL=true`，
  `CARGO_TARGET_DIR` 放 `%TEMP%`（别碰 `target/debug`，可能正有人在用）。冷编 3 分半，换一份前端再编 40 秒到 1 分钟。测完把那个目录删了（3 GB 多）
- 量的时候数据目录、`WEBVIEW2_USER_DATA_FOLDER` 都放 `%TEMP%`（`环境.md` 的 MSIX 那一条），经 DevTools 协议连上、关缓存、刷新

## 给用户的测试包别覆盖

- **出过的事**（2026-10-18）：重打协作测试包时，脚本开头 `rm -rf src-tauri/target/collab-test` 把用户正在主力电脑上运行的测试版的
  exe、仓库、配置删了（MSYS 的 `rm` 连运行中的 exe 都能删），只剩被锁住的索引
- **根因**：用户自己按步骤测，测试包就是他们正在用的东西，不是临时文件
- **怎么办**：新版本的包放进新的文件夹（collab-test-2、-3……），不覆盖、不删旧的；要删旧的先用 `Get-Process` 查有没有从那里运行的进程，
  有就让用户先关

## 起两个实例（协作、团队仓库）

做法在 `协同编辑.md` §19.2、§23.5，这里只记容易踩的：

- A = `launch.json` 的 `odea-team-a`（tauri dev，调试端口 9333），B = `odea-team-b`（release，
  `--config '{"identifier":"dev.odea.collab-b"}'` 构建，端口 9334）
- 用 `ODEA_VAULT` 打开的仓库不进 config.json 的 vaults 列表：要测跟着仓库记的东西（比如窗口 `placement`），
  先往临时数据目录的 config.json 里放一条
- 驱动脚本走 WebView2 的 DevTools 协议（`/json/list` 找页面，`Input.insertText` 真的打字），读编辑器用 `.cm-content` 的 `cmTile.view`
- tauri dev 里页面加载的模块带着 `?t=` 时间戳：自己 `import('/src/xxx.ts')` 拿到的是另一份 store，
  要从 `performance.getEntriesByType('resource')` 里找页面用的那个地址。浏览器预览的开发服务器也一样：它开着时改过的模块，
  新开的页面也按带 `?t=` 的地址加载 —— 无头 Chrome 脚本往 `import('/src/data/store.ts')` 里塞附件清单，页面用的那份没变，
  卡片显示「仓库里找不到」（2026-11-15；`fade-frames.mjs` 的 `mediabar` 场景已经照页面的地址 import）
- release 版里没法 import 模块：用 `window.__TAURI_INTERNALS__.invoke('命令名', 参数)` 直接调命令
- 团队设备密钥在设了 `ODEA_DATA_DIR` 时是数据目录里的 `collab/team-key`（种子的十六进制），可以事先生成、算出公钥写进 `.odea/devices`
- 加中继会写系统钥匙串（`collab-relay:地址`）：测完用 `collab_relay_remove` 删掉
- 窗口最小化着时 DevTools 的 `Page.captureScreenshot` 一直不回来；页面 JS 没有 unminimize 权限，用 PowerShell 的 EnumWindows
  按标题找到窗口 `ShowWindow(h, 9)`
- 弹出窗口（P12.3）在 `/json/list` 里是 url 为 `about:blank` 的页面；发 WM_CLOSE 等于 Alt+F4
- Node 24 的 WebSocket：脚本结尾 `process.exit` 偶尔报 `UV_HANDLE_CLOSING` 断言、退出码 127，输出已经打完，不影响结果
- 驱动脚本一律写成文件再跑，别用 heredoc（`环境.md`）
- 不想起 tauri dev 也能编两个 identifier 的调试版：`TAURI_CONFIG='{"identifier":"dev.odea.collab","build":{"devUrl":"http://127.0.0.1:1440"}}' cargo build --bin odea`，
  把 `target/debug/odea.exe` 拷走，换 identifier 再编一次（只重编 app 这个 crate，四十秒）。拷出去的两个 exe 各设 `ODEA_DATA_DIR`、`ODEA_VAULT`、
  `WEBVIEW2_USER_DATA_FOLDER`、`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=…` 再起，页面从 1440 的 vite 来（2026-11-18，`协同编辑.md` §29.2）

## 窗口级的动画要抓屏幕，照用户的原样操作

- **出过的事**（2026-10-29）：用户第三次说「启动器关掉时掉帧」才抓到。前两轮，一轮只看了 DWM 合成计数和亮度
  （系统的关窗动画其实边淡边缩，最后一帧跳 11px），一轮用 JS 调关闭、还当成了「打开仓库那一下」
- **根因**：窗口级的动画 WebView 里量不到；不照用户的原样操作（真鼠标点 ×、悬停）就会量错场景；只量亮度会漏掉缩放
- **怎么办**：
  - 用户说某个动效不对，先确认是哪个动作、哪个窗口，再用同样的操作复现，位置和亮度两样都量
  - 工具是 `scripts/perf/window-frames.py`（dxcam 抓屏，文件头写了怎么起单独 identifier 的开发版）
  - 抓屏会抓到用户别的程序：抓之前垫纯色的置顶底板、只抓要看的那一块；万一抓到了别的程序，图当场删掉，不细看

## 系统通知（提醒）

2026-11-12 做到点提醒时摸出来的：

- 应用要在 Claude 的 MSIX 容器外起（经 WMI `Invoke-CimMethod Win32_Process Create` 跑一个 .cmd），不然它登记的应用标识
  （`HKCU\Software\Classes\AppUserModelId`）进了重定向的注册表。从资源管理器起 .cmd 那条路没起来
- 调试版启动时往相对路径 `../src/lib/bindings.ts` 写绑定：WMI 起的进程工作目录是 System32，写不进去就 panic（退出码 101）。
  .cmd 里先 `cd /d` 到项目的 `src-tauri`（写绝对路径）
- 屏幕上的通知 UI 自动化找不到（容器里外都一样），按钮点不了。看结果用
  `[Windows.UI.Notifications.ToastNotificationManager]::History.GetHistory(<标识>)` 读内容；
  `HKCU:\...\Notifications\Settings\<标识>` 的 PeriodicInteractionCount 是用户点过几次
- 按钮的回调要人点

## 驱动脚本和临时环境（2026-11-15，桌面端验证第一段）

- **1420 被别人的 Vite 占着时**：除了上面 `beforeDevCommand: ""` 复用它，更稳的是自己起一个：`pnpm exec vite --port 1440 --strictPort`，
  `--config` 里写 `"build": { "beforeDevCommand": "", "devUrl": "http://127.0.0.1:1440" }`。别人那个随时可能被停，停了这边的页面就没了。
  这样编出来的 `target\debug\odea.exe` 带着这个 devUrl 和 identifier：之后有人直接跑这个 exe（经 WMI 测通知）要先按自己的配置重编
- **PowerShell 5.1 的 .ps1 不带 BOM、注释里有中文**：按 ANSI（936）读，半个汉字会吞掉后面的换行，下一行（`param(...)`）跟着变成注释，
  参数全是空的（报「Empty path name is not legal」）。.ps1 一律只写 ASCII，或者存成带 BOM 的 UTF-8；中文路径从 UTF-8 文件里读，别从命令行传（传过去是乱码）
- **从 PowerShell 给 `node -e` 传带双引号的 JS 会被拆坏**（5.1 给原生程序传参的老毛病）：驱动脚本的 JS 写成文件再跑。Bash 里单引号包着可以
- **速记小窗收起来以后页面的 `document.visibilityState` 还是 visible**：显示没显示用 Win32 `IsWindowVisible`（按进程号找类名 `Tauri Window` 的顶层窗口，小窗是 616×113 那个）
- **测「仓库文件夹一时打不开」用 `subst`**：`subst X: <临时目录>`、`ODEA_VAULT=X:\vault` 起，开着应用 `subst X: /D`。监听的句柄是打开时拿的，盘符没了它还活着，
  往底下的真目录里改文件照样有事件（路径带 `X:`），正好走到「扫一遍时仓库根打不开」。用完先关应用再撤 `subst`
- **另起进程独占一个文件**：.NET 的 `[IO.File]::Open(path, Open, ReadWrite, FileShare.None)`（Node 的 `fs.open` 总是共享打开，造不出 os error 32）
- 资源管理器的窗口用 `Shell.Application` 的 `Windows()` 按 `LocationURL` 找、`Quit()` 关；只认自己打开的那个地址，别列别的窗口（用户开着的文件夹）
- 容器里 `.txt` 的关联是坏的（`txtfilelegacy`，没有打开命令）：`open_path` 打开 txt 弹的是「选取应用」（`OpenWith.exe`），不是记事本

## 菜单、弹层和窗口焦点（2026-11-18，桌面端验证 §4.1）

- **菜单开着时窗口失焦，菜单就收了**（Radix 把焦点离开当成碰了外面；和原生菜单一样，不是毛病），窗口回来时焦点在触发按钮上。驱动脚本测菜单、弹层时，
  用户屏上别的窗口到了前台就会看到「开了又自己收」。要造失焦：页面里 `__TAURI_INTERNALS__.invoke("win_minimize")`，过一会儿 `invoke("win_focus")`，不用动别的窗口
- **Claude 的浏览器面板藏起来时页面是后台页**：`requestAnimationFrame` 不跑（等 rAF 的逻辑一直不走）、截图是空白。要看 rAF 之后的事（落焦点、动画）去桌面端或者让面板露出来

## 驱动脚本的坑（2026-11-15，桌面端验证第二段）

- **拿 `EditorView`**：这一版 CodeMirror 的 DOM 上挂的是 `cmTile`，不是老版本的 `cmView`：`document.querySelector('.cm-content').cmTile.root.view`
- **Vite 热更新过一次以后，页面加载的模块地址带 `?t=<时间戳>`**（哪怕应用是之后才起的）。`import('/src/data/store.ts')` 拿到的是另一份模块、另一个 store，调什么都没反应、也不报错。
  照页面真加载的地址 import：`performance.getEntriesByType('resource').map(e => e.name).find(n => n.startsWith(location.origin + '/src/data/store.ts'))`
- **包 `window.fetch` 假装后端回话**（IPC 走 `http://ipc.localhost/<命令>`）：回的 `Response` 要带 `Tauri-Response: ok`（报错是 `error`）和 `Content-Type: application/json`，不带的话前端当成出错
- **`cmd /c "x.cmd" "--带等号=的参数"` 起不来**：cmd 见到两对以上的引号会把头尾的剥掉，命令行坏了，什么都不报。参数直接写进另一个 .cmd
- **关主窗口进程不退**（`WM_CLOSE` 以后常驻，等提醒、速记）：要换启动参数重起时 `Stop-Process` 自己那个 PID（按 `Path` 是 `D:\OnTheWay\...` 认，别碰 `E:\Odea`）
- **窗口记着上次是最大化的**：`SetWindowPos` 改不了大小，先 `ShowWindow(SW_RESTORE)`。`--force-device-scale-factor=1.5` 下要 853×533 的视口，窗口外框给 1295×808（这台机器、这一版的边框）
- `Emulation.setCPUThrottlingRate`、`Tracing.start`（`devtools.timeline`，`UpdateLayoutTree` 的 `elementCount`）在 WebView2 上都能用

## 输入法（2026-11-15，桌面端验证第三段）

- **WebView2 里能用 `Input.imeSetComposition` 走组字**，事件序列和 Chrome 一样（`compositionstart` → `compositionupdate` → `beforeinput`（`insertCompositionText`）→ `input` … → `compositionend`）；
  提交发 `Input.insertText`，取消发空串。真输入法每键前还有一个 keyCode 229 的 keydown：`Input.dispatchKeyEvent` 发 `rawKeyDown`、`windowsVirtualKeyCode: 229`、`key: "Process"`
- **组字时直接发的 `Input.dispatchKeyEvent` 不经输入法**：会带着 `isComposing: true` 送到页面。拿它测「组字时按快捷键」可以；但 textarea 里直接发回车，浏览器会先把组字串当成字留下 —— 真输入法组字时回车是它自己的，别把这个当缺陷
- **开一篇笔记**：`app/navigate.ts` 的 `openDocument(noteRef(id), undefined, 新标签?)`（照页面加载的地址 import）。`useData` 的 `openTreeFile` 是开附件那类文件的，调了没反应
- **新的数据目录第一次起会弹「已更新到 …」**：先 Esc 关掉，不然焦点在对话框上、组字发不进正文（`config.json` 里写上 `lastVersion` 就不弹）

## 跨窗口拖标签、弹出窗口、真按键（2026-11-18，`标签页与分屏.md` §20）

- **前台可能是用户别的程序**（这次是一个游戏客户端）：`SetForegroundWindow` 拿不到前台，`keybd_event` / `SendInput` 发的键会落到那个程序上。
  先 `GetForegroundWindow` 看一眼是谁；不是自己的窗口就别发真的按键、别动鼠标，也别用「先按一下 Alt」这类抢前台的办法
- **发真按键之前、之后都要核对前台**（2026-11-21 又犯了一次）：脚本 `SetForegroundWindow` 以后只打印了「拿没拿到前台」，没拿到照样 `SendKeys`，
  两下按键（→、Ctrl+Shift+Y）落到了用户那边当时在前台的程序上。拿不到前台就退出，不发
- **程序抢到前台以后 `SendKeys` 的键进不了 WebView2 的页面**（2026-11-21，白板验 Ctrl+Shift+B）：窗口确实在前台，连普通的方向键页面里都收不到 keydown ——
  键盘焦点停在 Tauri 的顶层窗口上，不在 WebView2 的子窗口里。DevTools 协议的 `Input.dispatchKeyEvent` 又不经浏览器的快捷键。
  要验「WebView2 自己拿不拿某个组合键」只能真鼠标先点进窗口再按，或者请用户按一下
- **`PostMessage` 给 WebView2 渲染窗口（`Chrome_RenderWidgetHostHWND`）的 F5 不走浏览器快捷键**：主窗口、弹出窗口都不重载，`AcceleratorKeyPressed` 也不报。
  验「拦没拦住 F5」只能在前台真按
- **DevTools 协议拖到窗口外面是真的拖得出去**：`Input.dispatchMouseEvent` 的坐标给负数、给大于窗口的数，按下的那个元素照样收到 `pointermove`，`screenX` = 坐标 + 窗口的 `screenX`。
  跨窗口拖、拖出窗口开新窗口都能这样测；松手会让窗口没了的（拖走弹出窗口唯一的标签）那一下 `mouseReleased` 不回，套超时
- **最大化的主窗口盖着整块屏**：测主窗口 → 弹出窗口要先把主窗口还原、挪开（`ShowWindow(SW_RESTORE)` + `MoveWindow`），弹出窗口之间也别叠着
- 无边框窗口 `GetWindowRect` 比 `screenX` / `outerWidth` 四周多 8（看不见的缩放边）；`window.open` 的 left / top 按 `GetWindowRect` 算
- PowerShell 5.1 的 .ps1 里有中文、没有 BOM 时整个脚本解析错（`Add-Type` 的 here-string 断掉）：脚本里只写英文，或者存成带 BOM 的

## 标题栏、焦点、悬停提示（2026-11-21，`边栏.md` §10.1、`悬停提示.md` §9.5）

- **CDP 在拖拽带上的按下会真的调 `win_start_dragging`**：`TitleBar` 的 `onMouseDown` 不认得这是合成的。这次窗口没被拖走（系统的移动循环要真鼠标的键按着），
  但别指望它：要验「按在这里会不会拖窗口」，照页面加载的地址 import `lib/tauri.ts`，把 `win.startDragging` 换成计数器（模块里导出的对象，属性能改；
  `__TAURI_INTERNALS__.invoke` 改不了，见上面），验完换回去。双击（`clickCount: 2`）走的是 `win_toggle_maximize`，真的会最大化 / 还原，再双击一次回来
- **CDP 的 `Input.dispatchKeyEvent` 发的 Tab 会挪焦点**（真按键，有默认动作）；页面里 `dispatchEvent(new KeyboardEvent(...))` 的不会。测焦点循环用前者
- **用户的真鼠标也在窗口上**：窗口（尤其新开的弹出窗口）压在用户鼠标底下时，真的指针事件会让悬停提示出、收，读到的状态和 CDP 的鼠标对不上。
  读「提示出没出」的脚本要移过去、等出来、做事、再核一次还出着，不对就重来（`悬停提示.md` §9.5 的做法）
- **重放开场**：`sessionStorage.removeItem('odea.introPlayed')` 再 `Page.reload`；要逐帧记位置，先 `Page.addScriptToEvaluateOnNewDocument` 挂一个 rAF 记录器（同一个 CDP 连接里做，连接断了脚本就没了）

## 量导入（2026-11-19，`仓库与启动器.md` §21.1）

- **系统的选文件夹对话框**（`IFileDialog` + `FOS_PICKFOLDERS`）：`#32770`，「文件夹」框是类名 `Edit`、`GetDlgCtrlID` 1152（另存为是 1001），「选择文件夹」是按钮 1、「取消」是 2。
  `WM_SETTEXT` 填完整路径、`BM_CLICK` 按钮 1 就选上了。点完它马上藏起来，调用要 120–170ms 才返回（取消一样）
- **记「点下去的时刻」要在真的点的那一刻取时间**：第一版的脚本用的是那一轮循环开头的时间，中间 sleep 了 0.7 秒才点，量出来「进度条 900ms 才出来」，实际是 220ms
- **数 IPC 用 resource timing（`ipc.localhost/<命令>`），先 `performance.setResourceTimingBufferSize`**：缓冲默认只有 250 条，满了后面的就不记了，3000 次 `note_get` 只数出 155 次。
  包一层 `window.__TAURI_INTERNALS__.invoke` 拦不到页面自己的调用（试过，一条都没记下）
- **量「后端还能不能及时回」的探针别用重的命令，也别不等回来就发下一次**：每 250ms 调一次 `note_list`，两万多篇的仓库它本身几百毫秒，请求越积越多（一轮发了 2715 次），
  一直抢锁，把导入拖慢了半分钟，量出来的全是探针自己造成的。用很轻的 `vault_info`，上一次没回来就不发
- **探针别留在页面上**：脚本退出了，页面里的 `setInterval` 还在跑；结束时清掉（或者重新载入页面）
- **测试窗口置顶会挡着用户**：`monitor.py` 量屏幕时把窗口临时置顶、结束时（`atexit`）放回去；强停脚本时 `atexit` 不跑，窗口一直置顶（这次被用户最小化了）。
  最小化着的窗口不画帧、定时器降频，帧率和进度条出现的时间都量不准：量之前还原（`ShowWindow(SW_RESTORE)`）
- **杀渲染进程**：`msedgewebview2.exe` 里命令行带着这个实例的 WebView2 数据目录、`--type=renderer` 的那几个。杀完 CDP 的页面目标还是同一个，连接照样能用

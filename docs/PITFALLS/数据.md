# 数据

- 某天 / 某周期的文档是异步加载的，编辑器往往先以空文档挂载。`saveDocument` 在 `source` 还没回来时**必须直接返回**，否则用户一输入就把原有内容整篇覆盖。adapter 在数据没到时干脆不给 `editor`。
- `foreign_keys` 是连接级 PRAGMA，只在建库时设一次没用（旧库的事，搬家只读拷贝，不用管）。
- 文件改名 / 挪位置后按新路径写入前，索引里得先改路径**并清掉指纹**：标题来自文件名、归档与否来自位置，内容一模一样也得重新解析；不改路径的话旧路径那一行占着同一个 id，新文件会被当成一篇重复的笔记。
- 应用自己写的文件会触发文件监听：靠「写完立刻把修改时间、大小、指纹记进索引」识别，扫描时对得上就不算外部改动、不发通知。
- 外部程序用 CRLF 存过的文件：读进来统一成 `\n`，否则编辑器一打开就当成改过了。
- 编辑器分辨不了「store 里的正文变了」是外部改动还是自己的保存回来了（边打字边保存时两者都是 `当前 ≠ 已同步`）：store 只在外部改动真的改了正文时给 `externalRevisions` 加一，编辑器看这个数有没有变。
- `saveBus` 引用了数据 store，store 要 flush 编辑器时只能动态 `import("@/editor/saveBus")`，静态引入会成环。
- 这台机器的 Git 开了 `core.autocrlf`，工作区里的文件是 CRLF，Biome 按 LF 检查会报格式错；改过的文件存成 LF 即可（提交时本来就是 LF）。
- 全局搜索的位置按 UTF-16 给（编辑器里的位置），Rust 里按字节找到后要换算；不区分大小写别用转小写再找（有的字转小写会变长，位置就对不上），交给正则的大小写折叠。
- 全局搜索的全词判断要和 CodeMirror 一样（汉字也是词字符），不然搜出来的和跳进去后篇内查找的对不上。
- 延续来的「今天」不落库；跨过零点后缓存里的延续文档要丢掉，否则翻回昨天会把它当成昨天写的。
- Windows 上 `PathBuf::push("D:")` 会把前面的整条路径换掉（带盘符、没有根的段 = 「D 盘的当前目录」）：`fsio::abs(仓库, "笔记/D:/x.md")` 出来是 `D:x.md`，在仓库外面。
  只挡空段、`..`、以点开头、反斜杠不够。前端、访客、配置文件、文件内容里来的路径拼进 `abs` 之前，每一段都过 `fsio::is_plain_name`
  （`Path::new(段).components()` 正好是一个 `Normal`）（2026-11-14，审查 §4.25）。
- 文件名（不是整条路径）上限 255：ext4 按 UTF-8 字节，NTFS、APFS 按字符。应用卡标题 80 个字，80 个汉字 + `.md` 是 243 字节，
  再接什么都容易超：原子写入的临时文件名多 13–16 字节，冲突副本多「 (冲突 …)」25 字节。在已有的名字后面接东西都用 `fsio::fit_stem` 先截（2026-11-14，审查 §4.23）。
- 应用配置 `config.json` 是几个窗口共用的一份：读 - 改 - 写都走 `boot::edit_config`（拿着 `CONFIG_LOCK`），自己 `Config::load` 改完再存会盖掉别的窗口刚存的
  （2026-11-14 查出 8 处这样写的，并发 150 + 150 次丢 108 次）。`Config::save` 已经改成 `boot.rs` 私有，绕不开了（审查 §4.29）。
- **「失焦才存」的输入框，拆掉时也要存**：React 按 `key` 重挂、或者整块卸掉时，正聚焦着的输入框被拿走不发 blur，`onBlur` 里的保存不会跑。光标还在标题里按 Ctrl+Tab / Ctrl+W 换篇，改的标题就一声不响地没了；关窗走 `saveBus` 的 `flushAllEditors`，没登记的也不存。存用户写的字的输入框：卸载时再存一次、挂上时 `registerEditorFlush`，并记下正在存的那一版免得存两遍（`DocumentView.tsx` 的 `EditableDocumentTitle`）（2026-11-14，审查 §4.34）。
- **清空索引的地方都要先留住笔记的 id**：属性块里没写 id 的笔记（外来的），id 只在 `doc` 表里。`index.rs` 里整个清空 `doc` 的两处
  （`prepare` 版本不对、`sync_layout` 摆法变了）清之前都调 `keep_note_ids` 抄进 `kept_ids`；以后再加清空索引的地方也要。
  `kept_ids` 不进 `DROP` / `DELETE` 的名单，抄的时候不先清（连着清两次，第二次时 `doc` 是空的）。只有删了索引文件才换 id（2026-11-14，审查 §6.6，`技术方案.md` §5.3.1）
- **认属性块的规矩只有两份，别再写自己的正则**：Rust 是 `domain/search.rs::is_yaml_key`（`vault/frontmatter.rs` 用的也是它），
  前端是 `editor/frontMatter.ts::isFrontMatterKey`。2026-11-14 改成也认中文键时，审查记的是「三处」，`Grep` 出来前端另有三份抄的
  `/^[A-Za-z_][\w-]*\s*:/`（`lib/plainText.ts` 摘要、`lib/markdown.tsx` 目录、`render/staticHtml.ts` 导出），现在都调 `isFrontMatterKey`。
  规矩变了还要升索引的 VERSION：已经读进索引的按旧规矩拆过（`docs/提醒与属性.md` §3.3）
- **换掉正文、换仓库之前先存编辑器**：编辑器有 400ms 的防抖，存盘还可能在路上。拿 store 里的正文去替换别的文档（冲突副本「用这一版替换原文」）、
  删掉正开着的那篇、整页重载换仓库之前，先 `flushAllEditors()`（换仓库还要 `flushDrafts()`：存失败的草稿只在内存里）。整页重载的那种要在
  调后端之前存 —— 后端一返回已经换到新文件夹了，再存就写进了别的仓库（2026-11-14，审查 §4.38、§4.39）。
- **原生日期框收到它不认的值就当空的**：`<input type=date defaultValue="soon">`、`<input type=datetime-local defaultValue="2026-11-20">`（没有时间）的 `value` 都是 `""`。失焦时拿 `value` 和原来的比，「不一样」就写回 —— 点进去什么都不改、点到别处，值就被抹了（属性面板以前就是这样，2026-11-15 审查 §6.8）。给原生控件之前先确认它读得了（`yaml.ts::fitsKind`），读得了但格式差一点的先补齐（只有日期的给 datetime-local 补 `T09:00`）
- **跟着外面的状态走的编辑框，有没存的草稿时就别跟**：属性的「源码」框以前别处一改这一篇（另一个窗口、外部程序、协作的对方）就整个换成新的 YAML，打了一半的字没了。
  没动过才跟上（和文字值的「没在打字时跟上」一样）；有草稿时存的是框里的，别处那一处会被盖掉，要不要提示等用户定（2026-11-16，`REVIEWS/2026-11-15-桌面端验证.md` §3.11、§4.9）

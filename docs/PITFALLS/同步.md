# 同步（P8）

- Tauri 窗口在 `tauri.conf.json` 里是 `visible: false`，可它一建出来（还藏着、前端还没加载）就会收到一次 `WindowEvent::Focused(true)`。同步拿「获得焦点」当触发，第一轮就在前端订阅事件之前跑完了，冲突副本的提示没人收。现在第一轮之前的焦点不算，第一轮等 `ready`（2026-10-07）。
- libgit2 在 Windows 上走 WinHTTP 的默认代理（`netsh winhttp`），不读 Clash 这类工具设的系统代理；连不上报的错误类别是 `Os`，不是 `Net`。
- git2 0.21 的默认 features 是空的（不带 https）；`Reference::symbolic_target`、`Remote::url` 改成返回 `Result`。
- 设备码登录「等用户确认」那一步只能调一次（后端把这次登录拿走了）。放在 React effect 里会被 StrictMode 跑两次，第二次报「没有正在进行的登录」；现在在点击里发起（`SyncDialog.tsx` 的 `githubLogin`）。
- 断开同步时线程可能正在一轮的半路上，剩下的状态事件会在「已断开」之后到前端，把它改回「已同步」。停掉的线程现在不再往外发状态和提示（`Running.alive`）。
- libgit2 的 mempack 自己的 `dump` 只收**提交**和提交能走到的对象：只放进索引、还没提交时导出来是个 32 字节的空包，`reset` 之后对象就丢了，索引指着不存在的 blob。`stage_bulk` 自己建 packbuilder，按索引项的 id 一个个放进去（2026-10-07）。
- `Index::add_all` 会给每个新文件生成一份 diff（打开、读完、判断是不是二进制）：2000 个新文件、回调全返回「跳过」也要 5 s；`statuses()` 只比 stat，7 ms。要先知道有哪些文件就用 status。
- libgit2 每把一个文件写成 blob 都要从头查一遍属性（`.gitattributes`、info/attributes、全局的……，没有 session 缓存），Windows 上一次约 2 ms，一个文件两次；纯读文件 + 算哈希只要 0.05 ms。慢在等文件系统，不在 CPU：依赖开 -O3 没用，清空系统 / 全局配置的搜索路径也没用，多开线程一起等才有用。
- 想看真实应用里的同步：临时仓库 `git init -b main`，`git config odea.autosync true`，远端设成本机的一个裸仓库，用 `ODEA_VAULT` / `ODEA_DATA_DIR` 指过去再 `pnpm tauri dev`。
- GitHub 的刷新令牌用一次就作废，换的时候旧的访问令牌也跟着作废（官方文档 Refreshing user access tokens；开了令牌过期的 OAuth App 走同一个接口）。几个仓库的同步线程同时发现令牌快过期（隔夜打开、几个窗口一起恢复），拿同一个刷新令牌去换，后到的收到 `bad_refresh_token`，被当成「登录失效」。续期要一个一个来、拿到锁以后先重读钥匙串（`account.rs::access_token`，2026-11-14 审查 §4.30）。
- git 的凭据回调不看地址，令牌当密码交给要它的那个地址：从前端拿来的仓库地址要先查是不是这家托管方的 `https://` 地址（`Provider::owns_remote`，§4.31）。
- 设备码登录的「取消」（`LoginSlot::cancel`）只取消已经放进后端的那个码。领码（`sync_github_login_start`）要好几秒，这期间关对话框发的取消什么都没取消，
  码回来以后前端照样去 `wait`，后端每 5 秒问一次 GitHub、问到码过期（15 分钟）。前端拿到码时先问这次登录还要不要，不要了先取消、不去等
  （`lib/githubLogin.ts`，2026-11-14 审查 §4.40）。

## 协作 / 团队仓库（2026-11-15，`协同编辑.md` §27）

- **编辑器早就开着、会话是照本机某一版建的**（团队加入、接手主持、协作主持一篇）：读正文到编辑器挂上之间打的字，挂上时「以会话为准」整篇对齐就没了（审查 §4.36）。
  会话要记着自己照的哪一版（`session.markOrigin`），挂上时拿它算编辑器多打了什么、映射过去；新加建会话的地方别忘了记
- **`team_base` 是 null（或三方合跳过了撞上的段）时本机那一版不进会话**，做客时它还在自己磁盘上，**接手主持把会话写回磁盘会悄悄盖掉它**。
  这台第一次把会话的正文写回磁盘时要带「会话照着的那一版」当 base（`TeamIO.save` 的 `seen` → `markConflict`），后端才会另存冲突副本
- **团队的单测一个文件里起好几个 hub**：`team/store.ts` 收控制消息的回调认的是模块里的 `controller`，上一条测试的 hub 还没送到的 Presence（`setTimeout 0`）
  会送进下一条新起的 controller —— 它去加入上一条那台主持人，卡在「等第一包」8 秒。`afterEach` 里 `resetTeam` 之后等几十毫秒
- **测「挂上之前打的字」得在窗口里打完整的字**：光组字（拼音）测不出 origin 的作用 —— 以会话为准时，组字的改动映射过去照样对得上（拼音本来就会被换掉）。
  `collab-ime.mjs attach` 在窗口里先快快上屏一个词、再慢慢组下一个
- **`Entry.unseen` 原来存的是主持人那一版，不是本机那一版**（2026-11-17，`协同编辑.md` §28）：它是这台把会话写回磁盘时当 base 用的 `seen`（会话照着建的那一版）；本机没合进去的那一版在磁盘上，controller 以前没留。现在是 `{ seen, mine, from, hidden }`，要看本机那一版用 `mine`（`unseenText`）
- **团队单测的两个小坑**（2026-11-17）：`mockNet` 的 `hub.setBase(id, …)` 要在 `hub.device(id, …)` 之后调，之前调是静悄悄地什么都不做（`devices.get(id)?.`）；`merge3` 是逐行的，两边改的行挨着（一边改第 4 行、一边在第 4 行后面加一行）也当撞上 —— 想要「合得进去」的样例，两边改的地方隔开一段
- **从磁盘来的正文进 Loro 会话之前先换成 `\n`**（`collab/session.ts::toLF`：建会话、`markOrigin`、`mergeExternal` 的磁盘正文、团队 `join` 三方合之前的本机和 base）：
  CodeMirror 的文档里没有 `\r`，会话里留着的话两边下标对不上，编辑器以会话为准对齐时插进来的 `\r` 又成了一个换行 —— 别的编辑器存成 `\r\n` 的笔记，访客那边每行多一个空行（2026-11-15，`REVIEWS/2026-11-15-桌面端验证.md` §3.9）

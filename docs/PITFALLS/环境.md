
## 导出绑定别加 `--no-default-features`

重新生成 `src/lib/bindings.ts`：`cargo run --example export_bindings --features typegen`，带着默认的 feature。
加了 `--no-default-features` 走的是另一份命令清单，里面没有窗口命令（`ready`、`win_*`），导出来会把它们删掉
（2026-10-20、2026-11-10 各踩过一次，`技术方案.md` §7.1）。跑测试才用 `--no-default-features --lib`。

## 连 `::1` 一律 EACCES，一律用 127.0.0.1

- **现象**：内置浏览器打开是 chrome-error，`pnpm tauri dev` 一直卡在「Waiting for your frontend dev server」
- **根因**：这台机器上任何进程连 IPv6 回环 `::1` 都报 EACCES（经 WMI 在 Claude 的进程树之外起的也一样，关掉沙箱也一样），
  `127.0.0.1` 正常。Vite 默认的 `localhost` 只监听 `[::1]`，Node 也把 `localhost` 解析成 `::1`。
  最可疑的是 Clash Verge 的 TUN（Mihomo，`strict-route: true`，虚拟网卡只有 IPv4）或腾讯电脑管家，没让用户关掉试过（2026-10-18）
- **怎么办**：项目的 Vite（`vite.config.ts` 的 `server.host`、`tauri.conf.json` 的 `devUrl`）已经绑 127.0.0.1。
  新写的服务器、脚本一律绑 / 连 `127.0.0.1`，别靠 `localhost`

## Claude 起的进程在 MSIX 容器里

Claude 桌面端是 MSIX 包（`Claude_pzs8sxrjxfjjc`）。

**写 AppData、HKCU 被重定向。** 从它起的进程写 `%APPDATA%`、`%LOCALAPPDATA%`（开始菜单、应用数据目录）和 HKCU，
都被写进 `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\…`，用户和 Windows 看不到；读是合并视图，
所以自己读回来看着「写成功了」也不算数。`%TEMP%` 没被重定向。（2026-10-22 给用户建开始菜单快捷方式、测安装包钩子时查实）

- 要真改用户机器上的东西（快捷方式、跑安装包），用 `Invoke-CimMethod Win32_Process Create` 在容器外起 powershell 跑脚本，
  输出写到 Temp 里的日志再读
- 检查有没有漏进容器：看 `LocalCache\Roaming` 下有没有多出来的东西
- 调试版登记的 `odea://`、通知用的应用标识都进了重定向的注册表，外面的程序看不到：要测在别的程序里点 `odea://` 链接、
  测系统通知，调试版得从容器外起（`桌面端实测.md`）

**启动时间被拖慢。** 从 Claude 起的 WebView2 / CEF，配置目录在默认的 `%LOCALAPPDATA%\<identifier>\…` 时读写都经过重定向层，
「编辑器出来」明显变慢：WebView2 2.4–2.7 秒 → 放 `%TEMP%` 后 1.08–1.19 秒；CEF 3.5–3.9 秒 → 1.2–1.4 秒
（2026-11-10，P14.4）。CEF 吃亏更多，2026-11-03 量出的「CEF 晚 1.2 秒出来」就是这个假象（真实差 0.1–0.2 秒）。
用户机器上的应用不在容器里，没有这一层。

- 在这台机器上量桌面端或任何 WebView 外壳的启动时间、内存，先把数据目录指到 `%TEMP%` 下
  （WebView2 用 `WEBVIEW2_USER_DATA_FOLDER`，Odea 用 `ODEA_DATA_DIR`），或者经 WMI 在容器外起

## 项目文件夹改名

- **现象**（2026-11-13）：在 Claude 的会话里把 `D:\OnTheWay` 改名，`ren` 报「另一个程序正在使用此文件，进程无法访问」
- **根因**：Windows 不让改一个正被进程当工作目录的文件夹。会话自己的进程（`claude.exe`）、终端面板里的 shell 都开在它上面，
  另外开着的编辑器、别的命令行工具也一样。会话还在，就改不了
- **怎么办**：把开在这个文件夹上的会话、终端、编辑器都关掉，在资源管理器里改名（或者 `ren`），再在新的位置重新打开。
  别用 Git Bash 的 `mv`：改不动时不该让它有机会退成「拷一份再删」
- **改完要接回来的**（文件夹里记着绝对路径的地方）：
  - 别的工作树的 `.git` 指着旧路径：在新位置跑 `git worktree repair`
  - `node_modules`：pnpm 在 Windows 上建的是目录链接（junction），`.bin` 里的脚本也写着绝对路径，全断。
    `cmd /c rmdir /s /q node_modules` 再 `pnpm install --frozen-lockfile`
  - `E:\odea-spike-cef\node_modules` 是指到主仓库 `node_modules` 的目录链接：摘掉（`cmd /c rmdir`，只删链接）再 `mklink /J` 指到新位置
  - `src-tauri/target` 里记着旧路径，下一次编译会重编一部分，不用管

## 带中文的 .ps1 要写成 UTF-8 BOM

Windows PowerShell 5.1 把没有 BOM 的 UTF-8 脚本按 GBK 读，中文注释会把下一行吞掉，脚本静默地什么都不做。

## python 改文件会写成 CRLF，heredoc 会吃反斜杠

- **现象**：在 Git Bash 里用 `python - <<EOF` 读写源码，Windows 的 python 文本模式把 `\n` 写成 `\r\n`，整个文件变成 CRLF
  （仓库是 eol=lf），biome 报满屏格式错误。2026-10-30 做表格时踩了两次，五个文件变成 CRLF、`"\n"` 变成了真的换行
- heredoc 里的反斜杠（Windows 路径、`\n`、`\s`）会被先转义一遍，写进去的正则、字符串字面量是坏的；`\u0000` 会变成真的 NUL
- 2026-11-19、11-21 又各踩了一次（白板）：`open(p, "w")` 写出来整篇 CRLF；11-21 那次 heredoc 里的 `\r\n` 被转成了真的回车换行，正则断成好几行、tsc 报一串「未结束的正则」。
  打印带 `⌘`、`⇧` 的字符串还会因为控制台是 GBK 抛 `UnicodeEncodeError`
- **怎么办**：改文件用 Edit；批量替换用 `node -e` 或写成脚本文件再跑（fs 读写不改换行）；非用 python 不可就 `open(p, encoding="utf-8", newline="")` 读写。
  改完用 `git ls-files --eol` 检查（没跟踪的新文件不在里面：用 node 数回车，见下一条）

## Git Bash 里 `grep $'\r'` 查不出 CRLF

- **现象**：`grep -rl $'\r' src` 想找带 CR 的文件，结果每个文件都列出来了（2026-11-13 查 `cargo fmt` 有没有把换行改坏时，误以为 79 个文件全变成了 CRLF）
- **根因**：传给 MSYS 程序的参数里的回车被吃掉，模式成了空串，空模式匹配所有文件
- **怎么办**：用 node 逐字节数：`fs.readFileSync(f).includes(13)`；或者 `git ls-files --eol`（只看已跟踪的文件）

主屏 2560×1440、100% 缩放（96 DPI）、180Hz（2026-10-29 查实）。用户贴的截图是 1 倍屏的：1.5px 的描边在截图里是一排实色加一排半透明，
启动器 800×560 的窗口截出来就是 800 宽。

## Claude 的 Browser 面板藏着时，页面是后台页

- **现象**：`tabs_context` 说「The Browser pane is currently hidden」时，`requestAnimationFrame` 被节流到一百多毫秒一帧（30 帧量了 3.7 秒）。靠 rAF 的东西都晚到：命令面板打开后下一帧才聚焦输入框，紧跟着发的按键打不进去、`document.activeElement` 量出来是上一步的；motion 的动画时长也不对（2026-11-14 全项目审查 A 段）
- **怎么办**：发完按键先在 `javascript_tool` 里等几帧（`await new Promise(r => requestAnimationFrame(r))` 连着几次）再量、再发下一个键；截图会逼出一帧。动效的时长曲线、焦点的先后这类结论，面板藏着时量的不算数，写进「没验」

## 写测量脚本时的三个小坑（2026-11-15 量后端时各踩了一次，`REVIEWS/2026-11-15-桌面端验证.md` §2.4）

- **node 的 `import` 写 `D:/…` 的绝对路径直接报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`**（`D:` 被当成协议）：写 `file:///D:/…`。上一个会话写好的驱动一次没跑，就卡在这一行
- **PowerShell 把空字符串参数吞掉**：`node x.mjs a 5 "" label` 到 node 那里只剩三个参数，后面的往前挪（标签成了另一个参数，结果写进了别的文件）。占位用一个不会被认的值，或者改用环境变量
- **PowerShell 的 `-f` 格式串里 `{0:F1}}}` 输出字面的 `F1`**：格式说明里的 `}}` 被当成转义的右花括号。右花括号前面空一格（`{0:F1} }}`），或者先 `.ToString('F1')` 再拼
- **往文件里写看不见的字符（零宽空格、组合符号），写进去的成了真字符**（2026-11-15 第五段）：给 Edit 工具的文字里写 `"\u200b"`，落到文件里的是一个真的 U+200B（不是六个字符的转义），
  测试照样过、肉眼看不出两条样例有什么不同；`biome format` 不会把它改回来。测试里用 `String.fromCharCode(0x200b)` 拼，Rust 用 `"\u{200b}"`（花括号的不会被解掉）；
  文档里要写转义就用 Python 的 `chr(92) + "u200b"` 去换（命令文字里连着的两个反斜杠，到 Git Bash 的 heredoc 里也只剩一个；换完数一遍还剩几个）

## Browser 面板里写不了剪贴板

- **现象**（2026-11-17，`协同编辑.md` §28）：面板里点「复制」这类按钮，`navigator.clipboard.writeText` 报 `NotAllowedError: Write permission denied`，
  真的点（`computer` 的 `left_click`，有用户手势、`document.hasFocus()` 是 true）也一样；`navigator.permissions.query({ name: "clipboard-write" })` 是 `denied`
- **怎么办**：面板里只看得到失败那一支（按钮说「复制不了」）。成功那一支在单测里把 `navigator.clipboard` 换成假的验，或者到桌面端（WebView2 里应用的复制按钮一直能用）

## 在页面里 `import("/src/app/store.ts")` 拿到的可能是另一份 store

- **现象**（2026-11-20 边栏改版验收）：开发服务器起来以后 `store.ts` 被改过（别的会话、热更新都算），应用自己引的是 `/src/app/store.ts?t=<时间戳>`；
  `javascript_tool` 里不带 `?t=` 再 import 一次，Vite 当成另一个模块，拿到一份全新的 store —— `initialized: false`、`layout.plugins: []`，
  往里 `setState` 界面不动，读出来的状态和屏幕上的对不上（侧栏明明收起了，读出来 `panelCollapsed: false`）
- **怎么办**：先从 `performance.getEntriesByType("resource")` 里找应用实际加载的那个地址（带 `?t=` 的）再 import，挂到 `window` 上复用；
  拿到以后先读一个只有真 store 才有的值（`useData.getState().initialized` 是 true）对一下

## 用合成的指针事件验 React 的 `onPointerEnter` / `onPointerLeave`：要给 `relatedTarget`

- **现象**（同上，验边缘把手）：`dispatchEvent(new PointerEvent("pointerout"))` 不给 `relatedTarget`，React 当成「指针离开了窗口」，
  从目标一路往上每一层都发 `onPointerLeave`（包着把手的那一层也收到，起了缩回的定时器）；`pointerover` 不给就当成「从窗口外进来」。
  另外两个事件连着在同一段脚本里发，中间 React 还没重画，第二个事件的处理函数读到的是上一次渲染的状态
- **怎么办**：成对发 `pointerout`（`relatedTarget` = 要进的那个元素）+ `pointerover`（`relatedTarget` = 离开的那个），和浏览器真发的一样；
  每一步之间 `await` 几十毫秒再发下一个、再读

## 同一个文件夹里有别的会话开着开发服务器：浏览器预览会被热更新整页重载

- **现象**：另一个会话在同一个文件夹里改文件（2026-11-19 是 `CommandPalette.tsx`、`globals.css`），自己起的 `pnpm dev`（换了端口照样监听整个 `src`）跟着热更新、整页重载：
  拿到手的 `EditorView` 变成旧的、命令面板打字打到一半被重开，回车落到了「新建笔记「…」」上，点击落到了别的笔记上
- **怎么办**：要连着操作好几步的验证，用生产构建：`vite build --outDir <自己的目录>` 再起 `odea-preview`（`vite preview`，静态文件，不跟着源码变）。开发服务器只拿来看一眼

## Git Bash 把以 `/` 开头的参数改成 Windows 路径

- **现象**（2026-11-20）：`python addimp.py "@/lib/tooltip" …` 写进文件的是 `import { tip } from "@E:/Program Files/Git/lib/tooltip"`。
  MSYS 把传给非 MSYS 程序（python、node）的、看着像 POSIX 路径的参数换成 Windows 路径，`@/lib/…` 也被当成了路径
- **怎么办**：这类参数前面加 `MSYS_NO_PATHCONV=1`，或者把它写进脚本文件里、不从命令行传；改完 `grep -rn "Program Files" src` 核对一下

## Bash 工具传进去的命令里两个反斜杠并成了一个

- **现象**（2026-11-22，白板第 5 步）：用 heredoc（`<<'EOF'`，带引号的）喂给 python 改源码，脚本里写的是两个反斜杠加 b，
  文件里落的是一个退格符（0x08）—— python 收到的只有一个反斜杠加 b。单引号、带引号的 heredoc 都拦不住，`printf '%s'` 也一样：
  命令在到 Git Bash 之前两个反斜杠就并成了一个。连这一条坑一开始也是这么写坏的
- **怎么办**：改带反斜杠的源码（正则、转义）和文档用 Edit 工具；非要用脚本，改完 `grep -c $'\x08'`、看一眼改过的那几行

## cargo 不在 PATH 上


## 导出绑定别加 `--no-default-features`

重新生成 `src/lib/bindings.ts`：`cargo run --example export_bindings --features typegen`，带着默认的 feature。
加了 `--no-default-features` 走的是另一份命令清单，里面没有窗口命令（`ready`、`win_*`），导出来会把它们删掉
（2026-10-20、2026-11-10 各踩过一次，`技术方案.md` §7.1）。跑测试才用 `--no-default-features --lib`。

## 连 `::1` 一律 EACCES，一律用 127.0.0.1

- **现象**：内置浏览器打开是 chrome-error，`pnpm tauri dev` 一直卡在「Waiting for your frontend dev server」
- **根因**：这台机器上任何进程连 IPv6 回环 `::1` 都报 EACCES（经 WMI 在 Claude 的进程树之外起的也一样，关掉沙箱也一样），
  `127.0.0.1` 正常。Vite 默认的 `localhost` 只监听 `[::1]`，Node 也把 `localhost` 解析成 `::1`。
  最可疑的是 Clash Verge 的 TUN（Mihomo，`strict-route: true`，虚拟网卡只有 IPv4）或腾讯电脑管家，没让用户关掉试过（2026-10-18）
- **怎么办**：项目的 Vite（`vite.config.ts` 的 `server.host`、`tauri.conf.json` 的 `devUrl`）已经绑 127.0.0.1。
  新写的服务器、脚本一律绑 / 连 `127.0.0.1`，别靠 `localhost`

## Claude 起的进程在 MSIX 容器里

Claude 桌面端是 MSIX 包（`Claude_pzs8sxrjxfjjc`）。

**写 AppData、HKCU 被重定向。** 从它起的进程写 `%APPDATA%`、`%LOCALAPPDATA%`（开始菜单、应用数据目录）和 HKCU，
都被写进 `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\…`，用户和 Windows 看不到；读是合并视图，
所以自己读回来看着「写成功了」也不算数。`%TEMP%` 没被重定向。（2026-10-22 给用户建开始菜单快捷方式、测安装包钩子时查实）

- 要真改用户机器上的东西（快捷方式、跑安装包），用 `Invoke-CimMethod Win32_Process Create` 在容器外起 powershell 跑脚本，
  输出写到 Temp 里的日志再读
- 检查有没有漏进容器：看 `LocalCache\Roaming` 下有没有多出来的东西
- 调试版登记的 `odea://`、通知用的应用标识都进了重定向的注册表，外面的程序看不到：要测在别的程序里点 `odea://` 链接、
  测系统通知，调试版得从容器外起（`桌面端实测.md`）

**启动时间被拖慢。** 从 Claude 起的 WebView2 / CEF，配置目录在默认的 `%LOCALAPPDATA%\<identifier>\…` 时读写都经过重定向层，
「编辑器出来」明显变慢：WebView2 2.4–2.7 秒 → 放 `%TEMP%` 后 1.08–1.19 秒；CEF 3.5–3.9 秒 → 1.2–1.4 秒
（2026-11-10，P14.4）。CEF 吃亏更多，2026-11-03 量出的「CEF 晚 1.2 秒出来」就是这个假象（真实差 0.1–0.2 秒）。
用户机器上的应用不在容器里，没有这一层。

- 在这台机器上量桌面端或任何 WebView 外壳的启动时间、内存，先把数据目录指到 `%TEMP%` 下
  （WebView2 用 `WEBVIEW2_USER_DATA_FOLDER`，Odea 用 `ODEA_DATA_DIR`），或者经 WMI 在容器外起

## 带中文的 .ps1 要写成 UTF-8 BOM

Windows PowerShell 5.1 把没有 BOM 的 UTF-8 脚本按 GBK 读，中文注释会把下一行吞掉，脚本静默地什么都不做。

## python 改文件会写成 CRLF，heredoc 会吃反斜杠

- **现象**：在 Git Bash 里用 `python - <<EOF` 读写源码，Windows 的 python 文本模式把 `\n` 写成 `\r\n`，整个文件变成 CRLF
  （仓库是 eol=lf），biome 报满屏格式错误。2026-10-30 做表格时踩了两次，五个文件变成 CRLF、`"\n"` 变成了真的换行
- heredoc 里的反斜杠（Windows 路径、`\n`、`\s`）会被先转义一遍，写进去的正则、字符串字面量是坏的；`\u0000` 会变成真的 NUL
- **怎么办**：改文件用 Edit；批量替换用 `node -e` 或写成脚本文件再跑（fs 读写不改换行）。改完用 `git ls-files --eol` 检查

## Git Bash 里 `grep $'\r'` 查不出 CRLF

- **现象**：`grep -rl $'\r' src` 想找带 CR 的文件，结果每个文件都列出来了（2026-11-13 查 `cargo fmt` 有没有把换行改坏时，误以为 79 个文件全变成了 CRLF）
- **根因**：传给 MSYS 程序的参数里的回车被吃掉，模式成了空串，空模式匹配所有文件
- **怎么办**：用 node 逐字节数：`fs.readFileSync(f).includes(13)`；或者 `git ls-files --eol`（只看已跟踪的文件）

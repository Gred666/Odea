## `git worktree remove` 会顺着目录链接删到别处

- **出过的事**（2026-11-13）：注销一个旧的临时工作树（以前量性能时在 Temp 里建的），它里面的 `node_modules` 是指到主仓库
  `node_modules` 的目录链接（junction）。`git worktree remove` 递归删目录时把链接当成普通目录走了进去，主仓库的
  `node_modules/.bin`、`.modules.yaml` 和 `.pnpm` 里一部分包被删空，`pnpm lint` 报找不到 biome
- **根因**：Git for Windows 删目录不认 junction；`git status --ignored` 只说 `node_modules/` 被忽略，看不出它是链接
- **怎么办**：注销工作树、删临时目录之前先找链接：`Get-ChildItem -Recurse -Attributes ReparsePoint`，有就先把链接本身摘掉
  （`[System.IO.Directory]::Delete(路径, $false)` 或 `cmd /c rmdir 路径`，都只删链接不动目标）。临时工作树要用依赖就在里面
  `pnpm install`，别链到主仓库。`spike/cef` 的工作树（`E:\odea-spike-cef`）的 `node_modules` 现在还是这样链着的，要删它先摘链接
- **修**：`node_modules` 残了就整个删掉（`cmd /c rmdir /s /q node_modules`）再 `pnpm install --frozen-lockfile`，十来秒；
  在残的上面直接装会报 ENOENT
- **zustand 的 store 是模块级的，同一个测试文件里一条留下的状态带进下一条**：属性面板的测试里上一条 `requestAddProperty` 过，下一条一挂上面板就开着「加属性」那一行、顺手取了一览，一条本该挂的测试（「有属性就去取一览」去掉了）照样过；单跑那一条才挂。用到的 store 在 `beforeEach` 里放回初值，改完实现做变异检查时也单跑一遍（2026-11-15）
- **前后端「同一条」Unicode 正则，Unicode 表不是同一版**（2026-11-17，`提醒与属性.md` §3.3 放宽的实现记录）：Rust `regex-syntax` 0.8.11 是 16.0（`unicode_tables/*.rs` 文件头的 `ucd-16.0.0`），
  WebView2 151 带的 ICU 是 78（运行时目录 `icudtl.dat` 里搜 `icudt78l`）= Unicode 17.0，跑前端测试的 Node 24.10 是 ICU 77 = 16.0（`process.versions.unicode`）。
  所以**单测里两边一致，不代表桌面端里一致**：17.0 新加的字（CJK 扩展 J 等 4662 个字母）编辑器认、后端不认。要核对拿无头 Edge（同一版 Chromium、同一份 ICU）把全部码点各试一遍，和 Node / Rust 数个数比
- **能滚的 `<pre>`、`div` 不用加 `tabIndex={0}`**（2026-11-17，`协同编辑.md` §28）：Chromium 130 起，能滚、里面又没有能聚焦的东西的区域自己进 Tab 顺序，
  WebView2 151 有。Browser 面板里实测：Tab 进得去、PageDown 滚得动。biome 的 `noNoninteractiveTabindex` 也不让在 `<pre>` 上加

## CI 的 clippy 比本机新，新规则只在 CI 上冒出来

- **出过的事**（2026-11-17）：master 的「检查」从 2026-11-13 起一直挂在 Rust 的 clippy 上，没人发现（发版的打包不跑 clippy，0.9.0 照样打出来了）。
  挂的是 `src/vault/fsio.rs` 里长度固定为 2 的 `chunks_exact(2)` —— 新版 clippy 要换成 `as_chunks::<2>()`
- **根因**：本机的工具链是 1.96，CI 用 `dtolnay/rust-toolchain@stable`，每次取最新的（当时 1.100.0）。clippy 每个版本都加规则，本机两遍 clippy 过了不代表 CI 过；
  `cfg(not(windows))` 的代码本机也编不到
- **怎么查**：Actions 的日志要登录才看得到；不登录能看的只有哪一步挂了（`/actions/runs/<id>/jobs` 的 `steps`）。本机复现用 WSL（Debian，`~/.cargo` 里有 rustup）：
  `rustup toolchain install <CI 的版本> --profile minimal -c clippy`（只是多装一个，不改默认），`git archive HEAD | tar -x -C ~/odea-ci`（要整个仓库：
  Rust 用 `include_str!` 读了 `src/` 下的几份前端文件），然后 `cargo +<版本> clippy --no-default-features --lib -- -D warnings`，再加 `--profile test` 一遍。
  WSL 里没有 sudo 装不了 `libssl-dev`：从 `security.debian.org/debian-security/pool/updates/main/o/openssl/` 下那个 deb、`dpkg -x` 到用户目录，
  把 `usr/include/x86_64-linux-gnu/openssl/*` 拷进 `usr/include/openssl/`，在它的 `usr/lib/x86_64-linux-gnu/` 里建 `libssl.so`、`libcrypto.so` 指向系统的 `.so.3`，
  设 `OPENSSL_INCLUDE_DIR`、`OPENSSL_LIB_DIR` 指过去（clippy 只检查不链接，头文件版本差一点不要紧）
- **以后**：推上去以后看一眼「检查」是不是绿的；挂了先看是哪一步，clippy 挂了就照上面在 WSL 里用 CI 那一版复现

## 网络事件交给「现在的那个」对象，换了以后晚到的事件落到新的身上

- **现象**（2026-11-18，`协同编辑.md` §29.3）：`TeamUnseenBanner.dom.test.tsx` 第一条过、后面四条超时。第二条里李四加入时马上收到一个 DocClosed，
  回到一个人编辑，而加入那一步还要等 8 秒才放手（`busy`），在用例的 5 秒里一直不再试
- **根因**：`initTeam` 登记的 `onControl` / `openPipe` 回调调的是模块变量 `controller?.control(…)`。上一条用例的 mock 网络还有 `setTimeout` 里没发完的事件
  （窗格卸下时退出会话的那一下），`resetTeam` 以后新的 controller 一建好，这些晚到的事件就交给了它
- **修**：回调里用登记那一刻的那个 controller（`const owner = …; net.onControl((c) => owner.control(c))`），收掉的 controller 收到也不理
- **以后**：往网络、定时器里登记回调时，回调闭包里拿「当时的那个」对象，不拿会被换掉的模块变量。vitest 4 默认不打通过的用例的 `console.log`：
  加调试输出时看的是挂了的那几条，别以为「没输出」就是「没走到」

# 工程

- Tauri 在调 `setup` 之前就把配置里的窗口建好了（tauri 2.11 `app.rs` 的 `setup()`：先 `WebviewWindowBuilder::from_config`，再调用户的 setup），窗口位置插件更早，在 `Builder::build` 时就读了文件。要在它们之前动数据目录（改名时搬 WebView 数据），只能放在 `run()` 开头、建 Builder 之前。WebView 的数据目录：Windows / Linux 是「本地数据目录/标识」（`manager/webview.rs`），macOS 是系统按 bundle id 放的 `~/Library/WebKit/<标识>`
- `pnpm 10` 拦 postinstall，esbuild 不放行则 vite 起不来。
- `pnpm tauri dev` 会占 1420 端口，和已经在跑的 `pnpm dev` 冲突，先停一个。
- Python 脚本在 Windows 上写文件会把换行转成 CRLF，Biome 会报格式错。批量改文件后跑一次 LF 归一化。
- ~~这台机器上 `cargo run --example export_bindings` 编得过、跑不起来（`STATUS_ENTRYPOINT_NOT_FOUND`，DLL 加载的问题）；要新的 `bindings.ts` 就启动一次 debug 桌面端。~~ 2026-10-18 修好了，见下面「comctl32 v6」那条。桌面端在 `tauri dev` 里因为改了 Rust 自动重启时，写 `bindings.ts` 可能撞上文件正被占着（Windows 错误 1224「用户映射区域」）直接 panic 退出 —— 再启动一次就好（2026-10-07）。
- **不要跑 `cargo fmt`**：项目的 Rust 代码不是按 rustfmt 默认配置排的（不少行超过 100 列），也没有 `rustfmt.toml`。跑一次会改动整个 crate 二十多个文件，把没提交的改动里也混进一堆换行（2026-10-07 出过一次，靠 Claude Code 的文件快照还原）。
- `cargo test --no-default-features` 会因 `main.rs` 的 `run()` 被 feature 门控而失败，加 `--lib`。
- **每个窗口都挂着 `on_navigation`（`navigation.rs`，技术方案 §14.1.1）**，新建窗口、新加 iframe、换窗口的地址都要进它的名单，不然窗口是空的：
  窗口第一次载入就经过它（2026-11-15 在 Windows 上量的）。Windows 上它只管主框架，**macOS / Linux 上连 iframe 的导航也问它** —— 新加一种 iframe（别的协议、别的路径）在 Windows 上好好的，到那两个平台上加载不出来
- `url::Url::origin()` 对 `tauri://`、`odea-plugin://` 这类非特殊协议是 opaque 的，两个永远不相等：比「同源」要自己比协议、主机、端口。
  `file://别的主机/C:/…` 按 URL 标准（路径以盘符开头）主机被清空，解析出来是本机的 `file:///C:/…`。tauri-runtime-wry 把转不成 `Url` 的导航地址一律放行
- tauri-specta 三个 crate 的 RC 版本互不兼容，`=` 锁死，不要跟着 `cargo update` 走。
- 无事件时 tauri-specta 生成的辅助代码触发 `noUnusedLocals`，生成文件头加了 `// @ts-nocheck`，biome 也忽略它。

## `git worktree remove` 会顺着目录链接删到别处

- **出过的事**（2026-11-13）：注销一个旧的临时工作树（以前量性能时在 Temp 里建的），它里面的 `node_modules` 是指到主仓库
  `node_modules` 的目录链接（junction）。`git worktree remove` 递归删目录时把链接当成普通目录走了进去，主仓库的
  `node_modules/.bin`、`.modules.yaml` 和 `.pnpm` 里一部分包被删空，`pnpm lint` 报找不到 biome
- **根因**：Git for Windows 删目录不认 junction；`git status --ignored` 只说 `node_modules/` 被忽略，看不出它是链接
- **怎么办**：注销工作树、删临时目录之前先找链接：`Get-ChildItem -Recurse -Attributes ReparsePoint`，有就先把链接本身摘掉
  （`[System.IO.Directory]::Delete(路径, $false)` 或 `cmd /c rmdir 路径`，都只删链接不动目标）。临时工作树要用依赖就在里面
  `pnpm install`，别链到主仓库。`spike/cef` 的工作树（`E:\odea-spike-cef`）的 `node_modules` 现在还是这样链着的，要删它先摘链接
- **修**：`node_modules` 残了就整个删掉（`cmd /c rmdir /s /q node_modules`）再 `pnpm install --frozen-lockfile`，十来秒；
  在残的上面直接装会报 ENOENT
- **zustand 的 store 是模块级的，同一个测试文件里一条留下的状态带进下一条**：属性面板的测试里上一条 `requestAddProperty` 过，下一条一挂上面板就开着「加属性」那一行、顺手取了一览，一条本该挂的测试（「有属性就去取一览」去掉了）照样过；单跑那一条才挂。用到的 store 在 `beforeEach` 里放回初值，改完实现做变异检查时也单跑一遍（2026-11-15）
- **前后端「同一条」Unicode 正则，Unicode 表不是同一版**（2026-11-17，`提醒与属性.md` §3.3 放宽的实现记录）：Rust `regex-syntax` 0.8.11 是 16.0（`unicode_tables/*.rs` 文件头的 `ucd-16.0.0`），
  WebView2 151 带的 ICU 是 78（运行时目录 `icudtl.dat` 里搜 `icudt78l`）= Unicode 17.0，跑前端测试的 Node 24.10 是 ICU 77 = 16.0（`process.versions.unicode`）。
  所以**单测里两边一致，不代表桌面端里一致**：17.0 新加的字（CJK 扩展 J 等 4662 个字母）编辑器认、后端不认。要核对拿无头 Edge（同一版 Chromium、同一份 ICU）把全部码点各试一遍，和 Node / Rust 数个数比
- **能滚的 `<pre>`、`div` 不用加 `tabIndex={0}`**（2026-11-17，`协同编辑.md` §28）：Chromium 130 起，能滚、里面又没有能聚焦的东西的区域自己进 Tab 顺序，
  WebView2 151 有。Browser 面板里实测：Tab 进得去、PageDown 滚得动。biome 的 `noNoninteractiveTabindex` 也不让在 `<pre>` 上加

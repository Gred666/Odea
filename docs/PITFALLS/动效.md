# 动效

## 先对齐再动

同一类问题已经出过好几次（2026-10-06 全应用排查过一轮，2026-10-17 图片的悬停按钮又犯了）。
用户的描述总是「出来的时候闪一下」「0.1 秒左右重新渲染了一下」「先糊、再抖一下」。

**原因。** 元素一做 opacity / transform 动画，浏览器就把它提成单独一层，动画结束再放回页面里画。
层里和页面里是两种画法：层对齐到整物理像素、用灰度抗锯齿，transform 位移、缩放时整层当成位图重采样。
元素落在半个物理像素上（1.5 倍屏、居中排版很常见）时，动画结束那一帧整块挪不到一个像素、
笔画和圆角重新抗锯齿 —— 就是那一下「闪」。

**规矩。**

1. 出现、消失只淡 `opacity`。不位移、不缩放，3px 也不行（菜单、悬停卡片、图片上的按钮都只淡入）
2. 不给 `box-shadow`、`backdrop-filter`、`filter` 做过渡（`docs/技术方案.md` §10.1）。焦点框、选中描边直接出现
3. 会淡入淡出的小控件（悬停按钮、浮动工具条、角标、浮层上的按钮条）：
   - CSS 加 `will-change: opacity`，让它一直待在自己的图层上，淡入前后是同一种画法
   - 每次开始淡入 / 淡出之前调 `snapToDevicePixels`（`src/lib/devicePixels.ts`）对齐到整物理像素，
     层里画出来才不糊。位置跟着排版、滚动变，所以是每次动之前对齐，不是只在创建时
   - 一排很多个的（目录树每一条的收起箭头、文件列表每一行的「…」和箭头）改成淡 `color`、转 SVG 里的 `<path>`：原地重画、
     不进合成层，就不用 will-change、不用对齐。一个控件一个图层的话，两百条目录一百多个图层
4. 小控件别用毛玻璃，底色要够深（白图标放在 50% 透明的灰底上，看着就是糊的）
5. 要放大缩小的图片（大图查看）改 `width` / `height`，不用 `transform: scale`：
   位图被拉伸会发虚，停下来那一帧重画、清楚一下
6. fixed 定位的东西居中用 `margin: auto`，不用 `translate(-50%)`：宽度是奇数时落在半个像素上
7. 动排版（高度、`left`）的时候，字落在整像素上画，要看「每一帧实际挪了几个像素」：用 ease-out cubic
   这类起步就走、收尾短的曲线。从静止起步的弹簧头两帧几乎不动、末尾在最后一两个像素里磨蹭，
   条目停住、隔几帧跳 1px —— 用户说的「感觉帧数不高」（2026-10-17 目录树收起）
8. 一整块内容换成另一块（换篇、换页）用溶解，不用两份各淡各的：旧的拍快照、铺底色盖在上面退，
   新的一直不透明、不动（`SwapFade`）。各淡各的中间有一段两份都只剩一半，整块字先浅再深 ——
   用户说的「闪来闪去」（2026-10-28 今日TODO ↔ /GOAL）。快照挪了位置，容器查询要跟着补上，不然字号都不对
9. 窗口出现、消失也一样（2026-10-29 启动器，`docs/仓库与启动器.md` §16.2）：Windows 的关窗动画是「缩到约 0.95 + 淡出」，
   缩放到最后一帧猛跳 11px 然后停住 —— 用户说的「关那个小窗口时掉了几帧」。要退场的窗口关掉系统过渡、
   自己淡整窗透明度（`workspace::fade_out`）。一个窗口换成另一个时，旧的垫在底下不动，等新的盖上了再退

怎么逐帧验：`VERIFICATION.md`「逐帧对比」。

## 另外几条

- motion 自带的 `useReducedMotion()`：`MotionConfig` 只要设过一次 `reducedMotion="always"`，它之后就一直返回 true 直到刷新。要判断系统偏好用 `lib/motion.ts::usePrefersReducedMotion()`。
- 列表栏不能动画化 `marginLeft`：布局属性，动画期间 flex 行每帧重排，开了 lineWrapping 的 CodeMirror 逐帧折行，头几帧稳定 28ms 一帧。改成挂载即入流、只动 `x`；主内容用 `popLayout` + `anchorX="right"` 把退场屏冻结在原位交叉淡出。
- 中文文字的 `font-weight` 不能做 CSS 过渡：每一帧都是一个新的小数字重，回退字体（YaHei 没有可变轴）每次都要重新匹配，实测一个标签一帧 11ms、拉丁文只要 0.5ms。导航切换时新旧两个标签一起变，就是 22ms 一帧持续 140ms。
- 工作区进场不能带 transform：编辑器不能挂在正在平移的祖先里，否则得先渲染占位再换编辑器，两者排版不同（正文 15px vs 17px/1.4），一换整篇重排。
- `React.lazy + Suspense` 即便 promise 已 resolve，首次渲染也必然先 suspend 一次把 fallback 提交上屏。编辑器组件自己持有解析后的引用，bootstrap 里 await 预载。

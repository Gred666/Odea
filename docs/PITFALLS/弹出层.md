# 弹出层（Ctrl+E 表情选择器、`/模板`、命令面板）

- **盖在正文上的浮层不能整块从透明淡入**。用户报「按 Ctrl+E 正文会跳一下」，实机录屏（WebView2 远程调试逐帧记录 150 秒）里正文一个像素都没动过：是面板开在光标上方、前 100ms 半透明，一行行表情格子和底下的正文叠在一起，看着像正文在跳。入场方向要在挂载那一帧就对：面板尺寸是定的，先按常量算好位置，挂上以后再按量到的尺寸校正。
- **盖在正文上的浮层也不能缩放**。上一版「实心卡片 scale 0.97 → 1 + 内容淡入」，用户报「刚打开时字是模糊的，大概 0.1s，然后抖一下才变好」：带字的层一缩放就被当位图拉伸，动画那 ~200ms 字发虚、有重影，结束撤掉 transform 的那一帧重新按原尺寸画，字一下变清楚还挪了一点（1.5 倍屏无头 Chrome，`performance.now` + 文档时间线一起放慢 10 倍逐帧截图，对比最终帧确认）。现在卡片从贴光标的那条边展开 —— 破例动 `height`（fixed 小盒子，内容高度不跟着变，4 倍降速下每帧 3.5–8ms），内容不缩放、不变透明，每一帧露出来的部分和最终画面逐像素一致；往上开的用 `bottom` 定位，钉住贴光标的那条边；收起折回那条边，剩不到 10px 空白边时才淡掉（早淡的话半透明的一条带着搜索栏的字叠在正文上）。位置对齐到物理像素（`pinnedEdge`）。`lib/motion.ts` 的 `popoverCard`，`popupMotion.test.ts` 守着。
- **同类问题全应用排查（2026-10-06）**：同样「先糊、再抖一下」的还有命令面板（scale 0.97）、下拉菜单（CSS scale 0.96 + 上移）、悬停卡片（CSS scale 0.98 + 位移）、撤销 / 出错 / 通知提示条（scale 0.97）、日历「今天」按钮和列表栏标题右侧按钮（scale 0.9）。逐帧看：动画快结束时字已经不动了但还是虚的，最后一帧才跳清楚。只去掉缩放、保留 CSS 位移的菜单照样跳；只动 opacity 的从头到尾和终帧一致。现在命令面板用 `popoverCard` 展开，菜单和悬停卡片只淡入，提示条上滑 + 淡入不缩放（tween），两个按钮只淡入；没用到的 `popIn`（scale 0.97 的浮层预设）删掉了。日历切月的 spring 加了 `restDelta: 0.01`（默认差半个像素就跳到终点）。没问题的：左侧导航按下的 scale（主线程逐帧重画）、表格 / 目录 / 查找面板的上浮 3–4px（同上）、只有图标的缩放。

- 每张**不同的** `data:` SVG 图，Chrome 都要同步建一个隔离的 SVG 文档（trace 里是 `IsolatedSVGDocumentHost`，发生在布局里），再插一次还得再建。表情的静止帧图只适合「同一个表情画很多遍」的正文；选择器里 48 个各不相同，以前每次打开都建 48 个文档 —— 4 倍降速 + 2x 屏上首次 Ctrl+E 卡 0.75–0.94 秒。选择器的格子现在 `mount(host, { image: false })` 用活的 SVG。
- 界面字体里没有的字（↵ ⇧ ↑↓ ⌘ ⏎）第一次画时浏览器要把系统字体挨个找一遍兜底（装的字体越多越慢），只一个 ↵ 在 4 倍降速下就是 100ms。按键提示一律用 lucide 图标，`popupGlyphs.test.ts` 守着。
- 用户的桌面端（WebView2 + dev 构建 + 高分屏）比无头 Chrome 慢好几倍：1 倍速下 100ms 的开销到他那儿接近 1 秒。改了编辑器或弹出层，要在 4 倍 CPU 降速 + 2x 屏下量一遍**已有**弹出层的打开耗时（Chrome trace，不是看截图）。
- **模态对话框要管焦点，挂 `useModalFocus(open)`（`lib/modalFocus.ts`）**。全仓 13 个 `role="dialog" aria-modal="true"`（命令面板、提醒设置、同步……）以前都不管：打开时焦点留在 body，第一下 Tab 落在遮罩那个全屏按钮上、再往下走到后面的页面；关掉以后焦点掉在 body，Ctrl+K → Esc 接着打字什么都不进（2026-11-14 全项目审查 §4.41，无头 Chrome 发真的按键量的）。新加的对话框把它返回的 ref 挂在 `role="dialog"` 那个元素上：打开时焦点进面板（自己聚焦了输入框的不抢）、Tab 在面板里转、关掉还给打开之前最后一个不在模态框里的元素（从命令面板开的还给正文）。它认「遮罩按钮紧跟着装面板的那一层」这个结构（点遮罩那一下焦点先落在遮罩上），别把遮罩挪到别处去。面板藏着的内置浏览器量不了焦点（`环境.md` 最后一节），用无头 Chrome + `Emulation.setFocusEmulationEnabled`
- **在 keydown 里把焦点挪走，要拦掉这一下的默认动作**。焦点在按下的那一刻换了地方，浏览器接着把这个键的字（回车的换行）送给新拿到焦点的元素：属性面板回车存值、焦点还给正文，每存一条正文开头多一个空行（2026-11-14 全项目审查 §4.47）。`PropertiesPanel.tsx::leave` 现在收事件、先 `preventDefault()`；别处在 keydown 里 `focus()` 别的输入区同理。happy-dom 不会把字送过去，单测量 `defaultPrevented`
- **正文编辑器按篇挂（`key` 是这一篇），换篇就是带着焦点的那个被拆掉**：Ctrl+Tab、Alt+数字、Ctrl+W、从命令面板打开另一篇以后焦点掉在 body 上（§4.46）。现在 `lib/focusHandoff.ts` 交接：拆掉时焦点在里面就交（`MarkdownEditor` 的 layout effect 收尾，DOM 还没摘；普通 effect 收尾时 DOM 已经摘了，看不出焦点在不在），挂上时一秒内、焦点还在 body 上就接。新加的「换掉正文编辑器」的路径不用管，自己是另起一栏的（Ctrl+\）要显式交
- **下拉菜单（Radix `DropdownMenu`）别在 `onCloseAutoFocus` 里一律 `preventDefault()`**：那一下拦的是「收起以后把焦点还给触发按钮」，拦了以后 Esc、选完一项焦点都掉在 body 上（2026-11-14 全项目审查 §4.51，类型菜单、行菜单、仓库切换、日记本切换都是）。菜单都是 `modal={false}`：点了外面、动作自己把焦点放到别处（改名的输入框、打开的对话框）Radix 记成「碰了外面」，本来就不抢，不用自己拦。同理，一项一项能拆掉的东西（属性列表的「去掉 X」）点了以后按钮没了，焦点要显式交给接替它的那一项或者输入框（§4.50）；成组的格子（日历）只让一格进 Tab、格子之间用方向键（§4.53）
- **盖在列表上、点外面就关的卡片（文件夹选择器、智能文件夹）也挂 `useModalFocus`**，不然关掉焦点掉在 body、Tab 走出卡片时卡片还开着盖着焦点（§4.56）。三个细节：
  ① 面板里的输入框别用 `autoFocus`，在 `useModalFocus` 之后的 effect 里 `focus()` —— 开发时 StrictMode 把 effect 跑两遍，中间那次收尾把焦点还了回去，`autoFocus` 不会再来，焦点停在面板上；
  ② 在 `AnimatePresence` 里的用 `useModalFocus(useIsPresent())`，退场一开始就还焦点；③ Esc 挂在面板上，不只挂在输入框上。
  从下拉菜单里开的对话框，`modalFocus.ts` 记的「打开之前的那个」是菜单的触发按钮（菜单项一选就拆掉，不算）
- **对话框在矮视口里要有 `max-h`、中间那段能滚**：1280×800 的屏 150% 缩放只有 853×533，上面留 10–14vh 的对话框高过 450px 就把按钮推出窗口（提醒设置 §4.54、插件授权 §4.57）。
  按钮那一排放在滚动区外面，一直看得见；启动器窗口不能改大小（800×560），出错那一行要滚进来（§4.55）
- **Radix 菜单的触发元素（`asChild`）上别自己写 `id`**：`Slot` 合并时子元素的 `id` 盖掉 Radix 给的那个，菜单内容的 `aria-labelledby` 就指着一个不存在的 id。想让别的元素描述它（`aria-describedby`），换个办法 —— 属性面板「类型不符」改成给值的输入框挂一个 `sr-only` 的说明（2026-11-15 审查 §6.8；2026-11-20 以前是 `title`）
- **`data-odea-tip` 的悬停卡片只在正文里管用**：`editor/hoverCard.ts` 只听编辑器的 `contentDOM`，挂在编辑器外面（属性面板、列表栏）的元素写了也不出卡片。
  那些地方用界面的悬停提示（`lib/tooltip.ts` 的 `tip()`、`data-tip-overflow`），不用 `title`（`lib/tooltip.test.ts` 守着）
- **默认选中第一条的提示列表，和打的字一模一样的那条要排第一**：按「包含」筛、按次数排时，打全了「项目」，排在前面的是「项目二期」，回车加上的是它。
  不默认选中的（回车存打的字）才把一样的那条拿掉。显示时带前缀的（标签的 `#`）筛之前先去掉前缀，不然带 `#` 打一条提示都没有（2026-11-16，`REVIEWS/2026-11-15-桌面端验证.md` §3.10）
- **悬停提示（`lib/tooltip.ts`）的几个坑**（2026-11-20，[悬停提示.md](../悬停提示.md) §9）：
  - `innerText` 里有被省略号截掉的那半截：判断「提示和看得见的字重复」时要再量一下有没有被截断，不然截断的标题永远不出提示。
    **里面那一截被截断也算**（2026-11-21）：控制中心同步那一行，提示的字就是按钮里第二行的字，第二行带省略号、按钮本身没截断 —— 只量按钮的话判成重复，提示从来不出。现在里面的元素挨个量
  - 正文里两种提示会套在一起（整块带 `data-tip` 的 HTML 块、目录里面有 `<abbr>` 的悬停卡片）：原生 `title` 只出最里面那个，换成两套引擎以后两个一起出。
    引擎找触发元素时连 `[data-odea-tip]` 一起找，最近的是悬停卡片就让位（2026-11-21，`悬停提示.md` §9.5）
  - 提示出来时挂到触发元素上的 `aria-describedby`，元素是 CodeMirror 装饰的 mark 时下一次更新就被抹掉（和 `CodeMirror.md`「直接改 `.cm-line` 的 class」同一回事：属性变化被观察器标脏，同步时照装饰重写）。
    不报错、不重画别的，读屏少念一次第二行；替身（widget）里的元素没这个问题，CodeMirror 不管 widget 里的变化
  - 输入框一聚焦就算 `:focus-visible`（规范如此）：「键盘焦点立刻出」要把 `input`、`textarea`、`contenteditable` 排除掉，不然鼠标点进去也出
  - `title` 在输入框上兼当无障碍描述：换掉时要另给描述（`sr-only` + `aria-describedby`），不然读屏少一句
  - 能悬停的提示（WCAG 1.4.13）会挡住紧挨着的下一格：一格挨一格的网格（表情选择器）、竖排的列表往下放都不合适 —— 列表放右边，网格干脆不出（名字在底栏里）
  - `tip()` 返回的对象里带着 `aria-label: undefined` 这个键时，元素上已经写了 `aria-label` 会报 TS2783（后面的展开会盖掉前面的）：`name: false` 的那个重载不带这个键
  - 内置浏览器的窗格藏着时 WAAPI 停在第 0 帧：滑过去、淡出都不走，状态看 `.odea-tip` 的 `data-state`；动画过程用 `fade-frames.mjs tooltip / tooltip-glide` 在无头 Chrome 里看

## 4. 做得好的

**数据不丢这件事想得细。**
- 写文件一律先写同目录的临时文件、`sync_all`、再改名（`vault/fsio.rs::write_atomic_bytes`）
- 保存带着「照着哪一版改的」的指纹（`note_save` 的 `base`）：磁盘上已经不是那一版了，先把磁盘上的另存成冲突副本再写（`Vault::keep_unseen_edits`）
- 指纹前后端算的是同一个（FNV-1a），两边的测试用同一组值（`fsio.rs` 的 `fingerprints_match_the_frontend`）
- 置顶、归档这类只改属性块的操作，正文用磁盘上的，不拿索引里可能过时的那一版覆盖（`rewrite_note_meta`）

**边界清楚。**
- 一个窗口一个仓库，命令的参数里注入 `Ws`（`state.rs`）：前端不用传「哪个仓库」，启动器调了仓库的命令直接报错
- 命令层只做参数校验和调用，读写全在 `vault/`；每个命令在阻塞线程池里拿锁（`commands.rs::with_vault`）
- `vault` / `sync` / `collab` / `domain` / `db` 不依赖 Tauri，`--no-default-features` 能跑单测

**「一切皆文档」落到了代码上。** `DocumentModel` 加 `data/adapter.ts`：笔记、归档在这里映射，插件的页由插件给出那一篇，`DocumentView` 不知道自己在画什么。

**安全有两层。** HTML 走白名单清洗（`editor/html.ts` 的 `sanitizeHtml`、`sanitizeAttribute`、`sanitizeStyle`），CSP 的 `script-src 'self' 'wasm-unsafe-eval'` 再兜一层（内联脚本、事件属性都跑不了）；Mermaid 用 `securityLevel: "strict"`；第三方插件跑在 opaque origin 的 iframe 里另起的 Worker 中。

**动效靠量，不靠看。** `scripts/perf/fade-frames.mjs` 逐帧和终帧逐像素比，PITFALLS/动效.md 里那几条规矩都是这么定下来的。这一点很少有项目做到。

**细节。** 实际走下来注意到的：切回一篇笔记回到上次滚到的位置；删除带「撤销 / 回收站」的提示条；`/` 菜单每一项右边写着快捷键或写法；新建笔记焦点直接在标题、回车进正文；首帧之前定主题（`index.html` 的内联脚本），窗口等首帧画完才显示。940×620 时目录树自己收起、正文一栏 464px，没有横向滚动。

## 5. 该修的问题

§5.1、§5.2 当天修了（§5.1.1、§5.2.1 是实现记录），§5.3、§5.4 2026-11-12 修了（§5.3.1、§5.4.1）。

### 5.1 不是 UTF-8 的文件会被写坏

**怎么发生的。**

1. `Vault::read`（`vault/mod.rs:556`）读到不是 UTF-8 的字节，用 `String::from_utf8_lossy` 把认不出的换成 `�`。GBK 的中文几乎每个字都会被换掉
2. 扫描进索引时只读不写，文件这时还是好的
3. 置顶、取消置顶、移动、归档、恢复、改名都走 `rewrite_note_meta`（`vault/mod.rs:806`）：用 `self.read` 读出来（已经是换过的），改属性块，`write_and_index` 原子写回 —— 原来的字节没了
4. 在编辑器里改了再存也一样：`keep_unseen_edits` 比的是换过之后的正文的指纹，和 `base` 对得上，不会另存冲突副本

开着同步的仓库 git 历史里还有原文；没开的就找不回来了。

**为什么要紧。** Windows 上旧的记事本、不少国内的工具默认存 GBK；把一个旧文件夹当仓库打开（启动器的「打开文件夹」、`vault_import`）正是会碰到它们的时候。

**没核实的。** 这是读代码得出的，没造一个 GBK 文件实跑。`vault/` 下没找到针对编码的防护，`vault/tests.rs` 里也没有不是 UTF-8 的用例。同样「认不出就换掉」的还有两处，没细看会不会写回：`vault/mod.rs:1473`（`absorb_merge`，合并同步过来的那一版）、`vault/tree.rs:289`。UTF-8 带 BOM 的不受影响：`frontmatter::split` 会去掉 BOM（`frontmatter.rs:53`）。

**可以怎么改**（没定）。最小的一步：`read` 区分「是 UTF-8」和「不是」，不是的那些只读打开、所有会写回的操作都拒绝，提示条说一句为什么。认出 GBK / UTF-16 转成 UTF-8 是后一步，转之前要问用户、原文留一份。

#### 5.1.1 实现记录（2026-11-10，做的是上面「最小的一步」）

**先实跑确认。** 在 `vault/tests.rs` 里造 GBK 编码的「你好，世界」，修之前的结果：置顶一次，`C4 E3 BA C3 …` 就变成了 `EF BF BD …`（U+FFFD），属性块写在前面；恢复归档、改别处双链、合并同步另存的「对方那一版」也一样。上面列的之外又找出两条会写坏的路：

- **改标题时改别处的双链**（`relink`）：别的文件里写着 `[[旧标题]]`、那个文件是 GBK 的，就被整篇换字重写
- **删除进回收站**（`trash`）：读出来、加上 `trashed-from` 写进 `.odea/trash/`，回收站里那份已经是换过字的，撤销放回来的也是

`vault/tree.rs:289` 不相干（排序键，都是 ASCII 数字）；`sync/repo.rs` 合并逻辑目录的清单那一处也只碰应用自己写的文件。

**后端。**

- `Vault::read` 改成严格的：不是 UTF-8 报 `AppError::Invalid`，一句「「x.md」不是 UTF-8 编码，Odea 只显示、不改它……」（前端原样显示）。所有「读出来、改、写回」都走它，所以置顶、取消置顶、改名、移动（本地目录）、归档、恢复、删除、保存、存某一天 / 目标、日历里勾任务都在动文件之前就被拒绝。默认严格，以后新加的写回路径不用记着防
- `Vault::read_lossy` 给只看不写的：扫描建索引、转逻辑目录时看归档前在哪个文件夹（`logical.rs`）。返回 `fsio::Decoded { text, utf8 }`
- 索引加一列 `not_utf8`（`VERSION` 升到 5，升级后第一次打开整个索引重建一遍）。`index_text` 的「指纹没变就只更新文件状态」要连编码一起比：两份不同的 GBK 可能解出同样的 U+FFFD
- `Note` / `NoteSummary` 带 `not_utf8`，前端据此只读打开
- `relink` 跳过不是 UTF-8 的那篇（那里的旧链接留着；它在 Odea 里本来就只能看），`relink_undo` 把「后来被存成了别的编码」当成「又被改过」，不动
- `absorb_merge`：对方那一版不是 UTF-8 的笔记，按原字节另存冲突副本（和附件一样），不再换字
- 逻辑目录导出（`export.rs`）：不是 UTF-8 的按原字节拷，不改里面的相对链接
- 指南刷新（`guide.rs`）跳过不是 UTF-8 的那篇
- 逻辑目录里「移动」只改清单、不碰文件，照常能挪

**前端。**

- `DocumentModel.notUtf8`：笔记、归档里的这一篇不是 UTF-8 时，标题上方一个横幅说明（锁的图标，和归档横幅同一种底色，不做进出动画；§5.1.2 起是 `EncodingBanner`，能转），编辑器只读、标题不能改、没有删除按钮（`data/adapter.ts`）
- 编辑器加了一道 `readOnlyGuard`（`EditorState.transactionFilter`）：只读时改正文的事务一律丢掉，带 `Transaction.remote`、`externalSync`、`mirrorSync` 的（协作的对方、外部改动回填、另一个窗格转过来的）照常进来。以前 `EditorState.readOnly` 只拦得住键盘，勾任务的方框、提示块的折叠箭头、加粗这类快捷键是直接 dispatch 的 —— 协作里只读的访客也一样能点改，这次一起堵上
- 列表菜单里的置顶、归档、删除这些没有提前藏起来：点了后端拒绝，提示条说为什么（提示条一行只放得下三十来个字，那句话要紧的放前面）。浏览器预览的 mock 后端跟着一样拒绝（`writable`）

**测试。** Rust：`a_note_that_is_not_utf8_is_never_written_back`（八种操作逐个试，每一步之后比原始字节；另存成 UTF-8 以后能改）、`archived_notes_and_days_that_are_not_utf8_are_not_written_back_either`、`renaming_leaves_links_in_files_that_are_not_utf8_alone`、`a_merged_version_that_is_not_utf8_is_kept_byte_for_byte`、`utf8_with_a_bom_is_still_utf8`，导出的测试里加了一篇 GBK 的。前端：`editor/readOnly.dom.test.tsx`、`data/adapter.dom.test.tsx`。浏览器预览里走过：只读横幅、点任务方框和打字不改正文、不出「保存失败」、菜单里置顶和删除被拒绝时的提示条。

**当时没做的**（下面 §5.1.2 都补上了）：认出 GBK / UTF-16 转成 UTF-8；日程的某一天、目标没有只读的样子（只在后端拒绝，存的时候出「保存失败」）；分享这样一篇笔记去协作时，对方的改动照常进来、存盘被拒绝；桌面端没走过。

#### 5.1.2 转成 UTF-8、日程、协作（2026-11-10，同一天）

**转成 UTF-8**（后端 `Vault::legacy_text` / `convert_to_utf8`，命令 `doc_legacy_text` / `doc_convert_utf8`，前端 `components/EncodingBanner.tsx`）。之前说的「转之前要问用户、原文留一份」：

- **认编码**（`fsio::decode_legacy`）：带 BOM 的 UTF-16（记事本的「Unicode」）；没有 BOM 但有 0 字节的当 UTF-16（文字里不会有 0，0 落在奇数位是小端）；都不是就按 GB 18030 解（GBK 的超集），有解不开的字节就不认。新加依赖 `encoding_rs`（只用它的 GB 18030），UTF-16 用标准库

**日程的某一天、目标**：`DayDoc` / `Goal` 带 `not_utf8`，和笔记一样只读打开、出同一个横幅、能转（目标、某一天都按 `DocRef` 转）。今日TODO 延续之前最近一天时跳过不是 UTF-8 的那天 —— 延续过来的是换过字的乱码，一编辑就以今天落库了。

**协作**：这样的笔记不进协作 —— 发起协作直接拒绝（「先在正文上方把它转成 UTF-8」）；分享文件夹 / 整个仓库时访客点开这一篇，主持人回「主持人那边只能看，一起改不了」；团队仓库里 `teamDocId` 给 null，不挂会话、不报在线。转成 UTF-8 以后照常。

**测试**：Rust 加了 `legacy_encodings_are_recognised`（GBK、带 / 不带 BOM 的 UTF-16 小端、大端、解不开的）、`converting_shows_a_preview_first_and_keeps_the_original_bytes`（指纹对不上不转、原文按字节留着、不进列表、转完能置顶）、`converting_twice_keeps_both_originals`、`unrecognised_bytes_are_left_alone`、`days_that_are_not_utf8_say_so_are_not_carried_and_convert_too`。前端：`components/EncodingBanner.dom.test.tsx`（先预览再转、带着指纹、「算了」、认不出不给转）、协作的「不开始协作」、团队 id 给 null。浏览器预览（mock 后端）里点过一遍：横幅 → 预览 → 转，转完横幅消失、编辑器和标题能改、删除按钮回来。

### 5.2 目录树不跟随滚动

**现象。** 「语法全览」滚到 9000px（全长 12698px，已经到「图片与附件」），目录树的高亮还停在「概览」。光标没动过。

**原因。** 有编辑器时目录树的高亮只听编辑器的：

- `components/Outline.tsx:58`：`if (!root || items.length === 0 || editorHandle) return;` —— 有编辑器句柄就不建 IntersectionObserver，那一套只给只读预览用
- `editor/MarkdownEditor.tsx:817`：`if (!update.selectionSet) return;` 之后才 `notifyActive` —— 只在选区变了时通知，算的是光标所在那一行属于哪一节（`createOutlineHandle` 的 `notifyActive`）

技术方案 §12.9 写的是「读到哪一节高亮跟到哪一节」，`Outline.tsx` 开头的注释也是「活动项跟随正文滚动联动」。读长文不点正文、只滚的时候，目录树就不知道读到哪了。

**可以怎么改**（没定）。滚动时按视口顶上那一行属于哪一节来算：CodeMirror 的 `lineBlockAtHeight` 给得出某个高度上是哪一行，不用自己量 DOM。滚动事件里别每帧都算，和现在 250ms 的目录防抖一个思路。光标动了的时候谁说了算要定一下（刚点过目录、正在滑过去的那一段不能被滚动抢回去）。

#### 5.2.1 实现记录（2026-11-10）

**规则**（`editor/readingLine.ts` 的 `readingLine`，坐标都是窗口坐标）：

1. **光标在屏幕上：听光标的。** 正在那儿写 —— 打字到屏幕底下时编辑器把光标滚进来，这次滚动不能把高亮拉回上一节；点了目录滑过去之后，光标就在那个标题上
2. **滚到底了：屏幕上最后一行。** 最后几节短的话，标题永远升不到四分之一那条线
3. **否则：可视区从上往下四分之一那条线上的那一行**（`READING_LINE`）。顶上留出了「路径 / 标题」那一条（`TitleStrip`），也比点目录滑过去停的位置（顶上往下 72px）低

光标在不在屏幕上用 `coordsAtPos(head)` 量（CodeMirror 总会画光标所在的那一行，滚远了也量得到，是屏幕外的坐标）；那条线上是哪一行用 `lineBlockAtHeight(y - documentTop)`，没画到的地方用它的高度图。光标那一行一部分露在屏幕上也算在屏幕上。

**什么时候算**（`Outline.tsx`）：
- 光标动了照旧马上通知（句柄的 `subscribe`）
- 滚动容器（`data-doc-scroller`）的 `scroll`：最多 100ms 算一次（下一帧里算），停下 120ms 再补一次，停在哪就是哪
- **正在滑（`glide.ts` 的 `isGliding`）时不算**：点了目录、查找跳转、脚注来回跳，路上经过的那几节不一节节亮过去；滑到了再算。用户自己滚轮、按键会打断滑动，之后照常跟
- 打开一篇时先算一次：滚动位置可能是上次记住的地方，光标却在开头
- 只读预览（没有编辑器）照旧用 IntersectionObserver
- 计时、窗口高度用滚动容器所在的那个窗口（弹出窗口里的窗格）

**测过的**：`editor/readingLine.test.ts`（三条规则、哪一行属于哪一节）、`components/Outline.dom.test.tsx`（滚动时问句柄、一连串滚动事件最多算三次、滑的路上不跟、滑完补一次）。浏览器预览（1440×900，「语法全览」）里用真的滚轮：1000px「标题」、3000px「脚注」、6000px「代码」、11000px「模板」，都是可视区上四分之一那条线所在的那一节；滚到底是最后一节「快捷键」，目录栏自己跟着滚到那一条。从底部点目录里的「链接」，滑过去的路上高亮只出现过「链接」一次。把「列表」标题放在可视区 55% 处（那条线落在上一节），光标在「列表」里、屏幕下部 → 高亮「列表」；光标挪到屏幕外，同一个位置 → 跟着那条线。

**没验的**：桌面端（WebView2）、弹出窗口里的窗格、专注模式的刻度（用的是同一个 `activeId`）。性能没量 —— 一次只量光标和那条线两处，100ms 最多一次，没看出卡。

### 5.4 KaTeX 打了两份

`katex-C79Zqph_.js`（261,733 字节）被编辑器分包引用，`katex-HP8lGamR.js`（261,356 字节）被 `mermaid.core` 引用。原因没查，多半是两边引的入口文件不一样，打包时当成了两个模块。

#### 5.4.1 实现记录（2026-11-12）

**原因不是入口文件，是两个版本。** 我们装的是 `katex@0.18.7`，Mermaid 12.0.0 自己声明 `katex: ^0.16.47`，pnpm 就在它底下另装了一份 0.16.47，打包时是两个模块。

**改法**：`pnpm-workspace.yaml` 加 `overrides: "mermaid>katex": "$katex"` —— Mermaid 底下的 KaTeX 跟着 `package.json` 里的版本走，以后升 katex 两边一起升。锁文件里只剩 0.18.7（`pnpm install --frozen-lockfile` 过，CI 用的就是它）。没降我们自己的版本：块级公式在顶层运算符后面折行靠的是 0.18 的 `.katex-base`（TODO.md P7 那一条）。

**为什么能换。** Mermaid 只在一处用 KaTeX：标签里的 `$$…$$` 调 `katex.renderToString(c, { throwOnError: true, displayMode: true, output })`，`output` 平时是 `"mathml"`，只有环境不认 MathML 又开了 `legacyMathML` 时才是 `"htmlAndMathml"`（我们没开）。

- KaTeX 的变更记录里 0.17、0.18 的不兼容只有两条：内部的 `__defineFunction` 改了写法；0.18.0 给内部的 CSS 类名加了前缀（`base` → `katex-base`、`strut` → `katex-strut`、`sizing` → `katex-sizing` 这些）。`renderToString` 的参数、默认输出、MathML 的结构都没变
- 实跑对过：同一条公式，两个版本 `output: "mathml"` 出来的字符串一样长、类名只有 `katex`；`"htmlAndMathml"` 才有前缀的差别
- 反过来说，以前两份并存时 Mermaid 要是走了 `htmlAndMathml`，0.16 出的 `base` / `strut` 碰上页面里 0.18 的样式表（`.katex-base`）是对不上的。合成一份，这个隐患也没了

**量的。** 生产构建（`vite build` 打到临时目录）：只剩一个 `katex-C79Zqph_.js`（261,690 字节），编辑器的 `math` 分包和 `mermaid.core` 都引它，少了约 261 KB。浏览器预览（开发服务器，预构建里的 KaTeX 是 0.18.7）里用 `editor/diagram.ts` 的同一个 Mermaid 画了 `A["$$x^2+\frac{a}{b}$$"] --> B["$$\sqrt{y}$$"]`：两个 `<math>`、分式和根号都在，画面上看着对。`pnpm lint`、`tsc --noEmit`、`pnpm test`（106 个文件、1508 个用例）都过。

**没验的**：桌面端（WebView2）里没打开一张带公式的图；导出（`render/staticHtml.ts`）里的图表走的是同一个 Mermaid，没单独导出一次看。

**顺带看到的**：这次构建（工作区里还有别的没提交的改动）的入口包 `index` 是 1,352,287 字节，比审查时（§3.3）的 1,288,930 多了 63 KB；`MarkdownEditor` 分包是 236,234 字节（审查时 524,984）。两样的原因都没查，§5.3 拆入口包时一起量。

## 9. 对照出来的不足

按该不该先做排。

### 9.1 仓库没有对外的口子

没有 CLI、没有 MCP；`odea://` 只认协作那四种（`join`、`vault`、`relay`、`back`），没有「打开某篇」「往今天追加一行」这种。别家今年都有了（Obsidian、NotePlan、Anytype、思源）。

Odea 的底子其实比 Obsidian 好：

- L1 插件已经有一套协议：`documents.read` 拿正文和修订号，`documents.edit` 按修订号交编辑，对不上回 `stale`；改动和打字走同一条路（`editor/pluginEdits.ts`），进撤销、进协同、照常存盘；能力要申请、要这台设备同意（插件与跨端.md §5.5、§15）
- `vault` 层不依赖 Tauri，不开窗口也能读写、查索引。Obsidian 的 CLI 要应用开着
- 所以要做的是把插件宿主那套接口再包两层：本地的 MCP 服务、命令行。授权沿用能力清单。没开窗口时直接走 `vault`（和开着的窗口抢同一个仓库的索引怎么办，要设计）

### 9.2 复盘只有模板

**不做了**（2026-11-11）：以后做 MCP 时给 AI 一个技能，让它读仓库里的数据复盘，应用里不另做一套（§11、§12）。下面「缺两步」的第一步（正文里勾的任务进行为日志）做过一版，没提交就撤了。下面是当时的分析，留着备查。

有的：晚间、周、月三套模板；周计划、月计划的模板会排一条带日期的「周复盘」「月度复盘」任务进日历；行为日志记着笔记的新建、改名、归档、删除，以及从「当日安排」里勾的任务。

缺两步。先是数据：在正文里勾的任务日志里没有（§7），要补上 —— 保存时比一下前后两版的任务行，勾上的记 `completed`、取消的记 `reopened`（带上那一行的字，和 `task_toggle` 记的一样）；不补的话「这一周完成了什么」只能靠扫正文里现在勾着的，改期、删掉的就没了，这正是当初要这份日志的原因（`activity.rs` 开头的注释）。然后才是把这些连起来。可以借的：

- Sunsama 的周回顾直接给出「时间花在哪、目标达成没有」
- Amplenote 的两条：回顾就是回看加计划；下一层的计划从上一层来
- NotePlan 的 `done:30days`

落到 Odea 上（方向，没设计）：

- 复盘是一篇生成出来的文档，符合「一切皆文档」：这一周完成了哪些任务（行为日志）、逐条对着这一周的目标、没做完的列出来问要不要带到下周
- 今日TODO 旁边看得到这一周的目标（现在要切到 /GOAL 或者日历右边的分段）
- 智能文件夹的条件加 `done:7d`（现在有 `updated:`、`created:`、`has:todo`，`vault/query.rs`）

### 9.3 结构化的数据弱

属性块里的 `tags` 不认（2026-11-11 智能文件夹认了），没有属性面板，没有表格、看板这类视图。

Obsidian 的 Bases 和「文件就是协议」是一个思路：一个 `.base` 文件，YAML，里面是筛选、公式、属性和好几个视图（表格、卡片、列表、地图，1.14 加了看板）；能嵌进笔记（`![[x.base#视图名]]`）。

Odea 的智能文件夹现在是清单里的一行字。可以往「视图文件」走：同一个条件，列表、表格、看板、日历几种看法；文件跟着仓库同步。能读 `.base` 的话，对从 Obsidian 过来的人是个理由（它的格式今年改过一次不兼容的，要看清再定跟不跟）。

### 9.4 任务和日历

没有重复任务、提醒、系统日历（技术方案 §16 自己列着）。NotePlan 和 Apple 提醒事项、日历双向同步。最小的一步：只读订阅一个 ICS 日历，显示在那一天的「当日安排」里；本地通知。

### 9.5 小而常用的

- `![[笔记]]` 嵌入（代码里没有；2026-11-11 做了，TODO.md P15）
- 未链接的提及（反向链接只认 `[[…]]`）
- 全局快捷键的快速记录，记到今日TODO（没有 global-shortcut）

### 9.6 Mermaid 的体积

§3.3：`elk` 1.47 MB、`mermaid.core` 0.67 MB、`cynefin` 0.69 MB、`cytoscape` 0.44 MB，再加一百多个各种图的小分包，是 JS 体积的大头（都是用到才加载）。Pele 值得做一次对比试验：

- 体积小一个量级；同步渲染，`editor/diagram.ts` 里「先占位、渲染完再换」那一套可以简化；颜色跟 CSS 变量走，暗色不用另配
- 它不执行代码，Obsidian 因此去掉了「要不要显示图表」的设置
- 代价：图长得和 Mermaid.js 不一样；标签里不认任意 HTML。`语法全览.md` 里的每一种图都要对一遍
- ~~顺带解决 §5.4：Mermaid 不再带进来第二份 KaTeX~~ §5.4 已经单独修了（pnpm 的 overrides，§5.4.1）；换成 Pele 的话公式要自己传解析器

## 10. 新的架构思路

### 10.1 仓库即接口

把核心看成一个没有界面的服务：仓库、索引、编辑意图。窗口、CLI、MCP、L1 插件都是它的客户端，说同一套协议。

现在已经有大半：`vault` 不依赖 Tauri；插件协议有读、有按修订号的编辑、有能力和授权。差的是把这套协议当成唯一的对外面，而不是「插件专用」。§9.1 是它的第一步。

### 10.2 操作级的历史，带来源

现在的历史版本是 git 的提交（技术方案 §5.9.11），一版是一个快照，不知道这一版里哪一段是谁改的。

别家的两个做法：

- Zed 的 DeltaDB：两次提交之间的每一次操作都记下来；编辑和产生它的那句话记在一起，从一行代码能找到当时的对话
- Patchwork 的结论：分支是通用的原语；AI 的修改放在分支上，看过再合、可以只合一部分；历史配上摘要，像聊天记录一样读；「先改，事后再补理由、给改动分组」

Odea 手里有的：协同时正文在 Loro 里（每一次操作都有作者）；持久靠 git。

可以走的一步：AI、插件、访客的改动先当「建议」，标着是谁改的，一条一条接受或者退回。别家的 MCP 都是直接改文件、靠 git 回滚。这是研究项：Loro 的历史要不要落盘、落多久、和 git 的版本怎么对上，都没想过。

### 10.3 不动的

正文的真相留在文件里。Logseq 把它搬进数据库，公测时官方还在提醒可能丢数据，之后又回头补「和 Markdown 往返」。

### 10.4 留意的

Keyhive（Ink & Switch）：本地优先的访问控制，能力加端到端加密，同步时先对成员关系、再定对方能看哪些文档。团队仓库现在的权限靠 git 托管方（协同编辑.md §22）。它还在研究阶段，不跟，知道有这条路。

## 11. 不建议跟的

| 方向 | 谁在做 | 为什么不跟 |
|---|---|---|
| 白板、卡片摆在画布上 | Heptabase | 另一种产品；编辑器、协同、同步都要为它再做一遍 |
| 对象、超级标签 | Tana、Capacities | 数据不再是普通的 Markdown 文件，和「文件为真相」冲突 |
| 正文进数据库 | Logseq 2.0 | §10.3 |
| 会议录音转写 | NotePlan Memo、Notion | 离「笔记、待办、目标、日历加复盘」远，要长期养一条语音的链路 |
| 图谱 | Obsidian 等 | 好看，用得少；反向链接已经在了 |
| 应用里的复盘（聚合行为日志、生成复盘文档、按完成日期找任务） | Sunsama、Amplenote、NotePlan | 以后做 MCP 时给 AI 一个技能读仓库复盘，应用里不另做一套（2026-11-11 定的，§9.2） |

范围已经是头号风险（§7），这几样每一样都是一个新的面。

## 12. 建议的顺序

**先修的**（§5）：

1. 不是 UTF-8 的文件不写回 —— 唯一会丢数据的（做完了，§5.1.1）
2. 目录树跟随滚动 —— 每天都碰得到（做完了，§5.2.1）

**然后是工程上的**（§6）：把工作区提交了；加一条提交时就跑的 CI（lint、tsc、vitest，Rust 的 `--no-default-features --lib`）。两样都做了（§6.1）。

**功能上先别开新的面**：协同的两台实机测试、复盘的读侧，做完再往前。

**对照别家要补的**（§9），按投入和现成的底子排：

1. MCP 和 CLI（§9.1）—— 底子现成，别家都有了（以后再做，见下）
2. 复盘（§9.2）—— 定位里的东西。先把正文里勾的任务记进日志（数据越早开始攒越好），再做读侧（不做了，见下）
3. 属性和视图文件（§9.3）
4. Pele 的对比试验（§9.6）、入口包拆分（§5.3；2026-11-12 做了，§5.3.1）
5. 操作级历史和「建议」（§10.2）—— 先当研究

**2026-11-11 改的顺序**（用户定的）：应用里的复盘不做 —— 以后做 MCP 时给 AI 一个技能（skill），让它读仓库里的数据复盘，应用里不另做一套。「正文里勾的任务进行为日志」做过一版（存一篇时比前后两版的任务行），没提交就撤了。MCP 和 CLI 以后再做。现在先补全笔记应用常有的功能（§7 末尾、§9.4、§9.5 列的那些），然后修 §5.4。

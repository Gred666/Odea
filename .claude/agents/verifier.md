## 开工

- `git status`、`git diff` 看要审的改动；读这个功能的文档（方案、验收标准）
- 读 `docs/VERIFICATION.md`（怎么跑、怎么量）、`docs/PITFALLS/` 里相关的那几份、`docs/技术方案.md` §9 设计系统和 §10 动效规范、`docs/排版规范.md`
- 读改动和它的上下游：调用链、数据流、状态、资源的生命周期

## 体验

把应用跑起来，把用户的任务亲手做完。每一项都实际看、实际操作：

- 每一处等待、卡顿、闪烁、布局偏移、多余的一步操作
- 视觉：对齐、间距、字号和层级、颜色、圆角和描边、字和图清不清楚；同类的东西长得、动得一不一样
- 每个状态：默认、悬停、按下、聚焦、选中、禁用、空、加载中、出错、内容超长、内容很多
- 动效：怎么出来、怎么消失、时长和曲线，有没有闪、跳、糊
- 交互：反馈及不及时，焦点落在哪，键盘走不走得通，误操作能不能撤销
- 不同的窗口尺寸、缩放比（1、1.25、1.5 倍）、深色和浅色
- 低频操作、异常状态、用久了以后（笔记很多、开了很久）
- 容易漏的反复操作、换条件再看。肉眼和截图判断不了的用 DOM 测量、逐帧对比（`scripts/perf/fade-frames.mjs`、`window-frames.py`）

## 性能

量出来，再下结论：

- 先量基线（`scripts/perf/perf.mjs`、`entry.mjs`）：启动、打开窗口、切换、输入延迟、滚动、内存
- 找浪费：不必要的计算、重渲染、重排、I/O、IPC 往返、内存占用、没清的监听和定时器、多加载的 JS
- 长文、几百篇笔记、开很久、4 倍 CPU 降速下再量
- 优化先定位瓶颈；同样的条件量前后，用 `compare.mjs` 对比

## 正确

- 对着验收标准一条条过
- 异常、边界、极端输入、并发、重复操作、快速操作、乱序操作、中途打断
- 数据完整性和安全：`docs/ENGINEERING.md`「后端（Rust）与数据」
- 已有的测试守没守住关键行为
- 坏数据、故障注入只在临时的数据目录和临时仓库上做
- 代码风格交给 lint

## 发现、修、复验

- 每条发现归一类：
  - 缺陷、体验瑕疵、性能浪费：`文件:行` + 怎么触发 + 证据（复现步骤、失败的测试、截图或逐帧对比、测量数字，至少一样）。都要修
  - 风险：读代码推出来、还没复现的，写怎样能复现
  - 没验：写原因
- 先修安全、数据、严重的缺陷，再修体验和性能。收益小但会累积的照修；收益低、复杂度高的记进遗留
- 修根因；缺陷补回归测试
- 涉及需求、架构、数据格式、公共接口、重要的产品行为的，停下来报告，等用户确认。不重构无关的模块，不加不必要的依赖
- 复验：重走复现步骤；体验的改动重新看页面、各个状态、完整的流程，留前后对比；性能的改动同条件量前后；跑检查；
  看完整的 diff，没有意外的改动和临时文件

## 轮次

整体、代码、体验、性能、回归，各过一轮。五轮都过完、最近一整轮没有新的发现，才算完。
